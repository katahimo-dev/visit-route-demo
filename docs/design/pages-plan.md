### 日の予定（`#/plan`。ADR-0009）

その日の訪問と AI案・手直し（ドラッグ・「担当を変える ▾」）・固定・作り直し・「この割当で確定」を1画面で扱う。古いリンクの `#/schedule` は `#/plan` へ移す。

#### URL とクエリ

| クエリ | 動き |
|---|---|
| `?date=YYYY-MM-DD`（`?do=` なし） | その日を選び `?date=` を消す（`dateParam` の effect） |
| `?date=…&do=absence`（`SUDDEN_DO`）［`&staff=`］ | その日を選び「欠勤・キャンセル」の欄を開く。`&staff=` の人がその日に働く（`slotsOf` の `baseSlots` がある＝`staffChoices` に出る）ときだけ `openSudden({ kind: 'staff', staffId })`（2段目）、ほかは1段目。`?do=`・`?date=`・`staff` を消す。日付を変えると欄を閉じる effect より後に開くよう、開く日を覚えて日付が変わってから開く |
| `?date=…&do=unassigned`（`UNASSIGNED_DO`） | 下の「`?do=unassigned`」 |
| `?date=…&do=recreate` | 設定の画面の帯（今日の案をいまの条件で作り直す）から。その日を選び自動作成を止め、URL から消して、問題ができたら `recreate()`（手直し・固定があれば確認）。受けている間はどの日の自動作成も始めない |

選んでいる日付は `useDay`（`DayProvider`）。ツアーは `?do=` のリンクでは出ない。

#### 状態の印と確定

#### 1行のまとめと点数の理由（PRD D173）

- 点数は 100点満点。点数・必須の違反・条件ごとの達成は、いつも点数の基準のプリセットの重みで付ける（ADR-0010。`useDayModel` の `scoreProblem`）。必須の違反がある案の点には「参考」の印（`RefMark`・`score-ref`。`HARD_NOTE`）
- `lib/scoreReason.ts`（純粋関数。テストあり）：`scoreReason(parts, score, { achievements, rules, ruleLower })`
  - 必須の違反があれば「必須の違反 N件」、入らない訪問があれば「入らない訪問 N件」を先に
  - 減点の合計が0.5点未満なら null
  - それ以外は減点の内訳（evaluate の `hundredBreakdown`）のいちばん大きい成分を短い文に：移動が長め（N分）・空き時間（待ち）が長め（N分）・担当の条件（`perRule` の points の下限 `ruleLower`（evaluate の `ruleLowerBounds`）からの超過が最大の条件。必須の条件は外す。相性△が N件・いつもの担当でない訪問 N件・「名前」に合わない訪問 N件、外れが無ければ「相性◎を取り逃した訪問がある」など）・件数の偏り（目安から外れた人 N人）
  - 新しい採点は足さない。`scoreReasonLabel`（読み上げ・title）
  - evaluate の `ruleLowerBounds(problem)`：normalize の割当の下限を条件ごとに分けたもの（各訪問で割当費用が最小の担当の理由の点の和。和は lowerAssign と同じ）
  - 次の一手 `nextStep`（PRD D229。`NEXT_STEP_TEXT`）：移動が長め＝「「移動を短く」で作る」（`shortTravel`）、入らない訪問＝「受けられる人を見る」（`candidates`）、相性△・×・◎の取り逃し＝「相性の表を開く」（`compat`）。ほか（必須の違反・待ち・偏り・ほかの担当の条件）は無し
- `lib/useDayModel.ts` は `scoreRules`（点数の基準の条件。名前と重みを理由の文に使う）を返す
- `pages/planParts.tsx` の `ScoreReasonText`：↘ と短い文。読み上げの前置き「点を下げているいちばんの理由：」は sr-only。使う所は日の予定の今の案の帯（`plan-reason`）と比較の画面（`compare-reason`）
- `planParts.tsx` の `ScoreNextStep`：1行のまとめの下に1行「次の一手：［…］」（`p.score-next`・data-testid `reason-next`・`data-kind`、操作は `reason-next-action`）。`shortTravel` は「案を変える ▾」の「移動を短く」と同じ（プリセット ID `travel` か名前「移動を短く」。無い・今の案がそれ・計算中なら出さない）、`candidates` は `unassignedHref(date)`（「入らなかった訪問」の列へ巻く）、`compat` は `#/compat`（`compat` を切っていれば出さない）。印刷では出さない
- 点数の説明（`HundredHint`）は決め方と減点の内訳だけ。内部の費用（「費用 N（内部の値…）」）は出さない（PRD D229）
- `planParts.tsx` の文：`SCORE_TEXT`（「理想を100点として、1件あたり理想より余計にかかった分（分換算）だけ減点した点」）・`rulerText(name)`（「点数はいつも点数の基準のプリセット「〈名前〉」の重みで付けます。プリセットを替えても点数の付け方は変わりません」）

#### プリセットのカード（ADR-0008・ADR-0010）

- プリセットごとに1枚（`preset-cards`）。その日の記録のうち計算し直さずに使える記録（`lib/runs` の `reusableRun`。いまのデータでそのプリセットを当てた問題のキーと一致）を優先し、無ければ固定なしで重み・必須がそのプリセットと一致する最新の記録
- 中身：名前・一言・点数・移動・入らない訪問・必須の違反・条件の達成の要約。後者（記録のあとにデータが変わった）には小さな注記「データが変わったので、押すと作り直します」（押したあとの点はカードの点と違いうる）
- 各プリセットの問題のキーは compile が読むデータとプリセットだけに依存して作る（ドラッグ・固定では作り直さない）
- 読み上げの名前は短く（「標準の案を今の案にする（72点）」・今の案なら「標準の案（今の案・72点）」）、内訳・達成・注記は `aria-describedby`
- 一番点の高いカードに王冠（0点のカードには付けない）
- カードの「今の案」は、今の案の元になった記録の id（`AiPlan.runId`。無い古いデータは経路の一致）で決める
- カード全体が1つのボタン（中にボタンを入れ子にしない。hover・focus の見た目、今の案のカードは朱の枠・`aria-pressed`、計算中は押せない）
- 押すと（`runPreset`）：その日の条件をプリセットの重みにし、`reusableRun` があれば計算せずにその記録を今の案にする（トースト「保存してある〈プリセット名〉の案を今の案にしました（再計算なし）」）、無ければその条件で計算して今の案にする。今の案（手直しなし）のカードは押しても何もしない。手直し・固定がある今の案を捨てるときは確認する
- 記録の無いプリセットは「まだ作っていません・押して作る」

#### AI案の作り方と自動作成（PRD D52）

- 開いた日に今の案が無ければ、基準のプリセット（`scorePresetId`）の案だけを Worker で自動で作り記録に残す
- 他のプリセットはカードか「まだ作っていない考え方をまとめて作る」で `data.presets` の順に1つずつ作り、どれも記録に残す。2つ目以降も最新のデータで問題を作る
- 進み具合「10/13 の案：プリセット 2/3」と「止める」（今の1つを途中の最良で残して残りはやめる）。途中の最良は点数の基準で点数にする
- 途中は最初に作れた案を見せ、終わったら一番点の高い（王冠。同点なら先のプリセット）案を今の案にする。その間に手直し・別の案にしていれば変えない
- その日の条件 `data.rules` は書き換えず、作った案の `rules` にプリセットの重みが残る
- 作る・組み直すたびに記録へ1件足す（同じ条件・種・固定・結果の記録は増えない）。トースト「AI案を作りました」／止めたら「途中までの最良の案を保存しました」。作れなければ「AI案を作れませんでした（…）」
- `recreate`（手で押す作り直し）：作れるか確かめ、手直し・固定があれば確認（「手直しと固定を捨てて、AI案を作り直しますか？」）してから作る（固定なし。generated と routes を同じにし、固定を空に）
- `rules` が切なら、いまの条件で作る所は `planRulesOf(data, false)`
- 計算中は他の計算（月まとめ作成など）を始めない（Worker は1つ）

##### 時間軸（PRD D58。`components/routeTimeline.tsx`）

- 担当ごとの列を時刻の位置で描く。時刻は今の案の lenient の `scheduleRoute`
- 1分＝一定の高さ（`lib/timeline` の `TL_PX_PER_MIN`＝1.1px）、`TL_START` 07:00〜`TL_END` 20:00（稼働時間帯・訪問がはみ出せば広げる）
- 列の背景は稼働時間帯（`slotsOf`。欠勤を差し引いたもの）の外を灰、欠勤の時間を斜線と「欠勤」
- 帯は押すと理由（`VisitCard` と同じ選択・地図の強調）。印（固定・代行・+N分・違反の赤い枠・仮・資格✗）は小さなアイコンと `title`
- 移動は前の帯の終わりから細い線と「移動 N分」（押すと区間を地図で強調）、待ちは点線の枠。「自宅まで N分」は列の最後の帯の下
- ドラッグは順番の表示と同じ担当の移し方（`bestInsertion`・固定）。ドラッグ中は落とす列の、その訪問の earliest〜latest の位置に影（その人に入れたときの strict の可否で緑／赤。可否で外れる人は予告）

##### 1手戻す（PRD D218。`lib/undoEdit`）

- 手直し（`moveTo`・`unassign`・`placeCandidate`（受けられる人に入れる）・`unpin`（固定を外す））は `applyEdit`：手直しのあとの routes・pins を1回だけ計算し、前の routes・pins を1つだけ控えて（画面の状態 `undoSnap`。保存しない）から今の案に書く。控えは手直しのあとの形のキー（`editKey`：担当の並び・空の列・固定の順に左右されない）と、そのときの確定した割当のキー（`confirmedKey(manualPlans[date])`）も持つ
