### 条件の重み（`#/rules`）

点数の基準（ふだんの考え方）の重みを直す画面（ADR-0035。PRD D233）。メニューの「設定」の「条件の重み」のタブ（訪問の種類・特性の項目も同じく設定のタブ。見出しの下に設定のタブ。PRD D275）。`lead`「ふだんの考え方（点数の基準）の重み。月のまとめて作る・自動作成・作り直しはこの重みで作ります」。「点のしくみ」の説明（重み1＝1件あたり移動10分ぶん・必須）、その下に直している基準のプリセットの名前（`rules-basis`。「点数の基準」は `Term`）と、日の予定の「この日だけ試す重み」はその日の「AI にもう一度作らせる」だけに使いここで直すと基準に戻る旨（`rules-trial-note`）。作り直しの帯（`RebuildBand`。この日だけ試す重みがプリセットと違うときの案内と `SavePresetForm` も。[pages-common.md](pages-common.md)）が出る画面。

#### 条件

- 条件ごとの行：名前（`data.rules` の名前。ふだんは文字（`rule-name`）で、文字のボタン［名前を変える］（`rule-rename`）で入力欄（`rule-name-input`。Enter・欄を離れると決め（名前が変わっていなければ書かない）、Esc で取り消してフォーカスはボタンへ。変換中の Enter・Esc は変換のもの。空なら型の名前）。PRD D271）・種類・重みのスライダー（0〜5）・必須の切り替え・消す。重み・必須は `scoreRulesOf(data)`（基準のプリセットの型の重み）に下書きを当てて出す。同じ型の条件は同じ重みになる。名前・足す・消すはすぐ保存（`update`）、重み・必須は下書き（次の節）
- 消すときは独自の確認（「条件「〈名前〉」を消しますか？」）。必須の条件は本文に「必須の条件です。消すと「守らなければ担当にしない」決まりが無くなり、合わない人にも担当が入ることがあります。」（PRD D271）
- 重み・必須の下書き（PRD D286。ADR-0048。`lib/weightDraft`）：スライダー・必須の切り替えは保存せず画面の state（型ごとに触った欄（重み・必須）だけ。直している基準のプリセットの id と組）に置き、保存済みに重ねて出す（別のタブで変わった触っていない欄はその値で出し、確定でも上書きしない）。保存済みと同じ値に戻した欄・型は下書きから外れる
  - 違う行（`is-draft`・`data-draft`）：左に注意の帯（`--warn-line`）と淡い地（`#fffaf0`。狭い画面はカードの枠と帯）、重みの欄に印「変更あり 3→2.5」（`rules-draft-mark`。`changeText`。0 は「0（使わない）」、重みを使わない必須は「必須」）
  - 確定の帯（`rules-draft-bar`。下書きがある間だけ。画面の最後に置き `position: sticky; bottom: calc(var(--bottom-tabs-h) + 8px)` で巻いても見える。390px はボタンを横に同じ幅で1行。印刷では出さない）：「変更あり」の札と「重みの変更は、確定するまで保存しません」、文字のボタン「取り消す」（`rules-draft-discard`）と主ボタン「変更を確定（N件）」（`rules-draft-confirm`。N は変わった型の数）。その間「条件を足す」は枠（主ボタンは1つ）
  - 確定：独自の確認（見出し「重みの変更（N件）を確定しますか？」、確定「確定する」・取り消し「編集を続ける」）。本文は `confirmBody`：「変わる条件：」と「・〈名前〉：前→後」、点数の基準のプリセット「〈名前〉」の重みになり月のまとめて作る・開いた日の自動作成・作り直しと画面の点数に使う・試す重みも基準に戻る、影響する日（`draftStaleDays`：確定したあとのデータで今日以降の案と取り消しでない訪問のある日のうち `rulesStale` の日。「N日（未確定 a日・確定済み b日）は作った重みが無くなるので「条件が変わった」になり、作り直しの帯と月の予定の要対応に出ます。作り直すのは未確定の日だけで、確定済みの日は作り直しません。」。0日なら「…になる日はありません。」）。確定で `update(d => applyDraft(d, 下書き))`（d の保存済みに触った欄を重ね、型ごとに `setBasisWeight`。確認の間に別のタブで点数の基準が替わっていたら書かず「点数の基準が替わったので、重みの変更は確定しませんでした」）と知らせ「「〈名前〉」の重みを確定しました（N件）」。確定・取り消しのあとフォーカスは画面の見出し
  - 取り消す：確認なしで下書きを捨て、知らせ「重みの変更を取り消しました」
  - 下書きのまま離れる（`components/useLeaveGuard`・`lib/leaveGuard`）：アプリの中の別の画面へのリンク（`#/…`。メニュー・下のタブ・設定のタブ・帯のリンク）は捕捉の段で止めて独自の確認（`leaveDialog`：「重みの変更を捨てて、画面を移りますか？」「確定していない重みの変更（N件）があります。移ると捨てます。」「捨てて移る」（危険の色）／「編集を続ける」）。確定なら同じリンクを押し直す。コマンドパレットも移る前に確かめる。再読込・タブを閉じるは beforeunload。ブラウザの戻るは止めない（ADR-0023 と同じ）。下書きがある間は別のタブの変更の知らせを「保存すると上書きします」の側にする（`useDirtyMark`）
  - 整合：点数の基準を替える・基準のプリセットを消す・「初期値に戻す」で下書きを捨てる（下書きがあれば、基準のラジオは独自の確認「点数の基準を「〈名前〉」に替えますか？」「確定していない重みの変更（N件）は捨てます。」「捨てて替える」（危険の色）／「編集を続ける」で、断れば替えない。消す・初期値に戻すの確認の本文にも「確定していない重みの変更（N件）は捨てます。」）。案内ツアーの「今日の予定を開く」・まとめて作るの知らせの［月の予定を見る］も移る前に `confirmLeave` で確かめる。条件を消して型の条件が無くなった型・プリセットの節で保存済みが同じ値になった型は外す（`pruneDraft`）。足した条件はその型の下書きの値で出る
  - 作り直しの帯は保存した値で数えるので、下書きの間は出ない
- 条件を足すときの重み・必須は `addRule`（押した時点のデータで、試す重みが当てはまるプリセット `trialPresetOf`（基準を先に見る）、無ければ基準のプリセットのその型。プリセットが無ければ型ごとの既定）
- 狭い画面（600px 以下。PRD D220）：条件の表（`narrow-rules`）は1つの条件を1枚のカードに（[pages.md](pages.md) の「狭い画面の表」）。1行目に名前（文字と［名前を変える］）と「必須」の切り替え、続けて「種類」（札と説明）・「重み」（スライダーは幅いっぱい）、消すは右下。スライダーと必須は横に巻かずに見える
- 「詳細設定」（`rules-advanced`。`details` で畳み、読み直すと畳む）：乱数の種（`Term` `seed`）

#### プリセットの節（`preset-section`。ADR-0008）

- プリセットごとに名前・一言・型ごとの重み（0〜5、0.5刻み）・必須を編集（`preset-edit`。変えるとすぐ保存）
- 消す（最後の1つは消せない。独自の確認）
- 狭い画面（PRD D220）：見出し（`narrow-preset-summary`）の名前は1行（入らなければ「…」）、一言は次の行。重みの表もカード（1行目に条件の種類と必須、続けて重み）。「基準の重みを写して保存」「初期値に戻す」の行（`narrow-stack`）は縦に幅いっぱいで並べ、文字を折り返さない
- 「基準の重みを写して保存」（`SavePresetForm from="basis"`。基準のプリセットの重みを写して名前を入れて足す。6つまで。PRD D235）
- 見出しの印：基準のプリセットに「点数の基準」、この日だけ試す重みが基準と違うプリセットに当たるときだけそのプリセットに「試す重み」
- 基準のプリセットの重み・必須をこの節で変えても、表と同じく試す重みを基準にそろえる（`patchPreset`）
- 「初期値に戻す」：初期の3種に戻す。点数の基準も標準に。確認を出す
- 「点数の基準」のラジオ（`score-ruler-choice`。ADR-0010）でプリセットを1つ選ぶ（替えると試す重みも新しい基準にそろえる。ADR-0035）。基準のプリセットを消すと残りの先頭に移り、確認の文に出す
- 説明：ここで選んだプリセットがふだんの考え方。月のまとめて作る・自動作成・作り直しはこの重み・必須で作り、画面の点数（100点満点）もこれで付ける。上の表はこのプリセットの重みを直す。日の予定でプリセットを押して試す重みを変えても点数の付け方は変わらない
- `rules` を切ると、この画面は開けず、作るときは点数の基準のプリセットの重みを使う（`planRulesOf`）

### 特性と条件の入力（`components/conditions.tsx`。ADR-0002）

- 特性のあり/なしは「未確認・あり・なし」
- 条件は相手の項目ごとの1行のチェック表で、何も選ばない項目は問わない
- あり/なしの条件の「なし」は `is false`（未確認の相手は満たさない＝安全側）。`not` は画面からは作らない（前からある `not` は「そのほかの条件」に出して消せる）
- 保存の形は `Condition[]` のまま
- 使う所：〈スタッフ〉・〈利用者さん〉の編集の欄・訪問の種類の担当に必要な条件・空き状況の〈スタッフ〉の条件

### 訪問の種類（`#/types`。ADR-0012。PRD D36）

- `lead`「訪問の種類（介護・リハビリなど）と、担当する〈スタッフ〉に必要な条件を決めます」
- 種類の一覧（`types-table`）：色の丸・名前・標準の所要・担当に必要な条件の文・使っている訪問とパターンの数
- 足す・直す：名前 1〜20字・色 0〜7・標準の所要 5〜720分・担当に必要な条件（〈スタッフ〉の項目ごとの1行のチェック表＝`components/conditions.tsx`）・メモ。20を超えては足せない
- 消す：「〈名前〉を使っている訪問 N件・定期パターン M件は種類なしになります」の確認。消すと `typeId` を null にする

### 特性の項目（`#/items`）

- `lead`「〈スタッフ〉や〈利用者さん〉の特性（資格・ペットなど）を決めます」
- 項目（型：choice・multi・flag・number など）と選択肢を足す・直す・消す（選択肢を消すときは独自の確認）。項目「資格」の選択肢は週の資格のチップ・バッジに使う
- 狭い画面（PRD D220）：〈スタッフ〉・〈利用者さん〉の項目の表は1つの項目を1枚のカードに。1行目に名前の入力欄、続けて「種類」・「選択肢（人数）」（見出しを上に置き、選択肢の一覧と足す欄は幅いっぱい。`narrow-block`）・「使っている条件」、消すは右下

### 案を比べる（`#/compare`。ADR-0005・ADR-0010。PRD D19・D22）

- 日の予定の「案を変える ▾」の「2つの案を比べる」・振り直しの帯・パレットから開く（メニューには出さない。PRD D275）。開いているあいだメニュー・下のタブの今の画面の印は「予定」
- 見出し「案を比べる」。`lead`「選んでいる日の、条件を変えたAI案を2つ選んで比べます（案が1つならここでもう1案作れます）」（1行の説明。PRD D236）

#### 中身

- その日の記録と「今の案（日の予定の手直し後）」から任意の2つを A・B に選んで比べる。A と B に同じ案を選ぶと入れ替える。確定した割当との比較はしない
- 条件の差（重み・必須が違う条件の一覧）
- 合計点・移動・待ち・距離・入らなかった訪問・必須の違反、条件ごとの達成/違反。採点は A・B とも点数の基準のプリセットの同じ重み（`evaluate.score`。`score-ruler`「下の点数は A・B とも点数の基準のプリセット「〈名前〉」の重みで付けています。」）
- 記録の表の合計点の下に点数の理由（`compare-reason`。案ごとに `achievements` を取る）
- 記録の表に乱数の種は出さない。表の下の「詳細設定（記録ごとの乱数の種）」（`compare-advanced`。`details` で畳む）に記録ごとの種（PRD D229）
- 担当ごとの順番の左右比較
- 地図（A：点線、B：実線。線は担当の色。訪問・区間・「自宅まで」・担当を押すと日の予定と同じに強調・絞り込み（`lib/routeView`。[pages-plan.md](pages-plan.md)）、画面の外なら `MapDock`）
- 記録の一覧：「日の予定で開く」（その記録を今の案にする。`planOfRun`）・「試す重みを〈案〉と同じにする」（この日だけ試す重みの重み・必須を記録と同じにする。ふだんの重み＝点数の基準は変えない。確認「この日だけ試す重みを #N と同じにしますか？」・知らせ「この日だけ試す重みを #N と同じにしました」。ADR-0035）・「消す」
- 欠勤の振り直しの記録（「欠勤前」・案A・案B）は [pages-plan-absence.md](pages-plan-absence.md) の「比較の画面での振り直し」
- 狭い画面（PRD D220）：記録の表（`narrow-runs`）は1つの案を1枚のカードに。1行目に A・B の選択と案の名前（乱数の種）、続けて「作った時刻」・「合計点」（点数の理由も）・「移動」・「入らない」、操作（日の予定で開く・試す重みを同じにする・消す）は右下。A・B に選んだカードは地を淡く
- 空の画面（`compare-empty`。`compareEmptyGuide`。［日の予定で案を作る］）

#### もう1案作って比べる（PRD D160。`compare-another`）

- 候補が1つのとき：考え方の select（`compare-another-select`）・主ボタン「もう1案作って比べる」（`compare-another-make`）・output 要素に「（考え方の名前）で作っています…」・進み具合と止める（`compare-another-progress`）・エラー
- 選べる考え方は `lib/planMenu` の `anotherPlanOptions(presets, base, current)`（`AnotherOption`＝プリセット（「〈名前〉で作る」）か「試す重みで作る」）。base が AI が出したままの記録の条件なら、それと同じプリセットを除く（同じ考え方を出さない）。null ならどれも出す。base を渡すのは、記録の条件でいまのデータから作った問題の `problemKey` が記録の inputKey と同じときだけ
- 流れ：`compile({ ...data, rules }, date)` → `runSolve(p, { seed: data.seed, iterations: defaultIterations(p) })` → `update(addRun(...))`（今の案・条件は変えない）。記録に出たら（`findRun`）A＝今ある案、B＝作った案にしてトースト。同じ案なら（addRun が足さない）そう知らせる。止めた案はトーストの文を分ける
- 画面を離れたら・日付を変えたら計算を止め結果を捨てる（世代）
- 選択肢が無い（プリセットが1つ等）・計算できる訪問が無いときは理由（`compare-another-why`）
- 狭い画面（PRD D220）：考え方の select と主ボタンの行（`compare-another-row`）を、右の欄の確定のボタンの帯と同じく記録のカードの下に貼り付け（sticky・`bottom: var(--bottom-tabs-h)`。外の箱 `compare-another` は screen の 600px 以下で `display: contents` にしてカード全体を貼り付く範囲にする）、主ボタンが下のタブに隠れない
- 印刷では出さない

### 完了の条件

- [ ] 比較の画面で任意の2つの記録を左右に比べられる。訪問・区間（A は点線、B は実線の側）・「自宅まで」・担当を押すと、日の予定と同じに地図で強調・絞り込みされる
- [ ] 条件の画面で点数の基準を替えると日の予定の点が変わる（ADR-0010）
- [ ] 条件の重みの表で重みを変えて確定すると（動かしただけでは保存しない。PRD D286）、基準のプリセットと試す重みが変わり、月のまとめて作る・自動作成・作り直しがその重みで作る（ADR-0035。`src/lib/presets.test.ts`・`scripts/e2e-rebuild.cjs`）
- [ ] 案が1つの比較の画面の「もう1案作って比べる」：同じ考え方を出さない・記録が2件で A＝今ある案・B＝作った案・今の案は変わらない・プリセットが1つのときの理由（`scripts/e2e-plan-menu.cjs`）
- [ ] （ADR-0012）種類を足し、〈利用者さん〉のパターンをリハビリにすると、その訪問は理学療法士のいない人に入らず、理由に「種類（リハビリ）：… ✗」が出る。種類を消すと確認が出て、その訪問は種類なしになる
