### データ（`#/data`）

メニューの「設定」グループ（土台。切れない）。

#### 注意書き・呼び方

- 「データは**このブラウザの中だけ**に保存し、サーバーには送りません。実在の人の名前・住所などの個人情報は入れないでください。」（〈利用者さん〉の決まりごとの注意書きと同じ文）。保存できなければ「保存できませんでした：…。書き出して保管してください。」
- 画面での呼び方（`Term` `terms`）：訪問する人・訪問先（各10文字まで）と「変える」。同じ呼び方は使えない。呼び方もデータに保存され、書き出しに入る
- 容量超過（`QUOTA_MESSAGE`）のときは、保存できなかった文の下に「古い案と記録を片づける」（`data-tidy-go`）。押すと片づけの欄へ巻いてフォーカス（枠が見える）

#### 直前の状態に戻す（PRD D227。ADR-0032）

- 1世代の控えがあるときだけ、注意書きの下に欄（`data-prev-card`・aria-label「直前の状態に戻す」）。文（`data-prev-text`）「10/19 14:03 の『初期状態に戻す』の前の状態に戻せます」（`lib/backupReminder` の `previousText`。日本時間）
- 控えを残す操作（操作の名前）：初期状態に戻す（「初期状態に戻す」）・控えの読み込み（「控えの読み込み」）・Excel 全体の読み込み（「Excel 全体の読み込み」）・名簿の読み込み（「〈呼び方〉の名簿の追加・更新／総入れ替え」）。確認の本文の最後に見込み（`canKeepPrevious()`）で「いまのデータは控えとして1つだけ残し、この画面の「直前の状態に戻す」で戻せます。」、残せない見込み（保存が使えない・最後の保存が容量超過）なら「控えを残せません：容量不足。」。確認で OK になってから `keepPrevious(reason)` で残す（取り消す・確認中に閉じると控えは変わらない）。見込みに反して残せなければ、操作は止めずに完了のトーストに理由を添える（「初期状態に戻しました（控えを残せません：容量不足）」）。名簿が入らなかったら `cancel()` で前の世代に戻す
- 「直前の状態に戻す」（`data-prev-restore`）：独自の確認（危険の色。本文「〈文〉。いまのデータは控えと入れ替わり、もう一度「直前の状態に戻す」で戻せます。」）。確定で `restorePrevious()`（いまのデータを「直前の状態に戻す」として控え、控えのデータにする）とトースト「直前の状態に戻しました」。控えが無くなっていた・読めない・いまのデータを控えに残せない（「いまのデータを控えに残せないため戻せません：容量不足」。戻さず、控えは元のまま）ときはトーストで理由
- 別のタブで控えが変わったら（storage イベント）欄を読み直す
- 保存の容量が足りず控えを捨てたら（`previousDrops`）欄を消し、トースト「容量が足りないため、直前の状態の控えを消しました」（`DataWatch`）

#### 最後に書き出した日（PRD D227）

- 「ファイルに書き出す」の下に「最後に書き出した日：10/12（7日前）」（`data-last-export`。同じ日は「今日」、まだなら「まだ書き出していません」、Excel 全体なら「（Excel 全体）」を添える。`exportAgoText`）
- 控え（JSON）と Excel 全体の書き出しで更新（名簿だけの書き出しは数えない）。このブラウザの記録（`store/backup.ts` の `backupMemory`）で、データには入れない

#### 控え（バックアップ。JSON）

- `Term` `backup`。「ファイルに書き出す」（データ一式（AI案・記録・確定した割当も）を1つの JSON に）
- 読み込みは `FilePick`（`backup-file`・caption「読み込む控え（JSON）」）。選ぶと、置き換える前に確認する

#### Excel（ADR-0006・ADR-0020）

- 欄 `section.data-excel`（data-testid `excel-card`・`aria-labelledby` は見出し・`:focus` で枠）。`excel` を切っていれば欄ごと出さない（控えは残す）
- 対象 `excel-kind`（`fieldset.segmented`・aria-label「Excel の対象」）：全体／〈利用者さん〉の名簿／〈スタッフ〉の名簿
  - 全体：〈スタッフ〉・〈利用者さん〉・項目・条件・相性・稼働時間・訪問のシートごとの一覧。読み込むといまのデータがその内容に置き換わる（AI案・記録・確定した割当は消える）。書き方はブックの「使い方」のシート
  - 名簿：その一覧（シート1枚）だけ。列は全体のブックと同じで、全体のブックも名簿として読める。ID か名前で同じ人を探して直し、いない人は足す（AI案・記録・確定した割当・訪問は消えない）。読み込み方 `roster-mode`：追加・更新（ブックに無い人はそのまま）／総入れ替え（ブックに無い人を〈スタッフ〉は休止、〈利用者さん〉は段階「終了」にする。消しはしない）
- 「Excel に書き出す」と読み込み `FilePick`（`excel-file`。`key={excelKind}` で種類を切り替えたら選んだファイルの文を消す。caption は全体なら「読み込む Excel（全体）」、名簿なら「読み込む〈呼び方〉の名簿（Excel）」）
- 名簿の読み込みは確認の後にデータが変わっていないかを見直す（`pendingRoster`）

#### 最終勤務日の知らせ（PRD D209）

- 〈スタッフ〉の名簿を読み込んだら、読み込む前と後の名簿を `lib/personLinks` の `lastDayChanged(before, after)`（excel の `lastDaySet` と同じ決まり。ID も返す）で比べ、入ったら（`pendingRoster` の後で）トーストに加えて Excel の欄に知らせの帯（`section.data-notice`・aria-label「最終勤務日の知らせ」・data-testid `lastday-notice`）
- 文「最終勤務日の入った〈スタッフ〉がいます。〈スタッフ〉の画面（名前から開く）で担当の振り直しを確かめてください」。名前は `#/staff?id=` へのリンク（`lastday-link`。閲覧の欄）と「（最終勤務日 M/D）」
- 閉じる（`lastday-close`・aria-label「最終勤務日の知らせを閉じる」）でフォーカスは Excel の欄（枠が見える）
- 画面の state で保存しない。次の読み込みの始め・Excel の種類の切り替え・控えや Excel 全体の読み込み・初期状態に戻すでも消す。読み直すと出ない
- `offboard` を切っていれば出さない。印刷では閉じるボタンを出さない

#### 手直しの記憶（PRD D260。ADR-0043）

- 欄 `data-prefs-card`（aria-label「手直しの記憶」）。説明「日の予定で担当を手で変えて「次からもこの人にする」を選ぶと、同じ〈呼び方〉・同じ曜日・同じ時間の訪問は、次に作る案でその担当になります（その日に担当できないときはふつうに決めます）。」
- 件数（`data-prefs-count`）「いま N件 覚えています」／「いま覚えている手直しはありません」と［すべて消す］（`data-prefs-clear`。0件なら押せない。独自の確認（危険の色）「覚えている N件を消します。作った案と固定はそのままです。」→ `manualPrefs` を `{}` にしてトースト「手直しの記憶を消しました」）。一覧・1件ずつの編集は無い

#### 使い方の案内・初期状態に戻す

- 「案内をもう一度見る」（`tour-again`。`useTour()`）：初めて開いたときに出る短い案内（6枚）をもう一度。見たかどうかはこのブラウザに覚え、データには入れない（書き出し・初期状態に戻すでは変わらない）
- 「初期状態に戻す」：デモの架空の事業所のデータ（今日から7日分の AI案を含む。PRD D225）に戻す（独自の確認。危険の色）。取り消すと知らせなし、確定で知らせ
- 「画面を読み直す」

#### 古い案と記録を片づける（PRD D227。ADR-0032）

- 欄 `section.data-tidy`（`data-tidy-card`・`tabIndex=-1`・`:focus` で枠）。説明「保存の容量が足りなくなったときに使います。選んだ月より前の日の AI案と記録（比較の画面の記録）を消します。確定した日の AI案・確定した割当・訪問・人・条件は消えません。消す前に控えを書き出してください。」
- 消す範囲（`data-tidy-month`。今月〜12か月前の「〈年〉年〈月〉月より前の AI案と記録」。既定は3か月前。`lib/tidy` の `tidyMonthOptions`）。画面の状態で保存しない
- 見込み（`data-tidy-preview`）「N日分の AI案 N件・記録 N件（約 NKB 空きます）」（`tidyPreview`。JSON の文字数から。確定した日の AI案は数えず、あれば「。確定した日の AI案 N件は残します」）。無ければ「〈範囲〉に消せる AI案・記録はありません」で「古い案と記録を消す」（`data-tidy-run`）は押せない
- 押すと独自の確認（危険の色。件数・空く見込み・確定した日の AI案は残すこと・消えないもの・戻せないこと）。確定で `update((d) => tidyOld(d, ym))`（`aiRuns`・`aiPlans` だけ。`manualPlans` は消さない。確定した日（`manualPlans` のある日）は `aiPlans` を残し `aiRuns` だけ消す：今の案を消すと、その日を日の予定で開いたときに自動で作り直して「未確定の変更あり」になり、容量も戻るため）とトースト。1世代の控えは残さない（容量を空けるため）

#### データを守る知らせ（画面全体。`components/DataNotices.tsx`。PRD D227）

- 壊れたデータの知らせ（`BrokenDataNotice`・`data-broken-notice`。管理者の画面の本文の先頭、作り直しの帯の下）：起動したとき保存していたデータが読めず初期データで開いたら（`useDemoData().broken`）、注意の色の帯「保存していたデータを読めなかったため、初期データで開きました。元のデータはこのブラウザに残しています。…」（退避できなかったとき（`brokenKept` が false）は「元のデータを退避できませんでした。今すぐ書き出してください。」）と「読めなかったデータを書き出す」（`data-broken-download`。`brokenText()`＝`vrdemo:data:broken` の元の文字（退避できなければ開いたときに覚えた元の文字）をそのまま `visit-route-demo-broken-YYYY-MM-DD.json` に。`saveBlob`）と結果（`data-broken-message`）。閉じる（`data-broken-close`・aria-label「読めなかったデータの知らせを閉じる」）でフォーカスは画面の見出し。閉じたことは保存しない（次に読めれば出ない）。印刷で出さない
- 控えの知らせ（`DataWatch`）：起動したとき1回だけ、確定した日（担当の決まった訪問のある確定した割当）が1日以上あり、最後に書き出した日から14日以上（まだなら常に）、今日まだ知らせていなければトースト「控え（バックアップ）を2週間以上書き出していません。データの画面で書き出せます」（`shouldRemindBackup`。知らせた日を覚え1日1回まで）
- 別のタブの変更（`DataWatch`）：別のタブでデータが変わり読み直したらトースト「別のタブで変わったので読み直しました」。〈スタッフ〉・〈利用者さん〉の編集の欄に変更があるとき（`lib/dirtyForms` の `useDirtyMark`）は「別のタブで変わりました。保存すると上書きします」（入力はそのまま。編集の欄に変更があるかは、読み直したデータで描き直したあと（`setTimeout` 0）に見る）

#### ファイル選択（`components/FilePick.tsx`。PRD D192）

- `lib/filePick.ts`（純粋関数。テストあり）：`fileNameText(name)`（「選んだファイル：〈名前〉」・未選択は「ファイルを選んでいません」）、`FILE_PICK_LABEL`（「ファイルを選ぶ」）
- 見出し（`caption`）・見えない形の `input type="file"`（`opacity: 0`。見た目のボタンと同じ大きさで重ねる `.file-pick-hit`。`display: none` にしない）・見た目のボタンの `label`（`htmlFor`・`aria-hidden`）・選んだファイルの文
- 入力欄の名前は `aria-labelledby`＝見出し＋ボタンの文、説明は `aria-describedby`＝選んだファイルの文。フォーカスの枠は `input:focus-visible + label`。Space で選ぶ画面
- 選んだら `onPick(file)` を呼び、input の値を空に戻す（同じファイルをもう一度選べる）。`testId` で `-input`・`-name` も付ける
- src のファイル選択は控えと Excel の2つだけ

### 管理者設定（`#/settings`。ADR-0028。PRD D210〜D216）

- だれでも開ける。土台で切れない。`lead`「使う機能だけを入れると、メニューと画面がすっきりします。切った機能のデータは消えません」。主ボタンは置かない（スイッチはその場で保存）
- ひな形（`feature-templates`）：4つ（`feature-template`。今のひな形に「いまの設定」`feature-template-now`、どれとも違えば「カスタム」`feature-custom`）。「当てる」（`feature-template-apply`・aria-label「ひな形「〈名前〉」を当てる」）は独自の確認ダイアログで `templateDiff`（入る機能・切れる機能）を出し、取り消すと変わらない。説明「よく使う組み合わせを一度に当てます。当てたあとも、下のスイッチで1つずつ直せます。」
- グループ（`FEATURE_GROUPS`＝予定／当日・問い合わせ／人／AI の条件／連絡／データ。メニューのグループにそろえる。ADR-0034）ごと（`feature-group`）の行（`feature-row`）：名前・1行の説明・「切ると隠れるもの：…」・依存の注記（依存先が切なら「「〈名前〉」を入れると使えます」で押せない、入なら「「〈名前〉」が入っているときに使えます」）とスイッチ（`feature-switch`。`role="switch"`・`aria-checked`。「入」「切」）
- 押すとすぐ保存（`update`）とトースト「〈機能〉を入れました／切りました」
- 切るときデータがあれば `turnOffImpact` の件数と効き方の確認（相性など）。データの無い機能は確認なし。取り消すと変わらない
- 切った機能の URL を開くとホームへ移り、閉じられる知らせと管理者設定へのリンク
- 390px で横にはみ出さない。印刷で知らせ・「当てる」を出さない
