### 「欠勤・キャンセル」の欄（PRD D167〜D172・D243〜D246）

急な欠勤（遅刻・早退を含む）と当日キャンセルを1つの欄で段階に分けて扱う（起きたこと→人→影響→確定→連絡の5段。ADR-0038）。

#### 入口

| 入口 | 開き方 |
|---|---|
| 日の予定の操作の行の先頭「欠勤・キャンセルを登録」（`sudden-open`） | 1段目。主ボタンにしない・赤い縁（`.plan-sudden-btn`）。訪問も働く人もいない日は押せない。印刷では出さない |
| 列の見出しの「この人の欠勤を登録」「欠勤を直す」 | `openSudden({ kind: 'staff', staffId })`。その人を選んだ2段目（開くたびに差の欄へ移る印 `suddenToBar` を戻す） |
| `/plan?date=…&do=absence`（ホーム・メニュー・パレットの「欠勤・キャンセルを登録」・月の要対応・勤務時間（シフト）の右の欄） | 1段目（`&staff=` の人がその日に働けば2段目）。`?do=`・`?date=`・`staff` を消す |

下のタブは変えない（5つのまま）。日の予定で欠勤・キャンセルのメニューの項目に印を付けない。

#### 段階

|---|---|---|

| 2 | 「休む〈スタッフ〉と時間帯を選ぶ」：人（`sudden-staff`）と `AbsenceFields`。人を選ぶまで「次へ」（`sudden-next`）を押せない。時間帯の誤りは理由を出して押せない。既にある欠勤は `sudden-existing` | 「キャンセルの訪問を選ぶ」：訪問（`sudden-visit`）と当日キャンセルか（`sudden-same-day`。既定は当日キャンセル） |
| 3 | 「影響を確かめて振り直す」：見込み（`absence-preview`・`sudden-impact`）と振り直しのボタン | 「影響を確かめて取り消す」：`cancelImpact` の文（`sudden-cancel-impact`）と「当日キャンセルとして取り消す」／「取り消す」（`sudden-cancel-ok`） |

#### 5段目の連絡（PRD D243〜D246。ADR-0038）

- 一覧は1人に1枚（`sudden-contacts` の `sudden-contact`。`data-to`＝`staff|client`・`data-kinds`＝種類）：宛名・種類の印（担当が外れる・新しく入る（`chip-move`）・時刻が変わる（`chip-warn`）・中止、〈利用者さん〉は「〈利用者さん〉あて」）・連絡文（`sudden-contact-text`）・［文をコピー］（`sudden-contact-copy`。`copyText` とトースト）・〈スタッフ〉あての「メール」（`MailButton`・`MailLengthNote`。`sudden-contact-mail`。件名は `contactMailText`）・［連絡した］（`sudden-contact-sent`。印の鍵は宛先と文なので、確定し直して文が変われば消える）
- 上に説明（欠勤とキャンセルで分ける）と、欠勤の人に残る訪問があれば「欠勤の人に残る訪問 N件（連絡文には入りません。日の予定で確かめてください）」（`sudden-contacts-left`。日の予定が `leftCount` で渡す）、「連絡した N/M人」（`sudden-contacts-count`。`aria-live`）。行が無ければ「連絡が要る変更はありません。」、差を出せなければ「日の予定の「連絡の一覧」で確かめてください」（`sudden-contacts-none`）
- 帯は「終わる」（`sudden-finish`。主ボタン。差の欄へは移らない）と「戻る」（4段目）
- 日の予定（`PlanPage`）が作る：
  - 欠勤：差の欄と同じ `contacts`（`contactsOf`。元の案＝確定した割当、無ければ振り直す前の案 → 今の案。確定したあとは今の案＝確定した割当）
  - キャンセル：欄の取り消し（`suddenCancelVisit`）が、取り消す前の担当（確定した割当があればその担当だけ（無ければ担当なし）、確定が無ければ今の案）・開始（今の案の時刻、無ければ約束の開始）と、そのときの確定した割当（`suddenCancel`）を覚えてから `applyCancel`。差は `contactsOf({ problem, routes: orderConfirmed(そのときの確定した割当, 今の案, problem) }, { problem, routes: 今の案 })`（確定した割当の列は訪問データの並びなので、`baseOf` と同じ並べ方にしてから時刻を出す）（取り消した訪問は問題に無いので出ない）。確定が無かった日は中止だけ
  - 行は `contactRows(差, 取り消した訪問, contactWords)`。欄を開き直すと `suddenCancel` を消す

#### 2段目の欠勤の入力（`AbsenceFields`）

- 終日／時間帯のラジオ。時間帯は開始・終了（30分刻みの選択。空＝始業から・終業まで）と早道のボタン：午前だけ＝始業〜12:00、午後だけ＝12:00〜終業、〇時から（早退）＝開始だけ、〇時まで（遅刻）＝終了だけ
- メモ（100字まで）。「いまの時刻」の入力は無い（当日に終日の欠勤を登録しても、その日の訪問はすべて振り直す）
- 人の選択肢は `staffChoices`（その日にもともと働く人。「名前（稼働時間帯・訪問 N件・欠勤）」）。その日の稼働時間帯がもともと無い人は出さない
- 時間帯が正しくない（終了 ≤ 開始）・開始も終了も無いときは理由を出して進めない（`draftError`）

#### 3段目の見込みと振り直しのボタン

- 見込みは `previewOf`（3段目のときだけ計算。メモは key に入れない＝メモの入力では計算し直さない）。読み上げは `aria-live="polite"`
- `impactText(targets)`：「入らなくなる訪問 N件」と内訳「欠勤と重なる a件・間に合わない b件（・ほかの必須の条件 c件）」。無ければ「入らなくなる訪問はありません」。訪問の一覧は `AbsenceTargets`
- 「ほかの人の担当・順番・時刻は変えず、空き時間に入れます（〈名前〉さんの残りの訪問は、欠勤明けの移動で開始が遅れることがあります）」「（元の案：確定した割当／今の案）」
- `targetsOf` に続けて案A（`reassign`）の見込みも出し、入らない見込みがあれば案B を勧める（`recommendAnneal({ hasBase, unplacedA })`。「少し動かしてよい（案B）」の箱 `anneal-suggest` に「おすすめ」）
- ボタン：
  - 勧めるとき主ボタン「登録して案B も作る（おすすめ）」（`sudden-anneal`）。押すと「登録して振り直す」と同じに案A を今の案にし、続けて案B を作り始める
  - 「登録して振り直す（案A）」（`sudden-reassign`。勧めないときは主ボタン）
  - 「欠勤だけ登録」（`sudden-save-only`。計算中は押せない）
  - 既存の欠勤なら「欠勤を取り消す」（`sudden-remove`）
- 押せない理由（`reassignBlocked({ error, running, hasPreview, hasBase })`）：「計算中は押せません（終わるまで待ってください）」・「見込みを出せませんでした」・「この日はまだ案がありません。欠勤だけ登録できます（案を作るときは欠勤を除いて作ります）」
- 案の無い日（`sudden-no-plan`。`noPlanText(running)`）：計算中は「案を作っています。終わると振り直せます」、ほかは欠勤だけ登録できる

### 振り直し（案A。ADR-0011。PRD D26〜D32）

#### 登録して振り直す

- 欠勤を足したデータで compile した問題、元の案（`lib/absences` の `baseOf`：`manualPlans[date]` があれば、各担当の訪問を今の案の列の順（無い訪問は earliest の順）に並べたもの。無ければ `aiPlans[date].routes`）、`targetsOf`（`base.problem` はその日の欠勤を除いたデータで compile した問題）→ `reassign` で、結果を今の案にする
- `applyReassign`：routes・generated＝結果、pins＝結果の pins（全訪問が固定）、`reassign`＝元の案の情報（design.md §5。振り直す前の今の案の generated・runId も。続けて振り直すときは最初のものを引き継ぐ）。記録に `reassign` 付き・名前「欠勤の振り直し（〈名前〉さん）」で1件。欠勤の保存と合わせて1回の `update`
- 元の案が無ければ振り直せない（欠勤だけは登録できる）。元の案が確定した割当で今の案が「未確定の変更あり」なら、今の案の変更を捨てる確認を出す。計算中（Worker）は押せない
- 振り直したあとの今の案は全訪問が固定なので、「固定を残して作り直す」をしても担当が変わらない

#### 欠勤の取り消し

- `removeAbsence`：今の案は変えない（列の稼働時間帯は戻る）。差の欄の「元の案に戻す」で元の担当・固定に戻る
- 振り直しに使った欠勤が取り消されていたら差の欄に「欠勤は取り消されています。元の案に戻せます」

#### 列とカードの印

- 差の欄があるとき、変わらない人の列は薄く（押せる。文字のコントラストは保ち、背景・枠線・見出しの印だけを薄くする。透明度は使わない）
- 振り直した訪問のカードに「代行」の印（元の担当の名前を title・読み上げに）、開始が変わった訪問に「+N分」（早まったら「−N分」）
- 地図は振り直した訪問へ来る区間を太くする（`buildRouteMap` に強調する訪問の集まりを渡す）
- 欠勤の人に残る訪問に「欠勤と重なる：振り直していない（対応が必要）」などの赤い印（理由は `leftOf` の reason。`leftOf` は欠勤のせいの訪問（absence・unreachable）だけで、欠勤と関係ない元からの違反（notAllowed）は含めない＝必須の違反の赤い枠で出る）
- 欠勤の人の列の見出しの下に近道：「振り直し済み・入らない（全体） N件」（差の欄へ）・「欠勤の人のまま N件」（あれば）・「案B を作る」（案A で入らない訪問があり案B をまだ作っていないとき。作り始めて差の欄へ）
- 日の予定のあるときだけの帯（`band-reassign`）：「欠勤の振り直し：入らない N件・欠勤の人のまま N件」と「差の欄へ」

### 差の欄（`ReassignBar`）

今の案に `reassign` があるとき、担当ごとの順番の欄（本体）のすぐ上（欠勤の人の列の近く）。`tabIndex=-1`・見出しで名前づけ。

#### 中身

- 見出し「（案A：空き時間に入れた案）／（案B：少し動かした案）」。案B なら注記を「ほかの人の訪問も少し動かしています」に
- まとめ（`ReassignSummary`。4段目でも使う）：「変わる人 N人・振り直し N件・入らない N件・（あれば）欠勤の人のまま N件・移動 +N分」、「元の案：確定した割当／今の案」
- 入らない訪問の理由：「入らない訪問（N件）：ほかの人の空き時間に入らない」と一覧・案B か「受けられる人」へ
- 欠勤の人に残る訪問（`leftOf`。今の案に targetsOf を当てたもの。手直しで戻した等）の理由（`leftReasonText`）と「対応が必要」・「もう一度振り直す」。〈利用者さん〉の名前は `PersonButton`（`visitNode`。data-testid `left-client`）
- 「元の案に戻す」（`revertReassign`）：確認を出し、routes・pins を元の案（`baseRoutes`・`basePins`）に、generated・runId を振り直す前のもの（`baseGenerated`・`baseRunId`。無い古いデータは generated＝元の案・runId なし）に戻し、`reassign` を外す。続けて振り直したあとも最初の元の案へ
- 「比較の画面で見る」（A＝欠勤前、B＝今の案）
- 「連絡の一覧（訪問N件）」（`ContactButton`）
- 少し動かしてよい（案B）の欄（`AnnealBox`。下）
- 差は `reassignDiff`（before＝元の案を、振り直しに使った欠勤を除いたデータで compile した問題で、after＝今の案をいまの問題で）

#### 残り方・消え方

- 今の案を手直し・組み直ししても差の欄は残る（元の案との差を出し直す）。2人を順に欠勤にして振り直すと、差は最初の元の案との差
- 「AI に作らせる」・プリセットで別の案にすると消える
- 切った機能でも、すでに振り直した案の差の欄・帯・連絡の一覧は残す

#### 差の欄へ移る動き

- 「登録して振り直す」のあと、欠勤の欄が閉じて今の案が出たら差の欄へスクロールし、差の欄にフォーカスする（列の見出しへいったんスクロールしない）
- 欠勤の欄を閉じたときは、戻り先を差の欄に差し替える（`SidePanel.returnFocus`。preventScroll でフォーカスし、差の欄へのスクロールだけにする）。戻り先が消えていたら、その人の列の見出しへ
- 差の欄へ移る予約は、日付を変えたとき・1.5秒経っても今の案が出ないときに消す

#### `AnnealBox`（`pages/reassignParts.tsx`）

- 今の案が案A で、入らない訪問があれば「おすすめ」
- 「変更を減らす」のスライダー（0〜5・0.5刻み・既定3。今の案が案B ならその重み）と「担当が変わる1件＝移動N分ぶん・時刻のずれ10分＝移動M分ぶん」。近くに「重みが大きいと案A のままになることがあります（変更の減点が、得より大きいとき）」
- 「案B を作る」：Worker（`runSolve`。問題は `prepareAnneal` の問題、`initial` は案A、種はデータの種、反復は `defaultIterations`）。進み具合（回数。progress 要素は `aria-label="案B の進み具合"`）と「止める」（それまでの最良。案B の計算だけを止め、プリセットを順に作るのを止めた印は立てない）
- 押せないとき（欠勤が取り消されている・案A が無い・ほかの計算中）は理由を出す
- 日付を変えたら「案B も作る」の予約を消す
- 終わったら `settleAnneal` で確かめ、案A のままにしたときは理由を欄に出す（記録に足さない）。案B として出せるときは作り終えた時点で記録に1件足す（`addAnnealRun`。今の案は変えない。同じ結果・同じ重みなら足さない。作り始めたときと振り直しが違えば足さない）
- 差の表（案A と案B を並べる）：点数（点数の基準）・入らない・担当が変わる訪問（うち欠勤の人以外）・時刻がずれる訪問・変わる人・移動。列ごとに「〈案〉を今の案にする」（今の案の列は「今の案です」）
- 差の表の案B は、今の振り直し（元の案・欠勤・案A が同じ）のいちばん新しい案B の記録（`annealRunOf`）から出す。選ばなくても再読込で消えず、比較の画面で見られ、今の案が案B のとき「案A を今の案にする」を押しても案B を選び直せる（記録は増えない）

#### `lib/contacts.ts`（純粋関数。テストあり）

ひな形と載せる範囲は PRD D245・D246（ADR-0038）。差の欄の連絡の一覧と5段目で同じ。
