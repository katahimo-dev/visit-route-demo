# ADR-0005：比較は「手作業案 vs AI案」をやめ、AI案の条件を変えた記録どうしで比べる

- 日付：2026-10-12
- 状態：採用

## 背景
利用者から「比較は 予定 vs AI案 ではなく、AI案のパラメータを変えたときの比較にしたい。あらかじめの予定（手作業の割当）のデータは不要」と要望が出た。
いまの比較（ADR-0004 で別画面にした `#/compare`）は手作業案とAI案の左右比較で、手作業の割当をあらかじめ seed に入れておく前提になっている。
デモで見せたいのは「条件（重み・必須）を変えるとAI案がどう変わるか」であり、手作業案は比べる相手として不要。
前回のAI案（`prevAiPlans`）は1件しか残らず、3回以上試した結果を見返せない。

## 選択肢
1. 案A：手作業案 vs AI案のまま（seed に手作業の割当を入れ続ける）
2. 案B：AI案を作るたびに「条件と結果」を記録し、記録の中から任意の2つを比べる
3. 案C：案B ＋ 3つ以上を同時に並べる

## 決定
案B。
- seed は手作業の割当を入れない（訪問先の「いつもの担当」は残す）
- 条件のプリセットを3種（標準・移動を短く・人の組み合わせ重視）用意し、AI案の画面を開いた日にAI案がなければ標準で自動で作る
- AI案を作る・固定を残して組み直すたびに、その日の記録（`aiRuns`）に1件足す（1日20件まで）。`prevAiPlans` は廃止
- 比較画面で、記録と今の案から任意の2つを A・B に選んで比べる。手作業案との比較はやめる

## 理由とトレードオフ
- 得るもの：条件を変えた結果を、あとから好きな組み合わせで比べられる。初回は何も入れなくても標準のプリセットでAI案が出る。プリセット3種で、デモの利用者が「条件を変えるとこう変わる」を1回の操作で試せる
- 採点は A・B とも「いまの条件」の同じ物差しにそろえる。記録ごとに作ったときの条件で採点すると、重みが違う案どうしの合計点は単位が違い、比べられないため。代わりに「作ったときの点数」とは一致しないことがある（記録には作ったときの条件を残し、条件の差は一覧で見せる）
- 記録は1日20件まで、古いものから消す。理由は localStorage の容量（ブラウザごとに上限がある）。1件に条件・割当・順番・点数が入り、14日分が溜まるため。同じ条件・種・固定・結果の記録は足さない（再計算の連打で埋まらないように）
- 失うもの：手作業案と比べる画面。手作業の割当は予定画面（`#/schedule`）で引き続き編集でき、AI案を「予定に採用」もできるが、比較には使わない。3つ以上の同時表示（案C）は画面が混むので見送る
- 版は1のまま。`aiRuns` が無い古いデータは `{}` で補い、`prevAiPlans` は読み込み時に捨てる（移行のための版上げをしない）

## 影響
- 要件：PRD の D11・D14・D19 を変更、D1 に手作業の割当を入れない旨、D20（プリセット3種）・D21（初回は標準で自動作成）・D22（記録と任意の2つの比較）を追加
- 設計：store に `aiRuns` を足し `prevAiPlans` を消す（`repair` が `aiRuns` も直す）。seed は手作業の割当を入れず、`src/seed/presets.ts` にプリセットを置く。evaluate の `diff` は記録どうしの差。pages は最初の画面を `#/plan` にし、`#/compare` を記録の比較にする。§5 に `AiRun` とプリセットを足す
- 見直す条件：記録が20件では足りない、または容量が足りなくなったとき（IndexedDB への移行、設計書 §7）。3つ以上を並べたいという声が出たとき
