# ADR-0062：組み方の標準（標準の週）を決めて登録し、以後は標準で組む。予定のモードは［変更｜確認］の2つにする

- 日付：2026-10-24
- 状態：採用
- 関連：PRD D350〜D354（D314・D315・D348・D349 を書き直し）、ADR-0061（予定のモード。組むを変更へ統合）・ADR-0053（担当は訪問に持つ・繰り返しの担当）・ADR-0012／ADR-0013（定期パターン）・ADR-0010／ADR-0035（点数の基準のプリセット）・ADR-0043（廃止した手直しの記憶）

## 背景
- 予定のモード［組む｜変更｜確認］（ADR-0061）の「組む」は、毎月 AI で組み直す前提だった
- 利用者の見立て（2026-10-24）：使い始めに組み方と重みを決めたら、あとはそのパターンでずっと組む。毎月組み方を考えることはない
- 訪問看護・介護では「毎週同じ人が同じ時間に行く」のがふつうで、利用者さんも同じ人を望む。重み（プリセット）だけを決めても、AI が毎回組み直すと担当が週ごとに揺れる
- 版2（ADR-0053）では、繰り返しの回は見るときに計算し、担当は繰り返しの担当（`Pattern.usualStaffId`）になる。ただし開始は持たず（`start: null`）、AI で組むとピンでない回の担当は替わる
- 決めること：(1) 標準として何を残すか、(2) 標準の担当の強さ、(3) 標準を作る・直す入口の場所と予定のモード

## 選択肢
1. 標準として残すもの
   - A：重み（プリセット）だけ。毎月 AI がその重みで組む
   - B：中身（誰が・どの〈利用者さん〉へ・何曜・何時）を繰り返しに書き戻し、重みは点数の基準のプリセットに残す（2層）
   - C：1週間分の訪問を写して「ひな形の週」として別に持ち、毎週写す
2. 標準の担当の強さ
   - A：必ずその人（AI はピンと同じに扱う）。休み・条件に合わない日だけ AI が代わりを探す
   - B：重みで優先するだけ（今の「いつもの担当」の条件のまま）
3. 標準の入口と予定のモード
   - A：予定のモードに「組み方を決める」を足して4つにする
   - B：標準は予定の外（設定のタブとホームの案内）に置き、予定のモードは［変更｜確認］の2つにする。「組む」の操作は変更に入れる
   - C：今の3つのモードのまま、組むの中に標準の登録を足す

## 決定
1-B、2-A、3-B（利用者が決めた。2026-10-24）。

### 標準の中身（2層）
- 標準の週：繰り返し（`Pattern`）の担当（`usualStaffId`。今のまま）と、曜日ごとの標準の開始（`usualStarts`。新規）。計算した回はこの担当と開始で出る
- 標準の考え方：点数の基準のプリセット（`scorePresetId`。今のまま）
- 登録したことの記録：`DemoData.standard`（新規。登録した時刻・考え方・いつから・周期の週数）。ホームの案内と標準の画面の表示に使う

### 組み方の標準の画面（`#/standard`。設定のタブ）
1. 期間：来週の月曜から（週の予定と同じ区切り）、周期の週数（利用中の繰り返しの間隔の最大。毎月の第N週があれば4。1〜4週）
2. 考え方で作る：プリセットごとに期間の提案を作り、カードで比べる（点・移動・担当なし・人ごとの件数の偏り）。標準のピンは効かせず、手で付けたピンだけを効かせる。提案は保存しない。カードの「この考え方で作る」で、その提案を期間の訪問に書き（1手。元に戻せる）、そのプリセットを点数の基準にする（確認の文に書く）
3. 直す：週の予定（変更）で手直しする
4. 登録：期間の訪問から標準の差分（繰り返しごとの担当・曜日ごとの開始の前→後）を出し、「いつから」（既定は期間の最初の日。今日と伝えた日より前は選べない。伝えた日の回の ID と担当を変えないため）を決めて「標準として登録」。確認のあとで繰り返しを書き換える

### 登録の決まり（`lib/standard` の `standardDiff`・`registerStandard`。純粋関数）
- 担当：繰り返しの回の担当を曜日ごとに読む。同じ繰り返しで曜日によって担当が違えば、曜日ごとに繰り返しを分ける（`splitPattern` と同じく「いつから」で分ける）。同じ曜日で週によって担当が違う（毎週の繰り返しを2週で見た）ときは最初の週の担当にし、差分に注意を出す。担当なしの回は担当なし
- 開始：回の組んだ開始（`start`）を曜日ごとの `usualStarts` にする。時間の約束（開始（早）〜（遅））の外なら書かず、差分に注意を出す
- 「いつから」以降の保存した回（この回だけ日時などを変えた回は除く）：伝えた日（`snapshots` のある日）の回とピンの回は残す。新しい標準と同じ回は消す（計算した回と同じになる）
- 一時の変更（ピンでなく、新しい標準と担当・開始が違う回）があれば、登録の段に件数と一覧を出し、利用者が「標準に戻す（消す）」か「ピンを立てて残す」かを選ぶ（既定はピンを立てて残す。黙って消さない。利用者の指定 2026-10-24）
- 登録は store の update の1回（全体の「元に戻す」で戻せる）

### 標準の担当は必ずその人
- AI で組む（日・週・月の範囲・提案を比べる）は、計算した回（保存していない回）で担当があるものを、ピンと同じに扱う（`standardPinsOf`）。その担当が休み・条件に合わない（訪問ごとの検査の `off`・`notAllowed`）回だけピンにせず、AI が代わりを探す
- 保存した回（この日だけ替えた回）は今のまま（ピンの印があればピン）
- 欠勤の振り直し（案A・案B）は今のまま。案A は休む人の訪問だけを動かし、案B は「変更を減らす」重みと案A の列を守る仕組みで動くので、標準のピンを足さない
- 結果、標準を登録したあとの AI で組むは「標準で埋まらない所」（担当なし・休み・条件に合わない・単発の訪問）だけを埋める。訪問を自動では書かない（提案を出して「反映する」のまま。PRD §4）

### 予定のモード［変更｜確認］
- 「組む」を無くし、組むで出していた操作（AI で組む ▾・札を動かす）は変更に入れる（変更＝すべての操作。確認は今のまま）
- 既定：月の後半で来月の担当なしの日が2日以上なら変更、ほかは確認
- メニューの予定の子：今日の予定（確認）・◯月の予定（変更）・欠勤・キャンセル（変更）。古い `?mode=plan` は変更として読む
- 予定のナビの行の下の1行の説明は、標準を登録していないとき「組み方の標準を決める」へのリンクを添える

### 入口
- 設定のタブの先頭に「組み方の標準」。ホームは標準を登録していなければ「はじめに組み方の標準を決める」のカードを先頭に出す
- 標準を見直すのも同じ画面（今の標準から始め、期間の今の担当を出す）

## 理由とトレードオフ
- 得るもの：
  - 担当が週ごとに揺れない。標準を登録したあとは、先の月を開くだけで標準の担当・時刻が並び、要対応（担当なし・休み）だけを AI で埋めればよい
  - 標準は繰り返しの担当と開始なので、データの形を大きく変えない。計算した回・空き状況・Excel がそのまま標準を読む
  - 予定のモードが2つになり、切り替えの迷いが減る。年に数回の作業（標準を決める）を毎日の画面に置かない
- 失うもの：
  - 毎月の全体の組み直しで得られる移動の短さは捨てる（標準を見直せば取り戻せる）
  - 曜日で担当が違う繰り返しは、登録のときに曜日ごとに分かれる（繰り返しの数が増える。〈利用者さん〉の画面の繰り返しの節で行が増える）
  - 標準の担当が休みの日は、AI が代わりを探すまで要対応に残る（今と同じ）
  - 登録の前の標準へ戻すのは「元に戻す」の範囲だけ（標準の版の履歴は持たない）
  - 周期が4週を超える繰り返し・毎月の第N週は、4週の期間で見えた回だけを標準にする
- 1-A（重みだけ）は担当が揺れる。1-C（ひな形の週を別に持つ）は繰り返しと二重になり、繰り返しを直したときに食い違う。2-B（重みで優先）は「同じ人が行く」を約束できない。3-A はモードが増え、3-C は毎日の画面に年に数回の作業が混ざる
