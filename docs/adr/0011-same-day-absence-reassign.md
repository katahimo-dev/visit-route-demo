# ADR-0011：当日の急な欠勤を別の記録で持ち、他の人の予定を変えずに空き時間へ振り直す

- 日付：2026-10-13
- 状態：承認（1回目＝案A の範囲。細部は 2026-10-13 に利用者が推奨どおりに決定。2026-10-14 にレビューを受けて利用者が追加で決定。design.md §8 の「決めたこと」）。2026-10-14 に2回目（案B・連絡の一覧）を追記（推奨どおり。下の「追記」）。2026-10-14 に「いまの時刻」をやめた（利用者が決定。下の「追記：いまの時刻をやめる」）

## 背景
利用者から「当日のスタッフの急な欠勤で、**他のスタッフのそれまでの予定を極力変えずに**、欠勤の人の訪問を振り直したい」と要望が出た（2026-10-13）。
終日の欠勤だけでなく、途中の欠勤（午前だけ病院の付き添い＝9:00〜12:00 だけ不在、〇時から早退、〇時まで遅刻）も扱う。

いまできるのは、稼働時間の画面でその日の時間帯を上書きし、「AI案を作る」で全部組み直すか、ドラッグで1件ずつ手で移すことだけ。

- 全部組み直すと、欠勤と関係のない人の担当・順番・時刻まで変わり、利用者さん・スタッフへの連絡が増える（当日は連絡そのものが負担）
- 稼働時間を上書きすると、元の稼働時間が消え（取り消せない）、「なぜ時間が減ったか」（欠勤・メモ）が残らない
- ドラッグでは、どの訪問を誰に移せば入るかを人が探すことになる

決めること：(1) 欠勤の持ち方、(2) 振り直し方、(3) 振り直しの置き場所、(4) 振り直した結果の扱い、(5) 1回目と2回目の範囲。

## 選択肢
1. 欠勤の持ち方
   - A：稼働時間の上書き（`availability`）に書く（欠勤の時間を除いた時間帯で上書き）
   - B：**別の記録**（`absences: { id, staffId, date, from, to, note }[]`。終日は from・to とも null）として持ち、稼働時間帯の計算で差し引く
2. 振り直し方
   - A：**挿入だけ**（案A「空き時間に入れるだけ」）：他の人の担当・順番・開始時刻を変えず、振り直す訪問を、入れられる人の少ない順（同じなら regret の大きい順）に、費用の増えが最も少ない strict の位置へ1件ずつ入れる
   - B：変更の減点つき焼きなまし（案B「少し動かしてよい」）：solver の費用に、元の案から担当を変えた訪問への減点を足して解く
   - C：全部組み直し（いまの「AI案を作る」を欠勤を差し引いた時間帯で）
3. 置き場所
   - A：matching に足す（`bestInsertion` の隣）
   - B：solver に足す
   - C：**新しいコンポーネント reassign**（`src/reassign/`）
4. 結果の扱い
   - A：**今の案（AiPlan）にして全部固定**、記録（AiRun）にも振り直しの情報を付けて残す
   - B：今の案とは別の「欠勤の案」を持つ

## 決定
1-B、2-A（1回目）＋2-B（2回目）、3-C、4-A。1-B・2-A・4-A は利用者の方向づけ（2026-10-13）、細部（データの形・規則・置き場所）はこの ADR と design.md に書いた。

- データ：`DemoData.absences`（zod の既定値で `[]`。DATA_VERSION は1のまま、`aiRuns`・`presets` を足したときと同じ）。時刻は30分単位、`from` が null＝始業から、`to` が null＝終業まで、両方 null＝終日。1人1日1件（store の repair は稼働時間の上書きと同じく最後の1件）。Excel に「欠勤」シート（無い古いブックは欠勤なし）
- 差し引き：domain の `withoutAbsences`（デモ独自。`domain/availability.ts` に置き「働ける時間帯を決めるのはこのファイルだけ」を保つ）。compile・`useDayModel` の `slotsOf` がこれを通す。`Problem` の形は変えない
- 振り直す訪問：欠勤の人の元の案の訪問のうち、欠勤の時間と重なる訪問**すべて**（元の案の時刻を、その日の欠勤を除いた問題で出して判定する。時間に幅があって後ろへずらせば入る訪問も、欠勤の人のまま残さない。2026-10-14 利用者が決定）と欠勤のせいでその人に可にならない訪問、残すと strict で回れなくなる訪問（間に合わない）。欠勤と関係のない元からの違反は「欠勤と重なる」とは呼ばない（`notAllowed`）。いまの時刻で動かさない訪問は無い（下の「追記：いまの時刻をやめる」。当初は始まった訪問＝earliest ＜ いまの時刻 を除いていた）
- 元の案：その日の確定した割当（`manualPlans[date]`）があればそれ、無ければ今の案（`aiPlans[date].routes`）
- 結果：今の案（`AiPlan.reassign` に元の案・使った欠勤）にし、担当のいる訪問をすべて固定。記録にも `AiRun.reassign` を付けて残し、比較の画面で「欠勤前」と比べられる。種類を `kind` で持つ代わりに `reassign` の有無で表す（中身が要るため）。`method` は1回目 'insert' だけ
- 欠勤の取り消しでは今の案を戻さない。差の欄の「元の案に戻す」で戻す（担当・固定に加えて、振り直す前の今の案の generated・runId も `reassign.baseGenerated`・`baseRunId` に持って戻す。2026-10-14）
- 続けて振り直す（今の案が振り直しの案で、確定した割当が無い）ときは、今の案から振り直すが、元の案の情報は最初のものを引き継ぎ `absenceIds` を累積する。差も「元の案に戻す」も最初の元の案に対して（2026-10-14 利用者が決定）
- 候補から入れる（`placeVisit`）とき、空き時間に入らない人ではその人の後ろの訪問の開始が遅れうる。候補に遅れる件数・最大の分を出し、押したときに確認を出す。いまの列に元から必須の違反がある人は、空き時間に入れられない理由を候補に出す（2026-10-14 利用者が決定）
- 細部（2026-10-13 利用者が推奨どおりに決定）：欠勤は1人1日1件、30分単位・午前／午後の境は 12:00、半端な時刻は30分に丸める、候補から入れるとき訪問の時刻は変えない（間に合わなければ違反の赤い枠）、件数の上限は超えない、確定した割当を元にするとき今の案に未確定の変更があれば確認を出してから捨てる
- 1回目：PRD D26〜D33（欠勤の登録・案A・差・候補・固定と記録・取り消し・稼働時間の画面の印・Excel）。2回目：D34（案B）・D35（連絡の一覧）

## 理由とトレードオフ
- 得るもの：
  - 欠勤を消せば元の稼働時間に戻る。メモ（病院の付き添い）が残り、稼働時間の画面と予定の画面で「欠勤」と見せられ、2回目の連絡文にも使える
  - 案A は「他の人の担当・順番・開始時刻は変わらない」を規則として保証でき、テストで確かめられる。決定的で一瞬（Worker も要らない）。なぜその人に入ったか（増える移動・条件）を説明できる
  - 結果を今の案と固定にするので、手直し・「固定を残して組み直す」・「この割当で確定」・比較の画面をそのまま使える
  - reassign を分けたので、欠勤の運用の規則（入れる順・振り直す訪問の決め方）の変更が matching（条件 → 問題）・solver（焼きなまし）に波及しない
- 失うもの：
  - 案A は局所的なので、少し他の人を動かせば入る訪問も「入らない」に残る。候補（受けられる人・〇分ずらせば入る）を出して人が決める。2回目の案B で補う
  - 案A の位置は費用の増えが最小の局所的な選び方で、全体の最適ではない（AI案の点数は下がりうる）
  - 欠勤と重なる訪問は時間に幅があってもすべて振り直すので、欠勤の人のまま後ろへずらせば済む訪問も他の人へ移る（欠勤の人の予定を欠勤明けに詰め込まない方を選んだ）
  - 差し引く処理が compile と画面の2か所に入る（どちらも domain の同じ関数を呼ぶ）
  - 全訪問を固定するので、あとで AI に担当ごと組み直させたいときは固定を外すか「AI案を作る」が要る
  - 時刻が30分単位なので、10:15 の早退などは丸めて入れる

## 影響
- 要件：PRD D26〜D35、やらないこと（本人からの連絡の受付・通知の送信・複数日の一括入力・勤怠）
- 設計：契約 `absenceSchema`・`DemoData.absences`・`AiPlan.reassign`・`AiRun.reassign`（optional）・`src/contracts/reassign.ts`。domain の `withoutAbsences`、matching の `CompileInput.absences`、新しいコンポーネント reassign、store の repair、excel の「欠勤」シート、pages（欠勤の欄・差の欄・候補・比較の「欠勤前」・稼働時間の画面の印・`lib/absences`・`lib/runs`）
- 見直す条件：入らない訪問が多く、手で入れる手間が大きいと言われたとき（案B を早める）。1日に複数の欠勤の時間帯が要ると言われたとき（1人1日に複数件を許す）。始まっている訪問・時刻をずらす扱いが現場と合わないとき

## 追記（2026-10-14）：2回目＝案B「少し動かしてよい」と連絡の一覧（PRD D34・D35）

### 決めること
(a) 変更の減点の形と既定値、(b) 減点を採点（点数）に入れるか、(c) 案B の置き場所と初期解、(d) 動かさない訪問、(e) 画面の流れ、(f) 連絡の一覧の中身と連絡文。

### 選択肢
- (a) 減点：A：担当が変わった訪問1件だけ（小10・中30・大60 の3段）／**B：「変更を減らす」重み w（0〜5・0.5刻み・既定3）で、担当が変わった訪問1件＝w×10点・開始のずれ1分＝w×0.2点**（条件の重みと同じ「重み1＝移動10分」の物差し。スライダーは条件の画面と同じ部品）
- (b) 採点：A：evaluate の score にも減点を足す（solver と合計点が一致）／**B：solver の費用にだけ足し、採点・点数には入れない**（変更の数は差の表で別に見せる）
- (c) 置き場所：A：reassign に専用の局所探索／**B：既存の solver（`Problem.stay` を `routeCost` で足す）。`SolveOptions.initial` に案A を渡し、貪欲・素朴な初期解より高くなければ案A から始める**
- (d) 動かさない訪問：元の案で入らなかった訪問は案A と同じく入れない（当初は始まった訪問＝earliest ＜ いまの時刻 を案A の担当・開始に固定していたが、下の追記でやめた）
- (e) 画面：欠勤の欄の見込みで案A で入らない見込みがあれば勧め（「登録して、少し動かしてよい（案B）も作る」）、差の欄に案B の欄（スライダー・作る・進み具合・止める・案A と並べた差の表・選ぶ）。案B は作り終えた時点で記録に残し、選んだ方を今の案にする（2026-10-14 レビューで「選んだときに記録に残す」から変更）
- (f) 連絡の一覧：元の案と今の案の差から (1) 担当が変わる訪問先 (2) 時刻が変わる訪問 (3) 仕事が増える・減るスタッフ と、スタッフあて・訪問先あての連絡文（コピー・印刷。送信しない）

### 決定（推奨どおり。2026-10-14）
(a)-B、(b)-B、(c)-B、(d)・(e)・(f) は上のとおり。データは `ReassignInfo.method` に `'anneal'`、`stayWeight`（案B の重み）、`insertRoutes`（案A の結果。案B の初期解・比較の「案A」・「案A を今の案にする」）を足す（optional。版は1のまま）。

### 理由とトレードオフ
- 得るもの：solver・Worker（進み具合・止める）・決定性をそのまま使え、ほかの用途の費用は変わらない（`stay` が無い問題は今までと同じ）。案A から始めるので「案B は案A より悪くならない（費用＋変更の減点）」をテストで保証できる。点数の物差し（ADR-0007・ADR-0010）が変わらず、案A・案B・欠勤前を同じ点数で比べられる。変更の数は差の表で「担当が変わる訪問（うち欠勤の人以外）」「時刻がずれる訪問」として見える
- 失うもの：案B では進み具合の内部の費用（`bestScore`）と `SolveResult.score`（採点）が一致しない（`stay` の分）。案A に入っていた訪問は落とさない（下の「レビューの反映」）ので、ほかの訪問を外さないと入らない訪問は案B でも入らない（入れ替えるかは人が候補を見て決める）。重みが大きいと、入らない訪問を入れる以外の得（移動の減りなど）が変更の減点より小さくなり、案B が案A と同じになることがある（seed の14日×全スタッフの終日の欠勤 83件・反復6万回で、案B が案A と同じになったのは重み0で10件・重み3で37件・重み5で46件。入らない訪問が減ったのは、案A で入らない訪問がある41件のうち重み0で34件・重み3と5で35件で、重みを上げても減らなかった）。たとえば 10/17（土。働く人が3人）の s3 の終日の欠勤では、入らない c1 を担当できる s5・s6 の予定に空きがなく、c1 を入れるには誰かの訪問を外すしかない。修正前は重み0で c9 を外して c1 を入れる入れ替えをしていた（入らない件数は同じ1件のまま）。いまは c1 は案B でも入らず、重み0では移動を減らすために1件だけ動かし、既定の重み3以上では案A と同じになる。画面のスライダーの近くに「重みが大きいと案A のままになることがあります（変更の減点が、得より大きいとき）」を出す。振り直す訪問の担当の変化は減点しない（変えるしかない）。連絡文のひな形は固定（直すにはコードを変える）
- 見直す条件：連絡文の言い回し・住所の有無に現場から要望が出たとき。「時刻が5分ずれるだけなら連絡しない」などの閾値が要ると言われたとき。案B の計算が遅い（30人・150件で数秒を超える）と言われたとき

### レビューの反映（2026-10-14。利用者が決定）
- 入れ替えをしない：落とした訪問の点が `DROP_POINTS` 固定で、落とした訪問には変更の減点が付かないため、案B が案A に入っていた（振り直す訪問でない）訪問を落として振り直す訪問を入れることがあった（seed の 10/17 s3 の c9 など。入らない件数は同じでも、別の訪問が入らなくなる）。`ProblemStay.keep`（案A＝初期解に入っていて振り直す訪問でない訪問。始まって固定した訪問も含む）を落とした点を `KEEP_DROP_POINTS`（`DROP_POINTS`×10）にし、solver の差分（入れる・外す・入れ替える）と全体、`annealCost` に入れる。探索の途中で一時的に落とすのは許すが、最終解では落ちない。「入らない訪問は増えない」は件数でなく訪問ID の集合で「案B の入らない訪問 ⊆ 案A の入らない訪問」と言い直す（テスト：seed の14日×全スタッフの終日の欠勤、重み0と既定）
- 保険（`settleAnneal`）：案B の列に keep の訪問が1件でも無い、案A の `annealCost` が有限でない（計算中にデータが変わり案A が strict で回れない等で `SolveOptions.initial` が捨てられた）、案B の `annealCost` が案A より高い、のどれかなら、案B として出さず案A を返し、理由（「案A を超えられませんでした」など）を出す
- 記録：案B は作り終えた時点で記録に足す（同じ結果・同じ重みなら足さない。今の案は変えない）。差の表の案B は記録から出すので、選ばなくても再読込で消えず、比較の画面で見られ、今の案が案B のとき「案A を今の案にする」を押しても案B を選び直せる
- 画面の細部：案B の「止める」はプリセットを順に作るのを止めた印を立てない。日付を変えたら「案B も作る」の予約を消す。連絡の一覧のボタンの件数は連絡が要る訪問の数（担当が変わる＋時刻だけ変わる。同じ訪問は1件）

## 追記（2026-10-14）：いまの時刻をやめる・欠勤の後の動線

### 背景
利用者の報告（スクリーンショットつき）：10/14（当日）11:20 に「消防 まもる」を終日欠勤にして振り直しても、案A・案B とも 9:00 城跡・10:30 文化センターの訪問がまもるさんの列に「欠勤（終日）」「稼働時間帯に作業が収まらない」の赤い印のまま残った。再現のテスト（seed の 10/14・s4・素朴な案）で、いまの時刻を考えなければ2件とも振り直され、いまの時刻が 10:30 より後なら振り直す訪問が0件になることを確かめた。原因は、欠勤の欄の「いまの時刻」の初期値（当日は現在時刻）と「いまの時刻より前に始まる訪問は動かさない」の規則（固定・確定した割当・続けて振り直した場合も同じ結果で、ほかの原因は無かった）。あわせて「欠勤の後の案B への動線がわかりにくい（画面の上のほうにある）」との報告。

### 決めること
(a) いまの時刻の扱い、(b) 古いデータの `now`、(c) 欠勤の後の動線、(d) 振り直せない訪問の見せ方。

### 選択肢
- (a) A：初期値を空にし「いまの時刻を入れる」ボタンで入れ、動かさない訪問を「時刻が過ぎた訪問：対応が必要」と見せる／B：終日の欠勤は早朝（考えない）、時間帯は形に合わせて初期値を変える／**C：いまの時刻を機能ごとやめる**
- (b) A：契約に optional で残して無視／**B：契約から消し、store の repair（と zod の読み込み）で捨てる**
- (c) A：登録後に差の欄へスクロール／B：差の欄を担当ごとの順番の近くへ移す／C：画面の下に固定の帯／D：欠勤の人の列の見出しに近道
- (d) A：入らない訪問は「入らなかった訪問」の列の理由だけ／**B：差の欄に入らない訪問の理由、欠勤の人に残る訪問（`leftOf`）の理由を差の欄・列のカード・連絡の一覧に**

### 決定（2026-10-14。(a) は利用者が決定。(b)・(c) の組み合わせ・(d) は推奨として実装し、利用者の確認待ち）
(a)-C：時間帯を指定して休む場合も同じ不整合が起き、実際の運用でも過去の欠勤は登録しない（利用者）。振り直しは欠勤と重なる・間に合わなくなる訪問をすべて対象にし、時刻で動かさない訪問は無い。reassign の `ReassignOptions`・`targetsOf` の now・候補の `startsBeforeNow`・案B の始まった訪問の固定（`AnnealPrep.held`）・欠勤の欄のいまの時刻を消す。(a)-A・B は一度検討したが (a)-C に変えた。
(b)-B：古いデータの `ReassignInfo.now` は repair で捨てる（zod の読み込みも知らないキーを落とす）。版は1のまま。

### 理由とトレードオフ
- 得るもの：当日に欠勤を登録しても、その日の欠勤と重なる訪問がすべて振り直される（報告の不整合が起きない）。規則とコードが単純になる（いまの時刻の分岐・案B の固定・候補の確認が消える）。登録のあと、案A の結果・案B・連絡の一覧がすぐ目に入る
- 失うもの：すでに伺った・伺っている訪問も、欠勤と重なれば別の人へ振り直す案になる（過去の欠勤は登録しない前提。もし起きたら手直しかドラッグで戻す）。振り直した訪問が現在時刻より前の時刻に置かれることもある（同じ前提）。帯はもう1つ画面に浮かぶもの（差の欄が見えているあいだは出さない）
- 見直す条件：午後に「午前に遡った欠勤」を登録したい、すでに始まった訪問を動かしたくない、と言われたとき（いまの時刻を戻すなら、初期値は空にして明示的に入れる形にする）
