# ADR-0011：当日の急な欠勤を別の記録で持ち、他の人の予定を変えずに空き時間へ振り直す

- 状態：採用（2026-10-13。案B・連絡の一覧は 2026-10-14、「いまの時刻」の廃止も 2026-10-14）
- 関連：PRD D26〜D35・D167〜D172、ADR-0007・0010（点数の物差し）、ADR-0025（入口の欄）

## 背景
利用者から「当日のスタッフの急な欠勤で、他のスタッフのそれまでの予定を極力変えずに、欠勤の人の訪問を振り直したい」と要望が出た。終日だけでなく、途中の欠勤（午前だけ付き添い、早退、遅刻）も扱う。
当時できたのは、稼働時間の画面でその日の時間帯を上書きして「AI案を作る」で全部組み直すか、ドラッグで1件ずつ移すことだけ。
- 全部組み直すと欠勤と関係ない人の担当・順番・時刻まで変わり、連絡が増える（当日は連絡自体が負担）
- 稼働時間を上書きすると元の時間が消え、「なぜ減ったか」が残らない
- ドラッグでは、誰に移せば入るかを人が探すことになる

## 決定
欠勤は別の記録で持ち（1-B）、1回目は挿入だけ（案A）、2回目で「少し動かしてよい」案B を足す。置き場所は新コンポーネント reassign、結果は今の案にして全部固定（4-A）。

- データ：`DemoData.absences`（`{ id, staffId, date, from, to, note }`。from が null＝始業から、to が null＝終業まで、両方 null＝終日）。30分単位（半端は丸める。午前／午後の境は 12:00）、1人1日1件。版は1のまま。Excel に「欠勤」シート（無い古いブックは欠勤なし）
- 差し引き：domain の `withoutAbsences`（働ける時間帯を決めるのは `domain/availability.ts` だけ、を保つ）。compile と `useDayModel` がこれを通し、`Problem` の形は変えない
- 元の案：確定した割当（`manualPlans[date]`）があればそれ、無ければ今の案
- 振り直す訪問：欠勤の人の訪問のうち、欠勤と重なるものすべて（時間に幅があり後ろへずらせば入る訪問も、欠勤の人のまま残さない）・欠勤のせいで可でなくなる訪問・残すと strict で回れなくなる訪問。欠勤と関係ない元からの違反は「欠勤と重なる」と呼ばない
- 案A（挿入だけ）：他の人の担当・順番・開始時刻は変えず、入れられる人の少ない順（同じなら regret の大きい順）に、費用の増えが最小の strict の位置へ1件ずつ入れる。訪問の時刻は変えない（間に合わなければ違反の赤い枠）、件数の上限は超えない。決定的で一瞬（Worker 不要）
- 案B（少し動かしてよい）：既存の solver に `Problem.stay` を足し、「変更を減らす」重み w（0〜5・0.5刻み・既定3。担当が変わった訪問1件＝w×10点、開始のずれ1分＝w×0.2点）を費用にだけ足す。採点・点数には入れない（案A・案B・欠勤前を同じ物差し＝ADR-0010 で比べる）。案A を初期解（`SolveOptions.initial`）に渡すので案B は案A より悪くならない。振り直す訪問の担当の変化は減点しない
  - 案A に入っていた（振り直す訪問でない）訪問を落とさない：落とした訪問の点が固定で変更の減点が付かず、案B が他の訪問を落として入れ替えることがあったため、`ProblemStay.keep` を落とす点を `KEEP_DROP_POINTS`（`DROP_POINTS`×10）にした。「案B の入らない訪問 ⊆ 案A の入らない訪問」を訪問ID の集合で保証する
  - 保険（`settleAnneal`）：案B の列に keep の訪問が欠ける・案A の費用が有限でない・案B が案A より高い、のどれかなら案A を返し理由を出す
  - 案A に可でない組・strict で回れない・上限超えの列がある人は、その列だけ案A のまま外して（`AnnealPrep.held`）残りで案B を作り、「手で直してください」と出す（さもないと初期解が捨てられ、必ず案A のままになっていた）
  - 案B は作り終えた時点で記録に足し（同じ結果・同じ重みなら足さない）、選んだ方を今の案にする。選ばなくても比較の画面で見られる
- 結果：今の案（`AiPlan.reassign` に元の案・使った欠勤・`method` 'insert'|'anneal'・`stayWeight`・`insertRoutes`）にし、担当のいる訪問をすべて固定。記録にも `AiRun.reassign` を付ける。`reassign` の有無で種類を表す。続けて振り直すときは最初の元の案を引き継ぎ `absenceIds` を累積し、差も「元の案に戻す」も最初の元の案に対して
- 欠勤の取り消しでは今の案を戻さず、差の欄の「元の案に戻す」で戻す（担当・固定・generated・runId も戻す）
- 候補から入れる（`placeVisit`）：空き時間に入らない人は後ろの訪問の開始が遅れうるので、遅れる件数・最大の分を候補に出し、押したとき確認する。元から必須の違反がある列は理由を出す。確定した割当を元にするとき、今の案に未確定の変更があれば確認してから捨てる
- 連絡の一覧（PRD D35）：元の案と今の案の差から、担当が変わる訪問先・時刻が変わる訪問・仕事が増減するスタッフと、スタッフあて・訪問先あての連絡文（コピー・印刷のみ。送信しない）。件数は連絡が要る訪問の数（同じ訪問は1件）。ひな形は固定
- 「いまの時刻」はやめた：当日11:20に終日欠勤を登録しても、「いまの時刻より前に始まる訪問は動かさない」規則のため9:00・10:30の訪問が欠勤の人の列に赤印のまま残った（時間帯指定でも同じ）。過去の欠勤は登録しない運用なので、時刻で動かさない訪問を設けず（`targetsOf` の now・`startsBeforeNow`・`AnnealPrep` の始まった訪問の固定・欄のいまの時刻を削除）、古いデータの `ReassignInfo.now` は repair で捨てる
- 欠勤のせいの訪問（absence・unreachable）だけを `leftOf`（欠勤の人のまま残る訪問）に数える。notAllowed は必須の違反の赤い枠で出す
- 動線：入口は日の画面の「欠勤・キャンセル」・列の見出し・ホームのカードのどれからでも、段階のある右の欄（`SuddenPanel`。ADR-0025）に揃えた。振り直したあとは欄を閉じず4段目（まとめと案A・案B・確定・元に戻す）へ進み、差の欄へは「日の画面で差を見る」か閉じたときに移る。差の欄は担当ごとの順番のすぐ上に置き、画面の外にあるあいだだけ小さな帯（入らない N件・案B を作る・連絡の一覧・差の欄へ）を地図の上に積む。細部は design.md

## 検討した案
| 案 | 長所 | 短所 | 採否 |
|---|---|---|---|
| 欠勤1-A：稼働時間の上書きに書く | データが増えない | 元の時間が消え取り消せず、理由が残らない | 不採用 |
| 欠勤1-B：別の記録（absences） | 消せば元に戻る。メモが残り連絡文に使える | 差し引く処理が2か所 | 採用 |
| 振り直し2-A：挿入だけ | 他の人は変わらないと規則で保証・テスト可能。決定的で一瞬。理由を説明できる | 局所的で、少し動かせば入る訪問も入らない | 採用（1回目） |
| 2-B：変更の減点つき焼きなまし | 少し動かして入れられる | 重みが大きいと案A と同じになる（seed 実測で重み3のとき入らない訪問が減ったのは35/41件、案B が案A と同じ37/83件） | 採用（2回目） |
| 2-C：全部組み直し | 最適に近い | 無関係な人まで変わる | 不採用 |
| 置き場所：matching／solver／新コンポーネント reassign | reassign は運用の規則の変更が他へ波及しない | コンポーネントが増える | reassign を採用 |
| 結果4-A：今の案にして固定 | 手直し・固定・確定・比較をそのまま使える | あとで AI に組み直させたいときは固定を外す | 採用 |
| 4-B：別の「欠勤の案」を持つ | 今の案を汚さない | 画面・データが二重になる | 不採用 |
| 減点：担当が変わる1件だけ3段（小10・中30・大60） | 単純 | 条件の重みの物差しと別 | 不採用（重み w を採用） |
| 減点を採点にも足す | solver と合計点が一致 | 案どうしを比べる物差しが動く | 不採用 |

## 結果・トレードオフ・見直す条件
- 得るもの：欠勤を消せば元の稼働時間に戻り、メモが残る。案B は solver・Worker・決定性をそのまま使え、`stay` が無い問題は従来と同じ。登録のあと案A・案B・連絡の一覧がすぐ目に入る
- 失うもの：
  - 案A は局所的で全体最適ではない（点数は下がりうる）。欠勤と重なる訪問は幅があってもすべて振り直すので、欠勤明けに詰め込まない方を選んだ
  - 案B では進み具合の内部の費用と採点が一致しない。ほかの訪問を外さないと入らない訪問は案B でも入らない（入れ替えは人が候補を見て決める）。スライダーの近くに「重みが大きいと案A のままになることがある」と出す
  - すでに伺った訪問も欠勤と重なれば振り直す案になる（過去の欠勤は登録しない前提）。外した列は案B で良くならない
  - 時刻が30分単位なので 10:15 の早退などは丸める。全訪問を固定する
- 見直す条件：入らない訪問が多く手で入れる手間が大きいとき。1日に複数の欠勤の時間帯が要るとき。午前に遡った欠勤を登録したい、または始まった訪問を動かしたくないとき（いまの時刻を戻すなら初期値は空で明示入力）。連絡文の言い回し・閾値の要望。案B が遅い（30人・150件で数秒超）とき
