# ADR-0027：メニューを用途ごとに並べ替え、比較をメニューに入れ、コマンドパレット（Ctrl+K）を足す（UI/UX 改善の区切り7）

- 日付：2026-10-18
- 状態：採用（利用者の依頼（2026-10-18）「直感的にやりたいことが操作できるように」の区切り7。細部は推奨どおり。PRD D178〜D183。ADR-0019 のメニューの並びと「比較はメニューに出さない」を置き換え、ADR-0024 のスマホのメニューの仕組み（上の帯・引き出し・下のタブ）はそのまま使う。ADR-0025 の「これからの区切り」の7）

## 背景
画面の監査（2026-10-18。ADR-0025）で、メニューについて次が分かった。

- メニューが「データの種類」（〈利用者さん〉／〈スタッフ〉／割当の設定）で並んでいる（ADR-0019）。利用者のやりたいこと（月を組む・欠勤に対応する・問い合わせに答える）と合わず、欠勤の対応はメニューから届かない（日の画面の「欠勤・キャンセル」とホームのカードだけ）
- 「一覧・編集」が2つ同じ名前で並ぶ（見出しで見分けるしかなく、スマホでは上の帯の名前で補っていた＝ADR-0024）
- 比較の画面はメニューに無い（ADR-0019）。区切り3（PRD D156〜D160）で、比較の画面に案が1つでも「もう1案作って比べる」、区切り6（D176）で案が無いときの「日の画面で案を作る」を足し、比較を単独で開いても行き止まりにならなくなった。区切り3で「メニューに入れるかは区切り7で決める」と先送りしていた
- 画面が16に増え、名前を知っている画面・人に行くにもメニューか一覧をたどる必要がある。〈利用者さん〉を名前で開くには一覧を開いて探す（2〜3手）
- ADR-0019 が人ごとに並べた理由：相性は〈利用者さん〉×〈スタッフ〉の組み合わせで社内の決まりではない、稼働時間・稼働の見込みは〈スタッフ〉ごとのもの、「誰の何を直すか」でたどれる。この利点は残したい
- 制約：URL・データ・契約（`src/contracts/`）・store は変えない（ブックマークと `?do=`・`?id=` の入口をそのまま使う）。新しい依存（コマンドパレットのライブラリ）を足さない。スマホは表示の確認が主（PRD §7）。〈スタッフ〉はよみを持たない

## 選択肢
### メニューの並び
1. 案A：用途のグループ（ホーム／予定を組む（月・週・日・案を比べる）／当日の対応（欠勤・キャンセル）／問い合わせ（空き状況）／人の情報（〈利用者さん〉一覧・相性・〈スタッフ〉一覧・稼働時間・稼働の見込み）／AI の考え方（条件の重み・訪問の種類・特性の項目）／データ）。人の情報の中は人ごとの順にして ADR-0019 の並びを残す
2. 案B：用途のグループに分けるが、人の情報を〈利用者さん〉と〈スタッフ〉の2つの見出しのまま残す（グループが8つ）
3. 案C：今の人ごとの並びのまま、名前の重複だけ直す（〈利用者さん〉一覧・〈スタッフ〉一覧）
### 比較をメニューに入れるか
1. 案A：予定を組むの「案を比べる」に入れる（今の画面の印は「案を比べる」。スマホの下のタブには入れず、比較では「日」）
2. 案B：入れない（ADR-0019 のまま。コマンドパレットからは開ける）
### 探して移る道具
1. 案A：コマンドパレット（上の帯のボタンと Ctrl+K。画面・操作・人の名前を打って絞り込む。モーダル）を自前で作る（確認ダイアログの inert・フォーカスの戻しを使う）
2. 案B：上の帯に常に出る検索欄（打つと下に候補）
3. 案C：作らない（メニューとホームのカードだけ）

## 決定
- メニューは案A（PRD D178）。名前は「〈利用者さん〉一覧」「〈スタッフ〉一覧」（呼び方から引く）、画面の見出しもそろえる（D179）。当日の対応の「欠勤・キャンセル」は画面ではなく操作（`#/plan?date=今日&do=absence`）で、今の画面の印を付けない。並びは `lib/nav.ts` の `menuSections(terms, today)`（純粋関数。アイコンは名前で持ち、`App.tsx` が部品を引く）の1か所で、左のメニュー・引き出し・下のタブ・上の帯の名前・コマンドパレットの画面がここから引く
- 比較は案A（D180）。ADR-0019 の「見直す条件」（比較を日をまたいで使いたい要望）とは別に、区切り3・6 で比較の画面が単独で使えるようになったので入れる。今の画面の決まりはメニュー（`activeNavPath`：比較は `/compare`）と下のタブ（`activeTabPath`：比較は `/plan`）で分ける
- 探して移る道具は案A（D181〜D183）。中身と絞り込みは `lib/commandPalette.ts`（純粋関数）、見た目は `components/CommandPalette.tsx`。行き先は今ある URL だけ（画面・区切り1〜5 の `?do=`・閲覧の欄の `?id=`）
- 入力欄・テキストエリアの中の Ctrl+K：開く（Windows・Linux の Ctrl+K は文字の編集に使わず、ブラウザでは検索欄へ移ってしまうため）。入れた文字はそのまま、閉じたらその入力欄へ戻す。mac は ⌘K だけで開き、Ctrl+K（行末まで消す）は横取りしない。右の欄・確認・引き出しが開いているあいだは開かない（未保存の編集の上から別の画面へ移れてしまうため。今のメニューも右の欄の背景で押せない）。開かないときも Ctrl+K・⌘K の既定の動き（ブラウザの検索欄・アドレスバーへ移る）は止める（PR #43 のレビュー）

## 理由とトレードオフ
- 得るもの：メニューの上から順に「組む → 当日 → 問い合わせ → 人 → AI の考え方」と、仕事の流れで探せる。欠勤の対応がメニューから1手。同じ名前の項目が無くなり、上の帯の名前に頼らず見分けられる。人の情報の中は人ごとの順なので、ADR-0019 の「誰の何を直すか」でたどる並び（〈利用者さん〉の下に相性、〈スタッフ〉の下に稼働時間・稼働の見込み）は残る。パレットで、名前を知っている画面・操作・人に2〜3打で着く（〈利用者さん〉はよみでも）。行き先は今ある入口なので、機能を二重に作らない。新しい保存データ・依存・契約は無い
- 失うもの：ADR-0019 で慣れたメニューの位置が変わる（URL は同じなのでブックマークは効く）。人の情報の見出しが1つになり、〈利用者さん〉と〈スタッフ〉の境目は項目の名前で見分ける。メニューの項目が14から16に増える（左のメニューは縦に巻くことがある。1400×1000 では収まる）。上の帯にボタンが1つ増える（390px では「探す」だけにして1段目に収める）。〈スタッフ〉はよみを持たないので、漢字の名前はひらがなでは引けない（よみを足すとデータの版・Excel が変わるので今回はしない）。パレットを開くたびに全員の名前をそろえ直す（300人×60人で数 ms）
- メニューの案B はグループが8つになり、用途の並びの中で「人」だけ2つに割れる。案C は「やりたいことから入る」問題が残る
- 比較の案B は、メニューから比較に行けない（区切り3で入口を目的の言葉にしても、日の画面を開かないと届かない）
- 道具の案B は上の帯が狭い画面で2段になり、入力欄が常にあるので Tab の順が1つ増える。案C は画面・人が増えるほど遠くなる

## 影響
- 画面：`lib/nav.ts`（`menuSections`・`absenceHref`・`isNavAction`・`activeTabPath`・`isActiveTab`。`activeNavPath` の比較は `/compare` に。上の帯の名前を見出しと項目名に分ける `navTitleParts`。390px で入りきらなければ2行に折り返し、名前を切らない）、`app/App.tsx`（並びは `menuSections`、アイコンは `NAV_ICONS`。`NavGroups` は全部 `Link` で `aria-current` を自分で付ける。上の帯に「探す・移動」のボタン、Ctrl+K の受け、`CommandPalette`）、`components/CommandPalette.tsx`（`commandPalette.css`）、`lib/commandPalette.ts`、画面の見出し（`ClientsPage`・`StaffPage`・`ComparePage`）。データ・契約（`src/contracts/`）・store・URL は変えない
- 確かめ：`src/lib/nav.test.ts`・`src/lib/commandPalette.test.ts`、`scripts/e2e-nav.cjs`（メニューの並び・名前・aria-current、Ctrl+K → 打つ → 矢印 → Enter、人の名前で閲覧の欄、Esc とフォーカスの戻り、入力欄の中の Ctrl+K、390px のボタン、印刷、300人×60人の速さ）。`scripts/e2e-mobile.cjs` は新しい名前（上の帯・引き出しの見出し・項目の数 16）で確かめる
- ADR-0019：状態に「並びと比較は ADR-0027 で置き換え」を足す。ADR-0024：仕組み（上の帯・引き出し・下のタブ・`lib/nav`）はそのまま。下のタブの「比較では日」も変えない
- 見直す条件：パレットを使う人が多ければ、最近使ったものを先に出すか（保存が要る）を決める。〈スタッフ〉をよみで引きたい声があれば、〈スタッフ〉によみを足す（データの版・Excel の列）かを決める。メニューの「当日の対応」が欠勤・キャンセルだけで寂しいという声があれば、「今日の予定」をそこに置くかを決める

## レビュー（PR #43）で直したこと（追記）
- 吹き出し（予定の名前の i）の中から開いて閉じると、戻す先（吹き出しの中の要素）が消えていてフォーカスが body に落ちた。戻す先が文書につながっていなければ、上の帯の「探す・移動」へ戻す
- ↓ で末尾から先頭へ回ったとき、候補だけが見える位置に巻かれて種類の見出しが隠れた。先頭のときは一番上まで巻き、種類の先頭の候補のときは見出しごと見せる
- 操作の候補に「今日の案をいまの条件で作り直す」（`?do=recreate`。PRD D166）を足した。いまの条件がどのプリセットとも違うとき（`presetOf` が null。設定の画面の案内と同じ条件）だけ出す
- 右の欄・確認・引き出しが開いていてパレットを開かないときも、Ctrl+K・⌘K の `preventDefault` はする（押すたびにアドレスバーへ移らないように）。mac の Ctrl+K は今どおり横取りしない
- 画面の候補の別名に呼び方のよみを足した（`lib/commandPalette` の `TERM_READINGS`：既定の呼び方のうち漢字の「利用者さん」「お客様」。カタカナの呼び方（スタッフ・ヘルパー・シッター）はそろえるとひらがなになるので要らない）。事業所が呼び方を表に無い漢字に変えると、よみでは引けず漢字でだけ引ける（呼び方によみの欄を足すとデータの版が変わるので、今回はしない。声があれば決める）
