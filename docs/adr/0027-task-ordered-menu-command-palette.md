# ADR-0027：メニューを用途ごとに並べ替え、比較をメニューに入れ、コマンドパレット（Ctrl+K）を足す

- 状態：採用（2026-10-18）
- 関連：PRD D178〜D183、ADR-0019（メニューの並びと「比較はメニューに出さない」を置き換える）、ADR-0024（スマホのメニューの仕組みはそのまま）、ADR-0025（UI/UX 改善の区切り7）

## 背景
画面の監査（ADR-0025）で、メニューについて次が分かった。
- メニューが「データの種類」（〈利用者さん〉／〈スタッフ〉／割当の設定）で並び、やりたいこと（月を組む・欠勤に対応する・問い合わせに答える）と合わない。欠勤の対応はメニューから届かない
- 「一覧・編集」が2つ同じ名前で並び、見出しや上の帯の名前で見分けるしかない
- 比較の画面はメニューに無かった。区切り3・6で比較の画面が単独で開いても行き止まりにならなくなり、メニューに入れるかは先送りしていた
- 画面が16に増え、名前を知っている画面・人にもメニューか一覧をたどる必要がある（〈利用者さん〉を名前で開くのに2〜3手）
- ADR-0019 が人ごとに並べた利点（相性は〈利用者さん〉×〈スタッフ〉の組み合わせ、稼働時間・稼働の見込みは〈スタッフ〉ごと、「誰の何を直すか」でたどれる）は残したい

制約：URL・データ・契約・store は変えない。新しい依存（パレットのライブラリ）を足さない。スマホは表示の確認が主。〈スタッフ〉はよみを持たない。

## 決定
メニューは用途のグループに並べ替え、比較を入れ、コマンドパレットを自前で足す。

- 並び（PRD D178）：ホーム／予定を組む（月・週・日・案を比べる）／当日の対応（欠勤・キャンセル）／問い合わせ（空き状況）／人の情報（〈利用者さん〉一覧・相性・〈スタッフ〉一覧・稼働時間・稼働の見込み）／AI の考え方（条件の重み・訪問の種類・特性の項目）／データ。人の情報の中は人ごとの順にして ADR-0019 の並びを残す。名前は「〈利用者さん〉一覧」「〈スタッフ〉一覧」（呼び方から引く）、画面の見出しもそろえる（D179）。「欠勤・キャンセル」は画面でなく操作（今日の日の画面の `?do=absence`）で、今の画面の印を付けない。並びは `lib/nav.ts` の `menuSections(terms, today)`（純粋関数）の1か所で、左のメニュー・引き出し・下のタブ・上の帯の名前・パレットの画面がここから引く。メニューの項目は14から16
- 比較（D180）：「案を比べる」としてメニューに入れる。今の画面の決まりはメニューでは比較＝`/compare`、スマホの下のタブでは比較＝「日」（`activeNavPath`・`activeTabPath`）。上の帯の名前は「見出し・項目名」（`navTitleParts`）で、390px で入りきらなければ2行にし名前を切らない
- コマンドパレット（D181〜D183）：上の帯のボタン（390px では「探す」だけで1段目に収める）と Ctrl+K（mac は ⌘K）。画面・操作・人の名前を打って絞り込むモーダルで、確認ダイアログの inert・フォーカスの戻しを使う。中身と絞り込みは `lib/commandPalette.ts`（純粋関数）、見た目は `components/CommandPalette.tsx`。行き先は今ある URL だけ（画面・`?do=`・閲覧の欄の `?id=`）。〈利用者さん〉はよみ（カタカナ）でも引け、〈スタッフ〉は名前だけ。画面の候補の別名に呼び方のよみを足す（`TERM_READINGS`。既定の漢字の呼び方のみ。表に無い漢字の呼び方はよみで引けない）。操作には欠勤・キャンセルの登録・まとめて作るに加え、いまの条件がどのプリセットとも違うときだけ「今日の案をいまの条件で作り直す」（D166）
- キー操作：入力欄・テキストエリアの中の Ctrl+K も開く（Windows・Linux では文字編集に使わず、ブラウザでは検索欄へ移ってしまうため）。文字はそのまま、閉じたらその入力欄へ戻す。mac は ⌘K だけで開き、Ctrl+K（行末まで消す）は横取りしない。右の欄・確認・引き出しが開いている間は開かない（未保存の編集の上から別の画面へ移れてしまうため）。開かないときも Ctrl+K・⌘K の既定の動き（ブラウザの検索欄・アドレスバーへ移る）は止める。戻す先が消えていたら（吹き出しの中から開いたとき）上の帯の「探す・移動」へ戻す。↓ で末尾から先頭へ回ったら一番上まで巻き、種類の先頭の候補は見出しごと見せる
- データ・契約・store・URL は変えない。確かめ方は `src/lib/nav.test.ts`・`commandPalette.test.ts`、`scripts/e2e-nav.cjs`、`e2e-mobile.cjs`（項目の数16）。ADR-0019 の状態に「並びと比較は ADR-0027 で置き換え」を足す。画面の細部は design.md

## 検討した案
| 案 | 長所 | 短所 | 採否 |
|---|---|---|---|
| 並びA：用途のグループ（人の情報は人ごとの順で1つ） | 仕事の流れで探せる。欠勤がメニューから1手。同名項目が無くなる。ADR-0019 の「誰の何を直すか」も残る | メニューの位置が変わる（URL は同じ）。人の情報の見出しが1つで境目は項目名で見分ける | 採用 |
| 並びB：用途で分け、人の情報を〈利用者さん〉と〈スタッフ〉の2見出し | 境目が見出しで分かる | グループが8つになり、用途の並びの中で「人」だけ2つに割れる | 不採用 |
| 並びC：人ごとの並びのまま名前の重複だけ直す | 変更が小さい | 「やりたいことから入る」問題が残る | 不採用 |
| 比較A：メニューに入れる | メニューから比較に行ける | 項目が増える | 採用 |
| 比較B：入れない（パレットからは開ける） | ADR-0019 のまま | 日の画面を開かないと届かない | 不採用 |
| 道具A：自前のコマンドパレット | 名前を知っている画面・操作・人に2〜3打で着く。既存の入口を使い二重に作らない | 全員の名前をそろえ直す（300人×60人で数ms）。漢字の〈スタッフ〉はひらがなで引けない | 採用 |
| 道具B：上の帯の常設の検索欄 | 常に見える | 狭い画面で帯が2段になり、Tab の順が増える | 不採用 |
| 道具C：作らない | 実装不要 | 画面・人が増えるほど遠くなる | 不採用 |

## 結果・トレードオフ・見直す条件
- 得るもの：上から順に「組む → 当日 → 問い合わせ → 人 → AI の考え方」と仕事の流れで探せる。新しい保存データ・依存・契約は無い
- 失うもの：慣れたメニューの位置が変わる。左のメニューが縦に巻くことがある（1400×1000 では収まる）。上の帯にボタンが増える。〈スタッフ〉のよみは持たない（足すとデータの版・Excel が変わるので今回はしない）
- 見直す条件：パレットを使う人が多ければ最近使ったものを先に出すか（保存が要る）。〈スタッフ〉をよみで引きたい声（よみを足す）・呼び方によみの欄を足したい声。「当日の対応」が欠勤・キャンセルだけで寂しければ「今日の予定」をそこに置くか
