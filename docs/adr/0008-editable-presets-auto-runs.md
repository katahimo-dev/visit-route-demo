# ADR-0008：プリセットを利用者が編集できるデータにし、開いた日に全プリセットで案を作る

- 日付：2026-10-13
- 状態：採用

## 背景
ADR-0005 で条件のプリセットを3種（標準・移動を短く・人の組み合わせ重視）の**定数**として `src/seed/presets.ts` に置き、AI案の画面を開いた日にAI案が無ければ標準だけで1案を自動で作るようにした。
利用者から次の要望が出た（2026-10-13）。

- 開いた日に、プリセットの案を全部作っておいてほしい（1つずつ押して作るのが手間）
- プリセットごとの案を並べて、点数・移動・違反を一目で比べ、良いものを今の案にしたい
- プリセットの名前・重みを自分の事業所に合わせて変えたい。いまの重みをプリセットとして残したい
- 条件ごとにどれだけ守れたか（希望 18/20件 など）を件数で見たい

決めること：(1) プリセットをどこに持つか、(2) 開いた日の自動作成の範囲、(3) 並べたときの点数の物差し、(4) 達成の件数の数え方。

## 選択肢
1. プリセットの置き場所
   - A：定数のまま（編集はできない）
   - B：データ（`DemoData.presets`）に持たせ、store が持ち主になる。初期値は seed の3種
   - C：localStorage の別のキーに持つ（データ一式の外）
2. 開いた日の自動作成
   - A：標準だけ（今まで）
   - B：すべてのプリセットで順に作る（Worker で1つずつ）
3. 並べたときの点数
   - A：どのカードも「いまの条件」（`data.rules`）の同じ物差しで付ける
   - B：プリセットごとの条件の物差しで付ける
4. 達成の件数
   - A：条件（Rule）ごとに「その条件の判定がある訪問」を分母、「その条件の判定をすべて満たした訪問」を分子にする（相性は ◎・○・△・× の件数）
   - B：条件1つずつ（`PlanScore.perRule` の達成/違反の数のまま）

## 決定
1-B、2-B、3-A、4-A（利用者が決めた。2026-10-13。4 の分母は推測で決め、設計書に書いた）。

- データの形：`DemoData.presets: Preset[]`（zod。`src/contracts/rules.ts` の `presetSchema`）。`Preset`＝`{ id, name（1〜20字）, note（0〜60字）, weights: 条件の型 → { weight, hard } }`。版は1のまま。`presets` が無い古い保存データは、`migrate` で初期の3種（`INITIAL_PRESETS`）で補う
- 数は最大6つ（初期の3つ＋利用者が足す3つ）。最後の1つは消せない。「初期値に戻す」で初期の3種（id：`standard`・`travel`・`people`）に戻す
- `repair` が直すもの：id の重複（最初の1件）、6つを超える分（後ろを捨てる）、0件（初期の3種）、重み（0〜5 に収め 0.5 刻みに丸める。数でなければ 0）、必須にできない型の必須（外す）。重みの範囲は zod では止めず repair で直す（手で直した JSON で、データ全体が読めなくならないように）
- 自動作成：AI案の画面を開いた日に今の案が無ければ、`data.presets` の順に1つずつ Worker で作り、どれも記録（`aiRuns`）に残す。途中は最初に作れた案を見せ、終わったら一番点の高い（いまの条件の物差し。王冠の。同点なら先のプリセット）案を今の案にする（その間に手直し・別の案にしていれば変えない。2026-10-13 利用者の決定で「最初に作れた案」から変更）。2つ目以降も最新のデータで問題を作る。進み具合（「10/13 の案：プリセット 2/3」と反復回数）を出し、「止める」でいま作っている案を途中の最良で残して、残りはやめる。計算中は重み・プリセット・いまの重みを保存を押せない。その日の条件（`data.rules`）は書き換えない
- カード：AI案の画面の上部に、プリセットごとに「その日の記録のうち、固定なしで、重み・必須がそのプリセットと一致する最新の記録」を出す（記録の `presetId` ではなく重みで引く。プリセットを編集したら、古い記録は一致しなくなり「まだ作っていません」になる）。点数はいまの条件の同じ物差し（比較の画面と同じ）。一番点の高いカードに王冠の印（0点のカードには付けない）。「今の案」の印は、今の案の元になった記録の id（`AiPlan.runId`）で決める。「この案にする」でその記録を今の案にする（比較の画面の「AI案の画面で開く」と同じ）
- 達成の件数：evaluate に `achievements(problem, routes): RuleAchievement[]` を足す。相性の理由に `level`（2・1・−1・−2）を持たせ、◎・○・△・× を数える

## 理由とトレードオフ
- 得るもの：
  - 開いただけで、プリセットごとの案が並び、どれが良いかを同じ物差しで一目で選べる
  - 事業所ごとの考え方をプリセットとして残せる。データ一式（JSON・Excel）に入るので、ほかの端末・人へ渡せる
  - 件数で見ると「希望を2件落とした」のように、重みを変えた効果を言い直せる
- 失うもの：
  - 開いたときの計算がプリセットの数ぶん長くなる（3つで 10秒前後。最大6つ）。止められるようにして受け入れる
  - プリセットを編集すると、その前に作った記録はカードに出なくなる（記録としては残り、比較の画面で見られる）
  - 同じ型の条件が2つ以上あるとき、「いまの重みを保存」は型ごとの最初の条件の重みだけを残す（プリセットは型ごとの重みなので）
  - 達成の件数は「いまの条件」で有効な条件だけを数える（重み0の条件は判定しないので出ない）
  - 点数（3-A）は、プリセットを作ったときの条件の点とは一致しない（ADR-0005 と同じ理由で、比べられることを優先した）

## 影響
- 要件：PRD の D20・D21 を変更、D24（いまの重みをプリセットとして保存）・D25（条件ごとの達成の件数）を追加
- 設計：store の持つデータに `presets`。`Preset` の型を `src/seed/presets.ts` から `src/contracts/rules.ts` へ移す（契約）。seed は初期値 `INITIAL_PRESETS` と `applyPreset`・`presetOf(rules, presets)` を持つ。evaluate に `achievements`、`Reason.level`。Excel のブックに「プリセット」シート（列：ID・名前・一言・重み：〈条件の型〉…・必須）。pages：AI案の画面のカード・自動作成、条件の画面のプリセットの節
- 見直す条件：プリセットを6つより多く使いたい声が出たとき。開いたときの計算が長いと言われたとき（標準だけを先に作り、残りは押したときに作る案に戻す）

## 追記（2026-10-13）：物差しは ADR-0010 で基準のプリセットに固定
- 3-A（どのカードもいまの条件の物差し）は、ADR-0010 で「どのカードも点数の基準のプリセットの物差し」に置き換えた。自動作成の終わりに今の案にする「一番点の高い案」・王冠・カードの必須の違反・達成の件数も基準の物差し
- カードの「この案にする」と右の欄のプリセットのボタンは、ADR-0010 でカード全体を押せるボタンに一本化した（同じ条件・同じデータの記録があれば計算しない）

## 追記（2026-10-19）：一部を ADR-0035 で変更
- 「いまの重み」（`data.rules`）は「この日だけ試す重み」と呼ぶ。「いまの重みをプリセットとして保存」は、日の予定・作り直しの帯では「試す重みをプリセットとして保存」、条件の重みの画面のプリセットの節では「基準の重みを写して保存」（点数の基準のプリセットの重みを写す）
- 点数の基準のプリセットの重み・必須を編集すると、試す重みも基準にそろえる（ADR-0035）
