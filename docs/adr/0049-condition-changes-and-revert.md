# ADR-0049：作り直しの帯に「何が変わったか」と「戻す」（条件の変更の控え）

- 日付：2026-10-21
- 状態：採用
- 関連：PRD D290〜D292（D161〜D166 の続き）、ADR-0025（作り直しの帯）・ADR-0026（独自の確認）・ADR-0028（機能の入り切り）・ADR-0032（1世代の控え）・ADR-0035（条件の重み＝点数の基準）

## 背景
- 設定の画面の上に「条件が変わりました：影響する日 40日（未確定 0日・確定済み 40日）」と出るが、何が変わったのか分からない。変えたつもりも無く、戻す手段も無い
- 「条件が変わった」は2つの判定：(1) 今の案の記録の重み（`AiRun.rules`）が、試す重みにも各プリセットにも当てはまらない、(2) 記録の `inputKey`（問題のハッシュ）が今のデータで作った問題と違う。(2) はハッシュなので、昔の値は残っていない
- 制約：契約（`src/contracts/`）・データの版（1）は変えない。データを書き換えるのは store の `update(fn)` だけ。帯の数え方・［作り直す］［要対応を見る］［後で］は変えない

## 選択肢
1. 案A：DemoData の外（このブラウザの記録。`vrdemo:conditions:base`）に「最後に影響する日が0日だった時点」の条件の部分を1つ控え、今と比べる。控えは store の `update` で条件の部分が変わったときに（控えが無ければ）変わる前を書き、帯が0日を数えたら消す。控えの無いときは記録の重みと基準のプリセットの重みだけ比べる
2. 案B：記録（`AiRun`）に作ったときの条件の写しを持たせ、記録と今を比べる
3. 案C：変更の履歴（操作ごとの記録）を持ち、1つずつ元に戻す（取り消しの積み重ね）

## 決定
案A。あわせて次も決める。
- 控えに入れるのは問題・重みに効くもの：`org`（機能の入り切り・上限・呼び方）・`items`・`rules`・`presets`・`scorePresetId`・`staff`・`clients`・`compat`・`availability`・`visitTypes`・`patterns`・`clientLeaves`。訪問・案・記録・確定した割当は入れない。欠勤（`absences`）・手直しの記憶・乱数の種も日々の操作として入れない
- 控えを取るのは `update` だけ（どの画面の変更でも。管理者設定の入り切りも）。中身が同じ作り直しは変わったにしない（キーごとに参照を比べ、違えば JSON で比べる）。`replace`（読み込み）・`reset`（初期状態に戻す）・`restorePrevious`（直前の状態に戻す）は比べる元が違うので控えを消す。別のタブの変更では取らず、控えのキーの `storage` の知らせで読み直す（そのタブが取る）。作り直しは条件を変えないので控えに触れず、作り直して0日になったら消える
- 控えを消すのは、今のデータを数えて0日になったときだけ（入力が止まる前の古いデータを数えた0日では消さない）。数えるのは帯ではなく App の殻にいつも置く `ConditionsBaseSweep`（追記：PR #74 のレビュー。帯の無い画面・rules を切っているときに控えが残り、後の変更と混ざるため）。控えが無い間は数えず、日ごとの計算は月の予定・帯と覚えを分け合う
- 保存データが無い・読めずに初期データで始めたときも消す。本体の保存が容量超過なら、控えを捨ててから書き直す（1世代の控えより先に捨てる。本体の保存が先）
- 一覧は種類ごと（条件の重み＝基準のプリセット・ほかのプリセット・点数の基準・条件・この日だけ試す重み（基準にそろっていれば出さない）・機能・事業所の設定・特性の項目・訪問の種類・相性・人ごとの〈スタッフ〉と〈利用者さん〉・人ごとの勤務時間（シフト）・〈利用者さん〉ごとの休みと定期パターン）。はじめ畳み「変更内容を見る（N件）」
- 戻すは項目ごとと「すべて戻す」。独自の確認に戻るものを出す。戻したあと `repair` を通す。戻せるのは中身の書き換えだけで、足した・消したもの（人・定期パターン・特性の項目・訪問の種類・プリセット・条件）と特性の項目の直しは一覧に出すが戻さない（追記：PR #74 のレビュー。足した人を消すと訪問・相性・パターンの参照が、消した項目を戻すと特性の値が食い違う。各画面で直してもらう）。人の属性を戻すときは、消えた項目・選択肢を指す特性の値を外す。「すべて戻す」も戻せるものだけ。戻したこと自体は控えない（`update(fn, { keepBase: true })`）
- 控えが無いときは、重みで変わった日の記録の重みと基準のプリセットの重みの違い（いちばん多い組）を出し、戻すは基準のプリセットの重みを作ったときの値にする。それも無ければ「記録がありません」と正直に書く

## 理由とトレードオフ
- 得るもの：何が変わったか（相性・入り切り・人の勤務時間など、ハッシュでしか分からなかったもの）を言葉で見せ、1つずつ・まとめて戻せる。契約・データの版を変えず、書き出し・読み込みにも入らない。比べる元が「最後に0日だった時点」なので、戻すと帯が消える
- 失うもの：
  - 控えは1つで、取る前の変更（この仕組みより前・控えを消したあとに別の原因で残っていた日）は分からない（重みだけは記録から分かる）。一覧の上に「M/D H:mm からの変更」と書き、空なら「記録より前の変更」と書く
  - 控えは条件の部分の写しなので、〈利用者さん〉・〈スタッフ〉が多いと localStorage を使う（書けなければ開いている間だけ覚える）
  - 足した・消したものは戻せない（各画面で直す）
  - 定期パターン・種類を戻しても、作った訪問は戻らない
- 捨てた案：案B は契約（`AiRun`）に大きな写しを足し、記録ごとに容量を食い、データの版の扱いが要る。案C は操作ごとの記録で容量と実装（どの画面の操作も記録に包む）が大きく、ほかのタブ・読み込みとの整合も難しい

## 影響
- PRD：D290〜D292 を足す
- 設計：`docs/design.md`（store の持つデータ・API）、`docs/design/pages-common.md`（作り直しの帯）
- 実装：`store/conditions.ts`（新規。`CONDITIONS_BASE_KEY`・`conditionsOf`・`captureBase`・`conditionsMemory`）・`store/react.tsx`（`conditionsBase`・`clearConditionsBase`・`update(fn, { keepBase })`）、`lib/conditionChanges.ts`（新規。`conditionChanges`・`madeWeightsChange`・`applyRevert`・`revertAll`）、`components/rebuildBand.tsx`（変更内容の一覧と戻す）。契約・データの版は変えない
- e2e：e2e-rebuild（管理者設定で相性を切ると控えを取り「機能：相性を切」・戻すと帯と控えが消える・控えがあるときの2件とすべて戻す・控えの無いときの作ったときの重み・記録が無いときの文・足した人は［戻す］を出さず「各画面で直してください」・帯の無い画面でも0日なら控えを消す）
- 見直す条件：「控えより前の変更が分からない」声が多ければ、記録に作ったときの条件の要約（人数・相性の組の数など）を足して比べる。容量が問題になれば、控えを差分の形にする
