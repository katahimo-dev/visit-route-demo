# ADR-0046：週の範囲で作る・確定／要対応の数え方／未作成の表示（UI を直感的にする第3弾）

- 日付：2026-10-21
- 状態：採用
- 関連：PRD D280〜D282（D55・D151・D176・D223 の書き換えを含む）、ADR-0012（月まとめ作成）・ADR-0025（進み具合の帯・空の画面）・ADR-0031（まとめて確定）・ADR-0042（月まとめの計算を画面の外で）・ADR-0044（第1弾）・ADR-0045（第2弾）

## 背景
- 実機（1366×768・390×844）の評価で、第1・2弾のあとも次の3つが残っていた
  - 週の予定で案の無い週を開くと、次の一手は「11月の案をまとめて作る」だけで、押すと月の予定へ飛ばされ、その月の今日以降の30日ぶん（1〜2分）を作ることになる。見ていた週だけを作って確定する手段が無い
  - 欠勤を登録して振り直し、確定まで済ませても、その日は月の要対応・進み具合の帯・ホームに「要対応 1件」（欠勤）のまま残る。手当てが済んだのか分からず、本当に手当てが要る日が埋もれる
  - 定期パターンからまだ訪問を作っていない日が、週の見出しで「0件」、月のマスで白い「訪問なし」に見え、本当に訪問の無い日と区別できない。帯の「あと N件」と同じことを指しているとも分からない
- 制約：契約（`src/contracts/`）・データの版（1）は変えない。データを書き換えるのは store の `update(fn)` だけ。月まとめ作成の計算の中身（規則・手直しの記憶。ADR-0042・0043）は変えない。主ボタンは画面に1つ。要対応の数はホーム・帯・月で同じ（ADR-0025）

## 選択肢

### 週の範囲で作る・確定
1. 案A：週の見出しに主ボタンを状態で1つ（作る → 確定 → 済み）。作るは月まとめの入れ物（`lib/monthBatch`）に範囲を渡して週の今日以降の日だけを作り、確定は月の「問題の無い日をまとめて確定」の決まり（`bulkConfirmTargets`）を週の日に当てる
2. 案B：週の空の画面のボタンを、月の予定の「まとめて作る」の欄を開くまま（対象の日を週に絞った状態で開く）にする
3. 案C：週の予定に別の小さな計算（入れ物を使わず画面の中で回す）を置く

### 要対応の「欠勤」
1. 案A：欠勤のある日のうち、手当てが済んだ日（確定済みで、入らない訪問・必須の違反・休みの人に残る訪問が無い）を `attentionList` で数えない。情報「欠勤あり（対応済み）」として月の右の欄・一覧・マスに残す
2. 案B：欠勤を要対応から外す（いつも数えない）
3. 案C：欠勤の記録に「対応済み」の印を持たせ、振り直しの欄の最後で付ける

### 未作成の表示
1. 案A：訪問の無い今日以降の日で、定期パターンから作れる訪問があれば「未作成」と出す（週の見出し・表の合計・空の画面、月のマス・一覧）。帯の「あと N件」を「未作成 N件」にそろえる
2. 案B：日を開いたときに自動で展開して、未作成の日を作らない
3. 案C：表示は今のまま、凡例で「0件には未作成の日もある」と説明する

## 決定
すべて案A。あわせて次も決める。
- 作る日は「まだ案の無い日だけ」（月の既定と同じ）。条件が変わった日・確定していない日すべての作り直しは週では出さない（月の予定で選ぶ）
- 入れ物の `BatchJob` の `expandYm`（月）を `expand: { from, to }`（範囲）に替え、`source` に `week` と `weekStart` を足す。月の予定は月の1日〜末日を渡す（動きは今のまま）。上の帯の文は「〈M/D〉〜〈M/D〉の週の案を作っています N/M日」、リンクと知らせのボタンはその週の週の予定（その週を見ていれば知らせのボタンを出さない）
- 作っている間は週の予定にとどまり、上の帯（`BatchBand`。週の予定でも出す）で進み具合と［止める］。週の主ボタンは「この週の案を作っています…」で押せない。ほかの案を作っている間は押せず、理由を見える文で
- 確定は月と同じ確認ダイアログ（`bulkConfirmDialog`）・同じ書き方（`confirmDay`）。問題のある日・前に確定した割当と違う日だけ残ればボタンを出さず、日の予定で確定する理由を出す
- 月をまたぐ週は1度に作る・確定する（2つの月の日）。進み具合の帯は今どおり選んでいる日付の月を数え、次の一手（月のまとめて作る）は普通のボタンのまま
- 「欠勤あり（対応済み）」は地の色（赤・注意の色にしない）。マスの「欠」には「（済）」と読み上げ「（対応済み）」
- 「未作成」は注意の色にしない（点線の枠と文字だけ）。月のマスのボタンの `data-state` は `empty` のまま（`data-unmade` に件数）

## 理由とトレードオフ
- 得るもの：週を見ながら、その週だけを数十秒で作って確定でき、月の画面へ飛ばない。作る・確定は月と同じ仕組み・同じ決まりなので、数え方や作り方が週と月で食い違わない（手直しの記憶・使い回せる記録・データの差し替えで止める、も同じ）。手当てを終えた欠勤が要対応から消え、ホーム・帯・月の要対応が同じ1つの関数で同じ数になる。0件と未展開を取り違えない
- 失うもの：
  - 週の作るは「まだ案の無い日だけ」なので、条件が変わった日の作り直しは月の予定へ行く
  - 週の主ボタンと、空の画面の［この週の案を作る］が同じ動きで2つ見える（空の画面のほうは主ボタンにしない。未作成の日から作るへの導線として残す）
  - 週の予定でも、月の予定と同じく今日以降の日を compile・採点する（7日ぶん。日ごとの覚えを月・ホームと共有するので、帯と重ねても数え直しは増えない）
  - 確定済みでも欠勤のあった日は要対応の一覧から消えるので、あとから欠勤のあった日を探すときは「欠勤あり（対応済み）」の欄か勤務時間（シフト）で見る
  - 帯の「あと N件」の言い回しが変わる
- 捨てた案：週の案B は月の欄に週の範囲という別の状態を持ち込み、画面も移る（月へ飛ばされる問題が残る）。案C は止める・二重に始めない・データの差し替えで止める・終わった知らせを二重に持つ。要対応の案B は振り直しが済んでいない欠勤（入らない訪問が残る・未確定）まで見えなくなる。案C は契約（`Absence`）に項目を足しデータの版の移行が要るうえ、確定し直したときに印と実際が食い違う。未作成の案B は開くだけでデータが変わり（控え・別のタブ・直前の状態に戻す）、展開の時期を人が決められない。案C は区別がつかないまま
