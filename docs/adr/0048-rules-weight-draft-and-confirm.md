# ADR-0048：条件の重みの表を下書きにし、「変更を確定」と確認のあとで保存する

- 日付：2026-10-21
- 状態：採用
- 関連：PRD D233・D161〜D165・D286、ADR-0023・ADR-0026・ADR-0035（一部を変更する）・ADR-0036

## 背景
条件の重みの画面（`#/rules`）の表は点数の基準のプリセットの重みを直す（ADR-0035）。スライダー・必須の切り替えは動かすとすぐ保存していた。
基準の重みは月のまとめて作る・自動作成・作り直し・点数のすべてに効き、変えると今日以降の案が「条件が変わった」になる。
利用者から「スライダを動かしたら即確定？ 今の設定と違ったら分かるように色を変え、確定ボタンで確定し、確定したらどうなるかを出してほしい」と声が出た。
決めること：表の重み・必須をいつ保存するか。今の設定との違いの見せ方。確定の前に何を見せるか。確定していない変更を持ったまま画面を離れるとき。

## 選択肢
1. 案A：表の重み・必須は画面の中の下書きにし、「変更を確定（N件）」で独自の確認（変わる重み・作り方・影響する日）を出してからまとめて保存する。違う行は色と文字の印。離れるときは確認
2. 案B：今のまま即時に保存し、保存したあとにトーストで影響を知らせて［元に戻す］を付ける
3. 案C：画面全体（名前・条件を足す・消す・プリセットの節・乱数の種も）を下書きにして1つの保存ボタンで書く

## 決定
案A を採る（親の作業指示。2026-10-21）。

- 下書きは画面の state（型ごとの重み・必須。`lib/weightDraft`）。データ（`DemoData`）の形は変えない。確定で `update(d => applyDraft(d, 下書き))`（型ごとに `setBasisWeight`。試す重みも基準にそろう）
- 違う行：左に注意の色の帯・淡い地・「変更あり 3→2.5」（色だけに頼らない）。同じ型の条件はどの行にも出る（基準は型ごとの重み）。保存済みと同じ値に戻すとその型の下書きは消える
- 確定の帯：下書きがある間だけ画面の下に貼り付く（`position: sticky; bottom: 下のタブの高さ + 8px`。本文の最後まで巻くと本文の後ろに収まり内容を隠さない）。主ボタン「変更を確定（N件）」と文字のボタン「取り消す」。その間「条件を足す」は枠にして主ボタンは1つ（AGENTS.md・ADR-0036）。右の欄（`usePanelFoot`）はこの画面に無い
- 確認（ADR-0026 の独自の確認）：見出し「重みの変更（N件）を確定しますか？」、本文に変わる条件と重み（前→後）・点数の基準のプリセット「〈名前〉」の重みになり、月のまとめて作る・開いた日の自動作成・作り直しと点数に使うこと・試す重みも基準に戻ること・影響する日。影響する日は確定したあとのデータで `rulesStale`（作った重みがどこにも無くなる日。compile しないので押した時に数えられる）を今日以降の案と訪問のある日について数え、確定した割当の有無で未確定・確定済みに分ける。作り直しの帯は「条件が変わった」のうち重みによるものに加え、問題が変わった日（`planStale`）も数えるので、確認の本文は「作った重みが無くなるので」と理由を付けて書く
- 取り消すは確認なしで下書きを捨てる（保存していないので失うものが無い）。確定・取り消しのあとフォーカスは画面の見出し（押したボタンが消えるため。作り直しの帯の［後で］と同じ）
- 離れるとき：HashRouter（データのルーターでない）なので `useBlocker` は使えない。下書きがある間、document の捕捉の段でアプリの中の別の画面へのリンク（`#/…`。メニュー・下のタブ・設定のタブ・帯のリンク）の押下を止めて確認（「重みの変更を捨てて、画面を移りますか？」「捨てて移る」／「編集を続ける」。〈スタッフ〉の編集の欄の変更を捨てる確認と同じ形）し、確定なら同じリンクをもう一度押す（リンクの onClick もそのまま動く）。コマンドパレットは移る前に `confirmLeave()`。再読込・タブを閉じるは beforeunload（〈スタッフ〉の編集の欄と同じ）。別のタブの変更の知らせは「変更がある」側の文（`useDirtyMark`）
- 整合：点数の基準を替える・基準のプリセットを消す（基準が移る）・初期値に戻すと下書きを捨てる。条件を消してその型の条件が無くなった型、プリセットの節で保存済みが下書きと同じ値になった型は下書きから外す。条件を足すと、その型に下書きがあれば新しい行も下書きの値で出る
- そのまま：条件の名前・条件を足す・消す・プリセットの節（基準のプリセットの重みも）・点数の基準のラジオ・乱数の種はすぐ保存。作り直しの帯は保存した値で数えるので下書きの間は出ない（入力の間引き `SETTLE_MS` はプリセットの節・ほかの画面で使うので残す）

## 理由とトレードオフ
- 得るもの：
  - 動かしただけでは何も変わらないので、試しに動かしても月の案や点数を誤って変えない。今の設定との違いが行ごとに見える
  - 確定の前に、どの日が作り直しの対象になるか・確定済みの日は作り直さないことが分かる
  - データの形も、作り直しの帯の数え方も変えない
- 失うもの：
  - 重みを変えるのに1手（確定）と確認が増える
  - 同じ画面の中でもプリセットの節は即時のまま（基準のプリセットの重みを2か所で直せ、片方だけ下書き）。プリセットの節は名前・一言・ほかのプリセットの編集も混ざり、下書きにすると範囲が広がるので今回は表だけ
  - ブラウザの戻る・進むでは確認を出せず、下書きは黙って捨てる（ADR-0023 の〈スタッフ〉の編集の欄と同じ限り）
  - 確認の影響する日は重みによるものだけで、問題が変わった日（訪問の所要の変更など）は含めない
- 案B は保存してから知らせるので、誤って動かすと作り直しの帯と要対応がすぐ出て、元に戻すまでの間に月の予定を開くと混乱する。案C は名前の変更などの小さな操作まで確定が要り、手間が増える
