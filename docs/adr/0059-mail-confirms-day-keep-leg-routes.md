# ADR-0059：日のメールを作ったら確定にし、区間ごとの道順を残す。週のメールは見通しで、ボタンは見出しに

- 日付：2026-10-23
- 状態：採用
- 関連：PRD D346（D93・D97 を書き直し）、ADR-0017（メール連携）・ADR-0018（道順のリンク）・ADR-0053（版2：提案→反映→確定）

## 背景
- 「確定（伝えた）」は〈スタッフ〉に伝えた内容を残す操作で、AI で組み直さない守りと「未連絡の変更」（伝え直す一覧）の元になる（ADR-0053）
- ところが「組む → メールで送る → 確定を押す」の3手で、送ったあとに確定を押し忘れやすい。ユーザーからは「組んで確定って流れは必要？」と問われた
- 日のメールの区間ごとの道順は、URL の長さの目安（Windows・不明な端末 2000字。D96）を超えると最初に外していた。初期データでは訪問3件の日でも外れ、Windows の PC で送ると区間の道順が入らなかった
- 週の「週の予定をメールで送る」は週の表（〈スタッフ〉×曜日）の上にだけあり、時間軸の表示では見つからなかった。週のメールは確定していない日ごとに「（まだ確定していません）」と書き、読みにくかった

## 選択肢
1. 案A：今のまま（確定は手で押す）
2. 案B：日のメールを全員分作ったら、その日を確定にする（週のメールは見通しで確定にしない）。手の「確定」は残す
3. 案C：週のメールを送ったら、その週を全部確定にする

## 決定
案B。
- 日の予定の「予定をメールで送る」の欄（`DayMailPanel` の `confirm`）：送れる人（アドレスがあり `tooLong` でない）の「メールを作る」を押すたびに数え（`MailRows` の `onOpen`・`sent`。画面の状態だけ）、全員分になったら1回だけ確定する（`PlanPage` の `confirmByMail`。確認は出さず、知らせに「元に戻す」と要対応の件数）。アプリは送信を知れないので、メールアプリを開いたことで数える
- 欄の下に「確定（伝えた）にする」（`day-mail-confirm`。見出しの確定と同じ確認つき）。アドレスの無い人に電話で伝えたときなど
- 週のメールは見通し。送っても確定にしない。日ごとの「（まだ確定していません）」「（未確定）」をやめ、確定していない日があれば冒頭に1回だけ書く
- 日のメールの段階（`dayMailText` の `short`）は区間ごとの道順を残す段を先に試す：［要点1＋全行程＋区間（短い行「道順：URL」）、要点1＋区間、要点2＋区間、要点2＋区間（リンクだけ・帰りなし）］→ 区間を外した今までの段。短い段は冒頭（「10/22（木） 4件（未確定）」）と省いた知らせ（「※住所などは省略」「※鍵は省略」）も短くする。初期データでは目安 2000字で訪問5件まで区間の道順が残る
- 週の「予定をメールで送る」（`week-mail`）は日と同じく見出しの主ボタンの隣（枠のボタン）。どの表示でも出す

## 理由とトレードオフ
- 得るもの：送ったことがそのまま確定になり、押し忘れが減る。伝える手順が「週で見通し → 前日に日のメールで確定」の2段になり、現場の運用に近い。Windows の PC でも区間ごとの道順が届く
- 失うもの：メールアプリを開いただけで送らなかったときも確定になる（知らせの「元に戻す」で戻す）。区間を残す段では住所・決まりごとがメールから外れる（「本文をコピー」には全部入る）
- 案C は週の途中の欠勤・キャンセルで、ほとんどの日が「未連絡の変更」になり、伝え直しの一覧が増えるので取らない
