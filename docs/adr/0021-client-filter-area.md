# ADR-0021：〈利用者さん〉の絞り込みを共通の欄にし、地区は住所から取り出す

- 日付：2026-10-18
- 状態：採用（利用者が推奨どおりに決定（2026-10-18）。PRD D108〜D112）

## 背景
〈利用者さん〉を探す場所は、検索欄 `ClientPicker`（PRD D61・D62）で「人を選ぶ」形にそろえていた。

- 週間の時間軸（8人まで）と〈利用者さん〉×曜日の表（上限なし）が同じ選択（`?client=`）を共有している。表は選ばないと空で、全員を見るには近道から「あと N人を選ぶ」を押す。表で選んだ人数が時間軸では切られる
- 〈利用者さん〉の画面の一覧は、検索欄と段階の6つのボタン（PRD D73）で絞る。ふだん見たいのは「終了でない人」と、地区（区・町名）や手当てが要る人（担当が決まっていない・いつもの担当がいない・パターンが無いなど）
- 地区を持つ項目はデータに無い（住所の文字だけ）。データの版は変えたくない

## 選択肢
1. 案A：表と一覧は「選ぶ」をやめて「絞り込む」にする。共通の部品 `ClientFilter`（検索・地区・絞り込みのチップ・「終了の人も出す」）と純粋関数 `lib/clientFilter`。地区は住所から毎回取り出す（`lib/area` の `areaOf`）。時間軸は今の `ClientPicker` のまま
2. 案B：`ClientPicker` に地区・チップを足し、表でも選ぶ形のまま（近道の「まとめて選ぶ」を増やす）
3. 案C：〈利用者さん〉に地区の項目（市区・町名）を足し、画面で手直しできるようにする（データの版を上げる）

## 決定
案A。

- 週間の表は時間軸と選択を分け、最初からこの週に訪問がある人を全員出す（チップ「この期間に訪問がある人」を既定で押しておく。この週に訪問がある人は終了でも出す＝今までの表と同じ行で、その訪問をドラッグできる）。状態は URL の `?cf=`（既定のままなら書かない。履歴を増やさない `replace`）。検索の文字は部品の中にも持ち、日本語の変換中は URL に書かず確定後に、ふつうの入力は 300ms 待って書く（URL から入力欄へ戻すと変換が壊れるため）。表から時間軸へ移ったとき、時間軸の選択が空なら、表で絞り込んだ人のうち時間軸の候補（利用中の人と、休止中でもこの週に訪問がある人）にいる人の先頭8人を `?client=` に引き継ぐ
- 絞り込みはすべて AND。チップの人数は「押したら何人になるか」で、0人のものは薄くして押せない（`aria-disabled`）。「〈スタッフ〉が担当する人」だけは0人でも押せ、〈スタッフ〉を選び直せる（最初の〈スタッフ〉と選ぶ欄の人数は今の絞り込みで数える）
- チップの判定に使う集まり（期間に訪問がある人・担当が決まっていない訪問がある人・休み・パターン・〈スタッフ〉が担当する人・働ける〈スタッフ〉）は `filterFacts` で、週間の `weekDay`（今の案、無ければ確定した割当）の帯から作る。〈利用者さん〉の画面も、選んでいる日を含む週の `weekDay` から同じ関数で作る
- 地区は 政令市＋区／市・町・村（郡＋町村）と、その続きの町名。名前に「市」「郡」を含む市と東京23区は表で先に照らす。取り出せない人は「住所なし」。手直しの欄・データの項目は作らない
- 〈利用者さん〉の画面の段階の6つのボタンは「終了の人も出す」のチェック1つに（この画面では終了の人はチェックしたときだけ）。週間の時間軸の近道「仮押さえの人」はやめる（月間の検索欄は残す）

## 理由とトレードオフ
- 得るもの：表で全員がすぐ見え、時間軸の8人の上限に表が引きずられない。2つの画面で同じ絞り方・同じ言葉になる。地区はデータの版を上げずに使え、Excel・JSON の形も変わらない。判定は純粋関数なのでテストで固められる
- 失うもの：表で「好きな数人だけ」を並べることはできない（名前の検索で絞る）。住所の書き方が崩れていると地区がずれる（「住所なし」や別の町名になる）が、手で直す場所は無い。〈利用者さん〉の画面は1週間分の `weekDay`（compile 7回）を作るので、データを変えるたびに少し計算が増える

## 影響
- 設計書 §4 pages（週間・〈利用者さん〉の画面）と lib（`lib/area.ts`・`lib/clientFilter.ts`・`components/ClientFilter.tsx`）。契約（`src/contracts/`）・store・excel は変えない
- `ClientPicker` は週間の時間軸と月間だけで使う。近道「仮押さえの人」は `tentativeShortcut` を渡したときだけ（月間）
- 見直す条件：住所の表記ゆれで地区が割れる（「ケ」「ヶ」・旧町名など）という声が出たら、正規化の表か地区の手直しの欄（案C）を検討する。〈利用者さん〉の人数が数百人になり compile 7回が重くなったら、画面を開いている間だけ計算する・チップを押したときだけ計算するなどに変える

## 追記：訪問の種類での絞り込み（PRD D263）
- 「リハビリの人」のように、訪問の種類（`data.visitTypes`）で〈利用者さん〉を絞りたいという声に、`ClientFilter` へ「訪問の種類（どれか）」の欄を足した。種類ごとのチップを押すと、期間（週の表・相性はこの週、一覧は選んでいる日を含む週）にその種類の（取り消しでない）訪問がある人に絞る。複数押したら地区と同じく**どれか（OR）**、ほかの絞り込みとは AND。人数は「その種類の人が何人か」（種類を除いたほかの絞り込みをかけた数）で、0人は押せない
- 状態は `ClientFilterState.types?`（省略可。種類の id）。`?cf=` には押しているときだけ `type:t1,t2` と書く（古い URL・種類なしの URL はそのまま読める。消えた種類の id は無いものとして絞らない）。判定の集まりは `filterFacts` に `visitTypes` を渡して作る（`typeClientIds`・`typeIds`）。契約・store・excel は変えない
- 訪問の種類は機能の入り切り（ADR-0028）に無いので、種類が0件のときだけ欄を出さない。訪問に種類が無い（`typeId` が null）人は、どの種類のチップにも入らない（「種類なし」のチップは足さない）
- 週の時間軸の〈利用者さん〉の選び方（`ClientPicker`）には足さない。表で種類で絞ったまま時間軸へ移れば、既存の引き継ぎ（D139）で絞った人の先頭8人が入る。月の予定・日の予定に〈利用者さん〉の絞り込みの欄は無く（月は `ClientPicker` の検索欄だけ）、対象外
