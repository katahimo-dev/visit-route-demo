# ADR-0025：UI/UX 改善：やりたいことから入る導線（ホーム「今日やること」ほか）

- 状態：採用（2026-10-18。区切りはすべて済み。最後の「行き止まりから次の画面へ」は 2026-10-19）。一部を ADR-0034 で置き換え
- 関連：PRD D141〜D145（ホーム）・D151〜D155（進み具合の帯）・D156〜D160（案を変える）・D161〜D166（作り直しの帯）・D167〜D172（欠勤・キャンセル）・D173〜D177（言葉と案内）・D184〜D188（空き状況・週）・D189〜D193（スマホ・ツアー）・D194〜D197（右の欄の帯）・D201〜D204（行き先）。メニューとコマンドパレットは ADR-0027、独自の確認は ADR-0026

## 背景
利用者の依頼「直感的にやりたいことが操作できるように」に沿って画面を監査（2026-10-18）したところ、やりたいことに届くまでの迷いが見つかった。
- 起動すると案内なしで日の画面になり、今月の準備の進み具合や次の一手は月の画面を開かないと分からない
- メニューが「データの種類」で並び、やりたいこと（月を組む・欠勤に対応する・問い合わせに答える）と合わない。同じ操作の入口が複数あり（案を作る3か所・確定2か所）、逆に急な欠勤は見つけにくい
- 「案を変える ▾」は仕組みの言葉の10項目、設定を変えても案へ戻る導線が無い、用語の説明がその場に無い、空き状況・週・スマホの月・ファイル選択（英語）・右の欄の確定ボタン（内容から離れる）・要対応の行き先（行き止まり）などの問題

制約：新しい保存データを増やさない（データの版・Excel・JSON を変えない）。データを書き換えるのは store だけ。既存の URL・e2e を壊さない。スマホは表示の確認が主（PRD §7）。判定は純粋関数に置き、月の画面と同じ数え方にそろえる。

## 決定
既存の画面・操作へ移るだけの導線を足し、判断は区切りごとに 1区切り＝1PR で進めた。共通の考え方は「数え方・文の決まりを `lib/` の純粋関数1か所に置く」「新しい保存データ・契約を足さない」。

1. ホーム「今日やること」（D141〜D145）：起動（`#/`）と知らない URL の行き先をホームにし、メニューの先頭とスマホの下のタブ（5つ）に置く。カードは `lib/home.ts`（見る月 `homeMonths`＝今月、残り7日以下なら来月も。見る日・カード `homeTasks`：要対応 → 今日の予定 → 確定していない日 → 案を作る。のち ADR-0044 で作業の順（要対応 → 作る → 確認 → 今日）に改めた）。日の状態の計算は `lib/useDayStatuses.ts` に切り出し、月の画面と共有する（数が食い違わない）。月の画面の操作は `?do=batch|attention|unconfirmed` で開き、1回行ったら URL から消す。確定していない日は月の画面と同じ数え方（案の無い日も含む）。`?do=batch` はまだ案の無い日が0日なら欄を開かない。ホームは `useCompileInput` だけ使い今日の問題を二重に compile しない
2. 予定に共通の進み具合の帯（D151〜D155）：月・週・日の見出しの下に同じ形の細い帯（見ている月の今日以降の訪問・案・確定・要対応＋次の一手のボタン1つ）を置く。月の「今月の準備」①〜③と見出しの主ボタンを帯にまとめ、「訪問だけ作る」は欄の中へ。`lib/progressBand.ts`（`bandNext`・`bandMonth`・`bandHref`）、`components/progressBand.tsx`。次の一手は月の画面だけ主ボタン（日の主ボタンは「この割当で確定」で、帯は状態を見せるだけ）。済んだ「案 ✓」から開いても既定は「まだ案の無い日だけ」（作り直しは選んだときだけ）。読み上げは aria-label・空で置く aria-live。Ctrl・⌘・Shift・中ボタンは横取りしない。月の見出しの要約は帯に無い項目（入らない・当日キャンセル）だけにして同じ数字を2か所に並べない
3. 「案を変える ▾」を目的の言葉で（D156〜D160）：項目は減らさず、名前と1行の説明・見出し付きのまとまりに並べ直す（`lib/planMenu.ts`、`MenuButton` に `description`・`group`）。押せない項目は理由を見える文で出す。「固定した訪問は残して、ほかを作り直す」と名前を動きに合わせ、固定にならない手直しがあれば確認する（`hasUnpinnedEdits`）。比較の画面は案が1つでも「もう1案作って比べる」（既存の計算で記録に足すだけ。今の案・条件は変えない。選択肢 `anotherPlanOptions`）。サイドのメニューに比較は足さない（のち ADR-0027 で入れた）
4. 条件を変えたら影響と「作り直す」を出す（D161〜D166）：設定の画面の上に帯（`lib/rebuildBand.ts`・`components/rebuildBand.tsx`）。判定は `lib/month` の `rulesStale`：記録の作った条件（重み・必須）の鍵が「いまの条件に各プリセットを当てたもの」（記録の `presetId` が null の案はいまの条件そのもの）のどれにも無いときだけ「条件が変わった」。作り直しはいつも点数の基準のプリセットで作るので、作り直した案は必ず当てはまり消える（点数の基準を切り替えただけでは変わらない）。［作り直す］は月の画面の欄（`?do=stale`）を開くだけで、その場では作らない。いまの条件がどのプリセットとも違えば帯の2行目に案内と［今日の案をいまの条件で作り直す］・［プリセットとして保存］（D166）。記録の `presetId` は最後に作った（使い回した）時点で一致した最初のプリセットで、使い回しでも書き直す。日の画面の［作り直す］は `runPreset` をやめ基準の重みで解く。`?do=recreate` の間はどの日の自動作成も始めない。帯は貼り付き、数え直しは日ごとの覚えをモジュールに置く
5. 急な欠勤・当日キャンセルの入口（D167〜D172）：日の画面の操作の行の先頭に「欠勤・キャンセル」を置き、段階のある右の欄（`pages/SuddenPanel.tsx`、決まりは `lib/sudden.ts`）を開く。1 何が起きたか → 2 人と時間帯／キャンセルの訪問 → 3 影響と振り直し → 4 選んで確定。振り直し・案B・確定・元に戻すは既存の関数を呼び、4段目に差の欄と同じ `AnnealBox`。列の見出しの「急な欠勤」・ホームのカードも同じ欄を開く。入力欄は `AbsenceFields`（前の `AbsencePanel` を廃止）、見込みは `previewOf`。案Bがおすすめ（案Aで入らない見込み）のときは「登録して案B も作る（おすすめ）」を主ボタンにする（のち ADR-0044 で、主ボタンは「登録して振り直す（おすすめ）」の1つ・ほかは文字のボタンに改めた）。案の無い日・自動作成中の扱い（`noPlanText`）あり。下のタブには入れない（5つで 390px がいっぱい）。一覧の「取り消す」は前もって決まった取り消し用に既定ふつうのまま。確定していない日にも「この割当で確定」を出す
6. 言葉と案内（D173〜D177）：日の点数の理由は減点の内訳から1つ選ぶ純粋関数（`lib/scoreReason`。担当の条件は条件ごとの点の下限からの超過で比べ、必須の違反・入らない訪問は先に出す）。用語は辞書（`lib/glossary`）と部品 `Term`（ホバー・フォーカス・タッチで出る tooltip。同時に1つ。入力欄の名前は label の中に置かず `aria-labelledby`）。空の画面は「なぜ空か＋行き先」（`lib/emptyGuide`・`EmptyNext`）。月の凡例は畳み、マスの読み方はマスに `data-guide` の文だけを置き表に1つの見張りの吹き出し（`MonthCellTip`、文は `lib/monthGuide` の `createTipStore`）で出す（マスごとの部品は月まとめ作成の描き直しを重くするため。マスの `title` はやめる）。減点の表示名「空き時間（待ち）」。新しい採点は足さない
7. 空き状況の段階化と週の切り替え（D184〜D188）：空き状況は1画面のまま 1 いつ・何を（希望の曜日・時間帯・週の回数もここ）→ 2 場所（任意・畳む。中身は閉じても残す）→ 3 受けられる曜日・時間帯 → 4 次の一手（主ボタンは「要約をコピー」だけ）。案内文は開いているときだけ計算し、畳んだら捨て、計算し直し中は押せない。マスは○だけ人数、△は週の数（a/b）、×・？は数字なし（`lib/vacancyView`）。週は4つの表示の1つの切り替えで、URL は従来の `?view=`・`?by=` を読み書き（`lib/weekView`）
8. スマホ・ファイル選択・ツアー（D189〜D193）：390px の月は、はじめ日ごとの一覧（`?layout=`。押したら必ず書く。今日の行へ巻く。`lib/monthList`）。地図ボタンは下のタブの上端から12px・本文の下を空ける。ファイル選択は日本語の1部品 `FilePick`（控え・Excel 共通）。初回の案内ツアーは中央のカード（`lib/tour`・`components/Tour.tsx`。枚数と最後の枚は ADR-0031）で、「見た」は DemoData と別の localStorage キー `vrdemo:tour:seen`（`store/tour.ts`。初期状態に戻しても消さない。書けなければ開いている間だけ覚える）。`?id=`・`?do=` のリンクでは自動で出ない。最後の枚で見たことにする。e2e は `skipTour` で先に印を入れる（アプリに自動操作用の分かれ道を置かない）
9. 右の欄の確定ボタンの帯（D194〜D197）：帯を巻く領域の中で内容のすぐ後ろに置き `position: sticky; bottom: 0`（短ければ内容の直後、長ければ欄の下）。区切りは貼り付いている間だけ（番兵の IntersectionObserver、`usePanelFoot` の `data-stuck`）。帯の高さを `--drawer-foot-h` にして `scroll-padding-bottom`（Tab で入った入力欄が隠れない）。600px 以下はボタン2つまでは同じ幅で横、3つ以上は主ボタンを全幅（DOM の先頭が主ボタン。`order` で入れ替えない）。safe-area を避け、キーボード（visualViewport）は `panelFit` で欄を見えている所に合わせる。トーストは欄の外が360px以上あれば欄の外の真ん中、無ければ見出しの下（`--drawer-head-h`）に出し、押せない状態にしない。印刷は帯を出さない。部品1か所で全16か所の欄に効かせる
10. 行き止まりから次の画面へ（D201〜D204）：行き先は `lib/links.ts`（`attentionTarget`・`suddenHref`・`unassignedHref`・`workloadHref`）。日の画面の `?date=…&do=unassigned`（その日を選び「入らなかった訪問」の列へ巻く。自動作成の待ち方は、作り始めたときだけ待ち、走らない・作れないときは忘れる）と `?do=absence&staff=…`（その人の2段目。知らない人・その日に働かない人は1段目）を足し、読んだら `?date=`・`?do=`・`staff=` を消す（ツアーも出ない）。月の要対応：入らない訪問 → 「入らなかった訪問」、休みの人に訪問 → その日の「欠勤・キャンセル」1段目、拘束超過 → 稼働の見込みをその月・先頭の人（項目に `staffIds`）、そのほか → 日の画面。行全体を1つのボタンのまま（入れ子にしない）、「（〜で開く）」を添える。稼働の見込みの日付と〈スタッフ〉×日のマスをボタンに（title・見た目は従来）、稼働時間の右の欄に「この日の欠勤を登録する」リンク（その日に働く日だけ。`setDate` しないので Ctrl+クリックで元のタブの日付が変わらない）、空き状況の右の欄に日付ごとの「その日の案を見る」リンク（Ctrl+クリックで新しいタブ）。名前の吹き出しは付けない（D124）

## 検討した案
| 区切り | 採った案 | 捨てた案とその理由 |
|---|---|---|
| 1 ホーム | 起動時のホームにカード（既存の画面・操作へ移るだけ） | 日の画面の上の帯：日の画面が長くなり、月の準備が日の画面の話でなくなる／メニューの並べ替えだけ：今の状態が分からない（のち ADR-0027）／最初のツアーだけ：毎日の次の一手にならない（のち初回ツアーで補った） |
| 2 進み具合 | 月・週・日に共通の帯＋「今月の準備」を帯にまとめる | 帯＋今月の準備を残す：同じ数字が2か所で入口も2か所のまま／月のバッジだけ：週・日で次の一手が押せない |
| 3 案を変える | 項目は同じで目的の言葉・説明・見出しに並べ直す。比較は「もう1案作って比べる」 | 目的ごとのボタンを操作の行に並べる：主ボタンと並んで目立ちすぎ、390px で折れる／メニューに比較を足す：区切り7で並べ替えるので二重／日の画面へ移って作らせる：その場で作れない |
| 4 作り直しの帯 | 判定に「作った条件が変わった」を足し、帯の［作り直す］は月の欄を開くだけ | 判定は従来のまま：重みの変更で出ず問題が残る／いまの条件と記録の条件の差で判定：プリセットで作った案が最初から全部「変わった」になり、作り直しても消えない／帯でその場で作り直す：進み具合・止める・確認を二重に持つ |
| 5 欠勤 | 段階のある右の欄（Esc・フォーカス・確認ダイアログとの重なりが揃っている） | 中央のダイアログ：表・スライダーで縦に長く確認と重なる／専用画面と6つ目のタブ：日の画面の案・差の欄と離れる／入口だけ目立たせる：流れの分かれが残る |
| 6 言葉 | 辞書＋tooltip 部品・用語の理由を純粋関数で・マスは見張り1つ | 既存の `Hint`（押して開く）に寄せる：その場で読めず画面が散らかる／用語集の画面：行き来が要る／マスごとに `title`：キーボード・タッチで読めない |
| 7 空き状況・週 | 段階に並べ替え（1画面）＋週は4表示の1切り替え（URL 互換） | ウィザード：条件を変えて見比べるたび段を戻る、電話中に向かない／2×2の切り替えと新しいクエリ：古いリンクの読み替えが要り、スマホの段が減らない |
| 8 スマホ等 | 月は日ごとの一覧・ツアーは中央のカード・見たことは別キー | 月のマスを縮める：マスの印が読めない／週ごとに横巻き：土曜が隠れる／要素を指す吹き出しのツアー：幅ごとに指す先が変わり手間に対し得が小さい／見たことを DemoData に入れる：書き出し・初期化で人の状態とデータが混ざる |
| 9 右の欄の帯 | sticky の帯＋番兵の区切り | 欄の高さを中身に合わせる：欄の下に幕が見え引き出しの形が崩れる／確定ボタンを各欄の内容の最後に置く：14か所を直し長い欄で巻かないと届かない／区切りを CSS のスクロール連動や `background-attachment: local` で：ブラウザで揃わない・帯の上に影を出せない |
| 10 行き先 | `?do=unassigned` など既存の形で行き先を決める | `?focus=` など別名の値：ツアー判定・消し方を再利用できない／行の中に別リンクを足す：ボタンの入れ子で何が起きるか分かれる／休みの人から2段目で開く：要対応の行は人を持たない／拘束超過から日の画面：拘束の数字が日の画面に無い／空き状況をいつも新しいタブ：ほかの画面と不揃い |

## 結果・トレードオフ・見直す条件
- 得るもの：開いた人が1画面で次の一手に着き、同じ数字が同じ数え方でホーム・月・週・日・設定の画面に出る。入口が目的別にそろい、新しい保存データ・契約・データの版の変更は無い。部品1か所で効かせたので全部の欄・画面で同じ動き
- 失うもの：
  - 月・週・日・ホーム・設定の画面で今日以降の案のある日を compile・採点する（8人・約17件／日で、ホームは500ms以内、案が全部ある月の帯は約100ms。日ごとの覚えと `useDeferredValue` で数え直しを抑える）
  - 月の「今月の準備」①〜③の手順の見せ方と凡例つき積み上げ、月のマスの `title`、一覧の混み具合の棒、ツアーが要素を指さないこと（場所は文で読むので、メニュー名を変えたら `lib/tour.ts` も直す）
  - 案B の欄が4段目と差の欄の2か所に出る。当日キャンセルの入口が2つ（欄は当日キャンセル既定、一覧の行はふつう既定）。プリセットの重みを変えると要対応に「条件が変わった」が出やすくなる。いまの条件の重みだけ変えても、プリセットで作った案は出ない
  - 「見た」はブラウザごと。スマホの狭い画面の帯・タブぶん本文が狭くなる
- 見直す条件（主なもの）：カードが多すぎるならホームを月ごと1枚に、起動・帯が重い事業所（数十人・日に数十件）では今日から2週間だけ数える。要対応が手当て後も残るという声は次の一手から外す。一覧が長いなら「案を変える」のプリセットを1項目にまとめる。4段目と差の欄の2か所の案Bがまぎらわしければ作るのを差の欄だけにする。用語の下線が多ければ最初の1か所だけに。場所を最初に入れる問い合わせが多ければ空き状況の場所をはじめから開く。端末をまたいで「見た」を持ちたい声があってもサーバーには保存しない（PRD §4）
- 確かめ方：`src/lib/` の各テストと `scripts/e2e-home.cjs`・`e2e-progress.cjs`・`e2e-plan-menu.cjs`・`e2e-rebuild.cjs`・`e2e-absence.cjs`・`e2e-words.cjs`・`e2e-vacancy-steps.cjs`・`e2e-week.cjs`・`e2e-tour.cjs`・`e2e-mobile.cjs`・`e2e-panel-foot.cjs`・`e2e-links.cjs`。画面・関数の細部は design.md
