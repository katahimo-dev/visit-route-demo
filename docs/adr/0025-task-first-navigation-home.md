# ADR-0025：UI/UX 改善：やりたいことから入る導線（ホーム「今日やること」はその第1弾）

- 日付：2026-10-18
- 状態：採用（利用者の依頼（2026-10-18）「直感的にやりたいことが操作できるように」。第1弾のホームは PRD D141〜D145。第2弾以降は予定）

## 背景
画面の監査（2026-10-18）で、やりたいことに届くまでの迷いが分かった。

- 起動すると案内なしでいきなり日の画面（`#/plan`）になる。今月の準備がどこまで進んでいるか、次に何をすればよいかは、月の画面の「今月の準備」（PRD D59）を開かないと分からない
- メニューは「データの種類」（〈利用者さん〉／〈スタッフ〉／割当の設定）で並ぶ。やりたいこと（月を組む・欠勤に対応する・問い合わせに答える）とは合っていない
- 同じ操作が複数か所にある（案を作る＝月の見出しのボタン・今月の準備の②・日の「案を変える▾」。確定＝日と月の③）。逆に「急な欠勤」は列の見出しの小さいボタンで見つけにくい
- 制約：新しい保存データを増やさない（データの版・Excel・JSON の書き出しを変えない）。データを書き換えるのは store だけ。既存の画面の URL・e2e を壊さない。スマホは表示の確認が主（PRD §7）

## 選択肢
1. 案A：起動したときの画面に「ホーム（今日やること）」を足し、今の状態から次の一手をカードで出す。カードは既存の画面・既存の操作（月のまとめて作るの欄・右の欄、日の画面）へ移るだけ。判定は純粋関数で、月の画面と同じ数え方
2. 案B：日の画面の上に「今日やること」の帯を足す（起動は今のまま日の画面）
3. 案C：メニューを先にやりたいこと順に並べ替える（ホームは作らない）
4. 案D：最初にツアー（案内の吹き出し）を出す

## 決定
案A。決まりは `lib/home.ts`（純粋関数）の1か所：見る月 `homeMonths`（今月。残り7日以下なら来月も）・見る日 `homeDays`・カード `homeTasks`（要対応 → 今日の予定 → 確定していない日 → 案を作る）。日の状態は月の画面の計算を `lib/useDayStatuses.ts` に切り出して共通に使う（要対応・確定の件数が月の画面と食い違わない）。月の画面の操作は `?do=batch|attention|unconfirmed` で開き、1回行ったら URL から消す。起動（`#/`）と知らない URL の行き先をホームに。メニューの先頭とスマホの下のタブ（5つ）に「ホーム」。

## 理由とトレードオフ
- 得るもの：開いた人が1画面で「次に何をするか」が分かり、1クリックでその操作の画面に着く。新しい保存データが無いので、データの版・書き出し・移行は変わらない。月の画面と同じ数え方なので数字が食い違わない。カードの行き先は既存の操作なので、機能を二重に作らない
- 失うもの：起動のたびに今月（月末は来月も）の日を compile・採点する（月の画面と同じ重さ。8人・約17件／日の一月で 500ms 以内）。起動しても日の画面を開かないので、今日の案の自動作成（PRD D52）は今日のカードを押したときになる。スマホの下のタブが5つになり、1つの幅が狭くなる（390px で78px）
- 案B は日の画面がさらに長くなり、月の準備（来月の訪問を作る）が日の画面の話でなくなる。案C は並べ替えだけでは「今の状態」が分からない（第7弾で別にやる）。案D は一度見たら終わりで、毎日の「次の一手」にならない（第8弾の初回ツアーで補う）

## 影響
- 画面：`pages/HomePage`（`home.css`）、`app/App.tsx`（ルート `/home`・`*` の行き先・メニューの先頭）、`lib/nav.ts`（`BOTTOM_TABS` に `/home`）、`styles.css`（下のタブを5列）、`pages/MonthPage`（`?do=` と、日の状態の計算を `lib/useDayStatuses` へ移す。見た目は変えない）。データ・契約（`src/contracts/`）・store は変えない
- 確かめ：`src/lib/home.test.ts`（何も無い・全部済み・一部済み・月末）、`scripts/e2e-home.cjs`、`scripts/e2e-mobile.cjs`（下のタブ5つ）
- 見直す条件：カードが多すぎる（月ごとに3枚×2か月）という声があれば、月ごとのカードを1枚にまとめる。起動の重さが気になる事業所（数十人・日に数十件）では、ホームは今月の今日から2週間だけ見るかを決める

## これからの区切り（予定。1区切り＝1PR。着手のときにこの ADR に追記する）
2. 予定（月・週・日）に共通の進み具合の帯（作成済 x/y・確定 x/y・要対応）を置き、「まとめて作る」の重複をなくす
3. 日の「案を変える▾」の中身を目的の言葉に（もう一度作らせる／少し良くする／2つの案を比べる／元に戻す）。比較は案が1つでも「もう1案作って比べる」
4. 条件（重み・相性・稼働時間など）を変えたら「影響する日 N日 →［作り直す］［後で］」の帯をどの画面でも出す
5. 急な欠勤を目立つ入口に（日の画面のボタン、人を選ぶ → 振り直し案 → 確定 の段階）
6. 言葉と案内：点数の理由を一言、用語の言い換え・説明、空の画面に「なぜ空か＋次の一手」、凡例を畳む
7. メニューを用途ごとに並べ替え・名前を区別し、コマンドパレット（Ctrl+K）
8. 個別：空き状況の段階化、週の切替を1つに、スマホ（月の一覧表示・地図ボタンの重なり）、データのファイル選択を日本語に、初回ツアー
