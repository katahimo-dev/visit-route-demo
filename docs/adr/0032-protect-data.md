# ADR-0032：データを守る仕組み（1世代の控え・書き出しの知らせ・古い案の片づけ・壊れたデータと別のタブの知らせ）

- 状態：採用（2026-10-19）
- 関連：PRD D2・D3・D227〜D229、ADR-0001（ブラウザ完結・localStorage）・ADR-0006・ADR-0020（Excel の読み込み）・ADR-0026（独自の確認）

## 背景
データは利用者のブラウザの localStorage（`vrdemo:data:v1` の1つの JSON）にしか無い（ADR-0001）。調査（2026-10-19）で次が分かった。
- データの画面の「初期状態に戻す」「Excel 全体の読み込み」「控えの読み込み」「名簿の総入れ替え」は確認を出すだけで、置き換える前のデータはどこにも残らない。確定を押し間違えると戻せない
- 容量超過の文は「古い日の予定を消してください」だが、それをする画面が無い（`design.md` §8 の未決事項「古い月の案・記録の片づけ」）
- 保存していたデータが読めないと `vrdemo:data:broken` に退避して初期データで開くが、何も知らせない（利用者は消えたと思う）
- 別のタブで変わると黙って読み直す。編集の欄に入力中だと、保存したときに別のタブの変更を上書きする
- 書き出し（控え）を促すものが無く、いつ書き出したかも分からない

制約：サーバー・ログインは作らない（PRD §4）。外部送信を増やさない。DemoData の契約（`src/contracts/`）に項目を足さない。データの書き換えは store の `update(fn)` だけ。localStorage の容量（多くのブラウザで 5MB 前後）を倍にしない。

## 決定
置き換える前に**1世代だけ**別のキーに控え、データの画面から戻せるようにする。書き出した日をブラウザごとに覚えて2週間で知らせ、容量超過には「古い案と記録を片づける」を用意する。読めなかったデータと別のタブの変更は知らせる。

- 1世代の控え：store の `keepPrevious(reason)` が `vrdemo:data:prev`（置き換える前の DemoData の JSON）と `vrdemo:data:prev:info`（`{ at, reason }`）に書く。次に残すと上書き（1世代）。対象は データの画面の初期状態に戻す・控えの読み込み・Excel 全体の読み込み・名簿の読み込み（追加・更新も総入れ替えも）。確認の本文には見込み（`canKeepPrevious()`。書いてはみない軽い判定）で「控えとして1つだけ残し…戻せます」と書き、確認で OK になってから残す（確認中に閉じても控えは変わらない）。名簿が入らなかったら `cancel()` で前の世代に戻す。「直前の状態に戻す」（確認つき）は、いまのデータを控えと入れ替える（もう一度押せば戻る）。いまのデータを控えに残せなければ戻さない（「いまのデータを控えに残せないため戻せません：容量不足」。戻すといまのデータを失うため）
- 容量：控えが書けなければ前の世代を消して1回だけ試し直し、それでもだめなら残さず、完了の知らせに「控えを残せません：容量不足」を添える（操作は止めない。見込みで分かれば確認の本文にも出す）。本体の保存が容量超過なら控えを先に捨てて書き直し（いまのデータが控えより大事）、捨てたらトースト「容量が足りないため、直前の状態の控えを消しました」
- 最後に書き出した日：`vrdemo:backup:last`（`{ date, kind }`。控えの JSON と Excel 全体の書き出しで更新。名簿だけは数えない）。データの画面に「最後に書き出した日：10/12（7日前）」。起動したとき、確定した日が1日以上あり14日以上書き出していなければ（まだなら常に）トースト「控え（バックアップ）を2週間以上書き出していません」。知らせた日は `vrdemo:backup:reminded` に覚え1日1回まで
- 古い案と記録を片づける：データの画面の欄で月を選び（既定は3か月前。今月〜12か月前）、その月より前の日の `aiRuns`・`aiPlans` を `update(fn)` で消す。件数と空く見込み（JSON の文字数）を出して確認する。確定した割当（`manualPlans`）・訪問・人・条件は消さない（実績に近く、容量も小さい）。確定した日（`manualPlans` のある日）は `aiPlans` も残し `aiRuns` だけ消す（今の案を消すと、その日を日の画面で開いたときに自動で作り直して「未確定の変更あり」になり、空けた容量も戻るため）。容量超過の文（`QUOTA_MESSAGE`）はこの欄を指し、保存できなかった文の下に欄へ移るボタンを置く
- 壊れたデータ：`loadWithStatus()` が `broken` を返し、本文の先頭に閉じられる知らせ（注意の色）と「読めなかったデータを書き出す」（`vrdemo:data:broken` の元の文字をそのままファイルに）。閉じたことは保存しない。退避が容量超過なら控えを捨ててもう1回試し、それでも退避できなければ知らせの文を「元のデータを退避できませんでした。今すぐ書き出してください」にし、書き出しは開いたときに覚えた元の文字を使う
- 別のタブ：読み直したら「別のタブで変わったので読み直しました」、〈スタッフ〉・〈利用者さん〉の編集の欄に変更があれば「別のタブで変わりました。保存すると上書きします」（入力は残す。統合はしない）
- 控え・書き出した日・知らせた日はブラウザごとの記録で、ツアーの `vrdemo:tour:seen` と同じく DemoData の外（版・書き出し・読み込み・初期状態に戻すの対象外）。localStorage を触るのは store の中だけ

## 検討した案
| 案 | 長所 | 短所 | 採否 |
|---|---|---|---|
| 控えA：置き換える前に1世代だけ別のキー | 誤操作から1手で戻れる。容量は最大で倍まで | 2つ前には戻れない。大きいデータでは控えが残せない | 採用 |
| 控えB：複数世代（例 3世代） | 何回か前にも戻れる | 容量が3倍。5MB の上限で本体の保存を圧迫する | 不採用 |
| 控えC：控えを持たず、確認の文を強くするだけ | 容量を使わない | 押し間違いは戻せないまま | 不採用 |
| 控えD：IndexedDB に控える | 容量が大きい | 非同期の API で store が二重になり、デモには重い | 不採用 |
| 知らせA：最後に書き出した日を覚え、2週間で1日1回トースト | 押し付けず、書き出しを思い出せる | 別の端末の書き出しは分からない | 採用 |
| 知らせB：毎回の起動で確認ダイアログ | 確実に目に入る | 毎回止められて煩わしい | 不採用 |
| 知らせC：書き出した日を DemoData に持つ | 控えで他の端末へ渡る | 控えを読み込むと日付が戻り、契約に項目が増える | 不採用 |
| 片づけA：月を選び AI案と記録だけ消す | 手で範囲を選べ、確定した割当は残る | 消したものは戻せない（控えも残さない） | 採用 |
| 片づけB：容量超過のとき古いものから自動で消す | 手間が無い | 黙って消え、何が消えたか分からない | 不採用 |
| 片づけC：確定した割当も含めて日付で消す | よく空く | 実績に近い確定が消える。容量に効くのは主に記録 | 不採用 |
| 別のタブA：読み直して知らせる（編集中は上書きの注意） | 今の動きを変えず、黙って変わらない | 入力中の欄と別のタブの変更は統合しない | 採用 |
| 別のタブB：編集中は読み直さない | 入力は守れる | 画面と保存のデータが食い違う | 不採用 |

## 結果・トレードオフ・見直す条件
- 得るもの：初期化・読み込みを押し間違えても1手で戻れる。容量超過の文が画面の操作を指す。データが読めなかった・別のタブで変わったことが分かる。いつ控えを書き出したかが分かり、促される
- 失うもの：
  - 控えの分だけ localStorage を使う（最大で本体と同じ大きさ。容量が足りなければ控えを諦める）
  - 戻せるのは1つ前だけ。片づけで消した案と記録は戻せない
  - 書き出した日はブラウザごと。別の端末・別のブラウザで書き出しても知らせは出る
  - 別のタブの変更と入力中の欄は統合せず、保存すれば上書きする（知らせるだけ）
- 見直す条件：一月分以上を使って控えが残せないことが多ければ、控えを圧縮するか IndexedDB を検討する。2つ前に戻したい声が多ければ世代を増やす。知らせが煩わしいという声が多ければ日数（14日）を延ばす
- 影響：PRD §3 に D227、design.md §4 store（持つデータ・API・キー）・§5 エラー方針・冪等性・§7・§8（片づけの未決事項を解決し、控えの世代数・日数・既定を未決に）、`docs/design/pages-data.md`
