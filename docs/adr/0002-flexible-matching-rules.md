# ADR-0002：相性・特性・希望は「項目＋条件の型＋重み0〜5＋必須」で表す

- 日付：2026-10-11
- 状態：採用

## 背景
割当で管理者が見ているもの（性別・資格・経験・得意分野・ペット・喫煙・人柄の相性・いつもの担当・負担の偏り）は事業所ごとに違う。
PoC本体は性別希望と NG しか持たない。ClassClassify では「列（項目）の種類を4つに絞り、列ごとに重み0〜5、一緒に/別に のペア」で、利用者が自分で条件を組めている。

## 選択肢
1. 案A：固定のフィールド（資格・経験年数…）を増やす
2. 案B：自由な式（`staff.経験 >= 3 && …`）やスクリプト
3. 案C：利用者が定義する**項目**（あり/なし・1つ・複数・数値）と、決まった**条件の型**（必要条件・希望・相性・継続・均等・待ち）に、重み0〜5か必須を付ける

## 決定
案C。費用は移動時間と同じ「分」に換算する（重み1＝移動10分ぶん）。

## 理由とトレードオフ
- 得るもの：事業所ごとの考え方をコードを変えずに表せる。重みのスライダーで AI案がどう変わるかをその場で見せられる。理由を「移動+12分より相性◎を取った」と同じ物差しで説明できる
- 失うもの：条件の型にない考え方（例：AさんとBさんを同じ日に同じ地区へ行かせない）は表せない → デモで集めて型を足す
- 必須を増やしすぎると解がなくなる → どの訪問がどの条件で候補ゼロかを出す（matching の `infeasible`）

## 影響
- PoC本体の `requiredGender`・`ngStaffIds` は、「性別」項目＋必要条件、相性×に写す
- 見直す条件：協力法人の考え方の2割以上が型で表せないとき
