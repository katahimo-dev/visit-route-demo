# ADR-0055：スマホは日ごとのリストと下から出る欄・広い画面は帯をキーで動かす・パレットで担当と要対応を引く（5段の見直しの締め）

- 日付：2026-10-22
- 状態：採用
- 関連：PRD D333〜D338（D134・D274・D305 を置き換え、D132・D181・D304・D312 を書き直し）、ADR-0051（5段の見直しの5段目）・ADR-0052・ADR-0053・ADR-0054。一部を置き換えるもの：ADR-0024（スマホの下のタブ）・ADR-0045（下のタブの並び）

## 背景
- UI/UX の見直しの5段（ADR-0051）の最後。ユーザーの決定5は「スマホは見る・取り消す・担当替えまで（追加・移動はしない）」
- 4段目までの残り：
  - 390px の日の予定は見出し・今の担当の1行・担当ごとの1日・操作の行（2〜3段）が積まれ、最初の画面に訪問がほとんど見えない
  - 訪問の詳細の欄は狭い画面でも右の欄の形（画面いっぱい）で、押すボタンが小さい。複数選択の帯は 390px で高さ約190px
  - 週の表（〈スタッフ〉×曜日・〈利用者さん〉×曜日）・月では複数選択できない。スマホの既定は表なので選ぶ所が無かった
  - 訪問をキーボードで動かす手段が無く（ドラッグか欄）、パレットの訪問は〈利用者さん〉の名前と日付でしか引けない
  - 日の予定のその場の提案は日付を変える・画面を移ると消えた（範囲の提案はモジュールの入れ物なので残る）
  - 下のタブは［ホーム｜予定｜欠勤｜空き状況｜メニュー］で、「探す」は上の帯にあり帯が2段に折り返していた

## 選択肢

### スマホの予定
1. 案A：今の画面（順番のカード）を詰めるだけ
2. 案B：日の予定に日ごとのリスト（1行1訪問）を足してスマホの既定にし、順番・一覧は「その他 ▾」の「表示」に残す。週・月はスマホでも今の表示（週の表・月の日ごとの一覧）を「まとめて見る」として残す
3. 案C：週・月もスマホでは日ごとのリストにする（週・月の画面をスマホで出さない）

### 訪問の詳細の欄（スマホ）
1. 案A：今の右の欄（画面いっぱい）のまま
2. 案B：下から出る欄（ボトムシート。高さは内容に合わせる）にし、大きな4つのボタン［担当を替える｜取り消す｜道順｜日の予定で見る］で中身を開く

### キーボードの繰り返しの回
1. 案A：動かすたびに範囲の確認（モーダル）
2. 案B：「この回だけ」で動かし、画面の下に小さな帯「これ以降も／すべての回も／このまま」（選ぶと当て直す。何もしなければこの回だけ）

### 日のその場の提案
1. 案A：今のまま（画面の state。日付を変える・画面を移ると消える）
2. 案B：モジュールの入れ物に置き、画面を移っても・ほかの日を見ても残す（その日の日の予定で帯を出す）。保存はしない

## 決定
すべて案B。

### スマホの日ごとのリスト（PRD D334・D338。`components/dayList.tsx`）
- 600px 以下の日の予定の既定。行は時刻（今の担当の開始。無ければ開始の早い方）・〈利用者さん〉・担当の印（`StaffMark`）と名前・印（要対応・未連絡の変更・ピン）。取り消し・休みの回も薄く出す
- 上の帯の日付の切り替えで日を送る（上の帯は「探す」を下のタブへ移して1段になった）。リストを左右にスワイプ（pointer の横 60px 以上・縦 40px 以内。`touch-action: pan-y`）しても前・次の日
- 行を押すと訪問の詳細の欄。行を長押し（500ms）するか見出しの「選ぶ」で複数選択（選んでいる間は押すと選ぶ・外す。日付を変えると抜ける）
- 操作の行は1段（`ScheduleToolbar` の文字を 600px 以下で読み上げだけに残す `.tb-label`）。日の予定の表示の切り替え（日ごとのリスト・順番・一覧）は「その他 ▾」の「表示」。月の見せ方の切り替えはアイコンだけ
- 見出しの説明・アイコン・担当ごとの1日を出さず、今の担当の1行は訪問・入らない・点数・詳しくだけ。「予定をメールで送る」はアイコン
- 週・月は「まとめて見る」として今の表示のまま（スマホの基本は日ごとのリスト。下のタブの「予定」は最後に開いた表示で、既定は日）。〈利用者さん〉・〈スタッフ〉の画面の予定のスマホの日ごとのリストは2段目（ADR-0052）のまま

### 下から出る欄（PRD D334。`SidePanel` の `sheet`）
- 600px 以下で `VisitPanel` を下に寄せ、高さは内容に合わせる（上は 88% まで）。中身は要約と大きな4つのボタン：担当を替える（候補と保存の帯）・取り消す（ふつう／当日キャンセル・取り消しをやめる）・道順（Google マップ。前の訪問先・自宅から。担当なしは今いる場所から）・日の予定で見る（その日の日の予定を開いていれば閉じる）
- 日時の変更・範囲・新規は出さない（ADR-0051 の決定5）
- 複数選択の帯（`SelectionBar`）も同じ置き場所（下のタブのすぐ上・全幅）。スマホでは時刻をずらすを出さない（動かさない）

### 下のタブ（PRD D336）
- ［ホーム｜予定｜欠勤｜探す｜メニュー］。「探す」はコマンドパレットを開く。860px 以下では上の帯の「探す」を出さない。空き状況はメニューとパレットの画面から

### キーボード（PRD D333。`lib/visitKeys.ts`・`components/visitKeys.tsx`）
- 日の予定の時間軸の帯・週の予定の時間軸の帯で：↑↓ 15分・←→ 1日・Shift+←→ 隣の担当（日の予定は列の順・週の予定は利用中の〈スタッフ〉の順）・Enter で欄・Delete（Backspace）で取り消し（独自の確認）。Shift+Enter（複数選択）と Space（帯の詳細）は今のまま
- 書き込みは `lib/visitOps` の `applyVisitEdit`（時刻・日付は「この回だけ」で、担当はそのまま。担当はピン）と `cancelVisitOp`。update は1回で手の名前つき（「訪問を15分後へ」「訪問を次の日へ」「担当を〇〇さんへ」「訪問を取り消す」）
- 日の予定で ←→ はその日の日の予定へ移り、週の予定は週の外へ出たらその週へ移る。フォーカスは動かした帯（取り消したら「元に戻す」）。動いた先を `output`（aria-live）で読み上げ、できない理由は読み上げと知らせ
- 繰り返しの回は小さな帯（`KeyMoveBand`。画面の下に浮かせる）で「これ以降も／すべての回も」を選べる。選ぶと直前の手（この回だけ）を store の `undo` で戻し、範囲つきで当て直す（1手のまま）。あとから別の変更が入っていれば選び直さない

### パレットの訪問の検索（PRD D337。`lib/commandPalette`）
- 語を日付・「担当なし」「要対応」・名前に分ける。名前は〈利用者さん〉か担当の〈スタッフ〉に当て、索引は〈利用者さん〉ごと・〈スタッフ〉ごと・全部を持つ（`VisitIndex`）
- 「要対応」は日の予定と同じ訪問ごとの検査（`visitIssues`）を当たる候補の日だけ計算し、パレットを開いている間は日ごとに覚える。日付の語が無ければ今日から31日先まで（1日ずつ組むので、索引の期間 +92日より短く区切る）

### 提案を画面を移っても残す（PRD D335）
- 範囲の提案（`lib/monthBatch` の `proposal`）は元からモジュールの入れ物で、画面を移っても残る（e2e で確かめる）
- 日のその場の提案を PlanPage の state からモジュールの入れ物（`dayProposalStore`）へ移し、日付を変えても捨てない（帯はその日だけ）。どちらも保存せず、読み直すと消える。出したあとに訪問が変われば当てない

### 消したもの
- 600px 以下の日の予定の表示の切り替えのボタン（「その他 ▾」へ）・担当ごとの1日（狭い画面専用の畳んだ形）・下のタブの「空き状況」・860px 以下の上の帯の「探す」

## 理由とトレードオフ
- 得るもの：
  - 390×844 で日の予定を開くと、最初の画面に訪問が5件ほど見える（前は0〜1件）。訪問を押すと指で押しやすい4つのボタンが下に出る
  - スマホでも複数の訪問をまとめて担当替え・取り消しできる（長押し・「選ぶ」）
  - 広い画面ではマウスを使わずに訪問を動かせ、全体の元に戻すで1手ずつ戻せる。動いた先が読み上げで分かる
  - パレットで「消防 明日」「担当なし」「要対応」から欄を直接開ける
  - 提案を出したあとに別の画面を見に行っても、戻れば当てられる
- 失うもの（できなくなる・変わること）：
  - スマホの下のタブから空き状況へ1回で行けない（メニューか探すから。2回押す）
  - スマホの日の予定で、表示の切り替え・担当ごとの1日・今の担当の1行の守れない条件・移動・理由・次の一手がすぐには見えない（「その他 ▾」の表示・「詳しく」の欄で見る）
  - スマホの訪問の詳細の欄で、決まりごとの無い訪問は「前の場所から／ここへ道案内」の2つのリンクの代わりに「道順」1つ（前の場所から。担当なしは今いる場所から）
  - スマホの複数選択の帯から時刻をずらすを出さない（スマホでは動かさない）
  - 週の予定の時間軸の帯は、担当の列が無いので Shift+←→ は利用中の〈スタッフ〉の並びの隣の人
  - 日の予定のその場の提案は日付を変えても残る（別の日の帯には出さない。新しく組むと置き換える）
- 手を入れた決まり（推測を含む）：
  - 長押しは 500ms、スワイプは横 60px・縦 40px 以内
  - 「要対応」の検索は日付の語が無ければ今日から31日先まで
  - キーで日付を動かした先が今日より前ならできない理由（「今日より前の日にはできません」）
  - 「日の予定で見る」はその日の日の予定を開いていれば欄を閉じるだけ

## 5段の見直しで変わったこと（ADR-0051〜0055 の要約）
| 段 | 主な変更 | 主に消えたもの |
|---|---|---|
| 1（ADR-0051） | 訪問の詳細の欄 `VisitPanel` を1つにし、どこから開いても日時・担当・取り消し・範囲（この回だけ／これ以降／すべて）を同じ欄で扱う。ホームとパレットからも開く | `VisitForm`・週の移動の欄・一覧の鉛筆 |
| 2（ADR-0052） | 〈利用者さん〉・〈スタッフ〉の画面を全画面にし、タブ（先頭は予定）・予定のカレンダー（回から欄・空き枠から足す・ドラッグ・繰り返しの強調）・節ごとの「直す → 保存」 | 右の欄の閲覧・編集の2つのモード（ADR-0023） |
| 3（ADR-0053） | データを版2に：担当は訪問に持つ・AI は提案を出して「当てる」・確定は伝えた内容・繰り返しの回は見るときに計算・要対応は訪問ごとの検査 | 記録・今の案・確定した割当・手直しの記憶・この日だけ試す重み・作り直しの帯・「未作成」 |
| 4（ADR-0054） | 日・週・月を共通の部品（操作の行・「AI で組む ▾」の範囲・提案の帯・複数選択）に寄せ、メニュー6項目・全体の元に戻す（50手・Ctrl+Z） | 画面ごとの1手の元に戻す・日と週の進み具合の帯・週の「組む」の主ボタン |
| 5（この ADR） | スマホは日ごとのリスト・下から出る欄・長押しの複数選択・下のタブの「探す」、広い画面は帯をキーで動かす、パレットで担当・担当なし・要対応を引く、提案を画面を移っても残す | スマホの表示の切り替えのボタン・担当ごとの1日・下のタブの「空き状況」・上の帯の「探す」（狭い画面） |

- 用語は「訪問・繰り返し・担当・ピン・提案（AI）・確定（伝えた）・要対応・この回だけ／これ以降／すべて」を中心にそろった
- 残っている課題：
  - 日・週・月の本体（時間軸・表・カレンダー）は3画面のまま（共通の部品だけ）。日の予定の帯の詳細（理由・「担当を変える ▾」）と訪問の詳細の欄の2か所がある
  - 週・月の表（〈スタッフ〉×曜日・〈利用者さん〉×曜日・カレンダー）では複数選択・キーボードで動かすができない
  - スマホの下から出る欄はなぞって閉じる・高さを変えることができない。スワイプは日ごとのリストだけ
  - 元に戻すの履歴と提案は保存しない（読み直すと消える）
  - パレットの「要対応」は31日先まで。担当の名前は名字・名前の部分一致だけ（あいまいな一致はしない）
