# ADR-0013：第N曜日・曜日ごとの時刻、利用者さんの休み（派生で外す）、訪問先の決まりごと、空き枠の案内文

- 日付：2026-10-17
- 状態：採用（方向は依頼者が決定（ヒアリングを受けた第1弾。2026-10-17）。細部は推奨どおりに決め、この ADR に記録する）

## 背景
訪問看護事業所のヒアリング（2026-10-15）で、次の困りごとが出た（PRD D64〜D67 の背景）。

1. 予定は月ごとに手入力している。「第3・第4木曜」のような**毎月の第N曜日**の訪問は、いまの定期パターン（毎週〜4週ごと）で表せず、担当者が変わると引き継げない
2. 同じ利用者さんでも**回（曜日）ごとに時刻が違う**（月曜は 9:30、木曜は 15:00）。いまはパターンを曜日ごとに分けるしかない
3. 入院・ショートステイで**利用者さんが休んだのに予定が残り**、振替の漏れ・空振りの訪問が起きる
4. 鍵の置き場所・インターホン・駐車場の情報を LINE WORKS で別に管理していて、訪問の直前に探している
5. ケアマネから「空いている枠は？」と聞かれても**即答できず**、空き状況の画面を見ながら手で文を作っている

いまの形：定期パターン（ADR-0012）は `everyWeeks`（1〜4）と、パターン共通の開始（早）〜（遅）だけを持つ。展開した訪問は実体化し、ID は `${元の日}_${パターンID}`。利用者さんの不在は、訪問を1件ずつ取り消すしかない（取り消しは「この回だけの変更」として残る）。PRD §4 は「第N曜日・日付指定・祝日」をやらないことにしている。

決めること：(1) 第N曜日の持ち方、(2) 曜日ごとの時刻の持ち方、(3) 利用者さんの休みの扱い、(4) 決まりごとの持ち方、(5) 案内文の作り方。

## 選択肢
1. 第N曜日
   - A：**パターンに繰り返し方（`repeat`：毎週系／毎月）と第N（`monthWeeks`：1〜5を複数）を足す**。第N＝その月のその曜日の何回目（日の (日−1)÷7 の切り上げ）。第5の無い月は作らない
   - B：第N曜日用の別の型（`monthlyPattern`）を足す
   - C：日付の一覧を持たせる（月ごとに手で選ぶ）
2. 曜日ごとの時刻
   - A：**パターンに曜日ごとの上書き（`dayTimes`：曜日・開始（早）・開始（遅））を足す**。無い曜日はパターン共通の時刻
   - B：曜日ごとにパターンを分ける（いまのまま。画面で束ねて見せる）
3. 利用者さんの休み
   - A：**休み（期間）を別の記録 `clientLeaves` に持ち、訪問は消さずに「休みのため無し」と派生で扱う**（compile が問題に入れない。月・週・日の画面では薄く印付きで出す）。休みを消せば元に戻る
   - B：休みを入れたときに、その期間の訪問を取り消す（`cancelled`・`edited`）。休みを消したら取り消しを戻す
   - C：利用者さんを休止中（`active: false`）にする
4. 訪問先の決まりごと
   - A：**〈利用者さん〉に4項目（入り方・鍵・駐車場・注意。各200字）を足す**
   - B：項目（特性）として利用者が足す（自由な項目）
   - C：メモ（`note`）に書いてもらう
5. 空き枠の案内文
   - A：**空き状況の計算（`vacancyOf`）の結果から、純粋関数で文を作る**（期間：今週／来週／先4週、種類）。今週・来週は日付ごと、先4週は毎週続けて受けられる曜日ごと
   - B：問い合わせの試算の要約（`inquirySummary`）をそのまま使う

## 決定
1-A、2-A、3-A、4-A、5-A（第N曜日・休みを派生で扱う・決まりごとの4項目・案内文は依頼者の方針どおり。細部は推奨どおり）。

- 定期パターン：`repeat: 'weekly' | 'monthly'`（既定 `'weekly'`）、`monthWeeks: number[]`（1〜5。monthly のとき1つ以上。既定 `[]`）、`dayTimes: { weekday, earliestStart, latestStart }[]`（既定 `[]`。曜日は重ならない）。`repeat` が monthly のとき `everyWeeks` は使わない（1 のまま持つ）。展開した訪問の時刻はその曜日の `dayTimes`、無ければ共通の時刻。訪問の ID 規則・「以降すべて」・この回だけの変更は今のまま
- 週間の「以降すべて」（ドラッグで曜日を変える）：動かした曜日の上書き時刻は新しいパターンの共通の時刻になり、新しい曜日の上書きは持たない。毎月のパターンは第N（`monthWeeks`）をそのまま引き継ぐ（第3木曜を金曜へ動かすと第3金曜）
- 利用者さんの休み：`DemoData.clientLeaves: { id, clientId, from, to, note }[]`（既定 `[]`。from〜to は両端を含む日付）。訪問が「休みのため無し」＝取り消しでなく、その利用者さんの休みの期間に日付が入る。判定は domain の純粋関数（`leaveOn`）。compile は休みの訪問を問題に入れない（AI案・月まとめ作成・空き状況・混み具合・振り直しから外れる）。月・週・日の画面の数は取り消しと同じく数えない。訪問のデータ（パターンの回・この回だけの変更・確定した割当）は消さない。休みを消すと元に戻る。パターンを展開しても、訪問は残っているので重ねて作らない
- 休みを入れる・直すとき、休みと重なる**確定した日**（確定した割当にその利用者さんの訪問がある日）があれば注意（日付と「その日の案を作り直してください」）を出す。案は勝手に作り直さない（今の案のある日は D43 の「条件が変わった」が出る）
- 決まりごと：`clientSchema` に `entryNote`（入り方）・`keyNote`（鍵）・`parkingNote`（駐車場）・`cautionNote`（注意）。各200字、既定 `''`。〈利用者さん〉の画面で入れ、スタッフ画面の各訪問・日の画面の訪問の詳細に出す。条件（割当）には使わない
- 案内文：vacancy の `vacancyNotice(result, input)`。今週（今日〜その週の日曜。週は月曜はじまり）・来週（次の月曜〜日曜）は日付ごとに、その日に1人以上が受けられる開始時刻の連続した範囲。先4週（今日から4週）は曜日ごとに、どの週も受けられる（○）開始時刻の範囲。事業所名は `org.name`、呼び方は `org.terms`。案の無い日は文に入れず、画面に注記する。コピーは `lib/clipboard` の `copyText`
- データの版は1のまま。新しい項目はどれも zod の既定値で古いデータを読む。Excel：「定期パターン」に「第N週」「曜日ごとの時刻」（任意の列）と間隔「毎月」、〈利用者さん〉に「入り方」「鍵」「駐車場」「注意」（任意の列）、新しいシート「訪問先の休み」（無い古いブックは休みなし）

## 理由とトレードオフ
- 得るもの：
  - 第N曜日・曜日ごとの時刻を1つのパターンで持てるので、「月の手入力」をやめられ、引き継ぎ（何を・いつ）がパターンの一覧で読める。展開・ID・この回だけの変更・以降すべては今の仕組みのまま
  - 休みを派生で扱うと、訪問のデータを書き換えないので、休みを消すだけで元に戻り、パターンの展開で重複・復活の問題が起きない。AI案・月まとめ作成・空き状況は compile を通るので、一か所の判定で漏れなく外れる。振替の漏れ（休みなのに予定が残る）が画面の印で見える
  - 決まりごとを固定の4項目にすると、スタッフ画面で決まった場所に出せ、Excel でもまとめて入れられる
  - 案内文は計算済みの空き状況から作るので、画面の表と食い違わない。純粋関数なので単体テストで文を固定できる
- 失うもの：
  - パターンの形が少し複雑になる（毎週系と毎月で使う項目が違う。`everyWeeks` は毎月のとき使わない）。日付指定（毎月15日）・祝日は今回もやらない
  - 休みの期間の訪問はデータに残るので、件数（Excel の訪問の行など）には入る。休みかどうかは画面と compile で毎回判定する（休みは数件〜数十件の想定で、重さは問題にならない）
  - 休みを入れても確定した割当は自動では直らない（注意を出して人が作り直す）。今の案にも休みの訪問が残ったまま「条件が変わった」になる（作り直すと消える）
  - 決まりごとは割当の条件にならない（「駐車場なし → 自転車の人」は特性・条件で表す）
  - 案内文は「開始できる時刻」の目安で、目安の表（場所なし）なら移動は前後15分の見込み。入れ替えれば入る枠は出ない（D46 と同じ）

## 影響
- PRD：D64〜D67 を追加。§4 の「第N曜日…はやらない」を「日付指定（毎月15日）・祝日はやらない」に書き直す
- design.md：patterns（第N曜日・曜日ごとの時刻）、domain（`leaveOn`）、matching（休みの訪問を入れない）、store（`clientLeaves`・repair）、seed（決まりごとの例）、excel（列・シート）、vacancy（`vacancyNotice`）、pages（パターンの欄・〈利用者さん〉の休みと決まりごと・月／週／日の休みの印・スタッフ画面・空き状況の案内文）。契約は §5「定期パターンの第N曜日・曜日ごとの時刻と利用者さんの休み・決まりごと」「空き枠の案内文」
- データ：`DATA_VERSION` は1のまま（`clientLeaves` は `[]`、パターンの3項目・〈利用者さん〉の4項目は既定値）
- 見直す条件：日付指定・祝日の要望が出たら `repeat` に足す。休みの期間の訪問を本当に消したい声が出たら 3-B を検討。案内文のひな形（敬語・載せる範囲）はデモの反応で直す
