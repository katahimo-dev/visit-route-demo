# ADR-0013：第N曜日・曜日ごとの時刻、利用者さんの休み（派生で外す）、訪問先の決まりごと、空き枠の案内文

- 状態：採用（2026-10-17）
- 関連：PRD D64〜D67、ADR-0012（定期パターン）

## 背景
訪問看護事業所のヒアリング（2026-10-15）で出た困りごと。
1. 予定を月ごとに手入力している。「第3・第4木曜」のような毎月の第N曜日は、定期パターン（毎週〜4週ごと）で表せず、担当が変わると引き継げない
2. 同じ利用者さんでも曜日ごとに時刻が違う（月曜 9:30、木曜 15:00）。パターンを曜日ごとに分けるしかない
3. 入院・ショートステイで利用者さんが休んでも予定が残り、振替の漏れ・空振りが起きる（当時は訪問を1件ずつ取り消すしかなかった）
4. 鍵の場所・インターホン・駐車場の情報を別に管理していて、訪問の直前に探している
5. ケアマネから「空いている枠は？」と聞かれても即答できず、空き状況の画面を見て手で文を作っている

PRD §4 は第N曜日・日付指定・祝日をやらないとしていた。
決めること：第N曜日・曜日ごとの時刻・利用者さんの休み・決まりごと・案内文の持ち方。

## 決定
第N曜日・曜日ごとの時刻は既存パターンに足す。休みは別の記録にして派生で外す。決まりごとは〈利用者さん〉の固定4項目。案内文は空き状況の結果から純粋関数で作る。

- 定期パターン：`repeat: 'weekly' | 'monthly'`（既定 weekly）、`monthWeeks`（1〜5。monthly で1つ以上）、`dayTimes`（曜日・開始（早）・開始（遅）。曜日は重ならない）を足す。第N＝その月のその曜日の何回目（日の (日−1)÷7 の切り上げ）。第5の無い月は作らない。monthly のとき `everyWeeks` は使わない。展開した訪問の時刻はその曜日の `dayTimes`、無ければ共通の時刻。訪問の ID 規則・「以降すべて」・この回だけの変更は従来どおり
- 週間の「以降すべて」（ドラッグで曜日を変える）：動かした曜日の上書き時刻は新パターンの共通の時刻になる。毎月のパターンは第N を「落とした日の第N − 元の日の第N」だけずらす（1〜5 に収まらないものは捨てる）。新しい日にできない組み合わせでは「以降すべて」を断り「この回だけ」を勧める（データは変えない）。レビュー前は第N をそのまま引き継いでいたため、第N の違う日へ落とすとその月の回が消えた
- 利用者さんの休み：`DemoData.clientLeaves`（`{ id, clientId, from, to, note }`。両端を含む）。訪問は消さず、休みの期間に入る訪問を「休みのため無し」と派生で扱う（domain の `leaveOn`）。compile は休みの訪問を問題に入れないので、AI案・月まとめ・空き状況・混み具合・振り直しから外れる。月・週・日の画面では薄く印付きで出し、件数には数えない。休みを消せば元に戻る
  - 休みと重なる確定した日があれば注意（日付と「その日の案を作り直してください」）を出す。案は勝手に作り直さない。確定し直すとき、休みの訪問は前の確定した担当のまま確定した割当に残す
- 決まりごと：`clientSchema` に `entryNote`（入り方）・`keyNote`（鍵）・`parkingNote`（駐車場）・`cautionNote`（注意）。各200字・既定 `''`。〈利用者さん〉の画面で入れ、スタッフ画面の各訪問・日の画面の訪問の詳細に出す。割当の条件には使わない
- 案内文：vacancy の `vacancyNotice(result, input)`。今週（今日〜日曜。月曜はじまり）・来週は日付ごとに、その日に1人以上が受けられる開始時刻の連続範囲。先4週は曜日ごとに、どの週も受けられる（○）開始時刻の範囲。事業所名は `org.name`、呼び方は `org.terms`。案の無い日は文に入れず注記する。コピーは `copyText`
- データの版は1のまま（新項目は zod の既定値）。Excel：「定期パターン」に「第N週」「曜日ごとの時刻」（任意の列）と間隔「毎月」、〈利用者さん〉に4項目（任意の列）、新シート「訪問先の休み」（無い古いブックは休みなし）

## 検討した案
| 案 | 長所 | 短所 | 採否 |
|---|---|---|---|
| 第N曜日A：パターンに `repeat`・`monthWeeks` を足す | 展開・ID・この回だけの変更が今のまま | 毎週系と毎月で使う項目が違う | 採用 |
| 第N曜日B：別の型 `monthlyPattern` | 型が分かれて明確 | 展開・画面が二重になる | 不採用 |
| 第N曜日C：日付の一覧を手で選ぶ | 単純 | 月ごとの手入力に戻る | 不採用 |
| 時刻A：`dayTimes` で曜日ごとに上書き | 1つのパターンで持てる | 形が少し複雑 | 採用 |
| 時刻B：曜日ごとにパターンを分ける | 変更なし | 引き継ぎで読みにくい | 不採用 |
| 休みA：別の記録で派生に外す | 訪問を書き換えない。消すと元に戻る。パターン展開で重複・復活しない。compile の1か所で漏れなく外れる | 休みの訪問がデータに残り件数に入る。確定した割当は自動では直らない | 採用 |
| 休みB：期間の訪問を取り消す | 単純 | 休みを消すと取り消しを戻す処理が要る。取り消しの記録と混ざる | 不採用 |
| 休みC：利用者さんを休止中にする | 簡単 | 期間を表せない | 不採用 |
| 決まりごとA：固定4項目 | 決まった場所に出せ、Excel でまとめて入れられる | 割当の条件にならない | 採用 |
| 決まりごとB：自由な項目（特性） | 柔軟 | 出す場所が定まらない | 不採用 |
| 決まりごとC：メモに書く | 追加なし | 探しにくい | 不採用 |
| 案内文A：空き状況の結果から文を作る | 画面の表と食い違わない。単体テストで固定できる | — | 採用 |
| 案内文B：問い合わせの試算の要約をそのまま使う | 実装が少ない | 日付・曜日ごとの文にならない | 不採用 |

## 結果・トレードオフ・見直す条件
- 得るもの：月の手入力をやめられ、引き継ぎがパターンの一覧で読める。振替の漏れが画面の印で見える。ケアマネへの返答の文をすぐ作れる
- 失うもの：
  - 日付指定（毎月15日）・祝日は今回もやらない
  - 休みの期間の訪問はデータに残る（判定は画面と compile で毎回。数件〜数十件の想定で重さは問題にならない）
  - 休みを入れても確定した割当は自動では直らず、人が作り直す。今の案には休みの訪問が残ったまま「条件が変わった」になる
  - 決まりごとは割当の条件にならない（「駐車場なし → 自転車の人」は特性・条件で表す）
  - 案内文は開始できる時刻の目安で、場所なしの表なら移動は前後15分の見込み。入れ替えれば入る枠は出ない
- 見直す条件：日付指定・祝日の要望（`repeat` に足す）。休みの訪問を本当に消したい声（休みB）。案内文の敬語・載せる範囲はデモの反応で直す
- 影響：PRD §4 を「日付指定（毎月15日）・祝日はやらない」に書き換え
