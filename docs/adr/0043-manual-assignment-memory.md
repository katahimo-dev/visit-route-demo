# ADR-0043：手直しの記憶（手で選んだ担当を、同じ曜日・同じ時間の次の案でも固定する）

- 状態：廃止（ADR-0053で置き換え）
- 関連：PRD D260〜D262、ADR-0004（AI案を土台に手直し・固定）、ADR-0010（再計算を省く記録・inputKey）、ADR-0011（欠勤の振り直し）、ADR-0012（定期パターン・いつもの担当）、ADR-0030（1手戻す）、ADR-0032（直前の状態に戻す）

## 背景
- 日の予定で AI案の担当を手で直しても、次の週の同じ曜日の案（まとめて作る・作り直す）ではまた AI が別の人を選び、毎週同じ手直しをしている（利用者の声）
- 利用者の決定：自動ではなく**手で調整した割当**を覚え、同じ〈利用者さん〉・同じ曜日・同じ時間なら次からその人にする。変えたら最新だけ。キーに**曜日を入れる**。強さは**固定**（必ずその人）
- 追加の決定：手で変えるのは一時的なこともあるので、**毎回黙って覚えない**。変えた直後に確認を出し（既定は今回だけ）、モーダルで止めない。「次からも」を選んだら、来週以降のすでに割り当てた同じ訪問もまとめて変えるか聞く。まとめて変えたものも「元に戻す」（1手）で全部戻る
- PRD §4 は「相性の学習」をやらないことにしている。これは学習（データから傾向を推す）ではなく、利用者が選んだ手直しを記録して当てるだけと位置付ける
- 制約：solver は変えない（問題 `Problem` だけを読む）。データは localStorage の1つの JSON（版は1のまま）。採点・説明の物差しは変えない（ADR-0010）

## 選択肢
1. 案A：記憶の表（`DemoData.manualPrefs`：キー → 担当）を足し、案を作るときの問題で、その訪問を記憶の担当に**固定**する（手直しの固定 `pins` と同じ道：その担当だけを可にする）
2. 案B：定期パターンの `usualStaffId`（いつもの担当）を書き換える
3. 案C：記憶の担当を費用で優遇する（「いつもの担当」の条件のように割当費用を下げる）

## 決定
案A。
- データ：`manualPrefs: Record<キー, { staffId, updatedAt }>`（`src/contracts/data.ts`。無い古いデータは `{}`、版は1のまま）。キーは `clientId|曜日(0=日〜6=土)|earliestStart-latestStart|typeId または空`（`matching/manualPrefs` の `prefKey`。日付・所要・パターンは入れない）。同じキーは上書き（最新だけ）。上限 2000 件（`MAX_MANUAL_PREFS`。超えたら updatedAt の古い順に消す。書くとき `lib/manualPrefs` の `trimManualPrefs`、読み込みで store の repair。repair はいない〈スタッフ〉・いない〈利用者さん〉（キーの先頭）の記憶も消す。休止中の人は残す。`manualPrefs: null` は `{}`）
- 当てる：案を作る問題だけに当てる（`withManualPrefs(problem, data, pins)`）。記憶の担当が問題にいて、その組が可（休み・欠勤・時間帯外・最終勤務日の後・相性×・担当を限る・種類・必須の条件で外れていない）なら、その訪問はその担当だけを可にし（ほかの担当の理由「手直しの記憶（〇〇さんに固定）」、当てた組の理由「手直しの記憶：前に手で〇〇さんにした」。費用は変えない）、だめなら黙ってふつうに決める。手直しの固定がある訪問は固定が先。当てる所：AI案を作る・自動作成・プリセットを順に作る・プリセットのカード・固定を残して組み直す・月のまとめて作る（条件が変わった日の作り直しも）・比較の「もう1案」。**当てない所**：採点・説明の問題（日の予定の物差し。当てると前に作った案が違反に見える）、欠勤の振り直し（元の案からの最小の変更で、元の案はもう記憶を反映している。欠勤の人の記憶は可にならないのでどのみち当たらない）、空き時間に入れる（D50）、初期データの案
- 記録と「条件が変わった」：当てた固定を記録の `prefPins`（`AiRun`）に残す。`inputKey` は当てた問題のキーなので、記憶が変われば再計算を省く記録（`reusableRun`）は使わない。「条件が変わった」（`lib/month` の `planStale`）は記録の `prefPins` のまま当てて比べ、**記憶が変わっただけでは出さない**（手直しで記憶を書くたびに、その日や同じ曜日の日がすべて「条件が変わった」になるため）。記憶の担当が休むなどデータが変われば今どおり出る。同じ結果の記録を使い回すときは `prefPins` も今回のものに書き直す
- 書く（確認）：手で担当を変えた（ドラッグ・「担当を変える ▾」・受けられる人に入れる）ときは書かず、日の予定の帯（`components/prefAsk` の `PrefAskBand`）で「次からも 火曜 10:00 の〇〇様は△△さんにしますか？」［次からもこの人にする］［今回だけ］。何件か続けて動かしたら1つの帯にまとめる。既定は今回だけ（答えない・日を移る・作り直す（AI案を作る・固定を残して組み直す・保存してある案にする）・固定を外すと聞くのをやめる。日を移って戻っても前の帯は出さない）。最初の担当に戻した・同じ記憶がすでにある訪問・必須の条件に合わない人へ移した訪問（記憶しても次の案で当てられない）は聞かない。［次からも］で `manualPrefs` に書く。今回だけ・別の人に今回だけ変えても既存の記憶は消さない
- 消す：手で固定を外した（固定を外す・入らなかった訪問へ・AI が出したままに戻す）ときは、その訪問のキーの記憶が外した担当のときだけ消す（ほかの日で書き直した記憶は残す）。「AI が出したままに戻す」は固定をすべて捨てる操作なので、固定と同じ担当の記憶も消す（確認の本文に件数）。「捨てて作り直す」（AI案を作る）は記憶を消さない（作り直す案に記憶が効く）。データの画面に件数と［すべて消す］（確認つき）
- まとめて変える：［次からも］のあと、同じキーの訪問で今日より後の日に、今の案（無ければ確定した割当）で別の人が割り当たっているもの（`lib/manualPrefs` の `futureAssigned`）があれば、帯（`PrefBulkBand`）で「来週以降のすでに割り当てた N件（10/28・11/4 …）も△△さんに変えますか？」［まとめて変える］［変えない］。まとめて変えると、その日の今の案で担当を差し替えて固定（`applyFutureAssigned`。手直しと同じ `bestInsertion`）。**確定した日は確定した割当を変えず今の案だけを変える**（日の予定で「未確定の変更あり」になり、確定し直すかは利用者が決める。確定を勝手に作り直さない PRD §4 と同じ）。確定済みの日があれば帯に「うち確定済みの M日は今の案だけ変わり、確定し直しが必要です」と添える。今の案の無い確定した割当だけの日・その担当がその日に担当できない日（今の案の条件の問題で可でない）・〈利用者さん〉の休みで計算に入らない日は変えず、帯（`PrefBulkResult`）に「変えられなかった日」と理由（その日は担当できない／働かない／〈利用者さん〉の休み／確定した割当だけの日）を出す
- 戻す：「元に戻す」（1手。ADR-0030）の控えに、同じ1手で書いた記憶（キーと前の値）とまとめて変えたほかの日の今の案（前と後）を足し、日の手直し・記憶・ほかの日を一緒に戻す（`undoPrefExtras`）。ほかの日の今の案がそのあと変わっていたら戻さない（「ほかの日の案が変わりました」）。足す先の控えがもう戻せない（そのあとに今の案が変わった・確定した）なら、日の手直しの控えは捨てて記憶・まとめて変えた分だけの控えにする（「元に戻す」で記憶・来週分が確実に戻る）。記憶だけの控えは、作る・組み直すの計算が終わったら捨てる（作り直した案と別に記憶だけ戻すと食い違うため）。続けて何件か動かして1つの帯で［次からも］を選んだときの1手は、日の手直しは最後に動かした1件（ADR-0030 の1手のまま）、記憶はその帯で書いた全件、まとめて変えた分はそのあとの［まとめて変える］の全件。それより前に動かした訪問の担当は戻らない（記憶は戻る）。「直前の状態に戻す」（ADR-0032）はデータごと戻すので記憶も戻る
- 書き出し：JSON の控えにはそのまま入る（データの一部）。Excel のブックにはシートを作らない（全体の読み込みでは AI案・記録と同じく消え、確認の本文・説明にそう書く。名簿の読み込みでは残る）
- 画面の印：記憶で固定した訪問（今の案の元の記録の `prefPins` で、いまもその担当・手直しの固定でないもの）に、手直しの固定（橙の「固定」）と分けた青い点線の「記憶」（`pref-mark`）と、詳細に「手直しの記憶：前に手で〇〇さんにした（同じ曜日・同じ時間。作り直してもこの担当）」（`pref-note`）

## 理由とトレードオフ
- 得るもの：利用者が選んだ手直しが次の週の案でもそのまま効き、毎週の同じ手直しが要らない。固定は「必ずその人」という利用者の決定どおりで、既存の固定と同じ道なので solver・採点を変えない。担当できない日は黙ってふつうに決めるので、休み・欠勤で入らない訪問が増えない。確認を挟むので一時的な代行が勝手に覚えられない
- 失うもの：
  - キーに曜日・時間の約束・種類を入れるので、時刻を少し変えた訪問・別の曜日には効かない（意図どおり。同じ曜日・同じ時間だけ）
  - 記憶が変わっても「条件が変わった」は出ない。前に作った案に記憶を効かせるには作り直すか、［まとめて変える］を使う
  - 固定なので、記憶の担当に入れると移動が長くなる・ほかの訪問が入らなくなることがあっても、その人のまま（担当できない日だけ外す）
  - 記憶の一覧・1件ずつの編集は無い（件数と［すべて消す］・固定を外すで消すだけ）
- 案B（いつもの担当を書き換える）は、パターンの無い単発の訪問に効かず、曜日・時間ごとに分けられない（パターンは〈利用者さん〉ごと・複数の曜日をまとめて持つ）。また「いつもの担当」は重み付きの条件で、固定にならない。いつもの担当は人の詳細・Excel にも出るので、一時的な手直しで名簿が変わる
- 案C（費用で優遇）は「必ずその人」にならず、重みしだいで AI が別の人を選ぶ。どの程度優遇するかの決まりも要る
