# ADR-0061：予定にモード［組む｜変更｜確認］を設け、メニューに畳める子の項目を置く

- 日付：2026-10-24
- 状態：廃止（ADR-0063 で置き換え。予定のモードは無い）
- 関連：PRD D348・D349（D326 のメニューを書き直し）、ADR-0060（予定のナビの行）・ADR-0054（予定の共通の部品・メニュー6項目）

## 背景
- 月・週・日の予定は、どれも「組む・直す・確認する・伝える」の操作を全部持っていた。事前に月を組むとき、当日の欠勤に対応するとき、毎日確かめて連絡するときで、同じボタンが並ぶ
- 確認と連絡だけのときにも札をドラッグでき、うっかり動かす恐れがあった
- 左のメニューは6項目で縦に余白があり、人・設定のタブは画面を開くまで見えなかった

## 選択肢
1. 案A：ナビの行に［組む｜変更｜確認］のモードを置き、モードで出す操作を絞る。メニューの「予定」の子をモードの入口にし、人・設定の子をタブにして畳めるようにする
2. 案B：メニューを仕事の名前（来月を組む・欠勤・変更・今日の予定）の項目に分けるだけで、画面の中身は変えない
3. 案C：ホームのカードからモードの画面へ入る流れだけ作る

## 決定
案A。
- モードは `lib/scheduleMode.ts`（純粋関数。`modeTools`・`defaultMode`・`unassignedDays`・`menuBadges`）と `components/useScheduleMode.ts`（今のモード。sessionStorage）
- 出す操作：組む＝AI で組む・札を動かす、変更＝すべて、確認＝欠勤の登録・メール・確定（AI で組む・札を動かすは出さない）
- 既定：月の後半（15日以降）で、来月の担当なしの訪問がある日（今日以降・伝えていない日）が2日以上なら組む、それ以外は確認（ユーザーの指定）。数えるのは compile しない軽い数え方（担当が null の訪問）
- メニュー：ホーム・予定（今日の予定／◯月を組む／欠勤・キャンセル）・空き状況・人（タブ）・設定（タブ）。▾ で畳み、開け閉めは localStorage
- 「今日」の名前は、ナビの行の「今日」（今日を含む期間へ送る）とぶつかるので、モードは「確認」と呼ぶ

## 理由とトレードオフ
- 得るもの：仕事の段階で見るボタンが減る。確認のときに札を動かさない。メニューから目的の作業へ1回で入れる。件数の印で、開かなくても来月の残りと今日の未確定が分かる
- 失うもの：モードを知らないと「ボタンが無い」と迷う（ナビの行の下の1行の説明と、切り替えの title で補う）。メニューの行が増える（設定を既定で畳み、1366×768 に収める）
- 確認のモードでも訪問の詳細の欄では直せる（読み取り専用にはしない。急ぎの直しを止めない）

## 影響
- `src/lib/scheduleMode.ts`・`src/components/useScheduleMode.ts`（新規）・`ScheduleNav.tsx`（切り替え・説明）・`scheduleParts.tsx`（操作の行）・`visitParts.tsx`（`useVisitDrag` の `readOnly`）・`visitKeys.tsx`（`readOnly`）・`MonthPage`・`WeekPage`・`PlanPage`・`lib/nav.ts`（子の項目・`isActiveNav` のモード）・`App.tsx`（`NavGroups` の畳み・件数の印）・`styles.css`
- e2e：モードを見ない段は「変更」（すべての操作）で動かす（`scripts/lib/env.cjs` の `presetMode`）。モードは `scripts/e2e-modes.cjs` で確かめる
- 見直す条件：モードを切り替える手間が多いと分かったら、画面ごとに既定のモードを決める（例：月は組む）
