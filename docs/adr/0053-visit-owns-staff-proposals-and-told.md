# ADR-0053：データを版2にする（担当は訪問に持つ・AI は提案だけ・確定は伝えた内容・繰り返しの回は見るときに計算）

- 日付：2026-10-22
- 状態：採用
- 関連：PRD D314〜D325（D11・D13・D14・D19・D22・D30・D41・D43・D52・D155・D156・D159〜D164・D166・D225・D226・D234・D242・D243・D259〜D262・D280〜D282・D290〜D292 を置き換え）、ADR-0051（5段の見直しの3段目）・ADR-0052（2段目）。この ADR で置き換えるもの：ADR-0043（手直しの記憶）・ADR-0049（条件の変更の控えと戻す）。一部を置き換えるもの：ADR-0004（AI案を土台に手直し・固定）・ADR-0005（記録どうしの比較）・ADR-0010（記録と inputKey。点数の基準は残す）・ADR-0011（振り直しの情報の置き場所）・ADR-0012（展開して保存）・ADR-0031（初期データの案）・ADR-0035（この日だけ試す重み）・ADR-0042（月まとめ作成の書き先）・ADR-0046（未作成・作り直す日）

## 背景
- UI/UX の見直しの5段（ADR-0051）の3段目。1・2段目で訪問の詳細の欄と人の画面を作り、データに触る所を `lib/visitOps` などの薄い層に寄せた
- 版1では「訪問」に関わる状態が5つの層に分かれていた：定期パターン → 展開して保存した訪問（`pattern.edited`）→ 今の案（`aiPlans`：`routes`・`pins`・`generated`）と記録（`aiRuns`）→ 確定した割当（`manualPlans`）。さらに手直しの記憶（`manualPrefs`）・この日だけ試す重み（`data.rules`）・条件の変更の控え（DemoData の外）があった。日の状態は 案なし／案あり（未確定）／未確定の変更あり／確定済み／条件が変わった／未作成 の6つで、利用者が覚える言葉が多かった
- ユーザーが決めたこと：①確定＝〈スタッフ〉に伝えた内容（あとの変更は「未連絡の変更」として連絡の一覧に出す）②プリセットは残し、AI の実行と比較はその場だけ（保存しない）③人の画面は全画面（2段目で済み）④繰り返しの回は見るときに計算し、変えた回だけ保存する ⑤スマホは見る・取り消す・担当を替えるまで
- デモなので互換は要らない（古いデータは移さない）

## 選択肢
1. 案A：今の層のまま言葉だけ減らす（今の案・確定した割当を残し、画面の表示をまとめる）
2. 案B：担当を訪問に持ち、AI は提案（差）を出して「当てる」で訪問に書く。確定は伝えた内容の写し、繰り返しの回は見るときに計算。版を2に上げ、版1は移さず初期データで始める
3. 案C：案B に加えて、版1のデータを版2へ移す（`aiPlans`・`manualPlans` から訪問の担当を作る）

## 決定
案B。

### データの形（`src/contracts/`）
- `DATA_VERSION = 2`（キーは `vrdemo:data:v1` のまま）。`Visit` に `staffId`（担当。null＝担当なし）・`start`（組んだ開始。null は開始（早）で並べる）・`pinned`（AI で組み直しても担当を変えない）。`pattern.edited` は時刻・日付・所要・種類・メモを変えた回（担当・開始・ピンだけの違いは edited にしない）
- `DemoData` から `aiPlans`・`aiRuns`・`manualPlans`・`manualPrefs` を除き、`snapshots`（date → `DaySnapshot = { date, at, visits: ToldVisit[] }`。`ToldVisit = { id, clientId, staffId, start }`）と `reassigns`（date → `ReassignInfo`。当てた振り直しの日だけ。`from`・`baseGenerated`・`baseRunId` は無くした）を足した
- `Pattern.usualStaffId`（繰り返しの担当）を1つ。`Client.usualStaffId` は無くした
- `data.rules` の重み・必須は store の repair がいつも点数の基準のプリセットにそろえる（この日だけ試す重みは無い）

### 繰り返し（`src/patterns/`）
- `visitsOn(data, date)`・`visitsIn(data, range)`：保存した訪問と、利用中の〈利用者さん〉の繰り返しの計算した回（ID `${日}_${パターンID}`。同じ ID の保存した回があれば出さない）を、開始の順に返す。計算した回の担当は繰り返しの担当
- `findVisit`・`putVisits`（計算した回を書くときは保存した回にする）・`parsePatternVisitId`
- `splitPattern`：分けた日以降の、この回だけ変えていない保存した回は消し（新しい繰り返しで計算し直す）、変えた回は新しい繰り返しの回として ID を付け直す。`removePattern`：開始が今日より前の繰り返しは昨日で終わらせて残し（過去の予定を消さない）、今日以降の保存した回のうち変えていない回は消し、変えた回は単発にする。開始が今日以降なら繰り返しごと消す
- `applyPatterns`・`expandPattern` の展開して保存する使い方と、store の `extendDays`、「未作成」は無くした

### 日の割当と確定（`src/lib/dayPlan.ts`・`confirmDay.ts`）
- 日の割当（`routesOf`・`dayRoutes`）＝その日の計算に入れる訪問を担当ごとに開始の順に並べたもの。担当なしは `unassignedOf`、ピンは `pinsOf`
- 書く：`writeRoutes(data, date, problem, routes, { pins? })` が担当と開始（lenient で計算）を訪問に書く（変わる回だけ。計算した回は保存した回になる）。提案を当てる・ドラッグ・「担当を変える ▾」・振り直し・月や週の AI で組むはこれを使う。`settleDay` は今の並びのまま開始を書き直す
- 訪問ごとの検査 `visitIssues`：担当なし・担当が休み（`off`）・条件に合わない（`notAllowed`）・時間に間に合わない（`late`。`off` のときは重ねない）。日の要対応はこの数（`DayStatus.care`）
- 確定：`tellDay` が今の担当・開始を `snapshots` に書く。`toldChanges`（伝えた内容と今の差＝連絡の一覧）・`toldStateOf`（`'none' | 'told' | 'changed'`）・`contactsBetween`（開始が四捨五入で1分以上変わったら時刻の変更）
- `DayStatus = { date, count, state, unassigned, issues, care, changes, absence, overSpan, needsCare }`。月の要対応（`attentionList`）は `care`・`changed`・`overSpan` の3種

### 画面の決まり
- 日の予定：「AI で組む ▾」（AI で組む・プリセットを当ててみる・プリセットの提案を比べる・ピンをすべて外す）で提案を出し、提案の帯（変わる件数・点・当てる・やめる）。当てるとトーストと操作の行の「元に戻す」（1手。書く前の `visits`・`reassigns` を画面だけに控える）。開いた日に自動で作らない。主ボタンは「確定（伝えた）」（未連絡の変更があれば「確定し直す（伝えた）」）。連絡の一覧の帯
- 提案を比べる（`#/compare`）：欠勤前（`reassigns[date].baseRoutes`）・今の担当・その場で作った提案（考え方を選んで作る）。保存しない
- 月の予定：欄「N月の担当を AI で組む」（対象：要対応のある日だけ／伝えていない日をすべて組み直す（確認））。`monthBatch` は `BatchJob` に `expand` を持たず、`BatchDone` に `undo`（組む前の訪問に戻す1手）。マスの状態は none／told／changed の3つと 担当なし N・ほかの要対応・未連絡 N の印
- 週の予定：主ボタンは「この週の担当なしを AI で組む（N日）」→「この週の問題の無い日をまとめて確定（N日）」→ 済み。組んだ日はその画面にいる間はもう一度数えない（止めた日の残りは数える）
- 欠勤・キャンセルの欄：振り直しは `writeRoutes` で訪問に書き、`reassigns` に振り直す前の担当を残す。5段目を「連絡・確定」にし、「連絡したので確定」で伝えた内容を書いて閉じる
- 版1のデータ：`isOutdated` で版1と分かれば移さず、「データの形が変わったので初期データで始めます」（`OUTDATED_MESSAGE`）と知らせて初期データで始める。控えのファイル（JSON）の読み込みも同じ文で断る
- 初期データ（`seed`）：繰り返しの担当は、その〈利用者さん〉を内部の割当でよく担当した人から、繰り返しの曜日すべてに勤務があり、同じ人の回が30分より近く重ならない人を選ぶ（いなければ null）。`createInitialData` は今日から7日分を点数の基準の重みで組んで `writeRoutes` で訪問に書く（確定はしない）
- Excel：版2の形（訪問に担当・開始・ピン、繰り返しに担当）。案・記録・確定した割当のシートは無い

## 理由とトレードオフ
- 得るもの：
  - 状態が「訪問ごと（担当あり／担当なし／要対応）」と「日ごと（まだ伝えていない／確定済み／未連絡の変更あり）」の2軸になり、覚える言葉が約10語（訪問・繰り返し・担当・ピン・提案（AI）・確定（伝えた）・未連絡の変更・要対応・担当なし・プリセット）に減る
  - どの画面も同じ訪問を読む（今の案と確定した割当のどちらを見ているかの食い違いが無くなる）。人の画面のカレンダー・週・月・ホームの数が同じ関数から出る
  - 「確定」が現場の意味（伝えた）になり、あとの変更を連絡の一覧で漏れなく伝えられる
  - 繰り返しの回を保存しないので、先の週・月もすぐ見え、データが小さくなる（「未作成」と展開の待ちが無い）
- 失うもの（できなくなること）：
  - AI の実行の記録（1日20件）と、記録どうしの比較・記録を今の案にする・「AI が出したままに戻す」・「もう1案作って比べる」の保存（提案はその場だけで、読み直すと消える）
  - この日だけ試す重み（日の予定の「条件を調整する」）。重みは1組で、ほかのプリセットは当ててみるだけ
  - 手直しの記憶（「次からもこの人に」・来週分をまとめて変える。ADR-0043）。代わりは繰り返しの担当を直す（これ以降・すべて）
  - 「条件が変わった」の判定と作り直しの帯・条件の変更の控えと戻す（ADR-0049）。条件を変えても今の担当は変わらず、訪問ごとの検査で要対応が出る（重みだけを変えたときは要対応にならない）
  - 前の同じ曜日からコピー（`lib/copyDay`）
  - 「未作成」と「訪問だけ作る」・展開の日数の管理
  - 「欠勤あり（対応済み）」の表示（訪問の無い人の欠勤は要対応にならないので不要）
  - 日の予定を開いたときの自動作成（案の無い日は無く、担当なしの訪問が要対応で見える）
  - 版1のデータの読み込み（移さない。デモなので）
- 手を入れた決まり（推測を含む）：
  - 訪問の日付を動かしても担当は残す（版1は担当を外した）。新しい日で担当が休みなら要対応で分かる
  - メモの変更も「この回だけ変えた」に数える（保存した回として残すため）
  - 伝えた内容の1件には〈利用者さん〉も入れる（取り消した訪問の連絡の文に使う）
  - 繰り返しを消すとき、開始が今日より前なら消さずに昨日で終わらせる（過去の予定を消さない）

## 影響
- 設計書：§4 の store・seed・patterns・reassign の書き先、§5 のデータ一式・版・繰り返しの契約を版2に。画面の詳細（`docs/design/pages-*.md`）の「今の案・確定した割当・記録・未作成・条件が変わった」を書き直す
- e2e：`scripts/e2e-rebuild.cjs`（作り直しの帯）を消し、ほかは版2の言葉とデータ（`visits`・`snapshots`・`reassigns`）で確かめる。速さを見るものを除いて17本
- 4段目（予定の画面を1つの部品に）への申し送り：日・週・月は同じ `visitsOn`・`DayStatus` を読むので、1つの部品の拡大率にしやすい。メニューは6項目（ホーム・予定・欠勤・空き状況・人・設定）を目安にする
- 見直す条件：重みだけを変えたときに「組み直すと点が上がる日」を知らせたい声が多ければ、要対応とは別の「提案のある日」を足す（保存はしない）
