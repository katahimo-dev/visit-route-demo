# ADR-0020：Excel の名簿（〈利用者さん〉・〈スタッフ〉のシート1枚）を、案・記録を消さずに足す・直す

- 日付：2026-10-18
- 状態：採用（利用者が推奨どおりに決定（2026-10-18）。PRD D103〜D107）

## 背景
Excel の書き出し・読み込み（PRD D23。ADR-0006）は全シートの全置き換えだけで、読み込むと AI案・記録・確定した割当も消える。
人を指す列は名前で書き、同じブックの中だけで突き合わせている。

- よく増えるのは〈利用者さん〉で、1人足すたびに全体を読み込み直すと、組んだ案・確定した割当がなくなる
- 名簿だけを別の表（事業所の台帳など）から写したいが、全体のブックには訪問・相性など触りたくないシートも入っている
- 辞めた人・終わった人を消すと、その人を指す訪問・案・記録の扱いが難しくなる（今の画面も休止・段階「終了」で外している）

## 選択肢
1. 案A：〈利用者さん〉・〈スタッフ〉の名簿（シート1枚）の書き出し・読み込みを足す。読み込みは今のデータに当てて足す・直す（ID か名前で突き合わせ）。「総入れ替え」はブックに無い人を消さずに終了・休止にする。全体の読み込みは今のまま
2. 案B：全体の読み込みに「案・記録を残す」の選択を足す（全シートを読み、人・訪問を突き合わせて残せる案だけ残す）
3. 案C：名簿の読み込みも全置き換え（ブックに無い人は消す。その人を指す訪問・案は repair で外す）

## 決定
案A。データの画面の Excel で対象を「全体／〈利用者さん〉の名簿／〈スタッフ〉の名簿」から選ぶ。

- 名簿のブックはその人のシート1枚だけで、全体のブックの同じシートと同じ列・書式（シート名は呼び方）。全体のブックもそのシートだけを名簿として読める
- 読み込み方は「追加・更新」（既定）と「総入れ替え」。総入れ替えでもブックに無い人は消さず、〈利用者さん〉は段階「終了」、〈スタッフ〉は休止にする
- 同じ人：ID が入っていれば ID、空なら名前（全角半角・空白を同一視）。一致しなければ新しい人。ほかの人の参照は今のデータの〈スタッフ〉の名前で探す
- ブックに無い列は今の値のまま（新しい人は既定値）。知らない項目の列・いない人の名前・名前の重なりは、今までと同じ場所付きのエラーで止め、何も変えない
- excel は純粋な変換のまま（新しい DemoData と件数を返す）。画面が件数を見せて確かめてから store の `update` で入れる。最後は `migrate`（repair）で整える

## 理由とトレードオフ
- 得るもの：案・記録・確定した割当・訪問を残したまま人を足す・直せる。人を消さないので、その人を指す訪問・案・記録が壊れない（休止にした人を担当できる人から外すなどは今の repair の扱いのまま）。全体の読み込みの決まり（ADR-0006）は変えない
- 失うもの：ID を消して名前を変えた行は別の人として足される（ID を残せば防げる）。総入れ替えでも人は減らない（消すのは画面から）。名簿で変えた条件・段階で、作ってある案が今の条件と合わなくなることがある（「条件が変わった」の印で知らせるだけで、案は作り直さない）

## 影響
- `src/excel/`：`exportRosterWorkbook`・`importRoster`（`importRoster.ts`）・`rosterSummary`。全体の書き出しの〈利用者さん〉・〈スタッフ〉シートの作り方を名簿と共通にした（列・書式は変えない）
- `src/contracts/data.ts`：`RosterKind`・`RosterMode`・`RosterImportResult` だけを足す。データの形・版は変えない
- 画面：データの画面の Excel に対象の切り替えと、名簿の読み込み方（ラジオ）。主ボタンは増やさない
- 見直す条件：訪問・相性など、ほかのシートも部分的に入れたい要望が出たら、名簿と同じ「当てる」方式を広げるかを考える。名前の突き合わせで取り違えが起きたら、ID を必須にするかを考える
