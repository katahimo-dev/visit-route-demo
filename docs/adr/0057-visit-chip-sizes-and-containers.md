# ADR-0057：訪問の札を3段の大きさと3種類の入れ物にし、週の表のマスに札を積み、月のマスは右のリストへつなぐ

- 日付：2026-10-23
- 状態：採用
- 関連：PRD D342・D343（D83 を置き換え、D42・D56・D330・D333・D339・D340 を書き直し）、ADR-0056（訪問の帯の共通の部品）の続き。一部を置き換えるもの：ADR-0056（週の表のマスの訪問の行・〈利用者さん〉×曜日の表の帯・月のマスを押すと日の予定）。ADR-0051 の決定5（スマホは見る・取り消す・担当替えまで）・ADR-0054（予定の共通の部品・全体の元に戻す）・ADR-0055（スマホの日ごとのリスト・下から出る欄）

## 背景
- ADR-0056 で、訪問の帯の見た目・選ぶ・キー・ドラッグの落とし先の判定は共通の部品になった。ただ、帯そのものの形は画面ごとに違ったまま：
  - 週の〈スタッフ〉×曜日の表は、マスの3段バーの下に訪問を1行ずつ（時刻・〈利用者さん〉の名前の全文）並べていた。訪問が多い日はマスが縦に長くなり、表が1画面に収まらない
  - 週の〈利用者さん〉×曜日の表は3段の帯（時刻の位置に小さな切れ端）で、押せる所が小さく、印は帯の下の担当の名前のあとに別に出していた。帯の置き方（`ClientDayBar`・`clientLanes`）は時間軸とも行とも別の作り
  - 月は、マスを押すと日の予定へ移るので、その日の訪問を見て直すには Enter で一覧を開くか日の予定へ移るしかなかった。複数の訪問を別の日へまとめて移す手段も無い。スマホ（600px 以下）の月の日ごとの一覧では選ぶこともできない（ADR-0056 の残った課題）
- 日・週・月は「拡大率」として同じ部品を並べる（ADR-0054）と決めたが、訪問の帯は「何をどこに・どの大きさで見せるか」の決まりが無く、画面を足すたびに帯の形が1つ増えていた
- 速さの制約：月のマス（42個）はいまの軽い描き方のままにし、訪問を全部の日について描かない

## 選択肢
1. 案A：週の表は今のまま（ADR-0056。〈スタッフ〉×曜日は1行ずつ、〈利用者さん〉×曜日は3段の帯）。月はマスを押すと日の予定
2. 案B：訪問の札を3段の大きさ（大＝日の時間軸の帯・中＝リストの行・小＝表のマスの札）にし、入れ物を時間軸・表・リストの3種類にする。日・週・月は「同じ札をどの入れ物で何日分見せるか」。週の表のマスには小さな札を積み、月のマスは「その日のまとめ」のまま押すと右の欄にその日のリストの行を出す
3. 案C：日・週・月を1本の本体（時間軸の拡大率を props）に作り直す

## 決定
案B。

### 札の3段と入れ物（PRD D342）
- 札の大きさは3段：大＝日の時間軸の帯（日の予定・週の時間軸・人の予定表の回。`data-size="l"`）・中＝リストの行（`VisitRow`。`data-size="m"`）・小＝表のマスの札（`VisitChip`。`data-size="s"`）。印（担当・ピン・未連絡の変更・要対応など）は3段とも同じ判定・同じ意味（`data-marks`）
- 選ぶ・複数選択・キー・ドラッグの判定・全体の元に戻すは3段とも同じ部品（`useVisitItem`・`useVisitKeys`・`useVisitDrag`・`SelectionBar`）
- 入れ物は3種類：時間軸（時刻の位置）・表（マスに積む。`ChipStack`）・リスト（行）。キーの読み方は入れ物で決める（`KeyLayout`）：時間軸とリストは ↑↓ で15分、表は ↑↓ で隣の担当（行の順。時刻はそのまま）
- 週の時間軸は「日を並べた時間軸」の拡大率として残し、表と今どおり切り替える

### 週の表（PRD D342）
- 〈スタッフ〉×曜日・〈利用者さん〉×曜日のマスに小さな札（時刻と頭文字）を時刻の順に積む。〈スタッフ〉×曜日は〈利用者さん〉の頭文字（「9:00 図」）、〈利用者さん〉×曜日は担当の印（`StaffMark`）・担当なしは「なし」・休・取消・当日取消・「代」
- 1マス3件まで出し、残りは「+N」。押すとそのマスの札の一覧（リストの行）をモーダルにしない浮いた欄で出す。Esc と欄の外を押すと閉じ、フォーカスは「+N」へ。キーで動かした札・欄で開いた札は「+N」に隠さない
- 札は押す・Enter で訪問の詳細の欄、Shift／Ctrl＋クリック・Shift／Ctrl＋Enter で選ぶ、キーは ←→ で曜日・↑↓ で隣の担当（担当できない人は飛ばす）・Delete で取り消し
- 別のマスへドラッグすると担当（行）と曜日（列）が変わり時刻はそのまま（〈利用者さん〉×曜日は同じ行の別の日）。判定は時間軸と同じ部品（入る／入らないの影・確定日の確認・繰り返しの範囲は欄）
- 〈スタッフ〉×曜日のマスの3段バーと件数は残す

### 月（PRD D343）
- マスは「その日のまとめ」のまま（要対応 N・休 N の札・3段バー・状態の色）。訪問はその日の分だけ描く
- マス（日ごとの一覧の行も）を押すと、その日の訪問を右の欄の先頭にリストの行で出す。右の欄に出している日をもう一度押すと日の予定。マスの上の Enter はその日のリストの最初の行へフォーカス（キーは ←→ 日・↑↓ 週のまま）
- 右のリストの行を別の日のマスへドラッグすると日付を移す（落とした日を入れた訪問の詳細の欄）。複数選んで選択の帯の「別の日へ」で日付を選んで［移す］（時刻・担当はそのまま・この回だけ・今日より前の日へは移さない・確定した日が変わるなら確認・1手「M/D（曜）へ移しました」）
- スマホ（600px 以下）の月はマス・一覧の行を押すと下から出る欄（その日の行・「選ぶ」と長押しで選ぶ・欄の中の選択の帯は担当を替える・取り消すだけ・「この日の日の予定を開く」）。行を押すと欄を閉じて訪問の詳細の欄（ADR-0051 の決定5のとおり、日時は動かさない）

### 変えないこと
- データを書くのは store の update だけ（キーは `lib/visitKeys` → `lib/visitOps`、選んだ訪問は `lib/multiEdit`、ドラッグは欄の保存）。どの操作も全体の元に戻すの1手（手の名前つき）。画面の文はふつうの言葉で（PRD D307）

## 理由とトレードオフ
- 得るもの：
  - 週の表が1画面に収まり、どのマスでも訪問を押す・選ぶ・キーで動かす・ドラッグで動かすが同じにできる。〈利用者さん〉×曜日の押せる所が大きくなる
  - 札の形は3つだけになり、印・選ぶ・キーは入れ物によらず同じ。新しい画面は「どの入れ物で何日分か」を選ぶだけでよい
  - 月で日の予定へ移らずにその日の訪問を見て直せ、複数の訪問をまとめて別の日へ移せる。スマホの月でも選んで担当替え・取り消しができる
  - 月のマスの描き方は今のままで、速さは変わらない
- 失うもの（できなくなる・変わること）：
  - 〈利用者さん〉×曜日の表の3段の帯（時刻の位置で見る形）は無くなり札になる。時刻の位置は時間軸で見る
  - 月のマスを1回押しても日の予定へは移らない（2回押すか、右の欄の「この日の日の予定を開く」）
  - 週の表の札は〈利用者さん〉の名前の全文を出さない（頭文字。全文は読み上げ・title・「+N」の一覧）
  - 1マス4件目からは「+N」の中（押さないと見えない）
- 手を入れた決まり（推測を含む）：
  - 「+N」は1マス3件を超えたら出す（4件なら3件と「+1」）
  - 「+N」の一覧はモーダルにしない浮いた欄（裏の表を触れる。Esc・外で閉じる）。ドラッグ中は一覧を薄くしてマウスを受けず、閉じない（消すとドラッグが止まる）
  - 一覧の行のキーはリスト＝時間軸と同じ（↑↓ 15分・←→ 1日・Shift+←→ 隣の担当）
  - 月のマスは2回目の押しで日の予定（1回目は右の欄に出す。押したあともフォーカスはマス）
  - 「別の日へ」はこの回だけ（範囲は選ばない。範囲を変えるときは1件ずつ欄で）。同じ日の訪問は移さず理由
  - 〈スタッフ〉×曜日のマスの3段バー・件数は残す（札だけにはしない）
  - 表の ↑↓ の隣の担当の順は、〈スタッフ〉×曜日は表の行の順、〈利用者さん〉×曜日は利用中の〈スタッフ〉の順

## 影響
- 設計書：design.md §4（pages の共通の部品）、design/pages-common.md（札の3段・入れ物・`VisitChip`・`ChipStack`・「別の日へ」）、design/pages-week.md（表の札）、design/pages-month.md（マスと右のリスト・下から出る欄）、design/pages-bars.md（`ClientDayBar` を消す）、design/pages-plan.md・pages-clients.md（大の札の `data-size`）
- コード：`components/clientBar.tsx`（`ClientDayBar`）と `lib/week` の `clientLanes` は消した。`lib/visitKeys` に `KeyLayout`、`lib/multiEdit` に `moveManyToDate`
- テスト：`lib/visitKeys.test.ts`（表のキー・行の向きの理由）・`lib/multiEdit.test.ts`（別の日へ）。e2e は `scripts/e2e-chip-containers.cjs`（新）
- 残っている課題：
  - 日の予定の本体の帯（`routeTimeline`）は大の札として印・`data-size` をそろえただけで、部品は別のまま。人の予定表の回も同じ
  - 週の表の札をタッチでドラッグはしない（スマホは動かさない）
  - 「+N」の一覧の行から別のマスへのドラッグは、一覧を薄くしてマウスを受けないまま開いておく形（一覧の下のマスが見えにくい）
- 見直す条件：
  - 「+N」を押す回数が多い（1マス4件以上がふつう）なら、1マスの件数か表の行の高さを見直す
  - 月のマスを1回で日の予定へ移りたい声が多ければ、2回目で移る決まりを見直す
  - 時刻の位置を表の中で見たい声が多ければ、〈利用者さん〉×曜日に時間軸の拡大率（行ごとの小さな時間軸）を足すことを考える
