# ADR-0016：〈利用者さん〉の郵便番号→住所の補完と、住所→地図のピン（外部の検索サービスを押したときだけ使う）

- 状態：採用（2026-10-17。空き状況・〈スタッフ〉の自宅への拡張は 2026-10-18）
- 関連：PRD D86〜D90・D118〜D121、ADR-0001（外部送信の方針）

## 背景
〈利用者さん〉の位置（緯度・経度）は移動時間の概算と地図の線に使う。当時は住所を文字で入れ、位置は地図をクリックしてピンを置くしかなかった。Excel で〈利用者さん〉をまとめて読み込むと位置が空の人は「未登録」のまま残り、1人ずつ地図で探す手間がかかる。郵便番号から住所を書き起こす手間もある。
PRD §7 は「外部送信は地図タイルの取得のみ」としていた（ADR-0001）。住所から位置を出すには、外部の検索サービスに住所を送るか、住所と位置の対応表をアプリに同梱するしかない。
決めること：方式、何をいつどこへ送るか、郵便番号検索の呼び方（CORS・JSONP）、失敗時の扱い、まとめて置くときの呼び方、郵便番号の持ち方。

## 決定
外部の検索サービスを、利用者がボタンを押したときだけ呼ぶ。

- 送る先：郵便番号検索（zipcloud）と国土地理院の住所検索だけ。キー不要・無料で、ビルドに秘密情報を入れない
- 送るもの：郵便番号（7桁）か住所の文字だけ。名前・メモ・特性などは送らない
- 送るとき：〈利用者さん〉の編集の欄・空き状況の場所・〈スタッフ〉の自宅の「住所を探す」「地図に置く」と、一覧の「まとめて地図に置く」を押したときだけ。ボタンの近くに送る先と中身を常に書く（毎回の確認ダイアログは出さない。押すこと自体が同意）。開いただけ・入力しただけ・Excel 読み込みでは送らない
- 呼ぶ所：`lib/geocode.ts`（`lookupPostalCode`・`searchAddress`・`jsonp`）と `lib/placeAll.ts`。画面から呼び、solver・matching・evaluate・seed・patterns・vacancy・reassign・excel・store からは呼ばない
- 郵便番号は fetch（JSON）を先に試し、つながらない（TypeError＝CORS で読めない・通信できない）ときだけ JSONP で呼び直す。JSONP はコールバック名を呼ぶたびに一意にし、終わったら script とグローバル関数を消す。時間切れ後に遅れて届いた応答は何もしない関数で捨てる
- 時間切れは1回の押下ごとに8秒（fetch と JSONP を合わせた全体の締め切り）。時間切れのときは JSONP へ切り替えない。応答の形が想定と違うとき（`results` が null・空は「見つかりませんでした」、配列でない・緯度経度が数でないなど）は落とさず「応答の形が想定と違います」。失敗の種類（入力の誤り・見つからない・時間切れ・つながらない・形が違う・止めた）はどれも日本語の短い文で出し、データは変えない
- 候補：複数出たときは先頭を入れたうえで、ほかの候補（5件まで）を押して選び直せる
- 住所を入れるとき：見つけた住所（都道府県〜町名）で欄を置き換える。いまの住所が見つけた住所で始まるなら番地を消さずそのまま。違う住所のときは「元に戻す」を出す
- ピン：見つけた位置に置く。ずれていれば「位置を消す」→地図をクリックで直す。すでに位置がある人は「住所から置き直す」。ピンがある状態で郵便番号から住所を差し替えたときはピンを残し、「位置は前のままです。『住所から置き直す』を押してください」と知らせる
- まとめて置く：対象は位置が無く段階が「終了」でない〈利用者さん〉のうち、住所か郵便番号のある人（住所が空で郵便番号があれば先に住所を探して書く）。1人ずつ順に、呼ぶたびに400msあける。「止める」で次の呼び出しから止め、置けた人は1人ごとに `update(fn)` で書く（まだ位置が無く住所・郵便番号が探したときのままの人だけ。その間に利用者が直した人は上書きしない）。住所だけ見つかった人は「住所だけ入れました」。終わったら置けた人数・置けなかった人（名前・理由・編集ボタン）・住所も郵便番号もない人を出す。画面を離れたら止める
- 郵便番号の持ち方：〈利用者さん〉の `place.postalCode`（空か7桁。ハイフン・全角・「〒」・空白は保存時に直す `normalizePostalCode`）。Excel の〈利用者さん〉シートに任意の列「郵便番号」（先頭の0が落ちた数値は0で埋める。7桁にできない値は場所付きで止める）。〈スタッフ〉の自宅・空き状況の場所（`placeSchema`）には足さない
- 空き状況の場所・〈スタッフ〉の自宅にも同じ部品を使う（2026-10-18。PRD D118〜D121）：入力（郵便番号・住所・ボタン・注記・状態・候補・ピン）を `AddressField`（`components/placeLookup.tsx`）にまとめ、決まり（押せない理由・住所の当て方・「元に戻す」・知らせ・候補）は純粋関数 `lib/addressLookup.ts` に置く（外部は呼ばない）。空き状況では郵便番号を画面の状態だけに持ち、「仮の〈利用者さん〉として押さえる」で〈利用者さん〉を作るときだけ7桁にできれば `place.postalCode` に写す。自宅では部品の中だけに持ち保存しない（見出しに「保存しません」）。契約・`DemoData`・版は変えない。空き状況の計算に渡すのは位置があるときの住所・位置（`Place`）だけで、郵便番号を打っただけでは計算し直さない
- 探している途中に欄を書き換えた（ピンを動かした）ら呼び出しを止め、応答のあとも送った値と今の値が違えば捨てる。連打しても1回だけ呼ぶ
- データの版は1のまま。CSP などの設定はリポジトリに無いので足さない（置くときは両ドメインを `connect-src`・`script-src` に足す）。外部の検索は e2e では偽の応答に差し替える。細部は design.md

## 検討した案
| 案 | 長所 | 短所 | 採否 |
|---|---|---|---|
| 方式A：外部の検索サービスを押したときだけ呼ぶ | 軽い。ボタン1つで地図に並ぶ。送る先と中身が明示できる | 外部送信が増え、サービスの都合に左右される | 採用 |
| 方式B：郵便番号・住所と位置の対応表を同梱 | 外へ送らない | 約12万件で数十MBになり読み込みが重い。毎月の郵便番号の更新も追う必要 | 不採用 |
| 呼び方A：fetch を先に試し、つながらなければ JSONP | 通常は安全な経路、CORS で読めないときだけ JSONP | 実装が2経路 | 採用 |
| 呼び方B：JSONP だけ | 単純 | 常に相手のスクリプトを動かす | 不採用 |
| 呼び方C：fetch だけ | 最も安全 | CORS で読めないと使えない | 不採用 |
| まとめて A：1人ずつ順に400msあける | 相手に優しい。止められ、置けた人は残る | 100人で1〜2分 | 採用 |
| まとめて B：並べて一度に呼ぶ | 速い | 相手の負荷・制限に当たりうる | 不採用 |
| 自宅・空き状況に郵便番号を保存する | 開き直しても残る | 契約・Excel の列・版の移行まで広がる | 不採用（探す手がかりだけなので一時の入力で足りる） |

## 結果・トレードオフ・見直す条件
- 得るもの：Excel で読み込んだ〈利用者さん〉をボタン1つで地図に並べられ、郵便番号から住所の前半が入るので書き起こしの手間と誤記が減る。画面ごとに入力を作らないので文言・押せない理由・住所の当て方がずれず、〈利用者さん〉で確かめた動きを使い回せる。応答の形を確かめ、どの失敗でもデータは変えない
- 失うもの：
  - 「外部送信は地図タイルの取得のみ」ではなくなる（PRD §7・design.md §2 を書き換えた）。実在の住所を入れるとその住所が外部へ送られる（注記で知らせる。架空データの前提は変えない）
  - 外部サービスの停止・仕様変更・混雑で使えないことがある（地図のクリックで置ける）。JSONP は相手のスクリプトをこのページで動かす（CORS で読めないときだけ。送る先を固定し、使い終わったら消す）
  - 住所検索は文字の一致なので、番地の無い・表記の揺れた住所は町の代表の位置になることがある（地図で直す）
  - 〈スタッフ〉の自宅の郵便番号は開き直すと空に戻る
- 見直す条件：外部サービスが止まる・仕様が変わったら `lib/geocode` だけを差し替える。実データで使う声が出たら、送る前の確認ダイアログか同梱案を考え直す。自宅の郵便番号を保存したい声が出たら、自宅を `clientPlaceSchema` と同じ形にする（契約・Excel の列・版を見直す）
- 影響：PRD §7 の外部送信を「地図タイルの取得と、利用者がボタンを押したときの郵便番号・住所の検索」に書き換え
