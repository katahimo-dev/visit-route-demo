# ADR-0019：左のメニューを人ごとにまとめ、比較はメニューから外す

- 日付：2026-10-18
- 状態：採用（利用者が決定（2026-10-18）。細部は推奨どおり）

## 背景
D59 のメニューは「登録（〈利用者さん〉・〈スタッフ〉・稼働時間）／決まり（条件・項目・種類・相性）／その他（比較・データ）」だった。
利用者から「相性は決まりより登録の方が自然。稼働時間も〈スタッフ〉に付く」と指摘を受けた。

- 相性は〈利用者さん〉×〈スタッフ〉の組み合わせのデータで、社内の決まりではない
- 稼働時間・稼働の見込みは〈スタッフ〉ごとのもの。稼働の見込みが「予定」の中にあって浮いていた
- 比較はその日の案どうしを比べる画面で、単独で開いても「どの日の、どの案か」が決まらない
- 「項目」「種類」「条件」は名前だけでは何のことか分かりにくい

## 選択肢
1. 案A：グループを人ごと（〈利用者さん〉／〈スタッフ〉）と「割当の設定」に分け、比較はメニューから外して日の画面からだけ開く
2. 案B：案A と同じで、比較を「予定」の「日」の下に置く
3. 案C：案A と同じで、比較を「割当の設定」の「条件の重み」の隣に置く

## 決定
案A。メニューは「予定（月・週・日）／問い合わせ（空き状況）／〈利用者さん〉（一覧・編集・相性）／〈スタッフ〉（一覧・編集・稼働時間・稼働の見込み）／割当の設定（条件の重み・訪問の種類・特性の項目）／データ」（PRD D102）。
グループの見出しは呼び方（`org.terms`）から引く。相性の表は行が〈利用者さん〉なので〈利用者さん〉の下に置く。
比較を開いているあいだは「日」を選んだ状態で見せ、見出しに「M/D（曜）の予定に戻る」を出す。画面の見出しもメニューの名前にそろえる。

## 理由とトレードオフ
- 得るもの：「誰の何を直すか」でたどれる。比較は使う流れ（日の画面の「案を比べる」・欠勤の振り直し）と入口が一致する
- 失うもの：メニューから直接比較を開けない（`#/compare` の URL は残るので、ブックマークからは開ける）

## 影響
- `src/app/App.tsx` のメニュー、画面の見出し（条件の重み・訪問の種類・特性の項目）と画面どうしの案内の文。ルートの URL・データ・版は変えない
- 見直す条件：比較を日をまたいで使いたい要望が出たら、メニューに戻すかを考える
