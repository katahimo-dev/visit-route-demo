# ADR-0015：退職・担当替えの一括振り直し、稼働の見込み（拘束・交通費）、〈利用者さん〉の段階、当日キャンセルの印

- 状態：採用（2026-10-17）
- 関連：PRD D71〜D74・D170、ADR-0011・0013・0014、ADR-0025（当日キャンセルの入口）

## 背景
訪問介護・移動支援の事業所（正社員8名・利用者約20名・直行直帰）のヒアリングで、ADR-0013・0014 のあとに残った困りごと。
1. 10月末に退職者が出る。その人がいつもの担当・定期パターンの担当になっている利用者の組み直しに時間がかかる（当時は〈スタッフ〉を休止にするか、1人ずつ〈利用者さん〉とパターンを直すしかなかった）
2. 拘束10時間の日もあるが実働は8時間以内（休憩は移動に含める運用）で、拘束・実働の記録が無い。交通費は距離×10円/km を自作の表計算で出している
3. 案件は紹介元の相談員を通して「相談受付→返答待ち→顔合わせ/契約→利用中」を別のツールで管理している。〈利用者さん〉は「利用中／休止」と「仮押さえ」しか持たない
4. 当日キャンセルもふつうにあるが、取り消しの種類を残していない

決めること：最終勤務日の持ち方、振り直しの候補と適用の範囲、稼働の見込みの数え方、拘束の上限の扱い、段階と active・tentative の関係、当日キャンセルの持ち方。

## 決定
最終勤務日は〈スタッフ〉に持ち稼働時間の1か所で効かせる。振り直しは候補を出して選ばせ、案は作り直さない。拘束の上限は注意だけ。段階を正にして active を合わせる。当日キャンセルは訪問に種類を持つ。

- 最終勤務日：`staffSchema.lastDay`（null＝なし）。`availabilityOf` は最終勤務日の後なら（上書きがあっても）空。compile は理由 `AFTER_LAST_DAY = '最終勤務日の後'`（ruleId 'slot'）で外す。稼働時間を読む所は `availabilityOf` を通るので一か所で効く。案は勝手に作り直さない：後のその人の列の訪問は必須の違反になり、月間は「休みの人に N」、記録のある案は `problemKey` が変わり「条件が変わった」。担当できる人（ADR-0014）は利用中の人を数えるまま（後の人も数える）なので、その人だけに限った利用者さんは入らなくなる（黙って「限らない」にせず振り直しを促す）。稼働時間の画面では後の日に理由（勤務なし）を出し、上書きを保存しない
- 月間の印：最終勤務日のマスに「最終 名前」、後の日は「休 N」に数えない（もういない人）
- 振り直し（`lib/offboard`）：
  - 範囲：数え始める日 `from`（最終勤務日の翌日。今日より前なら今日）以降にその人が担当する訪問と、その人をいつもの担当・続くパターンの担当・担当できる人にしている利用者さん（終了の人は除く。ほかに勤める人が残る人は範囲に数えない）
  - 候補：`from` から28日（未展開の回も `applyPatterns` で入れる。データは書き換えない）の訪問ごとに、担当できる人の決まりを外した問題で、その日の案（`baseOf` で確定した割当を開始順に並べて作る。その人の列は除く）に `fitsOf` で入れられる人を数え、入れる回の多い順 → 受け持ちの少ない順 → 名前。既定は入れる回が1回以上ある先頭の人
  - 適用（`applyOffboard`）：`from` から受け持ちを移す。続くパターンは `splitPattern` で `from` から分け（前はその人、後ろは代わりの人）、`from` 以降に始まるパターンはその場で書き換え、前に終わるものはそのまま。〈利用者さん〉のいつもの担当は代わりの人に。これで `from` より前の日の「いつもの担当」は変わらず、その人が勤める日の案は「条件が変わった」にならない。担当できる人は代わりの人を足してその人は残す（「だれにもしない」ならその人を外す）。案は作り直さない
  - 分けたパターンの `from` からの回は作り直さず ID とパターンを付け替える（`renamed`。確定した割当・今の案・記録の古い ID も置き換える。作り直すと、ほかの人に確定していた日の割当・手作業の担当が repair で消えたため）。付け替えは元の日（`pattern.date`）で決める：元の日が `from` 以降の回は `from` より前へずらした回も付け替える（元のパターンは前日で終わり、残すと新パターンが元の日に回を作って二重になるため）。元の日が `from` より前で以降へずらした回は元のパターンに残す。付け替えで ID が重なるときは2つ目以降は元のまま
  - 確認の文に、付け替える回の数と、「だれにもしない」で担当を限らなくなる利用者さん（`unlimitedBy`）を出す
- 稼働の見込み（`lib/workload`・`#/workload`）：拘束＝最後の終わり−最初の開始（訪問＋訪問のあいだの移動＋待ち）。直行直帰なので自宅との行き帰りは拘束に入れず、距離（直線距離の概算）と交通費（距離×単価を日ごとに四捨五入）には入れる。数える案は確定した割当（あれば。開始（早）順）、無ければ今の案（日の画面だけは手直し中の案に注意するため今の案を先に）。月間の日のマスの「拘束超」は他の印と同じ今の案を先にする。拘束は分に丸めてから上限と比べる。画面は月の合計・〈スタッフ〉×日・選んだ人の日ごと。「表をコピー」と Excel の「稼働の見込み」シート（読み込みでは見ない）。どこにも「予定からの見込みで、実績ではない」と書く
- 拘束の上限：`orgSchema.spanLimitHours`（0〜24・0.5刻み・既定10。0＝注意しない）。超える日は月間に「拘束超 N」・要対応に名前、日の画面に帯、稼働の見込みの表に「!」。手当てが必要（赤）には数えない。単価と上限は稼働の見込みの画面で直す（Excel の「事業所」シートにも行。無い古いブックは10）
- 段階（`lib/clientStage`）：`clientSchema.stage`（相談受付・顔合わせ・契約・利用中・終了）。無い古いデータは `stageOfLegacy`（active=false→終了、tentative→相談受付、ほか→利用中）。`stageFlags` が active・tentative を決め、`repair` と画面が合わせる（利用中＝対象、終了＝対象でない、利用中の前は仮押さえのときだけ対象）。予定・AI案の対象を読む所は従来どおり active だけを見る。「本登録にする」は段階を利用中にする。Excel で「段階」を書いたときは段階を優先し、「利用中」「仮押さえ」が食い違っても段階に合わせる。〈利用者さん〉の画面に段階の絞り込み（件数つき）と「段階と紹介元」
- 紹介元：`clientSchema.referrer: { name, contact, note }`（既定は空。呼び方は中立の「紹介元」）。「返答待ち」は段階にせず紹介元のメモに書く
- 当日キャンセル：`visitSchema.cancelKind: 'sameDay' | null`。日の画面の取り消しを確認ダイアログから欄（ふつう／当日キャンセル）に変えた。`repair` は取り消していない訪問の `cancelKind` を null にする。月間に「当日キャンセル N件」、〈利用者さん〉の右の欄に「うち当日キャンセル」。Excel の「訪問」に「当日キャンセル」（○）。入口は一覧の各行の「取り消す」に加え、「欠勤・キャンセル」の欄の「〈利用者さん〉がキャンセル」（既定を当日キャンセルにして影響を見せる。PRD D170）。取り消し方・数え方は変えず、空いた時間へ入れ直す計算は足さない
- データの版は1のまま。Excel の新しい列・行はどれも任意。画面の細部は design.md

## 検討した案
| 案 | 長所 | 短所 | 採否 |
|---|---|---|---|
| 最終勤務日A：`lastDay` ＋ `availabilityOf` が翌日から空 | 稼働を読む所すべてに一か所で効く | 案は作り直すまで必須の違反が残る | 採用 |
| 1-B：その日に休止にする予約 | 簡単 | 休止は予定全体の対象外になる | 不採用 |
| 1-C：後の日ごとに稼働の上書き（空） | 追加なし | 日数分のデータ・期間の延長に弱い | 不採用 |
| 振り直しA：候補を出し選んで適用（案は作り直さない） | 既存の `fitsOf` と同じ判定で説明できる。知らないうちに先の予定が変わらない | 利用者ごとに別々に数える。入れ替えで入る人は数えない | 採用 |
| 2-B：適用と同時に先の案を作り直す | 手間がない | 意図しない変更 | 不採用 |
| 2-C：いつもの担当をその場で書き換える | 単純 | 最終勤務日より前の日の担当も変わる | 不採用 |
| 拘束3-A：最初の開始〜最後の終わり（直行直帰） | 現場の運用に合う | 自宅との行き帰りは入らない | 採用 |
| 3-B：自宅を出てから帰るまで | 長めに出る | 直行直帰の運用と合わない | 不採用 |
| 上限4-A：設定値で注意だけ | solver・採点・プリセット・記録のキーに触れない | AI案が上限を超えることがある。実働の上限は見ない | 採用 |
| 4-B：条件の型「拘束」で AI案に効かせる | 超えない案を作れる | 型に値を持たせる波及が大きい | 声が出たら |
| 段階5-A：`stage` を足し active・tentative を合わせる | 読む所を変えず古いデータも読める | 二重に持つ | 採用 |
| 5-B：stage だけにする | 一本化 | 読む所すべてを変える | 不採用 |
| キャンセル6-A：`cancelKind` | 回数を数えられる | — | 採用 |
| 6-B：メモの文で見分ける | 追加なし | 数えられない | 不採用 |

## 結果・トレードオフ・見直す条件
- 得るもの：最終勤務日の後は1か所で勤務なしになり、画面ごとに辞めた人を数え分けなくてよい。退職者のぶんを利用者さんごとに1つの表で選んでまとめて置き換えられる。拘束・移動・待ち・交通費が予定から自動で出る。古いデータもそのまま読める
- 失うもの：
  - 最終勤務日の後の列は作り直すまで必須の違反として残る。確定した割当の日は「条件が変わった」にならず「休みの人に N」で出る
  - 分けたパターンの回は ID が変わるので、その日の記録のキーも変わり「条件が変わった」になる。単発の訪問は利用者さんのいつもの担当に従うので、`from` より前でも「条件が変わった」になることがある。`from` より前へずらした回は、その1回だけ前の日でも代わりの人になる
  - 担当できる人に代わりの人を足すと `from` より前の日にも担当できるようになり、案は「条件が変わった」になる
  - 同じ人を何人もの代わりに選ぶと入りきらないことがある。見本の期間は28日で、それより先は見ない
  - 拘束の上限は注意だけで、実働の上限は見ない。移動の時間・距離は直線距離の概算
  - 段階ごとの期日・やることは持たない。当日キャンセルは回数のみ（請求・集金・連絡はしない）
- 見直す条件：拘束の長い案が続いて困る声（4-B）。実働の上限を見たい声（設定を足す）。退職者の後の日をまとめて作り直したい声（振り直しの欄から月まとめ作成を呼ぶ）。返答待ちを段階として数えたい声（段階を足す。版は1のまま）
- 影響：PRD §4 に「実績・打刻・サイン・請求様式・LINE 連携・集金はやらない」ほか
