# ADR-0015：退職・担当替えの一括振り直し、稼働の見込み（拘束・交通費）、〈利用者さん〉の段階、当日キャンセルの印

- 日付：2026-10-17
- 状態：採用（方向は依頼者が決定（ヒアリングを受けた第3弾。2026-10-17）。細部は推奨どおりに決め、この ADR に記録する）

## 背景
訪問介護・移動支援の事業所（2026-09-24 ヒアリング。正社員8名・利用者約20名・直行直帰）で、第1弾・第2弾（ADR-0013・ADR-0014）のあとに次の困りごとが残った（PRD D71〜D74 の背景）。

1. 10月末に**退職者**が出る。その人がいつもの担当・定期パターンの担当になっている利用者の組み直しに時間がかかる。いまは〈スタッフ〉を休止にするか、1人ずつ〈利用者さん〉と定期パターンを直すしかない
2. 拘束10時間の日もあるが実働は8時間以内、休憩は訪問のあいだの移動に含める運用で、**拘束・実働の記録が無い**（労務の心配）。交通費は距離×10円/km を自作の表計算で出している
3. 案件は紹介元の相談員を通して「相談受付→返答待ち→顔合わせ/契約→利用中」を別のツールで管理している。いまの〈利用者さん〉は「利用中／休止」と「仮押さえ」しか持たない
4. **当日キャンセル**もふつうにあるが、取り消しの種類を残していない

いまの形：〈スタッフ〉の稼働時間帯は `availabilityOf`（基本の曜日・時間と日ごとの上書き）が1か所で決める。〈利用者さん〉は `active`（予定・AI案の対象）と `tentative`（問い合わせの試算からの仮押さえ。予定に入る）を持つ。訪問は `cancelled` だけを持つ。事業所は `fareYenPerKm` を持つが画面では使っていない。月間は日ごとの計算を CompileInput のキーで覚える。

決めること：(1) 最終勤務日の持ち方と効かせ方、(2) 振り直しの候補と適用の範囲、(3) 稼働の見込みの数え方（拘束に自宅からの移動を含めるか・どの案を数えるか）、(4) 拘束の上限を条件に乗せるか注意だけか、(5) 段階と active・tentative の関係・古いデータの読み替え、(6) 当日キャンセルの持ち方。

## 選択肢
1. 最終勤務日
   - A：**〈スタッフ〉に `lastDay`（null＝なし）。`availabilityOf` が翌日から空を返す**（上書きも見ない）。compile は理由「最終勤務日の後」で外す
   - B：その日に休止（`active: false`）にする予約を持つ
   - C：最終勤務日の後の日ごとに稼働時間の上書き（空）を足す
2. 振り直し
   - A：**〈利用者さん〉ごとに候補（reassign の `fitsOf` で見本の訪問に入れる回を数える）を出し、選んで「まとめて適用」で、最終勤務日の翌日から いつもの担当・パターンの担当を移し（続くパターンは `splitPattern` でその日から分ける）、担当できる人に代わりの人を足す。訪問の案は作り直さない**
   - B：適用と同時に、最終勤務日の後の日の案を作り直す（月まとめ作成を走らせる）
   - C：〈利用者さん〉・パターンのいつもの担当をその場で書き換える（最終勤務日より前の日の担当も変わる）
3. 稼働の見込み
   - A：**拘束＝最初の訪問の開始〜最後の訪問の終わり（直行直帰。自宅との行き帰りは拘束に入れず、距離・交通費には入れる）。数えるのは確定した割当、無ければ今の案（日の画面だけは今の案を先に）**
   - B：拘束に自宅を出てから帰るまでを含める
4. 拘束の上限
   - A：**事業所の設定 `org.spanLimitHours`（既定10時間、0＝出さない）で注意だけ**（月間・日の画面・稼働の見込み）
   - B：条件の型「拘束」を足して重み・必須で AI案に効かせる
5. 段階
   - A：**`stage`（相談受付・顔合わせ・契約・利用中・終了）を足し、段階を正として active・tentative を合わせる**（利用中＝対象、終了＝対象でない、利用中の前＝仮押さえのときだけ対象）
   - B：active・tentative をやめて stage だけにし、読む所をすべて変える
6. 当日キャンセル
   - A：**訪問に `cancelKind: 'sameDay' | null` を足す**（取り消すときに選ぶ）
   - B：訪問のメモの文で見分ける

## 決定
1-A、2-A、3-A、4-A、5-A、6-A（方向は依頼者の方針どおり。細部は推奨どおり）。

- 最終勤務日：`staffSchema.lastDay: dateSchema.nullable().default(null)`。`domain/availability` に `afterLastDay`、`availabilityOf` は最終勤務日の後なら（上書きがあっても）空。compile の理由は `AFTER_LAST_DAY = '最終勤務日の後'`（ruleId 'slot'）。稼働時間帯を読む所（compile・月間・週間・日の画面・希望休・印刷・空き状況）はどれも `availabilityOf` を通るので一か所で効く。案は勝手に作り直さない：最終勤務日の後のその人の列の訪問は必須の違反になり、月間は「休みの人に N」（`absentLeftIds` に「最終勤務日の後」を足した）、記録のある案は `problemKey` が変わるので「条件が変わった」。担当できる人（ADR-0014）は利用中の人を数えるまま（最終勤務日の後の人も数える）で、その人だけに限った〈利用者さん〉は入らなくなる（黙って「限らない」にしない＝振り直しを促す）
- 月間の印：最終勤務日の日のマスに「最終 名前」、後の日は「休 N」に数えない（もういない人）。〈スタッフ〉を選ぶと後の日は「最終勤務日の後」（斜線）、右の欄に最終勤務日
- 振り直し（`lib/offboard`）：`offboardScope(data, staffId, today)` は、数え始める日 `from`（最終勤務日の翌日。今日より前なら今日）以降に確定した割当・今の案でその人が担当する訪問と、その人をいつもの担当・続く定期パターンの担当・担当できる人にしている〈利用者さん〉（終了の人は除く）。候補は、`from` から28日（`applyPatterns` で未展開の回も入れる。データは書き換えない）のその〈利用者さん〉の訪問ごとに、担当できる人の決まりを外した問題（必須の条件・稼働時間・種類の条件は効く）と、その日の案（確定した割当、無ければ今の案。その人の列は除く）に `fitsOf` で入れられる人を数え、入れる回の多い順 → 受け持ち（見本の期間にいつもの担当になっている訪問の数）の少ない順 → 名前。既定の選びは入れる回が1回以上ある先頭の人。`applyOffboard` は `from` から受け持ちを移す：実際のいつもの担当（パターンに無ければ〈利用者さん〉の）がその人のパターンは、`from` より前に始まって続くなら `splitPattern` で `from` から分け（前は その人と書き、後ろは代わりの人。パターンに無かったなら無いまま＝〈利用者さん〉の）、`from` 以降に始まるならその場で、`from` より前に終わるならその人と書く。〈利用者さん〉のいつもの担当は代わりの人に。こうすると `from` より前の日の「いつもの担当」は変わらず、その人が勤める日の案は「条件が変わった」にならない。担当できる人は代わりの人を足し、その人は残す（最終勤務日の前は勤め、後は勤務なしで入らない。ほかに勤める人が残る〈利用者さん〉は範囲に数えない）。「だれにもしない」ならその人を外す
- 画面（〈スタッフ〉）：編集の欄に「最終勤務日」。保存して振り直すものがあれば「担当の振り直し」の欄を開く（主ボタン「まとめて適用」。確認を出す）。欄には日ごとの担当の訪問の件数と日の画面へのボタン。一覧の上に「最終勤務日のある〈スタッフ〉」のカード
- 稼働の見込み（`lib/workload`・`#/workload`）：`workStats` は担当ごとの列を lenient の `scheduleRoute` で並べ、拘束 span＝最後の終わり−最初の開始＝訪問＋移動（訪問のあいだ）＋待ち、自宅との行き帰り home は span に入れず、距離（自宅→訪問…→自宅。直線距離からの概算）と交通費（距離×単価を日ごとに四捨五入）に入れる。数える案は `workRoutesOf`（確定した割当に担当があればそれ。開始（早）の順に並べ直す。無ければ今の案）。日の画面は手直し中の案に注意を出すため今の案を先に数える。画面は月の合計・〈スタッフ〉×日（拘束の時間と横棒）・選んだ人の日ごと（時間軸の横棒）。横棒は `components/workBars` に分け、次の弾で「訪問・移動・待ち」の3段に差し替える。「表をコピー」（タブ区切り）と、Excel の書き出しに「稼働の見込み」シート（読み込みでは見ない）。どこにも「予定からの見込みで、実績ではない」と書く
- 拘束の上限：`orgSchema.spanLimitHours`（0〜24・0.5刻み・既定10。0＝注意しない）。超える日は 月間の日のマスに「拘束超 N」・要対応に名前、日の画面に帯、稼働の見込みの表に斜線と「!」。手当てが必要（赤）には数えない。単価と上限は稼働の見込みの画面で直す（Excel の「事業所」シートにも行を足す。無い古いブックは10）
- 段階（`lib/clientStage`）：`clientSchema.stage: z.enum(CLIENT_STAGES)`。無い古いデータは preprocess の `stageOfLegacy`（active=false→終了、tentative→相談受付（予定には入ったまま）、ほか→利用中）。`stageFlags` が active・tentative を決め、`repair` と画面（`withStage`）が合わせる。予定・AI案の対象を読む所は今までどおり active だけを見る。問い合わせの試算の仮押さえは「相談受付」・仮押さえで入り、「本登録にする」は段階を利用中にする。〈利用者さん〉の画面に段階で絞り込むボタン（件数つき）と、欄に「段階と紹介元」
- 紹介元：`clientSchema.referrer: { name, contact, note }`（既定は空）。呼び方は中立の「紹介元」（役割の名前を直書きしない）
- 当日キャンセル：`visitSchema.cancelKind: z.enum(['sameDay']).nullable().default(null)`。日の画面の取り消しを確認ダイアログ（`confirm`）から欄（ふつう／当日キャンセル）に変えた。`repair` は取り消していない訪問の `cancelKind` を null にする。月間の見出しに「当日キャンセル N件」、〈利用者さん〉を選んだ右の欄に「うち当日キャンセル」。Excel の「訪問」シートに「当日キャンセル」（○）
- データの版は1のまま。新しい項目はどれも zod の既定値（stage は preprocess）で古いデータを読む。Excel の新しい列・行はどれも任意（無い古いブックも読める）

## 理由とトレードオフ
- 得るもの：
  - 最終勤務日までは今までどおり、その後は1か所で勤務なしになるので、画面ごとに「辞めた人」を数え分けなくてよい。候補は既存の可否・挿入（`fitsOf`）をそのまま使うので、AI案・振り直し・空き状況と同じ判定で説明できる
  - 退職者のぶんを〈利用者さん〉ごとに1つの表で選んでまとめて置き換えられる。案は作り直さず「条件が変わった」で知らせるので、利用者の知らないうちに先の予定が変わらない（ADR-0011 と同じ考え方）
  - 拘束・移動・待ち・交通費の見込みが予定から自動で出て、表計算での手計算と拘束の長い日の見落としが減る。注意だけなので solver・採点・プリセット・記録のキーに手を入れずに済む
  - 段階を正にして active を合わせるので、予定・AI案の対象を読む所（matching・patterns・画面）を変えずに、古いデータもそのまま読める
- 失うもの：
  - 最終勤務日の後のその人の列は、作り直すまで必須の違反として残る（月まとめ作成の「条件が変わった日を作り直す」か、日の画面で直す）。確定した割当の日は「条件が変わった」にならない（「休みの人に N」で出る）
  - 続くパターンを `from` で分けるので、`from` からの回（この回だけの変更・取り消しの回も）は新しいパターンの回になり、ID が「元の日_新しいパターンID」に変わる（中身・担当はそのまま。案・確定した割当・記録の ID も同じに置き換える）。ID が変わるので、その日の記録の問題のキーは変わり「条件が変わった」になる（その日はいつもの担当も変わるので、どのみち変わる）。パターンの無い単発の訪問は〈利用者さん〉のいつもの担当に従うので、`from` より前の日でも「条件が変わった」になることがある
  - 担当できる人に代わりの人を足すと、`from` より前の日にも代わりの人が担当できるようになり、その日の案は「条件が変わった」になる（日付で効く「担当できる人」は持たない）
  - 候補は〈利用者さん〉ごとに別々に数える（同じ人を何人もの代わりに選ぶと、実際には入りきらないことがある。受け持ちの少ない順で散らす）
  - 候補の「入れる回」は他の人の予定を変えずに入るかだけを見る（入れ替えれば入る人は数えない）。見本の期間は28日で、それより先の曜日・時刻は見ない
  - 拘束の上限は注意だけで、AI案は上限を超える案を作ることがある（勤務の時間帯の中には収まる）。実働（訪問＋移動）の上限は見ない。移動の時間・距離は直線距離からの概算で、実際の道のりとは違う
  - 段階の「相談員返答待ち」は段階に分けず、紹介元のメモに書く。段階ごとの期日・やることは持たない
  - 当日キャンセルは回数を数えるだけ（請求・集金・連絡はしない）

## 追記（PR #22 のレビューの反映。2026-10-17）
- 候補：その日の案は lib/absences の `baseOf`（確定した割当を開始の順に並べる）で作る。visits の順のままだと strict で回れず「入れる回」が 0 になっていた
- 適用：分けたパターンの `from` からの回は作り直さず、ID とパターンを付け替える（`applyOffboardWith` の `renamed`）。確定した割当・今の案（routes・unassigned・generated・pins・振り直しの元の案）・記録の古い ID も同じに置き換える。作り直していたときは、ほかの人に確定していた日の割当・訪問の手作業の担当が repair で消えていた。付け替えは `from` 以降の この回だけの変更・取り消しの回も対象（元のパターンのまま残ると、その人と書いた前の部分の「いつもの担当」になっていた）。前の部分（元のパターン）にその人と書くのは残す（〈利用者さん〉のいつもの担当を代わりの人にしても、前の日のいつもの担当を変えないため）
- 確認の文：付け替える回の数、「だれにもしない」で担当を限らなくなる〈利用者さん〉（`unlimitedBy`）を出す
- 拘束：分に丸めてから上限と比べる（表の h:mm と判定をそろえる）
- 月間の日のマスの「拘束超」は、ほかの印と同じ数える案（`dayPlanOf`：今の案、無ければ確定した割当）で数える。稼働の見込みの画面・Excel・印刷は確定した割当を先のまま（決定の「月間・稼働の見込み・Excel は確定した割当を先に」をこれで置き換える）
- 稼働時間の画面：最終勤務日の後の日は理由（勤務なし）を出し、上書きを保存しない
- Excel：「段階」を書いたときは段階を優先し、「利用中」「仮押さえ」が食い違っても段階に合わせて読む（読み込みに警告の仕組みは無いので、使い方のシートに書く）

## 追記（PR #22 の再レビュー。2026-10-17）
- ずらした回の付け替え：付け替えるかは元の日（`pattern.date`）で決める。
  - 元の日が `from` 以降で、`from` より前の日へずらした回も付け替える。レビューでは「日が `from` より前の回は元のパターンに残す」案が出たが、元のパターンは `from` の前日で終わるので、残すと新しいパターンがその元の日に回を作り直して二重になる（展開は ID で重なりを見るため）。代わりに、その1回だけは前の日でも「いつもの担当」が代わりの人になる（〈利用者さん〉の都合でずらした回で、まれ）
  - 元の日が `from` より前で、`from` 以降へずらした回は元のパターンに残す（元の日は元のパターンの期間内で二重にならない。その日は退職者が勤務なしなので「いつもの担当」の条件は効かない）
- 付け替えで同じ ID が2つになる（同じパターン・同じ元の日の回が2つある、新しい ID の訪問がすでにある）ときは、2つ目以降は付け替えずに元のまま残す
- 稼働時間の画面の保存は、入力の誤りでも aria-disabled＋理由（title）にそろえた

## 追記（2026-10-18）：当日キャンセルの入口（PRD D170。ADR-0025 の区切り5）
- 当日キャンセルは、一覧の各行の「取り消す」（取り消しの欄。既定はふつう）に加え、日の画面の「欠勤・キャンセル」の欄（ホームのカードからも開く）の「〈利用者さん〉がキャンセル」からも登録できる。欄では取り消しの種類の既定を当日キャンセルにし、影響（担当の予定から外れて時間が空く・回数に出る・請求はしない）を見てから取り消す
- 取り消し方・数え方は変えない（`cancelled: true`・`cancelKind: 'sameDay'`、定期パターンの訪問は「この回だけの変更」、今の案はそのまま計算から外れる、月の回数）。空いた時間へほかの訪問を入れ直す計算は足さない
