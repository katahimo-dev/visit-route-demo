# ADR-0030：担当替え・戻すをドラッグ以外でも（キーボード・タッチ）できるようにする

- 状態：採用（2026-10-19）
- 関連：PRD D217〜D219、ADR-0004（AI案を土台に手直し・固定）、ADR-0026（独自の確認ダイアログ）、PRD「共通の決まり」（キーボードと読み上げで使える）

## 背景
- 日の画面の手直し（訪問の担当を替える・「入らなかった訪問」へ移す）はドラッグだけだった（`onDrop` から `moveTo`・`unassign`）。訪問を押して選ぶと理由だけが出て、担当を替える部品が無かった。キーボード・読み上げ・タッチ（スマホ・タブレット。HTML のドラッグはタッチで動かない）では、入らない訪問を振り直しの「受けられる人」から入れる以外に担当を替えられない。PRD の共通の決まり「キーボードと読み上げで使える」に反する
- 移すと固定が付き、回る順は `bestInsertion` で変わる。間違えて移したときにドラッグで戻しても固定と順は戻らず、戻す手段は「AI が出したままに戻す」（`revert`。手直しと固定をすべて捨てる）だけだった
- 「この割当で確定」の確認は、入らない訪問・必須の違反があっても本文で触れず、担当なしの訪問を残したまま確定しうる
- 制約：契約（`src/contracts/`）・データ（`DemoData`）は変えない。ドラッグの動きは変えない。新しい採点を足さない（候補の判定は「受けられる人」の `candidatesFor` と matching の理由を使う）

## 選択肢
担当を替える部品：
1. 案A：訪問の詳細に `select` 要素（担当の一覧）を置く
2. 案B：訪問の詳細に「担当を変える ▾」（`components/MenuButton` の menu）を置き、候補の人ごとに1行の説明（移動・時間の約束・相性など）と押せない理由を出す
3. 案C：ドラッグのまま、キーボードのドラッグの代わり（訪問にフォーカスして Space でつかみ、←→ で列を選んで Space で落とす）を足す

戻す：
1. 案D：手直しの前の routes・pins を1つだけ控え、1手だけ戻す
2. 案E：手直しの歴史を積み、何手でも戻す・やり直す

## 決定
案B と案D。確定の確認には件数を足す。
- 「担当を変える ▾」（data-testid `plan-reassign`）：時間軸の帯・順番のカード・入らなかった訪問のカードの詳細に。まとまりは「今の担当」（印・押せない）／「ほかの〈スタッフ〉へ移す」（列のある人。押せる人を先に、必須の条件に合わない人は押せず理由）／「そのほか」（「入らなかった訪問へ」。担当のいる訪問だけ）。選ぶとドラッグと同じ `moveTo`・`unassign`（`bestInsertion`・固定・トースト）。振り直しの「受けられる人」がある入らない訪問には出さない（重ねない）。説明の文は `lib/reassignMenu`（純粋関数）
- 1手戻す：`lib/undoEdit`（純粋関数）の `takeSnapshot`・`canUndo`・`undoState`。手直し（移す・入らなかった訪問へ・受けられる人に入れる・固定を外す）の前に routes・pins を控え、今の案が手直しのあとの形のままのときだけ戻す。戻したら控えを消す。トーストに「元に戻す」（`components/Toast` にボタン1つの形を足す）と、操作の行の「元に戻す」
- 確定の確認：本文の先頭に「入らない訪問が N件あります（担当なしのまま確定します）」「必須の違反が N件あります（…）」（`lib/planMenu` の `adoptWarnings`。数は1行のまとめと同じ今の案の採点）。確認ダイアログには注意の色が無く（`danger`＝赤は消す・捨てる操作。D147）、確定は戻せる操作なのでオレンジのまま

## 理由とトレードオフ
- 得るもの：キーボード・読み上げ・タッチで担当を替えられる。候補ごとに理由が見え、ドラッグ（どの列に落とすかを見て決める）より判断しやすい。押せない人も消さずに理由を出すので、なぜその人に移せないかが分かる。部品は「案を変える ▾」と同じ（作法・キーボード・aria-describedby がそろう）。間違えて移しても1手で戻せ、固定と順も戻る
- 失うもの：
  - 必須の条件に合わない人へは、ドラッグなら移せる（移したあとに赤い枠）が、メニューでは押せない。わざと条件を破って移すのはドラッグだけ
  - 説明の「移動 +N分」「時間の約束」は「受けられる人」と同じ判定（ほかの人の開始を変えない入れ方）で、選んだあとの `bestInsertion` の入れ方とは違うことがある（目安）
  - 戻せるのは直前の1手だけ。2手前へは戻らない（何手も戻すなら「AI が出したままに戻す」）。控えは画面の状態だけで、読み直す・ほかの操作（作り直す・別の案・訪問の取消など）で今の案が変わると戻せない
- 案A の `select` は候補ごとの説明・押せない理由を出せず（option は1行の文だけ）、選んだだけで移るか別のボタンが要るかで迷う。案C は「つかむ・落とす」の操作を覚える必要があり、タッチでは使えず、候補の理由も見えない
- 案E は歴史の持ち方（作り直す・別の案・欠勤の振り直しと混ざるとき）と「やり直す」の画面が要り、デモには重い。間違えてすぐ戻したいという場面は1手で足りる

## 影響
- 画面：`pages/PlanPage.tsx`（`ReassignMenu`・`reassignOf`・`moveTo`・`unassign`・`placeCandidate`・`unpin` の控え・`undoEdit`・操作の行の「元に戻す」・`adopt` の本文）、`components/Toast.tsx`（`toast(msg, { action })`。ボタン付きは6秒・フォーカスがある間は消さない・ボタンだけ押せる）、`styles.css`（`.toast.has-action`・`.toast-action`）、`lib/undoEdit.ts`・`lib/reassignMenu.ts`・`lib/planMenu.ts`（`adoptWarnings`）。データ・契約・store・ドラッグは変えない
- 設計書：[design/pages-plan.md](../design/pages-plan.md) の「手直し（ドラッグ・担当を変える）と固定」「1手戻す」「状態の印と確定」
- 確かめ：`src/lib/undoEdit.test.ts`・`src/lib/reassignMenu.test.ts`・`src/lib/planMenu.test.ts`、`scripts/e2e-plan-menu.cjs`（一覧の role と説明・キーボードで移す・固定・トーストの「元に戻す」で戻る・確定の確認の件数・390px）
- 見直す条件：何手も戻したいという声が出たら案E。必須の条件を破ってでもメニューから移したいという声が出たら、押せない人を確認付きで押せるようにする
