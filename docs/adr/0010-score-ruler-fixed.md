# ADR-0010：点数の物差しを「点数の基準のプリセット」で固定し、プリセットのカードで切り替える

- 日付：2026-10-13
- 状態：採用

## 背景
点数（100点満点。ADR-0007 案A：round(100 −（費用 − 下限）÷ 訪問の件数)）は「いまの条件」（`data.rules`）から作った `Problem` と物差し（`normalize`）で付けていた（ADR-0005・ADR-0007・ADR-0008 の 3-A）。
予定の画面でプリセットのボタンを押すと、その日の条件がプリセットの重みに変わるので、**押すたびに同じ案の点数が全部変わった**。利用者の報告（再現済み）：同じ3つの案（標準・移動を短く・人の組み合わせ重視）のカードが

- 「標準」を押すと 70・69・70
- 「移動を短く」を押すと 76・78・76
- 「人の組み合わせ重視」を押すと 67・59・67

「どれが良いか」を比べるための点が、どのボタンを押したかで動くので、比べられなかった。

あわせて利用者から次の要望が出た（2026-10-13）。

- プリセットを押しても、条件が変わっていなければ再計算は不要（同じ案がすでに記録にある）
- 右の欄（重みの欄）のプリセットのボタンは不要。正面の「プリセットごとの案」のカードを押せるようにすればよい

決めること：(1) 点数の物差しをどの条件で作るか、(2) 必須の違反・条件ごとの達成をどちらの条件で数えるか、(3) 計算し直さずに記録を使う条件、(4) プリセットで切り替える操作の場所。

## 選択肢
1. 点数の物差し
   - A：**点数の基準のプリセットで固定する**（データに基準のプリセットの id を持ち、その重み・必須をその日の条件に当てた条件で採点する）
   - B：各案を、その案を作った条件の物差しで採点する
   - C：いまの条件のまま（今まで）
2. 必須の違反・条件ごとの達成
   - A：点数と同じ、点数の基準の物差し
   - B：いまの条件（作り方の条件）
3. 計算し直さない条件
   - A：プリセットの重みが一致する記録があれば使う（カードと同じ探し方）
   - B：条件（名前・ID・重み・必須まで）・乱数の種が同じで、記録の案がいまの問題でそのまま有効、かつ付け直した費用が記録の費用と同じ記録だけ使う
4. 切り替える場所
   - A：右の欄のプリセットのボタン（今まで）
   - B：正面のプリセットごとの案のカード全体をボタンにする

## 決定
1-A（利用者が選んだ。2026-10-13）、2-A、3-B、4-B（4 は利用者の要望。2・3 は推測で決め、ここと設計書に書いた）。

- データ：`DemoData.scorePresetId`（optional。zod）。初期データは「標準」（`standard`）。無い古いデータ・存在しない id は store の `repair` が先頭のプリセットにする（`presets` を足したときと同じく、版は1のまま）。プリセットが0件のありえない場合は条件そのものを物差しにする（`scoreRulesOf`）
- 物差しの条件：`scoreRulesOf(data)`＝`applyPreset(data.rules, 基準のプリセット)`。条件の追加・削除・名前・項目は反映し、重み・必須だけ基準のプリセットにする。プリセットのカード・重みの欄で `data.rules` の重みを変えても点数は変わらない。基準のプリセットの重みを編集すると点数も変わる（当然）
- `useDayModel` に `scoreProblem`・`scoreScale`・`scoreRulerName` を足す。物差しの条件がいまの条件と同じなら `compile` し直さずに同じ `Problem` を使う（重い compile を二重にしない）
- 点数の基準の物差しで出すもの：予定の画面（今の案の合計・内訳・AIが出したままとの差・必須の違反・条件ごとの達成・件数の偏り・プリセットごとの案のカード・王冠・自動作成の終わりに一番点の高い案を今の案にする選び方・計算中の「いまの最良 N点」）、比較の画面（記録の一覧の点・A・B の合計・差・必須の違反・条件ごとの達成/違反）
- いまの条件のままのもの：solver が最小にする費用・探索、訪問ごとの理由（点の内訳）・入らなかった訪問の理由（AI がどう組んだかの説明）、ドラッグしたときの「必須の条件に合わない」の警告（組み直すとどうなるか）
- 計算中の点：Worker の進み具合（`progress`）に、いまの最良の案（`bestRoutes`）を足す。画面は点数の基準の物差しで採点し直して「いまの最良 N点」を出す（解いている条件の費用 `bestScore` は物差しが違うので点にしない）
- 基準を選ぶ：条件の画面のプリセットの節に「点数の基準」のラジオ。基準のプリセットの見出しに「点数の基準」の印。基準のプリセットを消すと、基準は残りの先頭に移る（確認の文に出す）。「初期値に戻す」で「標準」に戻る
- 物差しの名前を小さく出す：プリセットごとの案の見出し・今の案の欄・比較の画面の記録の見出しに「物差し：標準」
- Excel：「プリセット」シートに「点数の基準」の列（○ を1行だけ）。書き出しは基準の行に ○。読み込みは ○ の行を基準にし、列が無い・無印なら先頭、○ が2行以上なら場所付きで止める。シートが無い古いブックは、いまの基準のまま
- プリセットのカードを押す（`runPreset`）：
  - その日の条件をプリセットの重みにする
  - 計算し直さずに使える記録（`lib/runs` の `reusableRun`）があれば、計算せずにその記録を今の案にする（トースト「保存してある〈プリセット名〉の案を今の案にしました（再計算なし）」）。使える記録＝その日の記録のうち、固定なし・途中で止めていない・作ったときの条件がプリセットを当てた条件と同じ（名前・ID・重み・必須まで）・乱数の種が同じ・訪問の集まりが同じ（どの列か未割当に1回ずつ）・担当はいまの問題の人だけ・必須と時間の違反なし・いまの問題で付け直した費用が記録した費用と同じ（誤差 1e-6）、の最新のもの。solver は同じ入力から同じ案を出すので、これらが同じなら作り直しても同じ案になるとみなす
  - 無ければ、その条件で計算して今の案にする（今まで）
  - 今の案（手直しなし）のカードは押しても何もしない（`aria-pressed`・オレンジの枠）。手直し・固定がある今の案を捨てるときは確認する。計算中は押せない
  - 同じ条件で作り直したいときは「AI案を作る」（いつも計算する）
- 右の欄（重みの欄）のプリセットのボタンをやめる。右の欄には「いまの重み：〈プリセット名〉」・「いまの重みをプリセットとして保存」・プリセットの編集へのリンク・重みのスライダーを残す

## 理由とトレードオフ
- 得るもの：
  - どのカードを押しても点数が動かないので、プリセットどうし・記録どうしを同じ物差しで比べられる。点の意味が「事業所が基準に選んだ考え方で見て、理想より1件あたり何分余計か」に固定される
  - プリセットは「どう組むか（solver が最小にする費用）」だけを変える、と言い切れる
  - 必須の違反・達成の件数も点数と同じ物差しなので、「参考」の印（必須の違反がある案の点）と点数が食い違わない。カードの必須の違反・達成もカードを押しても変わらない
  - 一度作ったプリセットの案へは計算なしですぐ戻れる（開いた日の自動作成で全プリセットを作っているので、ふつうは押すとすぐ切り替わる）
  - プリセットを選ぶ場所が、案の点数・中身を見る場所（カード）と同じになる
- 失うもの：
  - いまの条件で作った案でも、その条件では良くても、基準の物差しでは点が低く見えることがある（例：基準が「標準」のとき「人の組み合わせ重視」の案は、相性・希望の加点を標準の重みでしか数えない）。物差しの名前を小さく出して、基準は条件の画面で選べることを説明に書く
  - 基準と違う必須（例：あるプリセットだけ相性を必須）で作った案は、基準の物差しでは必須の違反にならない／基準だけが必須にしている条件は違反として数える。初期の3種は必要条件の必須がどれも同じなので、ふだんは食い違わない
  - 訪問ごとの理由（いまの条件）と点数（基準）の物差しが違うことがある。理由は「AI がどう組んだか」の説明として割り切る
  - 物差しの条件がいまの条件と違うときは、`compile` を2回する（データを変えるたび）
  - 計算し直さない判定は「同じになるはず」の推定（費用が偶然同じでデータが違う、はほぼ起きないが、ありうる）。気になるときは「AI案を作る」で作り直せる
  - Worker の進み具合のメッセージが少し大きくなる（100ms ごとに案を1つ送る）
- ADR-0005（比較の採点はいまの条件）・ADR-0007（物差しはいまの条件）・ADR-0008（3-A：カードはいまの条件の物差し、カードの「この案にする」、右の欄のプリセットのボタン）の該当部分を置き換える

## 影響
- 要件：PRD の D11・D18・D20・D21・D25 の点数・物差し・プリセットの操作の記述
- 設計：契約 `DemoData.scorePresetId`・`WorkerResponse` の `progress.bestRoutes`。seed に `scorePresetOf`・`scoreRulesOf`。store の `repair`。lib/presets の `removePreset`（基準を消すと先頭へ）・`setScorePreset`・`resetPresets`。lib/runs の `reusableRun`。`useDayModel` の `scoreProblem`・`scoreScale`・`scoreRulerName`。Excel の「プリセット」シートの「点数の基準」の列。pages：予定の画面のカード（全体がボタン）・右の欄、比較の画面、条件の画面の「点数の基準」
- 見直す条件：基準と違う必須のプリセットを使う事業所から、違反の数え方がわかりにくいと言われたとき。案ごとに「作った条件での点」も見たいと言われたとき（カードに小さく併記する）
