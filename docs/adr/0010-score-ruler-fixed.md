# ADR-0010：点数の物差しを「点数の基準のプリセット」で固定し、プリセットのカードで切り替える

- 状態：採用（2026-10-13）
- 関連：PRD D11・D18・D20・D21・D25、ADR-0005・0007・0008（該当部分を置き換える）

## 背景
点数（ADR-0007）は「いまの条件」（`data.rules`）から作った `Problem` と物差し（`normalize`）で付けていた。予定の画面でプリセットのボタンを押すとその日の条件がプリセットの重みに変わるため、押すたびに同じ案の点が全部変わった（同じ3案のカードが、「標準」を押すと 70・69・70、「移動を短く」を押すと 76・78・76、「人の組み合わせ重視」を押すと 67・59・67）。「どれが良いか」を比べる点が、押したボタンで動くので比べられない。
利用者の要望：条件が変わっていなければ再計算しない（同じ案が記録にある）。右の欄のプリセットのボタンは不要で、正面の「プリセットごとの案」のカードを押せればよい。
決めること：(1) 物差しをどの条件で作るか、(2) 必須の違反・条件ごとの達成をどちらで数えるか、(3) 計算し直さずに記録を使う条件、(4) 切り替える場所。

## 決定
1-A（物差しは点数の基準のプリセットで固定）、2-A（必須の違反・達成も同じ物差し）、3-B（入力の中身が同じ記録だけ再利用）、4-B（カード全体をボタンにする）。4 は利用者の要望、2・3 は推測で決めた。

- データ：`DemoData.scorePresetId`（optional）。初期は「標準」。無い・存在しない id は store の `repair` が先頭のプリセットにする（版は1のまま）。プリセット0件なら条件そのものが物差し
- 物差しの条件＝`applyPreset(data.rules, 基準のプリセット)`。条件の追加・削除・名前・項目は反映し、重み・必須だけ基準のプリセットにする。カードや重みの欄で `data.rules` の重みを変えても点は変わらない。基準のプリセットの重みを編集すれば点も変わる
- 基準の物差しで出すもの：予定の画面の点・内訳・AIが出したままとの差・必須の違反・条件ごとの達成・プリセットごとの案のカード・王冠・自動作成で一番点の高い案を今の案にする選び方・計算中の「いまの最良 N点」、比較の画面の点・差・違反・達成
- いまの条件のままのもの：solver が最小にする費用と探索、訪問ごとの理由・入らなかった訪問の理由（AI がどう組んだかの説明）、ドラッグ時の「必須の条件に合わない」警告
- 計算中の点：Worker の進み具合に、いまの最良の案（`bestRoutes`、optional）を足し、画面が基準の物差しで採点し直す。`bestScore` が前回と同じなら送らない（メッセージを小さくする）
- 基準は条件の画面の「点数の基準」ラジオで選ぶ。基準のプリセットを消すと残りの先頭に移り、「初期値に戻す」で「標準」に戻る。物差しの名前（「物差し：標準」）をカード・今の案・比較の記録の見出しに小さく出す
- Excel の「プリセット」シートに「点数の基準」列（○ は1行だけ）。列が無い・無印なら先頭、○ が2行以上なら場所付きで止める。シートが無い古いブックはいまの基準のまま
- カードを押す（`runPreset`）：その日の条件をプリセットの重みにし、再利用できる記録があれば計算せずその記録を今の案にする（トーストで再計算なしと知らせる）。無ければ計算する。今の案（手直しなし）のカードは何もしない。手直し・固定のある案を捨てるときは確認。計算中は押せない。同じ条件で作り直したいときは「AI案を作る」（いつも計算する）
- 再利用の条件（レビューで補強）：記録（`AiRun`）に optional の `inputKey` を持つ。計算に使った `Problem` の中身（日付・スタッフと稼働時間帯・訪問・移動と距離・可否・割当費用・待ちの点・均等など費用と可否に効くもの全部）を決定的に JSON にして FNV-1a で短くしたキー（`problemKey`。依存を増やさない）。再利用するのは、固定なし・途中で止めていない・条件と乱数の種が同じで、`inputKey` がいまの問題のキーと一致する記録のみ。`inputKey` が無い古い記録は使わず計算する。solver は同じ入力から同じ案を出すので、同じなら作り直しても同じとみなす
- 補強の理由：最初は「訪問の集まりが同じ・担当がいまの問題の人だけ・付け直した費用が同じ」で判定していたが、スタッフを足した・休みを外した・相性や稼働時間を変えたあとも古い記録を使ってしまった（使っていない担当や相性が変わっても費用は同じになる）。
- カードに出す記録は、再利用できる記録を優先し、無ければ重みが一致する最新の記録に「データが変わったので、押すと作り直します」と小さく添える
- 右の欄はプリセットのボタンをやめ、「いまの重み：〈プリセット名〉」・保存・プリセット編集へのリンク・重みのスライダーを残す
- 画面・契約・関数の細部は design.md

## 検討した案
| 案 | 長所 | 短所 | 採否 |
|---|---|---|---|
| 1-A：基準のプリセットで固定 | プリセットどうし・記録どうしを同じ物差しで比べられる | 基準と違う条件で作った案は点が低く見えうる | 採用 |
| 1-B：各案を作った条件で採点 | 作った考え方に忠実 | 案どうしの点が比べられない | 不採用 |
| 1-C：いまの条件のまま（従来） | 変更なし | 押すたびに点が動く | 不採用 |
| 2-B：必須・達成はいまの条件 | 作り方と一致 | 「参考」の印と点がずれる | 不採用 |
| 3-A：プリセットの重みが一致する記録を使う | 簡単 | データが変わっても古い案を使う | 不採用 |
| 3-B：入力の中身（キー）が同じ記録だけ | 取り違えない | キー作りの手間 | 採用 |
| 4-A：右の欄のボタン（従来） | 変更なし | 点・中身を見る場所と別 | 不採用 |
| 4-B：カード全体をボタン | 見る場所と選ぶ場所が同じ | 誤タップの余地 | 採用 |

## 結果・トレードオフ・見直す条件
- 得るもの：どのカードを押しても点が動かない。点の意味が「事業所が基準に選んだ考え方で、理想より1件あたり何分余計か」に固定される。プリセットは「どう組むか」だけを変える、と言い切れる。必須の違反・達成も点と同じ物差しなので「参考」の印と食い違わない。一度作ったプリセットの案へ計算なしで戻れる
- 失うもの：
  - 基準が「標準」のとき「人の組み合わせ重視」の案は、相性・希望の加点を標準の重みでしか数えず点が低く見える（物差しの名前を出し、基準を選べることを説明に書く）
  - 基準と違う必須で作った案は基準では違反にならない（初期の3種は必須が同じなので、ふだんは食い違わない）
  - 訪問ごとの理由（いまの条件）と点（基準）の物差しが違うことがある。理由は説明として割り切る
  - データを変えるたびに compile が2回（物差しの条件がいまと同じなら使い回す）。キーは「同じ中身なら同じ」だけの保証（32bit×2なので取り違えはまず起きない）。進み具合のメッセージが少し大きくなる
- 見直す条件：基準と違う必須のプリセットを使う事業所から違反の数え方が分かりにくいと言われたとき。案ごとに「作った条件での点」も見たいと言われたとき（カードに小さく併記）
