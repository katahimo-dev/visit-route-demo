# ADR-0022：相性の画面に詳細の吹き出しと列・行の絞り込みを足し、予定などの名前からも詳細を開く

- 状態：採用（2026-10-18。予定の名前への拡張は 2026-10-18、ほかの名前への拡張は 2026-10-19）
- 関連：PRD D113〜D117・D122〜D126・D205〜D209、ADR-0021（`ClientFilter`）

## 背景
相性の画面（行＝〈利用者さん〉、列＝〈スタッフ〉。セルで ◎○△× を入れる）は、列の見出しの名前が切れてだれの列か分からず、相性を入れるとき〈スタッフ〉の特性・稼働や〈利用者さん〉の条件・担当を確かめるには別の画面を探すしかなかった。人数が増えると表が大きく、「女性で看護師の列」「まだ相性を入れていない行」だけを見たい。浮かせて出す部品は `MenuButton` だけで、詳細の吹き出しの部品が無かった。
予定（月・週・日）でも同様に、名前から条件・特性・稼働を確かめられず、その名前の多くはすでに操作（ドラッグできる帯・カード、選ぶチップ、列へ移る行）になっている。週の時間軸・日の画面は描画が重い。日の画面の「入らなかった訪問」・欠勤の「受けられる人」・拘束超過の帯・休みの帯・担当の振り直しの欄でも名前が文字だけで、拘束超過の帯の「稼働の見込み」は1人目にしか行かず、名簿の読み込み後の最終勤務日の知らせは名前の無いトーストだけだった。

## 決定
詳細は吹き出し（`DetailPopover`）で出し、列は `StaffFilter`、行は共通の `ClientFilter` で絞る。中身は共通部品にし、開いている状態は画面全体で1つの小さな入れ物に持つ。

相性の画面
- 見出し・行の名前をボタンにし、押すと吹き出しで詳細を出す。名前は名字と名を空白で分けた2行で全部出し、列幅は保つ。吹き出しは `role="dialog"`、ボタンは `aria-expanded`・`aria-controls`。Esc・外を押す・もう一度押すで閉じ、フォーカスをボタンに戻す。body の直下に浮かせる
- 「〈スタッフ〉／〈利用者さん〉の画面で開く」は `?id=` を足して編集の欄を開く（開いたら URL から消す）
- 列の絞り込み `StaffFilter`（名前・特性のチップ。`?sf=`）：選択肢のある項目の選択肢ごとと、あり／なしの項目の「あり」「なし」。数値の項目は出さない。AND で、人数は「押したら何人になるか」、0人は押せない。行の絞り込みは `ClientFilter` に画面ごとのチップを引数（`extraChips`・`facts.extraTests`）で足す（「相性がまだ入っていない組がある人」「× がある人」。`?cf=` の `x:`。ほかの画面の `?cf=` は不変）
- 休止中の人を出さない今の決まりは変えない。相性のチップの判定は絞り込みを変えたときの相性の写しで行い、セルを押しても行は消さず、写しが古くなったら「表を並べ直す」を出す。絞り込みの欄は `<details>` で畳み要約に今の状態を出す。表の見出しの行と1列目は止める

予定などの名前（PRD D122〜D126・D205〜D209）
- 中身を `components/personDetail`（`StaffDetail`・`ClientDetail`）に切り出して相性と共通にし、開いている状態は React の外の小さな入れ物（`lib/personPopover` の `createPersonPopoverStore`）に持つ。名前のボタン（`PersonButton`・`PersonInfo`）は `useSyncExternalStore` で自分が開いているかだけを購読し、吹き出しは `PersonPopoverProvider`（App）の中の1つの部品が出す。相性の画面は自分の state のまま（絞り込みで見出しが消えたら閉じる決まりと e2e の data-testid を保つ）
- 名前が操作でない所（月の右の欄・週の表の行・日の訪問の詳細と一覧・週のチップの名前）は名前をボタンにし、押すと別の動きがある所（〈スタッフ〉のチップ・日の列の見出し・担当ごとの1日の行）は横に小さな「i」を置く。ボタンの入れ子にしない。帯・カードの中には置かず、押して出る詳細の欄に名前のボタンを置く
- 同じ人の名前が何か所あっても押したボタン（`useId`）で区別し、閉じたらそのボタンへフォーカスを戻す。ボタンが消えたら閉じる。ボタンのまま渡される人が変わる・開いている人がデータから消えたら閉じる。印刷では i を出さず名前の下線を消す
- 日の画面の「入らなかった訪問」は札の行の先頭に〈利用者さん〉の i（カードの外）。受けられる人の候補の名前・欠勤の人に残る訪問の名前・休みの帯の名前・担当の振り直しの行の見出しは `PersonButton`（select の中には置かない）。名前のボタンは箱を overflow で切らず中の span で「…」にし、フォーカスの枠を切らない
- 拘束が上限を超える帯は名前ごとの `PersonButton`。2人以上なら帯のボタンをやめ人ごとの小さなリンク「稼働の見込み」（`workloadHref`）、1人なら今のボタン
- 最終勤務日の知らせは、読み込む前後の名簿を比べて ID と名前を引き（`lib/personLinks` の `lastDayChanged`。excel の `lastDaySet` と同じ決まり）、データの画面の Excel の欄に閉じられる帯で出す（保存しない）。名前は閲覧の欄を開く普通のリンク。閉じたあとのフォーカスは Excel の欄の見出し（枠を見せる）。Excel の種類の切り替え・データの置き換えでも消す
- 契約・store・excel・matching・データの版は変えない。確かめ方は `scripts/e2e-details2.cjs`。細部は design.md

## 検討した案
| 案 | 長所 | 短所 | 採否 |
|---|---|---|---|
| 相性A：名前のボタン＋吹き出し（`DetailPopover`）＋`StaffFilter`／共通 `ClientFilter` | キーボード・タッチ・読み上げで開ける。表を離れず確かめられ、行の絞り方・URL が他画面と同じ | 絞り込みの欄が2つ並ぶ（畳んで要約）。部品が増える | 採用 |
| 相性B：hover のツールチップ＋相性だけの絞り込み | 実装が軽い | キーボード・タッチで開けない。絞り込みの作りが他画面とずれる | 不採用 |
| 相性C：縦書きの名前＋他画面へのリンクだけ | 簡単 | 表を離れないと確かめられない | 不採用 |
| 名前A：中身を共通部品にし、状態を React 外の入れ物で持つ | 開け閉めで描き直すのは押したボタン・前のボタン・吹き出しだけ。同時に1つが守られる | 相性だけ別の state（持ち方が2つ）。入れ物のテストは純粋関数で行う | 採用 |
| 名前B：画面ごとの `useState` | 単純 | 開け閉めで画面全体が描き直る（時間軸・日の画面が重い） | 不採用 |
| 名前C：Context に状態を入れる | 共有できる | Context の下が全部描き直る | 不採用 |
| 知らせA：データの画面に閉じられる帯＋名前のリンク | 名前からすぐ閲覧の欄へ。部品の決まりをそのまま使える | データの画面だけの見た目 | 採用 |
| 知らせB：トーストにリンクを入れる | 置き場所が同じ | トーストは2.5秒で消え押せない。全画面の知らせの読み上げ・置き場所（D197）を変える | 不採用 |
| 知らせC：知らせの名前も `PersonButton`（吹き出し経由） | 統一 | 閲覧の欄まで1手増える | 不採用 |

## 結果・トレードオフ・見直す条件
- 得るもの：表・予定の画面を離れずに確かめられる。判定は純粋関数でテストできる。契約・store・データの版を変えない
- 失うもの：
  - 相性のチップで絞っているとき、セルを押しても表が今の相性とずれる（「表を並べ直す」まで）
  - 〈スタッフ〉によみが無いので列の検索は名前のみ。数値の項目（経験年数など）では列を絞れない
  - 日の列の見出しの i は名前の横でなく2行目の右端になる（名前の幅を食わないため）。日の画面の拘束超過の帯は文が長くなる
  - 吹き出しの部品が `MenuButton` と別に増え、相性の画面だけ別の state（2つの持ち方）
- 見直す条件：数値の項目で絞りたい要望（「3年以上」などの段階を項目ごとに決める）。吹き出しをほかでも使うなら `MenuButton` と位置の決め方をまとめる。相性の画面も同じ入れ物に移すときは、絞り込みで見出しが消えたら閉じる決まりをボタンの後始末（`closeIf`）で代える
