# ADR-0022：相性の画面に詳細の吹き出しと列・行の絞り込みを足す

- 日付：2026-10-18
- 状態：採用（利用者が推奨どおりに決定（2026-10-18）。PRD D113〜D117）

## 背景
相性の画面（`pages/CompatPage`）は 行＝〈利用者さん〉、列＝〈スタッフ〉の表で、セルを押して ◎○△× を入れる。

- 列の見出しの名前は 5em で切れ、だれの列か分からないことがある
- 相性を入れるときに〈スタッフ〉の特性・稼働や〈利用者さん〉の条件・担当を確かめたいが、別の画面を開いて探すしかない
- 人数が増えると表が大きい。「女性で看護師の人」の列や「まだ相性を入れていない人」の行だけを見たい
- 〈利用者さん〉の絞り込みは、週間の表と〈利用者さん〉の画面で共通の欄 `ClientFilter`（ADR-0021）にそろえたばかり
- 浮かせて出す部品は `MenuButton`（メニュー）だけで、詳細を出す吹き出しの部品は無い

## 選択肢
1. 案A：見出し・行の名前をボタンにし、押すと吹き出し（新しい部品 `DetailPopover`）で詳細を出す。列は新しい `StaffFilter`（名前・特性のチップ。`?sf=`）、行は共通の `ClientFilter` をそのまま使い、画面ごとのチップを引数（`extraChips`・`facts.extraTests`）で足す（`?cf=` の `x:`）
2. 案B：見出しにマウスを重ねるとツールチップ（`title` や hover の吹き出し）で詳細を出す。絞り込みは相性の画面だけの欄を作る
3. 案C：見出しを縦書きにして名前を出し、詳細は〈スタッフ〉・〈利用者さん〉の画面へのリンクだけにする

## 決定
案A。

- 名前は名字と名を空白で分けた2行（空白が無ければ4文字ごと）で全部出し、列の幅は今と同じくらいに保つ
- 吹き出しは `role="dialog"` で名前を付け、見出しのボタンは `aria-expanded`・`aria-controls`。Esc・外を押す・もう一度押すで閉じ、閉じたらフォーカスをボタンに戻す。body の直下に浮かせ、画面の端で切れない位置に出す
- 「〈スタッフ〉の画面で開く」「〈利用者さん〉の画面で開く」は、その画面に `?id=` を足して編集の欄を開く（今までその人を選んで開く手段が無かった。開いたら URL から消す）
- 〈スタッフ〉の特性のチップは選択肢のある項目（choice・multi）の選択肢ごとと、あり／なしの項目の「あり」「なし」。数値の項目は段階を作らず出さない。AND で、人数は「押したら何人になるか」、0人は薄く押せない
- 行の相性のチップは「まだ相性が入っていない組がある人」（見えている列との組）と「× がある人」。`ClientFilterState.extra`・`FilterFacts.extraTests` は相性の画面だけが使い、ほかの画面の `?cf=` は今までと同じ文字のまま
- 休止中の人を出さない今の決まりは変えない（そのため「終了の人も出す」は出さない）

## 理由とトレードオフ
- 得るもの：キーボード・タッチでも詳細を開け、読み上げでも分かる。表を離れずに確かめられる。行の絞り方・言葉・URL の作り（変換中は書かない・`replace`）が週間・〈利用者さん〉の画面と同じになり、判定は純粋関数でテストできる。契約（`src/contracts/`）・store・データの版は変えない
- 失うもの：絞り込みの欄が表の上に2つ並び、表が下へ下がる。吹き出しの部品を新しく持つ（`MenuButton` とは別。位置の決め方は似ている）。`ClientFilter` に画面ごとの引数が増える。〈スタッフ〉によみが無いので列の検索は名前だけ。数値の項目（経験年数など）では列を絞れない

## 影響
- 設計書 §4 pages（相性・〈スタッフ〉・〈利用者さん〉の画面）と lib（`lib/compatView.ts`・`lib/clientFilter.ts` の追加）、components（`DetailPopover`・`StaffFilter`・`ClientFilter` の追加）。契約・store・excel・matching は変えない
- 見直す条件：数値の項目で絞りたい要望が出たら段階（「3年以上」など）を項目ごとに決める。吹き出しをほかの画面でも使うなら、`MenuButton` と位置の決め方をまとめる
