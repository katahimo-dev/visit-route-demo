# ADR-0022：相性の画面に詳細の吹き出しと列・行の絞り込みを足す

- 日付：2026-10-18
- 状態：採用（利用者が推奨どおりに決定（2026-10-18）。PRD D113〜D117）

## 背景
相性の画面（`pages/CompatPage`）は 行＝〈利用者さん〉、列＝〈スタッフ〉の表で、セルを押して ◎○△× を入れる。

- 列の見出しの名前は 5em で切れ、だれの列か分からないことがある
- 相性を入れるときに〈スタッフ〉の特性・稼働や〈利用者さん〉の条件・担当を確かめたいが、別の画面を開いて探すしかない
- 人数が増えると表が大きい。「女性で看護師の人」の列や「まだ相性を入れていない人」の行だけを見たい
- 〈利用者さん〉の絞り込みは、週間の表と〈利用者さん〉の画面で共通の欄 `ClientFilter`（ADR-0021）にそろえたばかり
- 浮かせて出す部品は `MenuButton`（メニュー）だけで、詳細を出す吹き出しの部品は無い

## 選択肢
1. 案A：見出し・行の名前をボタンにし、押すと吹き出し（新しい部品 `DetailPopover`）で詳細を出す。列は新しい `StaffFilter`（名前・特性のチップ。`?sf=`）、行は共通の `ClientFilter` をそのまま使い、画面ごとのチップを引数（`extraChips`・`facts.extraTests`）で足す（`?cf=` の `x:`）
2. 案B：見出しにマウスを重ねるとツールチップ（`title` や hover の吹き出し）で詳細を出す。絞り込みは相性の画面だけの欄を作る
3. 案C：見出しを縦書きにして名前を出し、詳細は〈スタッフ〉・〈利用者さん〉の画面へのリンクだけにする

## 決定
案A。

- 名前は名字と名を空白で分けた2行（空白が無ければ4文字ごと）で全部出し、列の幅は今と同じくらいに保つ
- 吹き出しは `role="dialog"` で名前を付け、見出しのボタンは `aria-expanded`・`aria-controls`。Esc・外を押す・もう一度押すで閉じ、閉じたらフォーカスをボタンに戻す。body の直下に浮かせ、画面の端で切れない位置に出す
- 「〈スタッフ〉の画面で開く」「〈利用者さん〉の画面で開く」は、その画面に `?id=` を足して編集の欄を開く（今までその人を選んで開く手段が無かった。開いたら URL から消す）
- 〈スタッフ〉の特性のチップは選択肢のある項目（choice・multi）の選択肢ごとと、あり／なしの項目の「あり」「なし」。数値の項目は段階を作らず出さない。AND で、人数は「押したら何人になるか」、0人は薄く押せない
- 行の相性のチップは「まだ相性が入っていない組がある人」（見えている列との組）と「× がある人」。`ClientFilterState.extra`・`FilterFacts.extraTests` は相性の画面だけが使い、ほかの画面の `?cf=` は今までと同じ文字のまま
- 休止中の人を出さない今の決まりは変えない（そのため「終了の人も出す」は出さない）
- （PR #31 のレビューで追加）相性のチップの判定は、絞り込みを変えたときの相性の写しで行う。セルを押しても行は消さず、写しが古くなったら「表を並べ直す」（小さいボタン）を出す。絞り込みの欄は `<details>` で畳み、要約に今の状態を出す（URL に絞り込みがあるときだけ開く。広い画面では横に並べる）。表の見出しの行と1列目は止める

## 理由とトレードオフ
- 得るもの：キーボード・タッチでも詳細を開け、読み上げでも分かる。表を離れずに確かめられる。行の絞り方・言葉・URL の作り（変換中は書かない・`replace`）が週間・〈利用者さん〉の画面と同じになり、判定は純粋関数でテストできる。契約（`src/contracts/`）・store・データの版は変えない
- 失うもの：絞り込みの欄が表の上に2つ並ぶ（畳んで要約だけにし、1280×900 で最初に表の行が10行以上見える）。相性のチップで絞っているときは、セルを押しても表が今の相性とずれる（「表を並べ直す」を押すまで）。吹き出しの部品を新しく持つ（`MenuButton` とは別。位置の決め方は似ている）。`ClientFilter` に画面ごとの引数が増える。〈スタッフ〉によみが無いので列の検索は名前だけ。数値の項目（経験年数など）では列を絞れない

## 影響
- 設計書 §4 pages（相性・〈スタッフ〉・〈利用者さん〉の画面）と lib（`lib/compatView.ts`・`lib/clientFilter.ts` の追加）、components（`DetailPopover`・`StaffFilter`・`ClientFilter` の追加）。契約・store・excel・matching は変えない
- 見直す条件：数値の項目で絞りたい要望が出たら段階（「3年以上」など）を項目ごとに決める。吹き出しをほかの画面でも使うなら、`MenuButton` と位置の決め方をまとめる

## 追記（2026-10-18）：予定（月・週・日）の名前からも詳細の吹き出しを開く（PRD D122〜D126）

### 背景
予定（月・週・日）で〈利用者さん〉・〈スタッフ〉の条件・特性・稼働を確かめるには、相性の画面や各画面を開いて探すしかない。相性の画面の吹き出し（`DetailPopover`）と中身はできているが、中身は `CompatPage` の中にあり、開いている状態も相性の画面の state だった。予定の画面は名前が出る所が多く、その多くはすでに操作（ドラッグできる帯・カード、選ぶチップ、地図の絞り込みの見出し、列へ移る行）になっている。週の時間軸・日の画面は描画が重い。

### 選択肢
1. 案A：中身を `components/personDetail`（`StaffDetail`・`ClientDetail`）に切り出して相性の画面と共通にし、開いている状態は画面全体で1つの小さな入れ物（`lib/personPopover` の `createPersonPopoverStore`。React の外）に持つ。名前のボタン（`PersonButton`・`PersonInfo`）は `useSyncExternalStore` で自分が開いているかだけを購読し、吹き出しは `PersonPopoverProvider`（App）の中の1つの部品が出す
2. 案B：画面ごとに state（`useState`）を持ち、相性の画面と同じく画面が吹き出しを出す
3. 案C：Context の値に開いている状態を入れる（`useDetailPopover` フック）

### 決定
案A。

- 名前の文字が今は操作でない所（月の右の欄・週の表の行・日の訪問の詳細と一覧・週の〈利用者さん〉のチップの名前）は名前をボタンにする。押すと別の動きがある所（〈スタッフ〉のチップ・日の列の見出し・担当ごとの1日の行）は横に小さな「i」（lucide の `Info`）を置く。ボタンの入れ子にしない。帯・カードの中には置かず、押したときに出る詳細の欄に名前のボタンを置く（ドラッグ・選択の動きを変えない）
- 同じ人の名前が画面に何か所あっても、押したボタン（`useId` の id）で区別し、閉じたらそのボタンへフォーカスを戻す。ボタンが消えたら（後始末で `closeIf`）閉じる。ボタンが残ったまま渡される人が変わったら閉じる（PR #33 のレビュー）。開いている人がデータから消えたら閉じる
- 相性の画面は今のまま自分の state で吹き出しを出す（絞り込みで見出しが消えたら閉じる決まりと e2e の data-testid を変えない）。中身だけ共通の部品にする
- 印刷では i を出さず、名前のボタンは下線を消す（`@media print`）

### 理由とトレードオフ
- 得るもの：開け閉めで描き直すのは押したボタン・前に開いていたボタン・吹き出しだけで、週の時間軸・日の画面の表は描き直さない（案B・案C は画面か Context の下が全部描き直る）。吹き出しは画面全体で1つになり「同時に1つ」が決まりとして守られる。契約・store・データの版は変えない
- 失うもの：React の外に小さな入れ物を持つ（テストは純粋関数で行う）。相性の画面だけは別の state のまま（2つの持ち方がある）。日の列の見出しの i は名前の横でなく2行目の右端になる（名前の幅を食わないため。PR #33 のレビュー）

### 影響
- components（`PersonPopover`・`personDetail` の追加。`PickChips` に `detailKind`、`ClientPicker` に `details`、`ClientName` に `detail`、`DayLines` に `detail`）、lib（`personPopover` の追加）、app（`App` を `PersonPopoverProvider` で包む）、pages（月間・週間・日の画面・相性）。契約・store・excel・matching は変えない
- 見直す条件：相性の画面も同じ入れ物に移す（2つの持ち方をやめる）ときは、絞り込みで見出しが消えたら閉じる決まりをボタンの後始末（`closeIf`）で代える
