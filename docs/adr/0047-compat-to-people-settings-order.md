# ADR-0047：相性を設定から「人」へ移し、設定のトップを訪問の種類にする（ADR-0045 の設定のタブの見直し）

- 日付：2026-10-21
- 状態：採用
- 関連：PRD D283（D178・D232・D275 の並びを書き換え）、ADR-0036（ボタンの3段）・ADR-0045（メニュー8項目・設定のタブ）

## 背景
- ADR-0045 で「設定」を1項目にし、タブを［条件の重み｜相性｜訪問の種類｜特性の項目｜管理者設定｜データ］とした。使ってみると2点の違和感が出た。
- 設定を開くと先頭が「条件の重み」で、めったに触らないのに最初に出て圧迫感がある。
- 相性は〈利用者さん〉と〈スタッフ〉の関係で、ふだんもよく更新する。設定の中にあると見つけにくい。
- 制約：URL・契約・データの版は変えない。機能の入り切り（`compat`）はそのまま効かせる。

## 選択肢
1. 案A：設定のタブを［訪問の種類｜特性の項目｜条件の重み｜管理者設定｜データ］にし、相性はメニューの「人」へ（9項目）。〈利用者さん〉一覧・〈スタッフ〉一覧の見出しの近くに文字ボタン「相性の表」を置く
2. 案B：タブの並びだけ変え、相性は設定に残す
3. 案C：相性を一覧の中の画面（タブや欄）にする

## 決定
案A。メニューの「人」は〈利用者さん〉一覧・〈スタッフ〉一覧・相性・勤務時間（シフト）の順。「設定」の既定は先頭の訪問の種類（土台で切れないので、機能の入り切りに左右されない）。相性の画面から設定のタブは外す。上の帯の名前・パレットの画面も「人・相性」。`compat` を切れば、メニュー・パレット・一覧の「相性の表」を出さない。ボタンは ADR-0036 の「ついで」（文字）で、主ボタンは変えない。

## 理由とトレードオフ
- 得るもの：設定を開いた最初の画面が軽くなる。相性が関係のある2つの一覧のそばに来て、見つけやすい。
- 失うもの：メニューが1項目増える（8→9）。設定のタブから相性が消えるので、ADR-0045 を見て覚えた人は「人」を探す。

## 影響
- `src/lib/nav.ts`（`SETTINGS_TABS`・`menuSections`・`screenSections`）、`CompatPage`（設定のタブを外す）、`ClientsPage`・`StaffPage`（「相性の表」）。
- PRD D178・D232・D275・D283、`docs/design/pages.md`・`pages-compat.md`・`design.md`、AGENTS.md の e2e の説明、e2e（nav・features・tour・mobile）の期待値。
- 作り直しの帯（`REBUILD_PATHS`）は相性の画面に今まで通り出る。「設定」が覚える最後のタブには相性は入らない。
- 見直す条件：メニューの9項目が多いと感じられたとき、または相性の更新がさらに増えたとき。
