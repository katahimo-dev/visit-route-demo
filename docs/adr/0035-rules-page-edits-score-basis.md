# ADR-0035：条件の重みの画面を「点数の基準（ふだんの考え方）を直す画面」にし、日の重みを「この日だけ試す重み」と呼び分ける

- 日付：2026-10-19
- 状態：採用
- 関連：PRD D24・D41・D52・D161・D163・D166・D233〜D235、ADR-0008・ADR-0010（一部を変更・補足する）

## 背景
月のまとめて作る・開いた日の自動作成・作り直しは「点数の基準」のプリセットの重みで作る（PRD D41・D52・D163。ADR-0010）。
一方、条件の重みの画面の表は「いまの条件」（`data.rules`）を直していた。いまの条件を使うのは日の予定の「AI にもう一度作らせる」だけ（D166）。
そのため、条件の重みの画面で重みを変えて月を作り直しても案は何も変わらない。画面の名前・置き場所から「ここで直せば AI の作り方が変わる」と読めるので、利用者が誤解する。
決めること：条件の重みの画面で直す重みを何にするか。日の予定の重み（`data.rules`）の呼び方。

## 選択肢
1. 案A：条件の重みの画面を「点数の基準（ふだんの考え方）を直す画面」にする。表の重み・必須は基準のプリセットの型のもので、変えると基準のプリセットを直す。いまの条件（`data.rules`）も基準にそろえる
2. 案B：画面はいまの条件のまま。「ここの重みは日の『AI にもう一度作らせる』だけで使います」の固定の文と［この重みを『標準』に保存］のボタンを置く
3. 案C：今のまま（D166 の帯の案内だけ）

## 決定
案A を採る（親の作業指示。2026-10-19）。

- データの形は変えない（版は1のまま。新しいフィールドは足さない）。「ふだんの考え方」＝点数の基準のプリセット（`scorePresetId`）
- 条件の重みの画面の表：名前・種類・並びは `data.rules`、重み・必須は `scoreRulesOf(data)`（基準のプリセットを当てたもの）を出す。重み・必須を変えると `setBasisWeight(d, 型, 変更)` で基準のプリセットのその型を直す。プリセットは型ごとの重みなので、同じ型の条件はどれも同じ重みになる。条件を足すときの重み・必須は基準のその型
- `data.rules` は「この日だけ試す重み」と呼ぶ。日の予定の右の欄（条件を調整する）のスライダーとプリセットのカードで変わり、「AI にもう一度作らせる」・「固定した訪問は残して、ほかを作り直す」・比較の画面の「試す重みで作る」だけが使う
- 基準が変わったら試す重みを基準にそろえる（`withBasisRules`）：基準のプリセットの重み・必須を変える（条件の重みの表・プリセットの節のどちらでも）、基準を替える、基準のプリセットを消して基準が移る、初期値に戻す。名前・一言だけの変更、基準でないプリセットの編集・削除ではそろえない。これで日の「AI にもう一度作らせる」の既定も基準と同じになる
- 月のまとめて作る・開いた日の自動作成・初期データの案・作り直し（月・日）はどれも `scoreRulesOf(data)` で作る（呼び方を1つにそろえた。中身は前と同じ）
- 文言：右の欄の見出し「この日だけ試す重み」・「試す重み：〈名前〉」・「試す重みをプリセットとして保存」、条件の重みの画面の `lead`「ふだんの考え方（点数の基準）の重み。…」と直している基準の名前、プリセットの節の保存は「基準の重みを写して保存」（基準の重みを写す）、帯の案内（D166）とパレットは「今日の案を試す重みで作り直す」。ツアー・用語「点数の基準」の説明も合わせる

## 理由とトレードオフ
- 得るもの：
  - 条件の重みの画面で直した重みが、月のまとめて作る・自動作成・作り直し・点数のすべてに効く。画面の名前どおりに動く
  - データの形も、点数の物差し（ADR-0010）も変えずに済む。「条件が変わった」（D161）の判定もそのまま使え、基準を直すと古い案が「条件が変わった」になり作り直しの帯が出る
  - 日の重みは「この日だけ試す」と名前で分かり、ふだんの考え方と混ざらない
- 失うもの：
  - 基準を直すと、日の予定で試していた重みは消える（基準に戻る）。試した重みで作った案は「条件が変わった」になる。残したいときは先に「試す重みをプリセットとして保存」する
  - 条件の重みの画面では、同じ型の条件を別々の重みにできない（基準のプリセットは型ごとの重み。作り直しは前から型ごとに同じ重みだった）
  - 基準を直すと点数も変わる（ADR-0010 の「基準のプリセットの重みを変えると点数も変わる」のまま）
  - 試す重みはデータに1つだけ（日ごとには持たない）。「この日だけ」は「その日の作り直しにだけ使う」の意味で、別の日の予定を開いても同じ試す重みが出る
- 案B は誤解を文で説明するだけで、直した重みが月に効かない問題は残る。案C は問題がそのまま

## 影響
- 要件：PRD に D233（条件の重みの画面＝点数の基準の重みを直す画面）・D234（この日だけ試す重みの呼び分けと、基準が変わったらそろえる）・D235（プリセットの節の保存・印・説明）。D24・D166・D182 を直す
- 設計：`lib/presets` に `withBasisRules`・`setBasisWeight`、`patchPreset`・`setScorePreset`・`removePreset`・`resetPresets` が基準の変更で試す重みをそろえる、`addPresetFromRules(d, name, note, from)`。`RulesPage` の表、`planParts` の `WeightPanel`・`SavePresetForm({ from })`、`lib/rebuildBand` の `customRulesText`・`rebuildWith`、`lib/planMenu`・`lib/commandPalette`・`lib/tour`・`lib/glossary` の文。`MonthPage`・`seed/plans`・日の `remakeStale` は `scoreRulesOf`
- ADR-0008：「計算中は重み・プリセット・いまの重みを保存を押せない」「いまの重みを保存」の「いまの重み」は、この ADR から「この日だけ試す重み」。プリセットの節の保存は基準の重みを写す
- ADR-0010：「カードや重みの欄で `data.rules` の重みを変えても点は変わらない」はそのまま（重みの欄＝この日だけ試す重み）。条件の重みの画面の表は、この ADR から基準のプリセットの重みを直す（点数も変わる）。「点数の基準を切り替えただけでは変わらない」（D161）は、基準を替えると試す重みもそろうので、試す重みで作った案は「条件が変わった」になりうる（プリセットで作った案は今までどおり変わらない）
- 見直す条件：日ごとに別の試す重みを持ちたい声が出たとき（`AiPlan` か日ごとのデータに持たせる）。同じ型の条件に別の重みを付けたい声が出たとき（プリセットを条件ごとの重みにする）
