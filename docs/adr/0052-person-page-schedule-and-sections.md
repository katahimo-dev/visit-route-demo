# ADR-0052：〈利用者さん〉・〈スタッフ〉の画面を全画面にし、予定のカレンダーと節ごとの「直す → 保存」にする（ADR-0023 の見直し）

- 日付：2026-10-22
- 状態：採用
- 関連：PRD D308〜D313（D127〜D131・D297 を置き換え）、ADR-0023（右の欄の閲覧と編集。この ADR で置き換え）・ADR-0051（訪問の詳細の欄・5段の見直し）・ADR-0012（定期パターン）・ADR-0013（休み）・ADR-0048（下書きのまま離れるときの確認）

## 背景
- UI/UX の見直しの5段の2段目（ADR-0051）。ユーザーが決めた「〈利用者さん〉の画面は右の欄から全画面へ（ADR-0023 の閲覧・編集の2つのモードを置き換える）」を作る
- 右の欄の閲覧の欄は住所・特性・担当の並びだけで、その人の**これからの訪問**が見えなかった。繰り返し（定期パターン）は読むだけの1行で、直すには「編集する」→ 欄を巻く → 鉛筆と深く入った
- 編集の欄の中で、繰り返しと休みだけが押した時点で保存され、欄の「取り消し」で戻らなかった（保存の仕組みが2通り）
- 1段目で訪問の詳細の欄（`VisitPanel`）と、データに触る薄い層（`lib/visitOps`）ができた。週の予定のドラッグも落とすと欄が開き範囲を選ぶ形になった
- データの形は今のまま（作り直しは3段目）。スマホは見る・取り消す・担当替えまで（ADR-0051 の決定5）

## 選択肢
1. 案A：右の欄のまま、閲覧の欄に「これからの訪問」の一覧を足す
2. 案B：`#/clients/:id`・`#/staff/:id` の全画面にし、タブ（先頭は予定）と、予定のカレンダー（週・月）・節ごとの「直す → 保存」にする。右の欄の閲覧・編集のモードはやめる
3. 案C：案B に加えて、データの形（訪問に担当を持つ）も同時に作り直す

## 決定
案B。
- ルート：`#/clients/:id`（`pages/ClientPage`）・`#/staff/:staffId`（`pages/StaffPersonPage`）。`new` は新しい人（基本の節が開いた形）。一覧（`ClientsPage`・`StaffPage`）は一覧だけにし、行・「開く」・「追加」で全画面へ移る。古い `?id=` は一覧が受けてその人の画面へ `replace` で移る。吹き出し・パレット・名簿の知らせのリンクは直に `/:id` へ
- 画面の殻：上に名前と状態、一覧へ戻るリンク、タブ（`components/personPage` の `PersonTabs`。設定のタブと同じリンクのナビ。`?tab=`）。人が替わっても同じ画面として扱う（`Guarded` の ErrorBoundary の key を `/clients/:id` にそろえ、作り直さない）
- 予定のタブ：`components/PersonCalendar`（週の時間軸・月のマス・狭い画面の日ごとのリスト）。回は `lib/personPage` の `clientCalItems`・`staffCalItems`（`visitOps` の `clientVisitsIn`・新しい `staffVisitsIn`・`assignmentOf`）で作り、押すと `useOpenVisit()`。〈利用者さん〉の広い画面だけ、空き枠を押す・縦にドラッグで新規（`newVisit` に〈利用者さん〉・日付・開始、`draft` に所要）、回の HTML のドラッグで落とした日時を `draft` に入れて欄を開く（範囲は欄で選ぶ。週の予定と同じ）。繰り返しを押すとその回を強調。期間と見せ方は URL の `cal`・`d`
- 繰り返し：今の `PatternsSection` を予定のタブの左に置き、「足す」「直す」「終わらせる」（新しい `visitOps` の `endPatternOp`）・直す欄の「消す」。休み：`ClientLeavesSection` を休みのタブに置く（予定のタブの左にはこれからの休みを読むだけ）
- 節：`components/personPage` の `EditSection`（読む ⇄ 直す → 保存・取り消し・Esc）。〈利用者さん〉は 基本・段階と紹介元・住所・特性・決まりごと（基本情報）、担当・求めること・相性（読むだけ。相性の表へのリンク）、〈スタッフ〉は 基本・自宅・特性・求めること・最終勤務日（基本情報）、ふだんの勤務・日ごとに変えた勤務（読むだけ）（勤務時間）、相性・担当（相性）。節ごとに保存する項目を決め（`SECTIONS`）、保存した中身にその項目だけ重ねる（`mergeFields`）。検査・正規化は今の保存と同じ（郵便番号・メール・同じ名前・アイコン・担当できる人・段階・まとめて置いた位置を残す・休止の確認・最終勤務日の振り直し）
- 変更の確認：節・繰り返し・休みの入力の変更の有無を画面が集め、変更があるまま 取り消す・Esc・別の節・タブ・メニューやリンクで移る（`useLeaveGuard`。確定で移るときに入力を捨てる `onLeave` を足した）・別の人の URL（画面が URL の人と開いている人を分けて持ち、断れば元の人の URL へ戻す）・再読込を確かめる。繰り返し・休みも保存を押すまで書かない
- 月の予定で〈利用者さん〉を選んだときの右の欄は、その人の画面の予定（月）へのリンクにする（回・集計・休みの重ねを消す）
- 消したもの：右の欄の閲覧・編集のモード（`personView` の `StaffView`・`ClientView`、`lib/viewMode` の `discardDialog`・`splitLeaves`、一覧の画面の編集の状態）、月の右の欄の〈利用者さん〉の集計・この月の回・担当した人・休み

## 理由とトレードオフ
- 得るもの：その人の予定を見ながら、繰り返し・1回分・休みを同じ画面で直せる（見直し案の「予定の変更依頼（来月から火→水）」が1画面）。どの節も「直す → 保存」で、保存の仕組みが1つ。カレンダーと欄は1段目の部品をそのまま使うので、段3でデータの形を変えても `visitOps` の差し替えで済む
- 失うもの：
  - 一覧と人の画面を行き来する（一覧を見ながら隣の人を開く動きは、戻る・一覧へ戻るリンクで1回多い）
  - 新しい人は基本の節だけで作り、住所・特性などは保存してから入れる（前の追加の欄は全部の項目を一度に入れられた）
  - 同じ人の `?id=` で編集を続ける動き（ADR-0023）は無くなった（`?id=` は一覧が受けて移るので、入力は捨てる）。人の画面の URL どうしの移動は確かめる
  - 〈スタッフ〉のカレンダーでは足す・動かすをしない（担当が替わると回がその人の予定から消え、分かりにくいため）。カレンダーの時刻は訪問の開始（早）と所要で、日の予定の時間軸（移動・待ちを入れた時刻）とずれることがある
  - 回の印「変」・取り消し・休みの白抜きは、月の右の欄の集計の代わり。月の数（予定の回数・代の回数）は出さない
- 見直す条件：段3（データの版2）で `staffVisitsIn`・`endPatternOp`・カレンダーの回の作り方を書き直す。段4で予定の画面を1つの部品にするとき、`PersonCalendar` と週の予定の時間軸を寄せる。段5でキーボードで回を動かす
