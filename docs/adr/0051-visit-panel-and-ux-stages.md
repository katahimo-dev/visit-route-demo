# ADR-0051：訪問の確認・編集の見直しを5段で進め、1段目で訪問の詳細の欄を1つにする

- 日付：2026-10-22
- 状態：採用
- 関連：PRD D300〜D304、ADR-0012（定期パターン）・ADR-0023（右の欄の閲覧と編集）・ADR-0027（コマンドパレット）・ADR-0030（担当を変える ▾）・ADR-0043（手直しの記憶）・ADR-0045（その他 ▾）

## 背景
- 1つの訪問を見る・直す入口が画面ごとに別の形だった：時刻・日付・取り消しは日の予定を「一覧」に切り替えたときの鉛筆（`VisitForm`）だけ、担当は日の予定のドラッグと「担当を変える ▾」、週は帯のドラッグと移動の欄（「この回だけ／以降すべて」）、繰り返しは〈利用者さん〉の編集の欄。時間軸の帯を押しても編集の入口が無く、時刻と担当を同時に変えられない
- 「誰が行くか」がデータの5か所（今の案・確定した割当・固定・手直しの記憶・いつもの担当）にあり、用語も多い。見直し案（UI/UX の見直し案）は、訪問を中心に置いて1つの欄から開き、データの形は後の段で版2にする道筋を出した
- ユーザーは「おすすめどおり5段で、1段目から」と決めた。デモ版なので互換性・過去データは気にしないが、1段目は今のデータの形のまま作る

## 見直しの全体方針（5段）
1. **訪問の詳細の欄を1つに**（この ADR の中身）：`VisitPanel` をどこから開いても同じにし、日時・担当・取り消し・範囲を1つの欄で扱う
2. 〈利用者さん〉の予定表：`#/clients/:id` を全画面にし、繰り返しの一覧と週・月のカレンダー（1段目の欄を使う）、節ごとの編集
3. データを版2へ：担当を訪問に持つ・AI は提案・確定＝伝えたもの・繰り返しの担当は1つ・訪問ごとの検査（「条件が変わった」・試す重み・手直しの記憶・「未作成」を外す）
4. 予定の画面を1つの部品に：日・週・月を同じ部品の拡大率に、メニューを減らし、全体の元に戻す・複数選択
5. スマホとキーボード・検索：日ごとのリスト・下から出る欄・矢印キーで動かす

### ユーザーが決めたこと（後の段のため）
1. 「確定」＝〈スタッフ〉に伝えた内容。確定のあとの変更は「未連絡の変更」として連絡の一覧に出す（段3）
2. プリセットは残し、AI の記録と案を比べるはその場だけ（保存しない）（段3〜4）
3. 〈利用者さん〉の画面は右の欄から全画面へ（段2。ADR-0023 の閲覧・編集の2つのモードを置き換える）
4. 定期パターンの回は見るときに計算し、変えた回だけ保存する（「未作成」を無くす）（段3）
5. スマホは見る・取り消す・担当替えまで（追加・移動はしない）。1段目から欄に当てる
6. （追加の決定）訪問の欄はホームとコマンドパレットにも置く。パレットで訪問を引く（PRD §4 の「訪問の検索はしない」を外す）

## 1段目の選択肢
1. 案A：今の `VisitForm`・週の移動の欄・「担当を変える ▾」を残し、入口だけ足す
2. 案B：1つの欄 `VisitPanel` を作り、`VisitForm` と週の移動の欄を吸収する。データには薄い層 `lib/visitOps.ts` 越しに触る。日の予定の帯・カードの詳細（理由・「担当を変える ▾」・トーストの「元に戻す」）は残し、そこに「詳細・変更」を置く
3. 案C：案B に加えて、帯を押したら詳細を出さずにすぐ欄を開き、「担当を変える ▾」も欄に吸収する

## 決定
案B。
- 部品：`components/VisitPanel.tsx`（`VisitPanelProvider`・`useOpenVisit`）。App の殻に1つ置き、どの画面・コマンドパレットからでも開く（画面を移っても欄は残る）。右の欄（`SidePanel`。狭い画面は今の右の欄の形）で、主ボタンは「保存」（新規は「追加」）の1つ。Tab は欄の中で回り、Esc で閉じ、保存・閉じたあとのフォーカスは開いた帯（作り直した回は新しい帯）、無ければ開く前の要素。印刷では出さない
- 中身：〈利用者さん〉の名前（`PersonButton`）・日付・時刻（受けられる時間帯）・所要・種類・担当（`StaffMark`・固定・いつもの担当）・「繰り返し：…（M/Dから）の回」・この回の変更の印（「繰り返しのとおりに戻す」）・メモ・決まりごと・道順。日の予定以外から開いたら「日の予定で見る」
- 操作：日時を変える（日付・時間の約束・開始・所要・種類・メモ）、担当を替える（候補は「担当を変える ▾」と同じ判定：reassign の `candidatesFor` と `reassignItemText`。欄の日時で計算し直す）、取り消す（ふつう／当日キャンセル）・取り消しをやめる。日時と担当は同じ保存で同時に変わる
- 範囲（繰り返しの回だけ）：「この回だけ」＝`lib/visitEdit` の `savedVisit`、「これ以降」＝`lib/week` の `moveFollowing`（所要・種類・幅・いつもの担当も変えられるよう `over` を足した）、「すべて」＝今日以降で最初の同じ曜日の回から「これ以降」。範囲は**同じ曜日の回**（週のドラッグの「以降すべて」と同じ）。この回だけ変えた・取り消した回はそのまま（欄に日付を出す）。確定した日が変わるなら確かめる
- 担当の範囲：この回だけ＝その日の今の案で固定（「担当を変える ▾」の手直しと同じ置き方）。これ以降・すべて＝分けた繰り返しのいつもの担当（`pattern.usualStaffId`）をその人にし、範囲の回のうち今の案のある日を固定し、手直しの記憶（ADR-0043）にも書く（作り直しても同じ人にする。今の仕組みの「次からも」と同じ意味なので）。今の案の無い日は当てず、トーストに件数を出す。担当なしは「この回だけ」だけ
- 書き込み：`lib/visitOps.ts`（純粋関数：`visitInfo`・`staffChoices`・`applyVisitEdit`・`cancelVisitOp`・`uncancelVisitOp`・`restoreOccurrenceOp`・`unassignedVisits`・`dayVisitRows`・`clientVisitsIn`）が新しい DemoData を返し、欄が store の `update` で当てる。トーストの「元に戻す」は書く前のデータに戻す（あとから別の変更があれば戻さず理由）
- 開く所：日の予定の時間軸の帯・順番のカード・入らなかった訪問のカードの詳細の「詳細・変更」、一覧の行の「開く」（鉛筆を置き換え）、「その他 ▾」の「訪問を追加」（新規）、週の予定の帯と〈利用者さん〉×曜日の表の訪問（押す・Enter。ドラッグは今のまま、落とすと落とした日時で欄が開き範囲を選んで保存。担当を選ばずに日時を変えたら今までの「空き時間に入れる」の知らせ）、月の予定で〈利用者さん〉を選んだときの「この月の回」、ホームの「今日の訪問」（担当なし → 案なし → これからの近い順に5件、あとは「あと N件（日の予定で見る）」）と「これからの入らない訪問」、ホームのいつでもの「訪問を追加」、コマンドパレットの「訪問」（〈利用者さん〉の名前・よみ＋日付（「10/28」「明日」など）でその日の回、名前だけなら今日以降の近い回。索引は打ってから作る）と操作「訪問を追加」
- 狭い画面（600px 以下）：見る・取り消す・担当替えだけ。日時の変更と範囲の選択を出さず、新規は出さない（「その他 ▾」の「訪問を追加」は押せず理由）
- 消したもの：`pages/VisitForm.tsx`、週の移動の欄（`move-*`）、一覧の鉛筆（「〜を編集」）。用語は「この回だけ／これ以降／すべて」にそろえる

## 理由とトレードオフ
- 得るもの：どこから開いても同じ欄で、時刻と担当を同時に、繰り返しの範囲つきで変えられる。週のドラッグと欄が同じ処理（`moveFollowing`）を使う。段3でデータの形を変えるときは `visitOps` を差し替えれば欄を書き直さずに済む
- 失うもの：
  - 日の予定の帯・カードの詳細（理由・「担当を変える ▾」）が残るので、帯から欄までは2回押す。今の手直し（固定・1手だけ戻す・手直しの記憶の帯）の動き・e2e を壊さないための割り切りで、詳細を欄に寄せるのは段4
  - 欄の担当替えは保存で当てるので、手直しの記憶の帯（「次からも」）は出さない（これ以降・すべてで記憶に書く）
  - 「これ以降」「すべて」の担当は、範囲の回を作り直す（ID が変わる）ので、その曜日の今の案は「条件が変わった」になり、いつもの担当が変わった日も「条件が変わった」になる（段3で消える状態）
  - 曜日が2つ以上の繰り返しでは、範囲は開いた回の曜日だけ（ほかの曜日の回は変えない）
