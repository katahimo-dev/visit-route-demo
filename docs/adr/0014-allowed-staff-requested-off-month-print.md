# ADR-0014：担当を限る（可否で外す）、希望休のまとめ入力（欠勤の記録をそのまま使う）、月の予定の印刷

- 状態：採用（2026-10-17）
- 関連：PRD D68〜D70、ADR-0011（欠勤・振り直し）、ADR-0013

## 背景
訪問看護事業所のヒアリング（2026-10-15）で、ADR-0013 のあとに残った困りごと。
1. 「この方は特定の2名だけで担当する」という社内の決まりがある。当時は相性 × を限った人以外の全員に付けるか、条件の重みで寄せるしかなく、人が増えるたびに付け直しが要り、決まりとして読めない
2. 常勤は月10日休みのシフト、非常勤は希望休を紙・LINE で集め、カレンダー・シフト表・予定へ三重に入力している。欠勤は日の画面で1人1日ずつ入れる作りで、月の初めのまとめ入力に向かない（PRD §4 は期間の一括入力をやらないとしていた）
3. 予定を紙のカレンダーにも書き写して貼っている

決めること：担当を限る持ち方と効かせ方、限った人がいなくなったときの扱い、希望休の持ち方と入れ方、案・確定のある日に希望休を入れたときの扱い、印刷の作り方。

## 決定
担当を限るのは可否で外す（常に必須）。希望休は欠勤の記録をそのまま使う。振り直しは勝手にしない。印刷は専用の経路。

- 担当を限る：`clientSchema.allowedStaffIds`（〈スタッフ〉の ID の並び。空＝限らない。最大50）。compile は、その日の問題にいる利用中の人だけを数え、1人以上いればその人たちだけを可にする。外れる組の理由は `ruleId: 'allowedStaff'`（`visitType` と同じ書き方。限った人は ✓・0点）。条件の重み・必須・プリセットとは無関係で、条件ごとの達成にも数えない。可否で外すので AI案・月まとめ・振り直し・週のドロップの「入れる人」・空き状況のすべてに一か所で効く。限っていない利用者の問題は従来と同じ（`problemKey` も同じ）
- 限った人がいなくなったとき：「限らない（だれでも担当できる）」に戻す。store の `repair` は、いない・休止中の〈スタッフ〉の ID と重なりを除く（全員いなくなれば `[]`）。compile も利用中の人だけ数えるので保存の前後で扱いが変わらない。〈スタッフ〉を休止にして保存するとき、その人を限った利用者さんがいれば名前と「だれでも担当できるようになります（利用中に戻しても戻りません）」を確認に出し、同じ `update` で外す
- 〈利用者さん〉の欄に「担当できる人（社内の決まり）」の節（チェックと利用中の〈スタッフ〉のチップ。限るのに1人も選ばなければ保存しない）。一覧のいつもの担当の列に「限 山田、佐藤」の印。週間の帯・表に「限✗」。Excel の〈利用者さん〉シートに任意の列「担当できる人」（「、」か改行区切り。いない名前は場所付きで止める）
- 希望休：`absenceSchema` は変えない。`isRequestedOff(a)`（`lib/requestedOff`）＝終日で、メモが「希望休」。日の画面でメモや時間帯を変えるとふつうの欠勤になる
- 入れ方：月間で〈スタッフ〉を選ぶと「休みを入れる」（`aria-pressed`）。入れている間は日のマスを押すと `toggleRequestedOff`（勤務日で欠勤が無ければ足す、希望休なら外す）。今日より前・勤務の無い日・希望休でない欠勤のある日は押せない（`aria-disabled`、理由を title と読み上げに出す）。上に「この月の希望休 N日」と最後の操作の結果（`aria-live`）
- 案・確定のある日に入れたとき：データは欠勤を足すだけで、案・確定した割当は変えない（ADR-0011 のまま）。その人の訪問がある日に入れると欄に「『急な欠勤』から振り直してください（自動では振り直しません）」と日へのリンクを出し、日のマスに「休みの人に N」（`absentLeftOf`）、要対応に「休みの人に訪問 N件」を出す。今の案のある日は「条件が変わった」も出る
- 月の印：「休 N（希M）」は勤務の無い人と希望休の人の合計。「欠 名前」と要対応の「欠勤」は希望休でない欠勤だけ（希望休は前もって入れる休みなので、それだけでは要対応にしない）。〈スタッフ〉選択時は「希望休 N日」と「欠勤 N日」を分けて出す
- 印刷：専用の経路 `#/month/print?ym=&staff=`（メニューの外の画面。`lib/monthPrint` の純粋関数）。担当は確定した割当があればそれ、無ければ今の案。取り消し・休止中の利用者さんの訪問は出さず、利用者さんの休みは「休：名前」。休む〈スタッフ〉は「休：山田(希)・佐藤(欠)・鈴木」（希＝希望休、欠＝欠勤、印なし＝勤務なし）。〈スタッフ〉で絞ってもその人の担当が決まっていない訪問は「案なし」「未定 N件」と出す。名前は名字（重なればフルネーム）。A4横の名前つきページ（`@page monthprint`）で連絡の一覧の印刷（A4縦）と混ぜず、CSS は印刷の画面の中だけに効かせ、週の行の途中で改ページしない。時刻は案の目安
- データの版は1のまま（`allowedStaffIds` は `[]`）。希望休は既存の欠勤の形なので JSON・Excel（「欠勤」シート）の往復もそのまま
- 区切りは「、」にそろえる（理由の文・画面の印・Excel。「・」は区切らない）。画面の細部は design.md

## 検討した案
| 案 | 長所 | 短所 | 採否 |
|---|---|---|---|
| 限る1-A：`allowedStaffIds` ＋ compile で可否から外す | 1か所に読める形で残り、人が増えても直さず、全機能に漏れなく効く | 「なるべくこの人たち」は表せない | 採用 |
| 1-B：相性 × を自動で付ける | 既存の仕組み | 相性の表を書き換え、決まりとして読めない | 不採用 |
| 1-C：条件の型「担当を限る」を足し重み・必須を選べる | 柔軟 | 型・プリセット・達成の波及が大きい | 不採用 |
| いなくなったら2-A：限らないに戻す | 訪問が入らなくなる事故を避ける | 読み込みで休止中の人だけを限っていた利用者さんは黙って限らないになる | 採用 |
| 2-B：だれも担当できない（印を別に持つ） | 決まりに忠実 | 訪問が入らず原因が見えにくい | 声が出たら |
| 希望休3-A：欠勤の記録を流用（終日＋メモ「希望休」） | 稼働差し引き・振り直し・連絡・Excel がそのまま使え、型・版を変えない | メモ書き換えでふつうの欠勤になる | 採用 |
| 3-B：欠勤に種類 `kind` を足す | 分けて数えられる | 型・Excel の変更 | 困る声が出たら |
| 3-C：稼働時間の上書きに空の時間帯 | 追加なし | 理由が残らない・欠勤の印と別 | 不採用 |
| 4-A：勝手に振り直さない | ADR-0011 のまま。注意・印・要対応で気づける | 人が振り直す手間 | 採用 |

## 結果・トレードオフ・見直す条件
- 得るもの：担当を限る決まりが1か所に残り理由として説明できる。希望休は月の日のマスを続けて押すだけで紙・LINE から1か所へ写せる。印刷は連絡の一覧の印刷と混ざらない
- 失うもの：
  - 限るのは常に必須で、期間（〇月まで）も持たない
  - 希望休をメモの文で見分けるので、日の画面でメモを書き換えると要対応・月の印の扱いが変わる。月10日などの日数の確認・申請・承認はしない
  - 印刷は1マスに載る件数に限りがある（全員表示で1日17件ほどだと週ごとにほぼ1ページ、〈スタッフ〉で絞ると1か月が1〜2ページ）。時刻は目安で、移動を入れた正確な時刻は日の画面で見る
- 見直す条件：限った人が全員いなくなったときに止めたい声（2-B）。希望休と急な欠勤を分けて数えたい声（3-B。版は1のまま既定値で）。印刷の項目・文字の大きさはデモの反応で直す
- 影響：PRD §4 の「複数日の欠勤の一括入力」を「期間での一括入力はしない（希望休は月間でまとめて入れられる）」に書き換え
