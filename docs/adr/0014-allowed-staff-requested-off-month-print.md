# ADR-0014：担当を限る（可否で外す）、希望休のまとめ入力（欠勤の記録をそのまま使う）、月の予定の印刷

- 日付：2026-10-17
- 状態：採用（方向は依頼者が決定（ヒアリングを受けた第2弾。2026-10-17）。細部は推奨どおりに決め、この ADR に記録する）

## 背景
訪問看護事業所のヒアリング（2026-10-15）で、第1弾（ADR-0013）のあとに次の困りごとが残った（PRD D68〜D70 の背景）。

1. 「この方は特定の2名だけで担当する」のような**担当を限る社内の決まり**がある。いまは相性（×）を限った人以外の全員に付けるか、条件（必要条件・継続）の重みで寄せるしかない。人が増えるたびに × を付け直す必要があり、決まりとして読めない
2. 常勤は月10日休みのシフト、非常勤は**希望休**を出してもらい、紙・LINE で集めてカレンダー・シフト表・予定へ**三重に入力**している。いまの欠勤（ADR-0011）は日の画面で1人1日ずつ入れる作りで、月の初めにまとめて入れるのに向かない。PRD §4 は「複数日の欠勤の一括入力（1日ずつ）」をやらないことにしている
3. 予定を**紙のカレンダー**にも書き写して貼っている

いまの形：〈利用者さん〉は必要条件・希望・いつもの担当・相性で担当を寄せる。欠勤は `absences`（1人1日1件・終日か時間帯・メモ）で、稼働時間帯から差し引く（compile）。振り直しは利用者が押す（ADR-0011）。月間（`#/month`）は〈スタッフ〉を1人選ぶとその人の日のマスになる（D55）。印刷は連絡の一覧（`@media print`）だけ。

決めること：(1) 担当を限る持ち方と効かせ方、(2) 限った人がいなくなったときの扱い、(3) 希望休の持ち方と入れ方、(4) 案・確定のある日に希望休を入れたときの扱い、(5) 印刷の作り方。

## 選択肢
1. 担当を限る
   - A：**〈利用者さん〉に `allowedStaffIds`（〈スタッフ〉の ID の並び。空＝限らない）を足し、compile が限った人以外との組を可否で外す**（理由 `ruleId: 'allowedStaff'`。種類の必要条件（`visitType`）と同じく常に必須）
   - B：相性 ×（-2）を限った人以外に自動で付ける（相性の表を書き換える）
   - C：条件の型「担当を限る」を足し、重み・必須を選べるようにする
2. 限った人が全員いなくなったとき（休止・削除）
   - A：**限らない（だれでも担当できる）に戻す**。休止にするときに確認を出す
   - B：だれも担当できない（その〈利用者さん〉の訪問は入らない）。「限っているが全員いない」の印を別に持つ
3. 希望休の持ち方
   - A：**欠勤の記録 `absences` をそのまま使い、終日の欠勤でメモが「希望休」のものを希望休とみなす**（型は変えない）
   - B：欠勤に種類（`kind: 'sudden' | 'requested'`）を足す
   - C：稼働時間の上書き（`availability` の空の時間帯）に書く
4. 案・確定のある日に希望休を入れたとき
   - A：**勝手に振り直さない**（ADR-0011 のまま）。入れた場で注意とその日へのリンク、日のマスに「休みの人に N」、要対応に出す
   - B：入れたら自動で案A（空き時間に入れる）で振り直す
5. 印刷
   - A：**印刷専用の経路 `#/month/print?ym=&staff=`**（左のメニューの外の画面。A4横の名前つきのページ `@page monthprint`。週の行の途中で改ページしない）
   - B：月間の画面に `@media print` を足し、印刷のときだけ見た目を変える

## 決定
1-A、2-A、3-A、4-A、5-A（担当を限る・希望休・印刷の方向は依頼者の方針どおり。細部は推奨どおり）。

- 担当を限る：`clientSchema.allowedStaffIds: z.array(idSchema).max(50).default([])`。compile は、その日の問題にいる（利用中の）人だけを数え、1人以上いればその人たちだけを可にする。外れる組の理由は `{ ruleId: 'allowedStaff', label: '担当を限る：山田・佐藤 ✗', points: Infinity }`、限った人には `✓`・0点（種類の必要条件と同じ書き方）。条件の重み・必須・プリセットには関係しない。条件ごとの達成（`achievements`）には数えない（`visitType` と同じ）。AI案・月まとめ作成・欠勤の振り直し（`targetsOf`・`reassign`・`candidatesFor`）・週のドロップの「入れる人」（`fitsOf`）・空き状況は、どれも compile の可否を使うので一か所で効く。限っていない〈利用者さん〉の問題は今までと同じ（`problemKey` も同じ）
- 限った人がいなくなったとき：store の `repair` は、いない・休止中（`active: false`）の〈スタッフ〉の ID と重なりを除く（全員いなくなれば `[]`＝限らない）。compile も利用中の人だけを数えるので、保存の前後で扱いが変わらない。〈スタッフ〉の画面で休止にして保存するとき、その人を限った〈利用者さん〉があれば名前と「担当できる人がいなくなり、だれでも担当できるようになります」を確認に出し、同じ `update` で外す
- 〈利用者さん〉の画面：欄に「担当できる人（社内の決まり）」の節。「担当できる人を限る」のチェックと、利用中の〈スタッフ〉のチップ（`components/PickChips` を「全員・全解除」なしで使う）。入れたときに誰も選んでいなければ、いつもの担当を最初に選ぶ。限るのに1人も選ばなければ保存しない。一覧の「いつもの担当」の列に「限 山田・佐藤」の印
- Excel：〈利用者さん〉シートの「いつもの担当」の次に「担当できる人」（名前を「、」か改行で区切る。任意の列。無い古いブックは限らない。いない名前はシート名・行番号付きで止める）
- 希望休：`absenceSchema` は変えない。`lib/requestedOff` の `isRequestedOff(a)`＝開始・終了とも無し（終日）かつメモが「希望休」。日の画面の欠勤の欄でメモや時間帯を変えると、ふつうの欠勤として扱う
- 入れ方：月間で〈スタッフ〉を選ぶと「休みを入れる」（通常のボタン。`aria-pressed`）。入れているあいだ、日のマスを押すと日の画面へ移らず `toggleRequestedOff`（勤務日で欠勤が無い＝終日の欠勤（メモ「希望休」）を足す、希望休＝外す）。今日より前・勤務の無い日（稼働時間の上書きで休みの日も）・希望休でない欠勤のある日は押せない（押せないマスは灰の枠・`disabled`・title と読み上げに理由）。押せるマスは紫の点線の枠、希望休のマスは紫の斜線。上に説明と「この月の希望休 N日」、最後の操作の結果（`aria-live`）
- 案・確定のある日：データは欠勤を足すだけで、今の案・確定した割当は変えない。その人に数える案（今の案、無ければ確定した割当）の訪問がある日に入れると、欄に「日の画面の『急な欠勤』から振り直してください（自動では振り直しません）」と「〈日〉の予定を開く」を残す。日のマスは `absentLeftOf`（欠勤の時間と重なるのにその人に残る訪問＝compile の 'slot' の欠勤の理由で可でない組）を数え、「休みの人に N」（赤）と手当てが必要の枠、要対応に「休みの人に訪問 N件」。今の案のある日は欠勤で問題が変わるので「条件が変わった」も出る（今までどおり）
- 月の印：全体の表示の「休 N」は、勤務の無い人と希望休の人の合計（`dayMarks.requested`。title に「休む〈スタッフ〉 N人／希望休：…／勤務なし：…」）。「欠 名前」は希望休でない欠勤だけ。要対応の「欠勤」も希望休でない欠勤だけ（希望休は前もって入れる休みなので、それだけでは要対応にしない）。〈スタッフ〉を選んだときのマスは「希望休」、右の欄に「希望休 N日」と「欠勤 N日」を分けて出す
- 印刷：`lib/monthPrint` の `printDay`・`monthPrint`（純粋関数）。担当は確定した割当（担当のいる訪問が1件以上）があればそれ、無ければ今の案。開始の時刻はその日の問題でその列を lenient に並べた時刻（確定した割当は開始（早）の順）、案に無ければ開始（早）。取り消し・休止中の〈利用者さん〉の訪問は出さない。〈利用者さん〉の休みの訪問は一覧に出さず「〈利用者さん〉休：名前」。休む〈スタッフ〉は「休：山田(希)・佐藤(欠)・鈴木」（希＝希望休、欠＝欠勤、印なし＝勤務なし）。〈スタッフ〉で絞ると、その人の担当とその人の休み（〈利用者さん〉の休みはその人の担当だった訪問のもの）だけ。画面 `pages/MonthPrintPage.tsx`：上に操作の帯（月間に戻る・月の送り・〈スタッフ〉・主ボタン「印刷する」＝`window.print()`。印刷しない）、見出し（月・事業所名・凡例・印刷日）、日曜はじまりの週の表（その月に日が無い週は出さない）。CSS は `@page monthprint { size: A4 landscape }` と `.mprint { page: monthprint }`（連絡の一覧の印刷に効かせない）、行（週）は `break-inside: avoid`
- データの版は1のまま。`allowedStaffIds` は zod の既定値で古いデータを読む。希望休は既存の欠勤の形なので、JSON・Excel（「欠勤」シート）の往復はそのまま

## 理由とトレードオフ
- 得るもの：
  - 担当を限る決まりが〈利用者さん〉の1か所に読める形で残り、〈スタッフ〉が増えても直さなくてよい。可否で外すので、AI案・振り直し・週のドラッグ・空き状況のどれにも漏れなく効き、理由として説明できる
  - 希望休は欠勤の記録そのものなので、稼働時間からの差し引き・日の画面の欠勤の印・振り直し・連絡の一覧・Excel の「欠勤」シートがそのまま使え、型・版・移行を変えない。月の日のマスを続けて押すだけで、紙・LINE から1か所へ写せる
  - 印刷は専用の経路なので、ナビ・ボタンを隠す CSS を全画面に足さずに済み、月間の画面の作り（memo・状態）を崩さない。名前つきのページで連絡の一覧の印刷（A4縦）と混ざらない
- 失うもの：
  - 限った人が全員いなくなると、だれでも担当できるに戻る（「だれも担当できない」で止めない）。休止にするときの確認で知らせるが、JSON・Excel の読み込みで休止中の人だけを限っていた〈利用者さん〉は黙って限らないになる
  - 担当を限るのは常に必須で、「なるべくこの人たち」は表せない（条件の希望・継続・相性で寄せる）。期間（〇月まで）も持たない
  - 希望休をメモの文で見分けるので、日の画面でメモを書き換えるとふつうの欠勤になる（要対応・月の印の扱いが変わる）。希望休の日数の決まり（月10日）の確認・申請・承認はしない
  - 印刷は1マスに載る件数に限りがある（全員の表示で1日17件ほどだと、週ごとに1ページ近くになる。〈スタッフ〉で絞ると1か月が1〜2ページ）。時刻は案の目安で、移動を入れた正確な時刻は日の画面・〈スタッフ〉の画面で見る

## 影響
- PRD：D68〜D70 を追加。§4 の「複数日の欠勤の一括入力（1日ずつ）」を「期間での一括入力はしない（希望休は月間でまとめて入れられる）」に書き直し、希望休まわりのやらないことを足す
- design.md：matching（`allowedStaff`）、store（repair）、excel（列）、evaluate（達成に数えない）、pages（〈利用者さん〉の欄・〈スタッフ〉の休止の確認・月間の「休みを入れる」・印・印刷の画面）、`lib/requestedOff`・`lib/monthPrint`・`lib/month`（`DayView.absentLeft`・`DayMarks.requested`・`StaffDay.requested`/`absentLeft`・要対応の `absentLeft`）。契約は §5「担当を限る・希望休・月の予定の印刷」
- データ：`DATA_VERSION` は1のまま（`allowedStaffIds` は `[]`）
- 見直す条件：限った人が全員いなくなったときに止めたい声が出たら 2-B（印を別に持つ）。希望休と急な欠勤を分けて数えたい・メモを書き換えて困る声が出たら 3-B（欠勤に種類を足す。版は1のまま既定値で）。印刷に載せる項目・文字の大きさはデモの反応で直す
