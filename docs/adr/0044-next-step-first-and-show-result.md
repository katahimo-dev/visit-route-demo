# ADR-0044：次の一手を1つに絞り、結果を見せる（UI を直感的にする第1弾）

- 日付：2026-10-21
- 状態：採用
- 関連：PRD D263〜D272（D142・D169・D218・D228・D239 の書き換えを含む）、ADR-0025（ホーム・欠勤の欄）、ADR-0033（狭い画面の表）、ADR-0036（ボタンの3段・左のメニュー）、ADR-0038（スマホのホームの先頭の欠勤）

## 背景
- 実機（1366×768・390×844）で主な作業（月の案を作って確定・急な欠勤・問い合わせ）を最後まで操作して評価した。個々の文言や手順はよくできているが、**次に押すものが1つに決まらない**所と、**押した結果が見えずに確定を求められる**所が残っていた
  - ホームの「次にすること」は 要対応 → 今日 → 確定していない日 → 案を作る の順（ADR-0025）。作業の順（作る → 確かめて確定 → 今日を見る）と逆で、同じ月の「案の無い日 N日」が確定のカードと作るカードの2枚に重ねて書かれていた。どのカードも同じ大きさで、どれから押すか見た目で決まらない
  - 欠勤・キャンセルの欄の3段目（影響）は、主ボタン（案A か案B）・枠の「案B も作る」または「案A」・「欠勤だけ登録」が並び、どれが勧めなのか読まないと分からない。4段目（確定）は件数のまとめだけで、誰のどの訪問が誰へ移るかを見ずに「この割当で確定」を押すことになる。「変更を減らす」のスライダーと説明がいつも開いていて、確定のボタンを下へ押し下げる
  - 日の予定の点数は入らない0・違反0でも朱の太字で、要対応に見える（D228 の「赤は要対応だけ」と食い違う）
  - 日付に関係しない画面（一覧・相性・設定・データ）にも上の帯の日付の選択が出て、何の日付か迷う
  - 細部：月の予定にいるときにも知らせに［月の予定を見る］が出る、日の予定（1366px）の列の名前が切れて「…」になる、左のメニューが 768px の高さに収まらず下の項目（管理者設定・データ）が見えない、条件の重みの名前がいつも入力欄で誤って書き換えられる、スマホの相性・勤務時間（シフト）の表で名前の列が広く列が2〜3つしか見えない
- 制約：契約（`src/contracts/`）・データの版・計算（solver・振り直し）は変えない。今ある画面の中で直す（画面を減らす・メニューを組み直すのは第2弾で ADR を別に書く）

## 選択肢
ホームの並びと強調
1. 案A：並びを作業の順（要対応 → 月ごとに作る → 確認（今月 → 来月）→ 今日）にし、先頭の1枚を「まずこれ」として幅いっぱい・主ボタンの塗りにする。同じ月の「案の無い日」は作るカードにだけ書き、案の無い日だけの確認のカードは作るカードがあれば出さない
2. 案B：並びは今のまま、作るカードと確認のカードを月ごとに1枚にまとめる
3. 案C：ホームを「今日の1枚」だけにして、ほかは月の予定へ任せる

欠勤の3段目のボタン
1. 案A：主ボタンは「登録して振り直す（おすすめ）」の1つ（おすすめが案B なら案B も作る）。もう一方の案と「欠勤だけ登録」は本文の「ほかのやり方」に文字のボタンで置く。おすすめの説明カードに縁と札
2. 案B：案A・案B を選ぶラジオにして、主ボタン「登録して振り直す」で選んだ方を作る
3. 案C：今のまま（主ボタン＋枠のボタン2つ）

4段目の結果
1. 案A：振り直しの差（`ReassignDiff`）から、担当が変わる訪問と入らない訪問を1行ずつ（時刻・〈利用者さん〉・元の担当 → 新しい担当）。「変更を減らす」は「詳しく」（details）に畳む
2. 案B：日の予定の差の欄へ移ってから確定させる（欄を閉じる）

## 決定
すべて案A。あわせて次も決める。
- 点数の色：入らない・必須の違反があるときだけ要対応の色（赤）。無ければ地の文字の色（点が低い理由は「移動が長め」などの注意の色の理由で示す）
- 日付の選択を出す画面：日・週・月の予定・案を比べる・勤務の見込み・勤務時間（シフト）。ほかでは出さない（選んでいる日付は覚えたまま。外枠の `data-date`）。〈利用者さん〉一覧・相性の絞り込みの週は選んでいる日付の週のまま（「N/D からの週」と書く）
- 知らせ：行き先が今いる画面と同じボタンは出さない。ボタン付きは6秒から文の長さで延ばし10秒まで、マウスを重ねている間・フォーカスがある間は消さない
- 日の予定の時間軸：列の最小幅 150px → 128px、名前は空白で折り返して切らない、件数の札は入らなければ次の行。右に続きの列がある間は端に影（広い画面でも）
- 左のメニュー：高さ 860px 以下では項目 30px・グループの間 4px に詰め、1366×768 で最後の項目まで見せる。それでも入らないときは下の端に影（巻くと消える）。タッチできる端末は 44px のまま
- 条件の重みの名前：ふだんは文字、［名前を変える］で入力欄（Enter で決め、Esc で取り消す）。必須の条件を消す確認には「守らなければ担当にしない決まりが無くなる」本文
- 狭い画面（600px 以下）の相性・勤務時間（シフト）：名前の列を 7em に詰めて折り返す（相性の行の頭文字の丸は隠す）。上の帯の名前は 400px 以下で少し小さくして切らない

## 理由とトレードオフ
- 得るもの：ホームを開くと押すものが1つに決まり、作業の順に上から押していける。欠勤は主ボタンを押すだけでおすすめの振り直しになり、確定の前に誰の何が変わるかを見られる。赤が要対応だけに戻る。日付の選択が出る画面では、それが中身を変えると分かる
- 失うもの：
  - ホームの今日のカードが最後になる（今日の手当ては要対応のカードが先頭に出るので、困るのは「今日を見るだけ」のとき。スマホは先頭の欠勤の入口と下のタブの「今日」で届く）
  - 確認のカードの日数は今どおり案の無い日を含む（月の予定・帯と同じ数）。案の無い日だけのときはカードを出さないので、その月の確定していない日の数はホームでは作るカードの「案の無い日 N日」で読む
  - 欠勤の「案A だけ」「案B も」を選ぶには文字のボタンを探すことになる（おすすめで足りる日が多い）
  - 「変更を減らす」は1手多く開く（差の欄の AnnealBox も同じ部品なので同じく畳む）
  - 日付の無い画面で日付を変えたいときは、日・週・月の予定へ移る
- 捨てた案：ホームの案B は「次の一手」が月ごとに2つの作業を1枚に詰め込み、押した先が1つに決まらない。案C は月の準備（作る・確定）がホームから見えなくなる。欠勤の案B（ラジオ）は1段増え、選ぶ前に違いを読む必要がある点は変わらない。4段目の案B は確定の前に欄を閉じることになり、5段目（連絡）へ続かない
