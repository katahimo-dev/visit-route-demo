# ADR-0033：狭い画面では一覧の表をカードに組み替える（ADR-0024 の見直し）

- 状態：採用（2026-10-19）
- 関連：PRD D220〜D222、ADR-0024（スマホのメニュー。「各画面の中身はスマホ向けに作り直さない」をこの決定で置き換える）、ADR-0025 追記（月の日ごとの一覧 D189）

## 背景
ADR-0024 は「管理者役は PC、スマホは表示の確認」（PRD §7）として、メニュー・上の帯・下のタブだけを狭い画面向けにし、各画面の中身はスマホ向けに作り直さないと決めた。見直す条件は「スマホで予定を直す使い方が増えたら」。

390px（CSS px）で確かめると、表示の確認にも使えない画面がある。
- 条件の重み：名前・種類の列しか見えず、重みのスライダーと必須の切り替えが画面の外。プリセットの名前・ボタンの文字が1字ずつ折り返す
- 特性の項目：選択肢の列が画面の外。行が高く空白ばかり
- 〈スタッフ〉一覧（7列）：特性の列が画面の外。1行が約200px の空白
- 〈利用者さん〉一覧：最初の画面は絞り込みのチップだけで、一覧は2画面目。チップも切れる
- 案を比べる：表が1字ずつ折り返し、主ボタンが下のタブの裏
- 週：最初の画面は見出しと絞り込みだけ。時間軸（`min-width: 860px`）で今日の列が切れる。月はすでに 600px 以下で日ごとの一覧が既定（D189）
- 空き状況：横の表が 7:00 の × の列から始まる
- 格子の表（相性・稼働時間・空き状況など）：相性だけ見出しと1列目を止め、ほかは止めない。どの表にも右に続きがある印が無い

制約：広い画面の見た目・URL・データは変えない。表の印（`table`・`tr`・`td`・data-testid）は e2e と読み上げが使うので変えない。新しい境目を作らない（今の 600px。`MONTH_LIST_QUERY`）。契約（`src/contracts/`）は変えない。

## 決定
狭い画面（600px 以下）では、**一覧の表**を1行1枚のカードに CSS だけで組み替え、**格子の表**は表のまま1列目を止めて右に続きがあることを示す。週は〈スタッフ〉×曜日の表を既定にする。ADR-0024 の「各画面の中身はスマホ向けに作り直さない」は、この決定で置き換える（メニュー・上の帯・下のタブの決定はそのまま）。

- 一覧の表（D220）：`table.narrow-cards`。1行目に名前（`narrow-title`）と大事な値（`narrow-head`。必須・状態・A／B）、ほかのマスは `td::before { content: attr(data-label) }` の見出しと値、操作（`narrow-act`）は右下。列は隠さない。`thead` は読み上げにだけ残す。対象は条件の重み・プリセットの重み・特性の項目・〈スタッフ〉一覧・〈利用者さん〉一覧・比較の記録
  - 〈利用者さん〉一覧の絞り込みは「絞り込み（N）」のボタンの下に畳む（N は効いている絞り込みの数。開いたかは画面の中だけ）
  - 比較の「もう1案作って比べる」は、右の欄の確定のボタンの帯（panel-foot）と同じく記録のカードの下に貼り付け、下のタブに隠さない
- 格子の表（D221）：相性・稼働時間・稼働の見込み・空き状況・週の表と時間軸。1列目（名前・曜日・時刻）を止め、縦に長い表は見出しの行も止める。右に続きがある間は右の端をぼかし、端まで巻くと消す（`components/EdgeScroll`・`lib/scrollEdge`）。空き状況ははじめ 9:00 の列から
- 週（D222）：`?view=`・`?by=` が無ければ〈スタッフ〉×曜日の表（URL に書かない。押した表示は書く。月の `?layout=` と同じ）。今日の列まで横に巻き、案内（「この週は案がありません」）が出ていなければ、最初の1回は今日の列の見出しまで縦にも巻く
- 確かめ方：`lib/scrollEdge`・`lib/weekView`・`lib/clientFilter` のテスト、`scripts/e2e-mobile.cjs`（390×844。横にはみ出さない・スライダーと必須が画面の中・主ボタンがタブの上・今日の列・9:00・1400px は今のまま）

## 検討した案
| 案 | 長所 | 短所 | 採否 |
|---|---|---|---|
| A：今のまま（表を横に巻く） | 作り直しが無い | 操作の列（スライダー・必須・開く）が画面の外で、表示の確認にも使えない | 不採用 |
| B：狭い画面で列を隠す | 簡単 | 隠した列の情報がスマホで見えない。どの列を隠すかが画面ごとに揺れる | 不採用 |
| C：一覧の表を CSS だけでカードに（印は今のまま） | 列を隠さない。e2e・読み上げの印が変わらない。広い画面は変わらない | 1枚が縦に長い。CSS の決まりが1つ増える | 採用 |
| D：スマホ用の部品を別に作る | 見た目を最適にできる | 部品が二重になり、直し漏れが出る | 不採用 |
| 格子の表もカードに | 横に巻かない | 曜日×時刻・人×日の見比べという表の意味が無くなる | 不採用（表のまま1列目を止める） |
| 週の既定：時間軸のまま | 広い画面と同じ | 7列が入らず今日が切れる | 不採用 |
| 週の既定：〈スタッフ〉×曜日の表 | 1人1行・小さい3段バーで、名前の列を止めれば今日の列を名前と並べて見られる | 帯のドラッグは時間軸に移ってから | 採用 |
| 週の既定：日ごとの一覧を新しく作る | 月の一覧とそろう | 新しい表示が増える | 不採用 |

## 結果・トレードオフ・見直す条件
- 得るもの：390px で条件の重み・特性の項目・一覧・比較が横に巻かずに使える。格子の表は1列目が見え、続きがあると分かる。週は開いてすぐ今日が見える。広い画面・URL・データは変わらない
- 失うもの：
  - カードは縦に長く、一覧の人数が多いと巻く量が増える（絞り込みで減らす）
  - 狭い画面の既定（週の表・絞り込みを畳む）が幅で変わるので、同じ URL でも幅で最初の表示が違う（押した表示は URL に書くので、送った URL は同じ表示）
  - CSS の決まり（`narrow-*`）を新しい一覧の表にも付ける手間
- 見直す条件：スマホで予定を直す（ドラッグ・確定する）使い方が増えたら、時間軸・日の画面のスマホ向けの作りを別に決める。カードが長すぎるという声が多ければ、カードの2行目以降を畳む
- 影響：PRD §3 に D220〜D222、`docs/design/pages.md` に「狭い画面の表」、各画面の設計（rules・staff・clients・compat・vacancy・week）
