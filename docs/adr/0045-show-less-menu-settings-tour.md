# ADR-0045：見せる量を減らす（UI を直感的にする第2弾）：初回は「基本」、メニューを8項目、設定を1つのタブに、ツアー3枚、操作の行の「その他 ▾」

- 日付：2026-10-21
- 状態：採用
- 関連：PRD D273〜D279（D134・D178・D180・D192・D210・D216・D226・D232 の書き換えを含む）、ADR-0024（下のタブ）・ADR-0025（ツアー）・ADR-0027（メニュー・パレット）・ADR-0028（機能の入り切り・ひな形）・ADR-0034（5つのグループ・「今日」のタブ）・ADR-0036（ボタンの3段・予定のタブ）・ADR-0044（第1弾）

## 背景
- 実機（1366×768・390×844）の評価で、個々の文言・手順より**量**が問題だった。初めて開くと機能のひな形が「すべて」で、メニューが6グループ17項目、初回の案内が6枚、月と日の操作の行にボタンが7〜8個並ぶ。これまでの直し方は「足して並べ直す」（ツアー・パレット・用語の説明・帯）で、画面や入口を減らす判断はまだしていなかった
- 予定の移り方が2つある：左のメニューの「月の予定・週の予定・日の予定」と、画面の上の［月｜週｜日］（D59・ADR-0036）。同じ画面に3つの呼び名がある（メニュー「日の予定」・下のタブ「今日」・タブ「日」）
- 「案を比べる」は日の予定の「案を変える ▾」の続き、「勤務の見込み」は勤務時間（シフト）・月の予定の続きで、メニューに独立して置く理由が薄い。「訪問の種類」「特性の項目」「条件の重み」「相性」「管理者設定」「データ」は、ふだんの作業ではたまにしか開かない設定
- 制約：契約（`src/contracts/`）・データの版（1）・URL（古いブックマーク・リンク）は変えない。保存データがある人の機能の入り切りは変えない（今まで全部入りだった人は全部入りのまま）。e2e は全部入りの前提が多い。e2e のためだけの分かれ道をアプリに置かない（ADR-0025）。主ボタンは画面に1つ

## 選択肢

### 初回の機能のひな形
1. 案A：保存データが無い（初めて開いた）ときだけ「基本」で初期データを作り、初回の案内の1枚目で「どこまで使いますか（基本／すべて）」を1問だけ聞く。保存データがある人（features が無い古いデータも）は今までどおりすべて入
2. 案B：契約の既定値（`orgSchema.features` の既定 `{}`）を「基本」にする
3. 案C：今のまま（すべて）にし、管理者設定へ誘う知らせだけ出す

### 予定と設定のメニュー
1. 案A：メニューは「予定」「設定」を1項目ずつにし、切り替えは画面の上のタブ（予定は今の［月｜週｜日］、設定は新しい［条件の重み｜相性｜訪問の種類｜特性の項目｜管理者設定｜データ］）。項目は最後に開いた表示・タブを開く。URL は今のまま、パレットは1画面ずつ引ける
2. 案B：設定を新しい1画面（`#/settings` の中にすべての欄）にまとめる
3. 案C：メニューのグループを畳める（開閉）ようにする

### 下のタブ（390px）
1. 案A：ホーム・予定・欠勤・空き状況・メニュー（「メニュー」を上の帯から下のタブへ移す）
2. 案B：ホーム・予定・今日・空き状況・〈利用者さん〉
3. 案C：今のまま（ホーム・月・週・今日・空き状況）

### 操作の行
1. 案A：月は主ボタン（進み具合の帯）と月送り・今月だけを出し、ほか（表示の選択・印刷・勤務の見込み・作り直し・マスの見方の説明）を「その他 ▾」（既存の `MenuButton`）へ。日は「この割当で確定」（見出し）・「欠勤・キャンセルを登録」・「案を変える ▾」・「元に戻す」・時間軸／順番／一覧を出し、訪問を追加・メールで送る・使い方を「その他 ▾」へ
2. 案B：操作の行を2段（よく使う／たまに使う）に分けて出したまま
3. 案C：今のまま

## 決定
すべて案A。あわせて次も決める。
- 初回の判定は store（`loadWithStatus` の `fresh`。`localStorage` に `vrdemo:data:v1` が無い）。入り切りは案を作る前に入れる（`createInitialData(today, features)`。計算に効く機能（相性・担当を限る）が案の記録と食い違って「条件が変わった」にならない）。1枚目の選択は初めて自動で開いたときだけ出し、矢印で選び直すたびには当てず、1枚目を離れるとき（次へ・とばす・Esc）に当てる。起動してからデータに手が入っていなければその入り切りで初期データを作り直し（`reset(features)`）、別のタブ・画面で変わっていれば入り切りだけ書き換える（作り直してほかの変更を消さない）。「初期状態に戻す」は今の入り切りを残し（事業所の設定なので。D216 を書き換え）、今のデータが無い（読み込みの例外から戻す）ときはすべて入
- e2e と、全機能を見せたいデモの前準備のため、DemoData と別のキー `vrdemo:features:start` に `all` があれば初回もすべて入（`{}`）で始める（ツアーの「見た」の印と同じ扱いの、ブラウザの記録。e2e は `scripts/lib/startFeatures.cjs` を `skipTour` が既定で呼ぶ）
- メニューは8項目：（見出しなし）ホーム・予定／当日・問い合わせ（欠勤・キャンセルを登録・空き状況）／人（〈利用者さん〉一覧・〈スタッフ〉一覧・勤務時間（シフト））／（見出しなし）設定。「予定」の既定は日の予定（最後に開いた表示はその間だけ覚え、保存しない。比較は覚えない）。今の画面の印は「予定」が月・週・日・比較、「設定」が設定のタブ、勤務時間（シフト）が勤務の見込みにも付く。「設定」の既定は先頭のタブ（すべて入なら条件の重み、基本なら相性）
- 勤務の見込みの入口は勤務時間（シフト）の見出しの枠のボタンと、月の予定の「その他 ▾」（ほかに拘束の上限の帯・要対応の行き先）。案を比べるの入口は日の予定の「案を変える ▾」と振り直しの帯（ほかにパレット）
- 上の帯の画面の名前・パレットの画面は「画面の一覧」（`screenSections`。メニューから外した画面も1つずつ）から引く。予定は「月の予定・週の予定・日の予定」、設定は「設定・条件の重み」など。下のタブの「今日」をやめ、呼び名を「日の予定」（タブは「日」）にそろえる。パレットの操作は「日の予定（今日）を開く」
- ツアーは3枚：ホーム（＋初回の1問）／予定で案を作って確定（［月｜週｜日］と3段）／欠勤・キャンセル。条件の重み・Ctrl+K の枚は外す（探すは上の帯の「探す」が見えている。条件は設定のタブ）。最後の枚の主ボタン「今日の予定を開く」は今のまま
- 月の凡例（「凡例を見る」の1行）は「その他 ▾」に入れず今の場所のまま（すでに畳んであり、マスの色を読む唯一の手がかりのため）。表示の選択は、〈スタッフ〉・〈利用者さん〉・混み具合を選んでいる間・休みの入力中はたたまない（何を見ているかを隠さない）

## 理由とトレードオフ
- 得るもの：初めての人のメニュー・画面が「基本」の機能だけになり、聞かれた1問で「すべて」にも1手で戻れる。メニューは 17 → 8項目で、予定の移り方は［月｜週｜日］の1つ、呼び名も1つ。下のタブで欠勤が1手、全部の画面（引き出し）も1手。ツアーは初見で読み切れる3枚。月・日の操作の行は主ボタンと毎日使う操作だけになる。URL・契約・データの版・保存データのある人の入り切りは変わらない
- 失うもの：
  - 月・週・日の予定、比較・勤務の見込み・設定の各画面へは1手増える（メニュー → タブ・画面の中の入口。パレットでは今どおり1手）
  - スマホで今日の日の予定を開くのが「予定」（最後に開いた表示）になる。別の日・月を見ていた後は、［日］のタブか日付の選択で今日へ戻す
  - 「メニュー」が上の帯から下のタブへ移り、慣れた位置が変わる
  - 月の表示の選択・印刷・作り直し、日の訪問を追加・メールで送る・使い方は「その他 ▾」を開く1手が増える
  - 初回に「基本」を選んだ人は、条件の重み・案を比べる・勤務の見込みなどがあることを、管理者設定を開くまで知らない（1問の説明と注記で補う）
  - 初回のキー `vrdemo:features:start` は e2e とデモの前準備のためのもので、画面からは書けない
  - 「どこまで使いますか」は初めて自動で開いたときだけ出すので、答えずに読み直す（ツアーを閉じずにページを読み直す）と2度目は出ない（保存データがあるため。管理者設定のひな形で選び直す）
- 捨てた案：初回の案B は契約（`orgSchema` の既定）を変えるので、features の無い古いデータ・控えまで「基本」になり、全部入りだった人の画面が変わる（データの版の移行も要る）。案C は量が減らない。メニューの案B は設定の画面が長くなり、今の URL・画面の部品（作り直しの帯・閲覧の欄・e2e）を作り直すことになる。案C は畳んだグループの中身が見えず探す手間は変わらない。下のタブの案B は〈利用者さん〉より欠勤のほうが急ぐ、案C はメニュー統合と合わない。操作の行の案B は量が減らない

## 影響
- PRD：D273〜D279 を足し、D134・D178・D180・D192・D210・D216・D226・D232 を書き換える
- 設計：`docs/design.md`（store の初回の入り切り・キー）、`docs/design/pages.md`（メニュー・下のタブ・パレット・機能の入り切り）、`pages-common.md`（ツアー）、`pages-month.md`・`pages-plan.md`（操作の行）、`pages-data.md`・`pages-rules.md`・`pages-compat.md`・`pages-staff.md`（設定のタブ・勤務の見込みの入口）
- 実装：`lib/nav`（`menuSections`・`screenSections`・`settingsTabs`・`isActiveNav`・`tabClick`）・`app/App.tsx`・`components/SettingsTabs`、`lib/commandPalette`、`lib/tour`・`components/Tour`、`store`（`start.ts`・`loadWithStatus` の `fresh`・`reset(features)`）・`seed/plans`（`createInitialData(today, features)`）、`MonthPage`・`PlanPage`・`VisitForm`・`AvailabilityPage`。契約・データの版は変えない

- 見直す条件：「予定」の既定（日）で月の作業が遠いという声が多ければ既定を月に。設定のタブで相性が見つからない声があれば「人」に戻す。初回の「基本」でほぼ全員が「すべて」を選ぶなら初回の既定を「すべて」に戻す。下のタブの「欠勤」をほとんど押さないなら〈利用者さん〉一覧に替える
