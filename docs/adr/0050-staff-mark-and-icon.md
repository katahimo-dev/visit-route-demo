# ADR-0050：〈スタッフ〉の印を1つの部品にそろえ、任意のアイコン（1〜2文字）を持たせる

- 日付：2026-10-22
- 状態：採用
- 関連：PRD D298・D299、ADR-0002（データの形）・ADR-0006・ADR-0020（Excel）・ADR-0017（メールアドレスを足したときの流儀）・ADR-0049（条件の変更の控え）

## 背景
- 〈スタッフ〉の印が画面ごとにまちまちだった：日の予定の列の見出し・担当ごとの1日・件数の偏り・比較・一覧の表は 10px の色の点、地図の凡例は色の線、週のチップは角の丸い小さな四角、相性の列は〈利用者さん〉と同じ丸に頭文字（`.dot`）、〈スタッフ〉一覧・月の見出しは `UserRound` のアイコン（月は〈利用者さん〉の見出しも同じアイコン）、勤務時間（シフト）・勤務の見込み・週の〈スタッフ〉×曜日の表・欠勤の候補・連絡の一覧・吹き出しは印なし
- 色の出どころは同じ（`staffColor`。全員を名前の順に並べた位置）だが、`useDayModel` と相性の画面がそれぞれ Map を作っていた。〈スタッフ〉のデータに色の欄は無い（〈利用者さん〉の `color` とは別）
- あわせて「〈スタッフ〉の編集の欄でアイコンを登録できるとよい。既定は苗字の最初の漢字」という要望
- 制約：データの版は上げない（無い古いデータを既定で読めるなら）。画像は localStorage を圧迫するので持たない。動き・data-testid・読み上げを変えない

## 選択肢
1. 案A：〈利用者さん〉と同じ丸に頭文字（`.dot`）を〈スタッフ〉にも使う
2. 案B：〈スタッフ〉専用の部品 `StaffMark`（角の丸い四角に1〜2文字）を作り、〈利用者さん〉は丸のまま形で見分ける
3. 案C：色の点のまま大きさだけそろえる

## 決定
案B。
- `components/StaffMark.tsx`（`StaffMark`・`StaffMarkById`）と `lib/staffMark.ts`（`staffColorMap`・`staffMarkText`・`surnameInitial`・`staffIconError`）。色は `staffColorMap(data.staff)` の1か所から引き、`useDayModel` の `colorOfStaff`（地図の線・列の上の線・週の帯の縁）も同じ関数にする
- 形は角の丸い四角、大きさは4段（xs 16・sm 20・md 28・lg 44px）。〈利用者さん〉の丸は変えず、週のチップの〈利用者さん〉の色だけ角の丸い四角から丸に直す（最小限）
- 印は `aria-hidden`。文字は CSS の `attr(data-text)` で描く（DOM の文字にしない）ので、周りの textContent・コピー・読み上げ・e2e の文字の確かめが変わらない
- 契約：`Staff.icon`（`staffIconSchema`：文字列・前後の空白なし・32コード単位まで（`STAFF_ICON_MAX_UNITS`）。`default('')`）。無い古いデータは ''（未設定）。版は上げない。この形に合わない値は読み込みを止める（メールアドレスと同じ）。repair は触らない（ほかを指さない）
- 見た目で2文字まで（`STAFF_ICON_MAX`。書記素で数え、`Intl.Segmenter` に頼る）の検査は、入れる所だけで行う：画面の `staffIconError`（編集の欄の保存）と Excel の `readStaffIcon`（行番号つきで止める）。保存データの読み込み（zod）では見ない。`Intl.Segmenter` の無い環境や数え方の違いで、保存データ全体が「壊れたデータ」にならないようにするため（読み込んだ3文字以上の値は印にそのまま出す）
- 既定の文字：名前を空白（全角も）で区切った先頭の語の最初の1文字（苗字の最初の1文字）。空白が無ければ名前の最初の1文字
- Excel：〈スタッフ〉のシートの「メールアドレス」の次に「アイコン」の列（任意。列の無い古いブックは ''、名簿の読み込みで列が無ければ今の値のまま、2文字を超えれば行付きで止める）
- 条件の変更の一覧（ADR-0049）の〈スタッフ〉の項目に「アイコン」を足す（問題 `Problem` には入らないので、アイコンだけ変えても影響する日は増えない）

## 理由とトレードオフ
- 得るもの：どの画面でも同じ形・同じ色・同じ文字で〈スタッフ〉が分かる。地図の線・時間軸の帯と色がそろう。〈利用者さん〉とは形で見分けられる。同じ苗字の頭文字が重なる人はアイコンで見分けられる
- 失うもの：
  - JSON を手で書き換えれば3文字以上のアイコンも読めてしまう（読み込みは形だけ見るため。画面・Excel からは入らない）
  - 色は名前の順で決まるので、名前を変えたり人を足したりすると色が替わる（前からの決まり。編集の見本は保存したあとの色を出す）
  - 印の文字は CSS で描くので、印だけを選んでコピーしても文字は写らない（名前は横に文字である）
  - 細い行・チップの中で 10px の点より少し場所を取る

## 影響
- 設計書：design.md §4 store・§5 の `Staff` の型と Excel の列、design/pages.md の「〈スタッフ〉の印」、pages-staff.md の編集の欄
- テスト：`lib/staffMark.test.ts`（既定の文字・アイコンの検査・色・schema の読み込み）、`excel.test.ts`（アイコンの列）、e2e-view の `staffIcon`（「訪」を保存すると一覧・日の予定の列の見出しの印が「訪」、3文字は保存しない、空に戻すと苗字の最初の1文字）
- 見直す条件：〈スタッフ〉が 9人以上で色が重なって困るという声があれば、色の欄を足す（版を上げる）か、アイコンで見分ける案内を出す
