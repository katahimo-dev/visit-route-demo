# ADR-0023：〈スタッフ〉・〈利用者さん〉の詳細を、編集の前に閲覧の欄で開く

- 状態：採用（2026-10-18）
- 関連：PRD D127〜D131・D198〜D200、ADR-0015（担当の振り直しの欄）、ADR-0022（吹き出し・`?id=`）、ADR-0026（独自の確認ダイアログ）

## 背景
〈スタッフ〉・〈利用者さん〉の画面は、一覧の鉛筆のボタンや `?id=`（相性・予定の吹き出しのリンク）で人を開くと、いきなり編集の欄になった。
- 見たいだけのときも入力欄が並び、誤って書き換えるおそれがある（利用者の要望）
- 欄の中には押すとすぐデータを書き換える部品がある（定期パターンの足す・直す・消す、休み、仮押さえの「本登録にする」「取り消す」）。欄の「保存」とは別に即時に書く
- 変更を捨てる確認は `?id=` で別の人を開くときだけで、閉じるボタン・Esc では確かめずに捨てていた
- 吹き出しの中身（`StaffDetail`・`ClientDetail`）は相性・予定で共通にしたばかり
- 〈スタッフ〉の閲覧の「相性・担当」は件数だけで、だれなのか分からず、相性の画面で探し直していた（D198〜D200）

## 決定
既存の人はまず閲覧の欄で開き、右上の「編集する」で同じ欄の中身を編集に替える。保存・取り消しで閲覧に戻る。即時に書く部品は閲覧では読むだけにする。中身の行は吹き出しと共通の部品にする。

- 状態：各画面に閲覧している人の ID（`viewId`）と編集の入力（`form`）。`form` があれば編集、無くて `viewId` の人がいれば閲覧。欄（`SidePanel`）は1つのまま、中身・見出し・下の操作だけ替え、替えたら最初の入力欄（閲覧は欄そのもの）へフォーカスを移す（`focusKey`）。右上の操作は `headActions`
- 開き方：一覧の「開く」（目のアイコン）・`?id=` は閲覧。「追加」はすぐ編集（取り消すと閉じ、保存するとその人の閲覧）。「まとめて地図に置く」で置けなかった人の「編集」は住所を入れるため編集で開く。編集中かどうかは URL に持たない
- 戻り方：保存・取り消しでフォーカスを「編集する」に戻す。「保存しました」は既存のトースト。欄の節の見出しは h3。〈スタッフ〉で振り直すものがあるときだけ従来どおり欄を閉じて振り直しの欄（ADR-0015）を開く
- 確認：変更があるまま取り消す・閉じる（×・Esc）・別の人を開く（`?id=`）ときに確認する。欄はモーダルなので、編集中は一覧などに届かない（念のためコードでも同じ確認を通す）。判定と文は `lib/viewMode`（`isDirty`：既存は保存した中身、新しい人は空の欄と JSON で比べる。特性の未入力は `cleanTraits` で取り除き、担当できる人は保存時と同じ値にそろえてから比べる。`discardDialog`：場面ごとの文）。編集中と同じ人の `?id=` は編集を続ける。変更があるときだけ `beforeunload`（ブラウザの仕様でブラウザの確認のまま）。確認は独自のダイアログ（ADR-0026。「編集を続ける」を取り消し側、「捨てて閉じる」を危険の色の確定）で、`okToDiscard` は Promise を返す
- 閲覧の中身：`components/personView` の `StaffView`・`ClientView`。行の部品は `components/personDetail` に切り出して吹き出しと共通にする。空は「—」。位置は `RouteMap` に1点で小さく（クリックしても何もしない）。定期パターンは読むだけの一覧、休みはこれからの休みと終わった件数。仮押さえの2つのボタンは編集の中だけ
- 相性・担当の名前（D198〜D200）：閲覧の欄では相手の名前を並べ、予定と同じ `PersonButton`（押すと詳細の吹き出し）にする。〈スタッフ〉は「いつもの担当の〈利用者さん〉」と記号ごとの4行（人数・名前。利用中の人だけ・12人を超えたら「あと N人」。`staffClientGroups`）、〈利用者さん〉は担当できる人・いつもの担当の名前を `ClientStaffRows` の `names` で出す。吹き出し（相性・予定）の中身は件数と名前の文字のまま（吹き出しの中に名前のボタンを置くと、前の吹き出しが消えたとき位置とフォーカスの戻り先を失うため）
- 右の欄の中から吹き出しを開くので、吹き出しは名前を含む `aria-modal` の要素（欄）の中に portal する（body 直下だとモーダルの外で読み上げがたどれない）。`SidePanel` の Tab の閉じ込めは、吹き出しの中にフォーカスがあるとき・吹き出しが端の Tab を受けて閉じたときは何もしない。Esc は吹き出しが受けて欄は閉じない。欄を巻いて名前が見える範囲から出たら閉じる
- データ・契約は変えない。確かめ方は `scripts/e2e-view.cjs`

## 検討した案
| 案 | 長所 | 短所 | 採否 |
|---|---|---|---|
| A：閲覧の欄で開き「編集する」で替える | 見るだけのとき書き換える手段が画面に無い。吹き出し→閲覧→編集と深く入れる。行の部品を共通にでき直し漏れが減る | 直すとき1回多く押す。項目の並べ方を閲覧と編集で2つ持つ | 採用 |
| B：編集の欄のまま入力欄を読み取り専用に | 作りが単純に見える | 枠・select で読みにくい。即時に書く部品・地図のピン・住所検索ボタンを個別に止める必要 | 不採用 |
| C：閲覧は別の画面（`#/clients/:id` など） | 閲覧と編集が分かれる | 画面と経路が増え、欄の動きと離れる。`?id=` の行き先も変わる | 不採用 |
| D：今のまま確認だけ足す | 最小 | 誤って書き換えるおそれが残る | 不採用 |
| 名前：相性の画面へ `?id=` で飛ぶリンクだけ | 簡単 | だれかは分からないまま | 不採用 |
| 名前：件数を押すとその記号の人で相性画面を絞り込む | 絞れる | 画面を移り閲覧の欄を離れる | 不採用 |

## 結果・トレードオフ・見直す条件
- 得るもの：見るだけで誤って書き換えない。閉じる・Esc でも変更を捨てる前に確かめる。項目を足したときの直し漏れが減る。閲覧の欄から相手の人へすぐ移れる
- 失うもの：直すとき「編集する」を1回余計に押す。保存のあと続けて直すときも押し直す。ブラウザの戻る・左のメニューでの画面移動では確認を出せず、編集中の変更は黙って捨てる（確認は欄の中の操作・`?id=`・再読込・タブを閉じるときだけ）
- 見直す条件：「編集する」を押す手間の声が多ければ、一覧に鉛筆（すぐ編集）を並べるかを見直す。閲覧の項目の並びは事業所でのデモの反応で見直す
- 影響：`e2e-compat`・`e2e-details` は閲覧の欄を、`e2e-address` は「編集する」を押してから確かめる
