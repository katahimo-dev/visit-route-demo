# ADR-0023：〈スタッフ〉・〈利用者さん〉の詳細を、編集の前に閲覧の欄で開く

- 日付：2026-10-18
- 状態：採用（利用者が推奨どおりに決定（2026-10-18）。PRD D127〜D131）

## 背景
〈スタッフ〉の画面（`pages/StaffPage`）・〈利用者さん〉の画面（`pages/ClientsPage`）は、一覧の鉛筆のボタンや `?id=`（相性・予定の吹き出しのリンク。ADR-0022）で人を開くと、いきなり編集の欄（`SidePanel` の入力欄）になる。

- 見たいだけのときも入力欄が並ぶので、操作を誤って書き換えるおそれがある（利用者の要望）
- 欄の中には、押すとすぐデータを書き換える部品がある（定期パターンの 足す・直す・消す `PatternsSection`、休み `ClientLeavesSection`、仮押さえの「本登録にする」「仮押さえを取り消す」）。欄の「保存」とは別に即時に書く
- 〈利用者さん〉は保存しても欄を開いたまま、〈スタッフ〉は最終勤務日を入れて振り直すものがあれば欄を閉じて担当の振り直しの欄（`OffboardPanel`。ADR-0015）を開く
- 変更を捨てる確認は `?id=` で別の人を開くときだけにあり（ADR-0022）、閉じるボタン・Esc では確かめずに捨てていた
- 吹き出しの中身 `StaffDetail`・`ClientDetail`（`components/personDetail`）は相性・予定で共通にしたばかり

## 選択肢
1. 案A：既存の人はまず閲覧の欄で開き、右上の「編集する」で同じ欄の中身を編集に替える。保存・取り消しで閲覧に戻る。即時に書き換える部品は閲覧では読むだけの一覧にする。中身の行は吹き出しと共通の部品に切り出す
2. 案B：編集の欄のまま、入力欄を読み取り専用（`readOnly`・`disabled`）にして「編集する」で外す
3. 案C：閲覧は別の画面（`#/clients/:id` など）にし、編集は今の欄のまま
4. 案D：今のまま（編集の欄で開く）で、閉じる・取り消すときの確認だけ足す

## 決定
案A。

- 状態：各画面に「閲覧している人の ID（`viewId`）」と「編集の入力（`form`）」を持つ。`form` があれば編集、無くて `viewId` の人がデータにいれば閲覧。欄（`SidePanel`）は1つのまま中身・見出し・下の操作だけ替え、替えたら最初の入力欄（閲覧は欄そのもの）へフォーカスを移す（`SidePanel` の `focusKey`）。右上の操作は `SidePanel` の `headActions`
- 開き方：一覧の行の「開く」（目のアイコン）・`?id=` は閲覧。「追加」はすぐ編集（取り消すと閉じ、保存するとその人の閲覧）。「まとめて地図に置く」で置けなかった人の「編集」は、住所を入れるためなので編集で開く。編集中かどうかは URL に持たない
- 戻り方：保存・取り消しで閲覧に戻り、フォーカスを「編集する」に戻す（`SidePanel` の `focusKey` が変わったとき `data-return-focus` の要素を先に探す）。「保存しました」は今までのトースト（`output`）で知らせる。欄の中の節の見出しは h3（`SectionLevelProvider`。この2つの画面の欄だけ）。〈スタッフ〉で振り直すものがあるときだけは今までどおり欄を閉じて振り直しの欄を開く
- 確認：変更があるまま 取り消す・閉じる（×・Esc）・別の人を開く（`?id=`）ときは `confirm`。欄はモーダル（後ろは押せない）なので、編集中に「追加」・一覧の「開く」・「担当の振り直しを開く」・「まとめて地図に置く」の「編集」は届かない（念のためコードでは同じ確認を通す）。判定と文は `lib/viewMode` の純粋関数（`isDirty`：既存の人は保存した中身、新しい人は開いたときの空の欄と JSON で比べる。特性の未入力（null・空の文字・空の配列）は `cleanTraits` で取り除いてから比べる。〈利用者さん〉の担当できる人は、比べる前に保存のときと同じ値（限らなければ空、限るなら利用中の人だけ）にそろえる。`discardMessage`：場面ごとの文）。`?id=` の確認もこれにそろえ、編集中と同じ人の `?id=` では編集を続ける。変更があるときだけ `beforeunload` を付け、再読込・タブを閉じるときにブラウザの確認を出す
- 閲覧の中身：`components/personView` の `StaffView`・`ClientView`。行の部品（移動手段・特性・稼働時間・最終勤務日・相性の件数・段階・地区・条件・担当できる人とその他）は `components/personDetail` に切り出し、吹き出しと共通。空の項目は「—」（`orDash`）。〈利用者さん〉の位置は `RouteMap` に1点（クリックしても何もしない）で小さく出す。定期パターンは読むだけの一覧、休みはこれからの休み（`splitLeaves`）と終わった件数。仮押さえの2つのボタンは編集の中だけ

## 理由とトレードオフ
- 得るもの：見るだけのときに書き換える手段が画面に無い（入力欄・即時に書くボタンを出さない）。吹き出し → 画面の閲覧 → 編集と、詳しさの順に深く入れる。閉じる・Esc でも変更を捨てる前に確かめる。行の部品を共通にしたので、項目を足したときの直し漏れが減る
- 失うもの：直したいときに1回多く押す（「編集する」）。ブラウザの戻る・左のメニューでの画面の移動（HashRouter の経路の切り替え）では確認を出せず、編集中の変更は黙って捨てる（確認が出るのは欄の中の操作・`?id=`・再読込・タブを閉じるときだけ）。〈利用者さん〉の保存のあとに続けて直すときも「編集する」を押し直す。閲覧と編集で項目の並べ方を2つ持つ（行の部品は共通だが、編集の欄の入力は別）
- 案B を採らない理由：入力欄の見た目のまま読み取り専用だと、読みにくく（枠・選択肢の select）、即時に書く部品の扱いが別に要る。地図のピン・住所の検索ボタンも個別に止める必要がある
- 案C を採らない理由：画面と経路が増え、一覧から開いて閉じる今の動き（欄）と離れる。`?id=` のリンクの行き先も変わる
- 案D を採らない理由：要望（誤って書き換えるおそれ）が残る

## 影響
- 設計書：§4 pages（〈スタッフ〉・〈利用者さん〉の閲覧の欄）、`components/personDetail`・`components/personView`・`lib/viewMode`、`SidePanel` の `headActions`・`focusKey`
- データ・契約：変えない（`src/contracts/` に足すものは無い。画面の状態だけ）
- e2e：`scripts/e2e-view.cjs` を足した。`?id=` で編集の欄が開くことを確かめていた e2e-compat・e2e-details は閲覧の欄を、e2e-address は「編集する」を押してから確かめる
- 見直す条件：「編集する」を押す手間の声が多ければ、一覧に鉛筆（すぐ編集）を並べて置くかを見直す。閲覧の欄の項目の並びは訪問の事業所でのデモの反応で見直す

## 追記（2026-10-18。ADR-0026）
- 変更を捨てる前の確認は、ブラウザの `confirm` から独自の確認ダイアログ（ADR-0026。PRD D146〜D150）に替えた。文は `lib/viewMode` の `discardDialog`（見出し「変更を捨てて、欄を閉じますか？」など・本文「◯◯（〈スタッフ〉）の変更を保存していません。」・確定「捨てて閉じる」など（危険の色）・取り消し「編集を続ける」）。`okToDiscard` は Promise を返す。再読込・タブを閉じるときの `beforeunload` は、ブラウザの仕様で置き換えられないのでブラウザの確認のまま

## 追記（2026-10-18。PRD D198〜D200）
- 背景：〈スタッフ〉の閲覧の欄の「相性・担当」は件数（◎・○・△・× といつもの担当の人数）だけで、だれなのか分からず、相性の画面で探し直していた（利用者の要望）。〈利用者さん〉の閲覧の欄の担当できる人・いつもの担当も名前の文字だけで、そこから〈スタッフ〉を見られなかった
- 決定：閲覧の欄では相手の名前を並べ、名前を予定と同じ `PersonButton`（押すと詳細の吹き出し。ADR-0022 追記）にする。〈スタッフ〉は「いつもの担当の〈利用者さん〉」と記号ごとの4行（人数・名前。利用中の〈利用者さん〉だけ・〈利用者さん〉の並びのまま・12人を超えたら「あと N人」）。分けるのは `lib/compatView` の `staffClientGroups`（純粋関数）。〈利用者さん〉は `ClientStaffRows` に名前の描き方（`names`）を渡せるようにし、閲覧の欄だけ `PersonButton` で並べる
- 吹き出し（相性・予定）の中身は件数と名前の文字のまま。吹き出しの中に名前のボタンを置くと、押した名前（＝開いている吹き出しの中）が新しい吹き出しの置き場所になり、前の吹き出しが消えると位置もフォーカスの戻り先も失うため
- 右の欄の中から開くので、吹き出しの重なりを右の欄（1100）の上・コマンドパレット（1150）の下（1120）にし、`SidePanel` の Tab の閉じ込めは吹き出しの中にフォーカスがあるときは吹き出しに任せる。Esc は吹き出しが受けて止める（欄は閉じない）
- 採らなかった案：相性の画面へ `?id=` で飛ぶリンクだけ置く（だれかは分からないまま）、件数を押すとその記号の人で相性の画面を絞り込む（画面を移るので閲覧の欄を離れる）
- e2e：`scripts/e2e-view.cjs` の `names`
