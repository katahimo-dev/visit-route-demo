# ADR-0037：用語の説明の目印を ⓘ にし、同じ語の説明は1画面で1か所にする

- 状態：採用（2026-10-19）
- 関連：PRD D240〜D242（D174・D175 の言い回しも）、ADR-0025 追記（用語の説明の部品）

## 背景
用語の説明（`components/Term`。PRD D175）は、用語の文字に点線の下線を引くボタンだった。説明を付ける語が増える（AI案・固定・確定・未確定・プリセット・要対応・条件が変わった。D242）と、点線が1画面に何本も並ぶ。名前のボタン（`PersonButton`）も点線の下線なので、どれが用語の説明でどれが名前の詳細か見分けにくい。勤務の見込みのように同じ語（出勤〜退勤（拘束）・空き時間（待ち））が上の設定・合計の表・日ごとの表に繰り返し出る画面では、同じ説明の入口が3つずつあった。

タッチでは、文字の高さ（20px ほど）しか押せる所が無い。

## 選択肢
1. 案A：点線の下線のまま、語を増やす
2. 案B：用語の文字は普通の文字にし、後ろに ⓘ だけのボタン（`aria-label`「〈用語〉の説明」）を置く
3. 案C：用語の文字と後ろの小さな ⓘ を1つのボタンにし、下線はやめる。同じ画面の同じ語は最初の1か所だけ説明つきにする

## 決定
案C。

- ボタンは用語の文字と ⓘ（lucide の `Info`、`aria-hidden`）。読み上げの名前は見える用語の文字（ⓘ は読まない）。説明は今どおり `aria-describedby` の先の `role="tooltip"`
- 下線は付けない。フォーカスの輪はボタン全体。ⓘ は文字に合わせて 1em。`pointer: coarse` では ⓘ のまわり 24px 角を押せる（WCAG 2.5.8。文字の上も同じボタン。見た目は変えない）。44px は 390px で隣の操作（選ぶ欄・凡例の開け閉め・畳んだ節）に重なったのでとらない。印刷では ⓘ を出さない
- 同じ画面で同じ語が繰り返し出るときは、最初の1か所（上の設定・表の最初の行・最初の表の見出し）だけ説明つきにし、ほかは文字だけ（`Term` の `plain`）。開く欄（右の欄・吹き出し）は別の画面として数える

## 理由とトレードオフ
- 得るもの：説明のある語が増えても、点線が並ばない。名前のボタン（点線）と用語の説明（ⓘ）の見分けがつく。見える文字と読み上げの名前がそろう（案B の `aria-label` は見える文字と別の名前になる）。今までの開け閉め（重ねる・Tab・Esc・押す・同時に1つ）と e2e はそのまま使える
- 失うもの：ⓘ のぶん語が少し長くなる。説明の入口は ⓘ だけでなく文字の上にもある（文字を押しても開く）ので、案B より押せる所が広い。表の2行目からは説明が無いので、上の1か所へ戻って読む

## 影響
- `src/components/Term.tsx`・`term.css`（`plain` を足す）、`src/lib/glossary.ts`（D242 の語）、各画面の `Term` の付け方。`docs/design/pages-common.md` の「用語の説明」
- 名前のボタン（`PersonButton`）の点線と小さな i は変えない（別の部品）
- 見直す条件：ⓘ が名前の i（`PersonInfo`）や長い説明の「説明」（`Hint`。`ui.tsx` の summary の `Info`）と紛れるという声が出たとき、説明を付ける語がさらに増えて ⓘ も多すぎるとき
