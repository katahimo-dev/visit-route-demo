# ADR-0024：スマホのメニュー（上の帯・引き出し・下のタブ）と、週間の時間軸の〈利用者さん〉の初期値

- 日付：2026-10-18
- 状態：採用（1. スマホのメニューは利用者が提案どおりに決定（2026-10-18）。PRD D132〜D135。2. 週間の時間軸の〈利用者さん〉の初期値は利用者の要望（2026-10-18）で、引き継ぎの決まりは推奨どおり。PRD D136〜D139）

## 1. スマホのメニュー

### 背景
狭い画面（幅860px以下。`styles.css` の `@media (max-width: 860px)`）では、左のメニュー（`src/app/App.tsx` の `AdminShell`。ADR-0019）が上に横一列で並ぶ。

- 13項目が横に並ぶので、横に巻かないと見えない（右端をぼかしているだけ）
- グループの見出し（予定・問い合わせ・〈利用者さん〉・〈スタッフ〉・割当の設定）を隠しているので、〈利用者さん〉と〈スタッフ〉の「一覧・編集」が見分けられない
- 右下の地図（`MapDock`）・左下の欠勤の振り直しの帯（`ReassignDock`）・トーストは、画面の下端からの位置を CSS の変数（`--map-dock-*`・`--reassign-dock-top`）で避け合っている
- 端末の前提は「管理者役は PC、スマホは表示の確認」（PRD §7）。各画面の中身はスマホ向けに作り直さない

### 選択肢
1. 案A：上の帯にロゴと今の画面の名前（グループの見出し＋項目名）・「メニュー」・日付の切り替え。「メニュー」で左から引き出し（全部のメニューを見出し付きの縦並び。dialog）。下によく使う4つ（月・週・日・空き状況）のタブを常に並べる
2. 案B：今の横一列のまま、グループの見出しだけ出す
3. 案C：下のタブだけ（残りは「その他」のタブから一覧）
4. 案D：引き出しだけ（下のタブなし）

### 決定
案A（利用者が提案どおりに決定）。決まりは `lib/nav.ts`（純粋関数）の1か所：今の画面をどの項目と見るか（`activeNavPath`。比較は日の続きなので「日」＝ADR-0019 のまま）、上の帯の名前（`navTitle`）、下のタブ（`bottomTabs`）。引き出しは `src/app/NavDrawer.tsx`（`SidePanel` と同じ閉じ込め方・フォーカスの戻し方）。下のタブの高さは CSS の変数 `--bottom-tabs-h`（広い画面・印刷では 0）にし、浮いている部品・本文の下の余白・トーストはこの変数で避ける。

### 理由とトレードオフ
- 得るもの：横に巻かずに全部のメニューに届く（2手）。よく使う予定・空き状況は1手。今の画面の名前で「一覧・編集」を見分けられる。広い画面の見た目は変わらない（足した部品は 861px 以上で `display: none`）。今の画面の決まりが1か所になり、左のメニュー・引き出し・タブ・名前で食い違わない
- 失うもの：狭い画面で上の帯が2段になることがある（帯の高さを測って `--header-h` に出し、貼り付く要素がずれないようにする）。下のタブの分（約58px＋ホームバー）だけ本文が狭くなる。メニューの項目が左のメニューと引き出しの2か所に描かれる（同じ部品 `NavGroups`）
- 案B は横に巻くのが残る。案C は「その他」の中身がもう1枚の画面になり、〈利用者さん〉・〈スタッフ〉の見出しの問題が残る。案D はよく使う画面にも毎回2手かかる

### 影響
- 画面：`App.tsx`（`AdminShell`・`NavGroups`）、`app/NavDrawer.tsx`、`styles.css`（860px以下の上の帯・下のタブ・引き出し・印刷）、`plan.css`（`.reassign-dock` の860px以下の bottom）、`components/ui.tsx`（`FOCUSABLE` を export）。データ・契約（`src/contracts/`）・URL は変えない
- 印刷：下のタブ・引き出しは出さない。用紙の幅が860px以下のときは上の帯も出さない（左のメニューはもともと860px以下で隠れる）。PC で印刷しても、A4 縦（印刷の幅は約 720〜800px）は860px以下なので狭い画面の決まり（左のメニューを出さない・上の帯を出さない・本文は1列）になる。A4 横（約1050px）は広い画面の決まり（左のメニューが出る）のまま。どちらも下のタブ・引き出しは出ない
- 確かめ：`scripts/e2e-mobile.cjs`（390×844 と 1400px）
- レビュー（PR #35）で足したこと：今の画面の項目（引き出し）・下のタブを押し直しても移り直さない（URL のクエリ＝画面の状態を消さない）。引き出しは body の直下に出し、開いているあいだ `#root` を inert、`aria-haspopup="dialog"`・開いているときだけ `aria-controls`・中の一覧は「画面の一覧」・見出しは h2。裏のロックは数を数える `useBodyScrollLock`（`lib/scrollLock`）にまとめ、右の欄（`SidePanel`）と重なっても最後の1つまで戻さない。開いたまま広い画面へ戻したら、フォーカスは左のメニューの今の項目へ。viewport に `viewport-fit=cover` を足し、上の帯・本文・タブ・引き出し・地図・〈スタッフ〉のスマホ画面の余白を safe-area で避ける（Chromium では safe-area が 0 なので、実機の横向きでは未確認）
- 見直す条件：スマホで予定を直す使い方（実際の操作）が増えたら、各画面の中身（表・時間軸）のスマホ向けの作りを別に決める。下のタブの4つは、デモの反応で入れ替える

## 2. 週間の時間軸の「〈利用者さん〉で見る」の初期値（追記）

### 背景
週間（`pages/WeekPage`）の時間軸の「〈利用者さん〉で見る」は、検索欄 `ClientPicker` で人を選ぶ（8人まで・`?client=`。PRD D61・D62・D108）。

- 選んでいないと空で「選んでいません」。開くたびに近道か検索で選び直す手間がかかる（利用者の要望）
- 〈スタッフ〉で見るときはチップ `PickChips` で全員が並び、選ばなくても全員が出る。見る人によって操作が違う
- 表（〈利用者さん〉×曜日。ADR-0021）から移ったときだけ、時間軸の選択が空なら表の先頭8人を引き継ぐ。初期値を足すと「空なら」の条件と食い違う
- 表の絞り込みは `?cf=` で、既定のままなら URL に書かない

### 選択肢
1. 案A：この週に訪問がある人をチップで並べ（表の既定と同じ人・同じ順）、`?client=` が無ければ先頭8人を初期値にする（URL に書かない）。検索欄は「ほかの人を探す」に畳んで残す。表からの引き継ぎは「`?client=` があればそれ。無ければ、表で絞り込んでいればその先頭8人、絞り込んでいなければこの週の先頭8人」
2. 案B：初期値を URL に書く（開いたら `?client=` を先頭8人で埋める）
3. 案C：チップは足さず、検索欄のまま初期値だけ先頭8人にする
4. 案D：引き継ぎは今のまま（選択が空なら表の先頭8人）

### 決定
案A。決まりは `lib/timelineClients.ts`（純粋関数）の1か所：初期値 `defaultTimelineClients`、選んでいる人 `timelineSelection`、URL に書く値 `clientParamOf`（初期値と同じ人なら書かない）、チップの人 `timelineChipIds`、表からの引き継ぎ `handoffFromTable`。チップは〈スタッフ〉と同じ `PickChips`（`actions` で「全部外す」「先頭8人に戻す」を足す）、検索欄は `ClientPicker`（`showChips={false}`）。

### 理由とトレードオフ
- 得るもの：開いたらすぐ帯が見える。〈スタッフ〉で見るときと同じ操作・同じ i。初期値を URL に書かないので、週を送るとその週の人になり（前の週の人が残らない）、URL も短い。引き継ぎと初期値が1つの決まりになり、表で絞り込まずに移ったときも開いたときと同じ人が出る
- 失うもの：この週に訪問がある人が多いとチップが何行にもなる（今のデータで20人・1400px で4行ほど、390px で10行ほど）。レビュー（PR #35）で、畳んだときは選んでいる人と2行ぶんだけ出し、残りは「あと N人」で開くことにした（PRD D140。下の「畳む」）。「全部外す」のあと（`?client=` が空）は週を送っても空のまま（明示して外したので）。表で絞り込んで移ったあとは `?client=` に書くので、週を送っても同じ人のまま
- 案B は週を送ると前の週の人が残り、URL も毎回長くなる。案C は〈スタッフ〉で見るときと操作がそろわず、だれが選ばれているか一目で分からない。案D は空なら引き継ぐ条件が初期値と食い違う（空のときが無くなる）

### 影響
- 画面：`pages/WeekPage`、`components/PickChips`（`actions`）、`components/ClientPicker`（`showChips`）、`pages/week.css`。データ・契約（`src/contracts/`）は変えない。URL の `?client=` の意味は「あればそれ」で今と同じ（無いときの意味が「空」から「先頭8人」に変わる）
- 確かめ：`scripts/e2e-drag.cjs`（初期値の8人・上限の文・「全部外す」「先頭8人に戻す」と、その状態で帯をドラッグできること）、`scripts/e2e-details.cjs`（〈利用者さん〉のチップの i）
- 見直す条件：この週に訪問がある人が多い事業所（数十人）でチップが長すぎれば、チップも絞り込み（`ClientFilter`）で減らすか、「もっと見る」で畳むかを決める

### 畳む（レビュー（PR #35）で追記。PRD D140）
- 案1（採用）：選んでいる人と上から2行ぶんだけ出し、残りは「あと N人」で開く。選んでいる人は2行に入らなくても出し、並び順は変えない（押した人が動かない）。開いているかは画面の中だけで覚える
- 案2：選んでいる人を前へ並べ替える（押すたびに位置が変わる）
- 案3：チップにも絞り込みの欄を付ける（20人では重い）
- 行は描いた位置（上端）で数える（`lib/fold` の `foldHidden`。幅・人・選んでいるかが変わったときだけ描く前に測り直す）。390px では選んでいる8人だけで4〜5行になるので、時間軸の上端は最初の画面の少し下（約930px／844px）。1400px では最初の画面に入る（約530px）
- 見直す条件：390px で時間軸まで遠いという声があれば、狭い画面では選んでいる人も「あと N人」に含める（✓の人数だけ見出しに出す）かを決める
