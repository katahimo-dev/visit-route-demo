# ADR-0024：スマホのメニュー（上の帯・引き出し・下のタブ）と、週間の時間軸の〈利用者さん〉の初期値

- 日付：2026-10-18
- 状態：採用（1. スマホのメニューは利用者が提案どおりに決定（2026-10-18）。PRD D132〜D135）

## 1. スマホのメニュー

### 背景
狭い画面（幅860px以下。`styles.css` の `@media (max-width: 860px)`）では、左のメニュー（`src/app/App.tsx` の `AdminShell`。ADR-0019）が上に横一列で並ぶ。

- 13項目が横に並ぶので、横に巻かないと見えない（右端をぼかしているだけ）
- グループの見出し（予定・問い合わせ・〈利用者さん〉・〈スタッフ〉・割当の設定）を隠しているので、〈利用者さん〉と〈スタッフ〉の「一覧・編集」が見分けられない
- 右下の地図（`MapDock`）・左下の欠勤の振り直しの帯（`ReassignDock`）・トーストは、画面の下端からの位置を CSS の変数（`--map-dock-*`・`--reassign-dock-top`）で避け合っている
- 端末の前提は「管理者役は PC、スマホは表示の確認」（PRD §7）。各画面の中身はスマホ向けに作り直さない

### 選択肢
1. 案A：上の帯にロゴと今の画面の名前（グループの見出し＋項目名）・「メニュー」・日付の切り替え。「メニュー」で左から引き出し（全部のメニューを見出し付きの縦並び。dialog）。下によく使う4つ（月・週・日・空き状況）のタブを常に並べる
2. 案B：今の横一列のまま、グループの見出しだけ出す
3. 案C：下のタブだけ（残りは「その他」のタブから一覧）
4. 案D：引き出しだけ（下のタブなし）

### 決定
案A（利用者が提案どおりに決定）。決まりは `lib/nav.ts`（純粋関数）の1か所：今の画面をどの項目と見るか（`activeNavPath`。比較は日の続きなので「日」＝ADR-0019 のまま）、上の帯の名前（`navTitle`）、下のタブ（`bottomTabs`）。引き出しは `src/app/NavDrawer.tsx`（`SidePanel` と同じ閉じ込め方・フォーカスの戻し方）。下のタブの高さは CSS の変数 `--bottom-tabs-h`（広い画面・印刷では 0）にし、浮いている部品・本文の下の余白・トーストはこの変数で避ける。

### 理由とトレードオフ
- 得るもの：横に巻かずに全部のメニューに届く（2手）。よく使う予定・空き状況は1手。今の画面の名前で「一覧・編集」を見分けられる。広い画面の見た目は変わらない（足した部品は 861px 以上で `display: none`）。今の画面の決まりが1か所になり、左のメニュー・引き出し・タブ・名前で食い違わない
- 失うもの：狭い画面で上の帯が2段になることがある（帯の高さを測って `--header-h` に出し、貼り付く要素がずれないようにする）。下のタブの分（約58px＋ホームバー）だけ本文が狭くなる。メニューの項目が左のメニューと引き出しの2か所に描かれる（同じ部品 `NavGroups`）
- 案B は横に巻くのが残る。案C は「その他」の中身がもう1枚の画面になり、〈利用者さん〉・〈スタッフ〉の見出しの問題が残る。案D はよく使う画面にも毎回2手かかる

### 影響
- 画面：`App.tsx`（`AdminShell`・`NavGroups`）、`app/NavDrawer.tsx`、`styles.css`（860px以下の上の帯・下のタブ・引き出し・印刷）、`plan.css`（`.reassign-dock` の860px以下の bottom）、`components/ui.tsx`（`FOCUSABLE` を export）。データ・契約（`src/contracts/`）・URL は変えない
- 印刷：下のタブ・引き出しは出さない。用紙の幅が860px以下のときは上の帯も出さない（左のメニューはもともと860px以下で隠れる）
- 確かめ：`scripts/e2e-mobile.cjs`（390×844 と 1400px）
- 見直す条件：スマホで予定を直す使い方（実際の操作）が増えたら、各画面の中身（表・時間軸）のスマホ向けの作りを別に決める。下のタブの4つは、デモの反応で入れ替える
