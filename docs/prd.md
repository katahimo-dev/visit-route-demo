## 1. 背景と課題

PoC本体（visit-route-poc）は Firebase・Cloud Functions・Python（OR-Tools）で組んでおり、
デプロイ・費用・認証の準備が重く、協力法人や社内に「触ってもらって意見をもらう」サイクルが遅い。

また、ヒアリング（alca様）で、管理者が割当を決めるときに見ているのは距離だけでなく
**顧客とスタッフの相性・スタッフの特性（資格・経験・得意分野）・顧客の希望（性別・人柄・継続）**だと分かっている。
PoC本体はこのうち「性別希望」と「NG」しか持たず、相性は登録のみ（学習しない）とスコープ外にしている。

本デモ版は次の2つを目的にする。

1. **すぐ触れる**：URLを開くだけで動く。サーバー・ログイン・費用なし。データはブラウザに残す。
2. **割当の条件を柔軟に試す**：ClassClassify のように「項目」と「重み（0〜5）」と「必須」で、
   事業所ごとに違う割当の考え方を管理者自身が組み立て、AI案がどう変わるかをその場で見られる。

デモで集めた反応（どの項目・重みが使われるか）を、PoC本体の要件（相性・希望の扱い）に戻す。

追加の要望（2026-10-16。ADR-0012）：

- 日々の訪問は、利用者さんごとの**決まった曜日・時刻の繰り返し**（定期パターン）が大半。1日ずつ訪問を入れて案を作るのでは、一月の見通しが立たない。一月分を先にまとめて作り、週・月で見渡したい
- 新規の問い合わせ（「火曜の午前に週1回、リハビリを」）に、**空き状況を即答できず機会を逃している**。どの曜日のどの時間なら受けられるかを、移動も含めてすぐ答えたい
- 訪問には**種類**（介護・リハビリなど。別法人では家事代行・ベビーシッター）があり、種類によって担当できる人（資格）が変わる

## 4. やらないこと（スコープ外）

- ログイン・アカウント・事業所の分離・サーバー保存・複数人での同時編集（1ブラウザ1事業所）
- Firebase・Cloud Functions・Python 最適化サービス・Google Maps Platform（移動時間は直線距離からの概算のみ）。D97〜D101 の道順のリンクは Google Maps Platform（キーの要る API）ではなく、公開の Maps URLs のリンクを作るだけ（ADR-0018）
- スタッフの記録（はじめる/おわる）・位置計測・ジオフェンス・勤怠・承認・CSV・実証データ出力・通知（D23 の Excel はマスタと予定の入出力で、記録の出力ではない）
- Excel の名簿（ADR-0020）：名簿の読み込みで人を消すこと（総入れ替えでも終了・休止にするだけ）、〈利用者さん〉・〈スタッフ〉以外のシート（訪問・相性・定期パターンなど）だけの部分の入出力、名簿の差分の一覧（どの列が変わったか）の表示、読み込みの取り消し（控えは「控え（JSON）」で取る）
- 〈利用者さん〉の絞り込みまわり（ADR-0021）：地区の手直しの欄・地区のマスタ（住所から毎回取り出す）、絞り込みの保存・名前を付けた絞り込み、〈利用者さん〉の画面の絞り込みを URL に残すこと（週間の表だけ `?cf=`）、住所の表記ゆれの自動の直し（「ケ」「ヶ」・旧町名など）
- スマホのメニューまわり（ADR-0024）：指でなぞって引き出しを開く操作、下のタブの並びを利用者が選ぶこと、各画面の中身（表・時間軸など）のスマホ向けの作り直し（スマホは今までどおり表示の確認が主。§7）
- コマンドパレットまわり（ADR-0027）：最近使ったもの・よく使うものの記録と並べ替え、打ち間違いを許すあいまいな一致、訪問・日付・設定の値（条件・種類の中身など）の検索、パレットの中での書き換え（操作は今ある画面の入口へ移るだけ）、キーの割り当ての変更、〈スタッフ〉のよみ（データに持たない）
- 実在の個人情報の入力を前提にした機能（注意書きを出す。保存は利用者のブラウザだけ）
- 相性の**学習**（実績から自動で相性を推定する）。相性は人が入れる
- 勤務シフト（スタッフの出勤日・勤務時間）の自動作成。月まとめ作成（D41）は、決まった勤務の中で訪問の割当を**1日ずつ**作るだけ。日をまたいだ最適化（月の件数の均等・同じ人が続けて担当する並べ方）はしない（偏りは D51 の表で見るだけ。ADR-0012）
- 事業所（法人）の分離は今までどおりしない。別法人（家事代行・ベビーシッター）は別のブラウザ・別のデータ（JSON・Excel）で使う（ADR-0012）
- 定期パターンの日付指定（毎月15日）・祝日の扱い。繰り返しは週単位（毎週〜4週ごと）と毎月の第N曜日（D64）だけ
- 〈利用者さん〉の休みで、訪問を自動で振り替える（別の日に移す）こと・確定した割当を勝手に作り直すこと（注意を出すだけ。D65）。訪問先の決まりごとを割当の条件に使うこと（表示だけ。D66）。案内文の送信（コピーと、メールアプリを開くだけ。送信は人が押す。D67・D95）
- 希望休まわり（ADR-0014）：スタッフ本人からの希望休の申請・承認・締め切り、月の休みの日数の決まり（月10日など）の確認・自動の割り振り、希望休を考えた勤務シフトの自動作成、有給・勤怠の管理。担当を限る決まりの期間（〇月まで）・理由の記録。印刷の書式の細かい設定（文字の大きさ・載せる項目）・PDF の直接の書き出し（ブラウザの印刷を使う）
- 実績・打刻・サイン・請求様式・LINE 連携・集金はやらない（PoC本体の範囲。ADR-0015）。稼働の見込み（D72）は予定からの見込みで、実働・拘束の記録（勤怠）ではない。拘束の上限を AI案の条件にすること（注意だけ）、実働の上限の確認、退職者の訪問の自動の作り直し（D71。利用者が月間・日の画面で作り直す）、段階ごとの期日・やることの管理・紹介元とのやりとりの記録（D73）、当日キャンセルの請求・キャンセル料（D74）
- 問い合わせの試算（D46）で、他の人の予定を動かして入れる提案（入れ替え）。見るのは空き時間に入るかだけ
- PoC本体へのコードの書き戻し・自動同期（反応と仕様だけ PoC本体の PRD に戻す）

## 7. 制約

- 期限：初回デモ用の公開は**着手から1週間以内**（PoC本体 α版＝10月末と並行のため、PoC本体の作業を止めない分量にする）
- 予算：0円（GitHub Pages・GitHub Actions の無料枠）。そのため**公開リポジトリ**が前提（GitHub Free で Pages を使う条件）
- 使う技術：React + Vite + TypeScript、Leaflet（国土地理院の地図。キー不要）、Web Worker。PoC本体の `packages/shared` の純粋関数と seed の生成ロジックを**写して**使う
- 端末：管理者役は PC のブラウザ（Chrome・Edge・Safari の最新）。スマホは表示の確認だけ
- 法規・セキュリティ：架空データのみを同梱する。公開リポジトリに実データ・パスワード・キーを置かない。利用者が入れたデータは端末の外に送らない（外部送信は地図タイルの取得と、利用者がボタンを押したときの郵便番号・住所の検索（郵便番号検索サービス・国土地理院）。送るのは郵便番号か住所の文字だけ。D90・D120。ADR-0016）。メール（D92〜D95）は `mailto:` で端末のメールアプリを開くだけで、アプリからは何も送らないので外部送信に当たらない（送信は人がメールアプリで押す。ADR-0017）。道順のリンク（D97〜D101）も Google マップの公開の URL を画面・メールに置くだけで、アプリからは何も送らないので外部送信に当たらない（押した人の端末が Google マップを開き、そのとき URL の場所が Google に渡る。ADR-0018）
