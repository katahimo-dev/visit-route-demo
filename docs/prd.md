## 1. 背景と課題

PoC本体（visit-route-poc）は Firebase・Cloud Functions・Python（OR-Tools）で組んでおり、
デプロイ・費用・認証の準備が重く、協力法人や社内に「触ってもらって意見をもらう」サイクルが遅い。

また、ヒアリング（alca様）で、管理者が割当を決めるときに見ているのは距離だけでなく
**顧客とスタッフの相性・スタッフの特性（資格・経験・得意分野）・顧客の希望（性別・人柄・継続）**だと分かっている。
PoC本体は「性別希望」と「NG」しか持たず、相性は登録のみ（学習しない）。

本デモ版の目的：

1. **すぐ触れる**：URLを開くだけで動く。サーバー・ログイン・費用なし。データはブラウザに残す。
2. **割当の条件を柔軟に試す**：「項目」と「重み（0〜5）」と「必須」で、事業所ごとに違う割当の考え方を
   管理者自身が組み立て、AI案がどう変わるかをその場で見られる。

デモで集めた反応（どの項目・重みが使われるか）を、PoC本体の要件（相性・希望の扱い）に戻す。

## 3. 要件

D番号は src・テストが参照するので振り直さない。置き換えた要件は「（廃止。→Dn）」で残す。各表は D番号の昇順。画面の細部（文言・寸法・読み上げ）は `docs/design.md`・`docs/design/`。

### 共通の決まり

- 「〈スタッフ〉」「〈利用者さん〉」は事業所の呼び方（`org.terms`）、事業所名は `org.name`
- 色だけで区別しない（形・文字を添える）。細かい数字は title と読み上げへ
- キーボードと読み上げで使える。モーダル（右の欄・確認・パレット・ツアー・引き出し）はフォーカスを中で回し、裏を操作させず、閉じたら元の要素へ戻す
- 狭い画面（390px）ではみ出さない。印刷では操作のボタン・浮く部品を出さない
- 主ボタン（濃い朱の塗り）は画面に1つ。ボタンは塗り＝主／枠＝副／文字＝ついでの3段（D238）。画面の見出しは同じ型（D236）。確認は独自の確認ダイアログ（D146〜D150）
- 文字・枠・フォーカスの輪は背景と見分けられる濃さにする（WCAG AA）。動きを減らす設定では動きを止め、タッチではアイコンのボタンを押しやすくする
- 画面の状態（開閉・選択・絞り込み）は特記が無ければ保存しない。要対応・進み具合などの数は保存せず毎回計算する
- URL の `?do=`・`?date=` は画面が1回だけ行い、URL から消す
- 古いデータ・ブックに無い列・シートは、空・なしとして読む

## 4. やらないこと（スコープ外）

- ログイン・アカウント・事業所の分離・サーバー保存・同時編集（1ブラウザ1事業所。別法人は別のデータで使う）
- Firebase・Cloud Functions・Python 最適化・Google Maps Platform（移動は直線距離の概算。道順は公開のリンクだけ）
- PoC本体の範囲（記録・位置計測・勤怠・実績・打刻・サイン・請求・LINE 連携・集金・通知）、PoC本体へのコードの書き戻し、PWA のオフライン対応、実在の個人情報を前提にした機能
- 相性の**学習**（手直しの記憶 D260 は学習ではなく、利用者が「次からも」と選んだ手直しを記録して固定するだけ。ADR-0043）、勤務シフトの自動作成・日をまたいだ最適化（まとめて作るは1日ずつ。ADR-0012）、定期パターンの日付指定・祝日
- 休みで訪問を自動で振り替える・確定を勝手に作り直すこと。決まりごとを割当の条件に使うこと（ADR-0013）
- 欠勤（ADR-0011）：本人からの連絡の受付・通知の自動送信・複数日の一括入力（希望休は D69）・理由の分類・有給・欠勤を入れただけでの振り直し・応援の臨時追加・中止や日時変更の自動提案・「いまの時刻」の扱い
- 希望休・担当を限る・印刷（ADR-0014）：申請・承認、休みの日数の決まりの確認・割り振り、担当を限る期間・理由、印刷の書式設定・PDF の書き出し

- 試算で、ほかの人の予定を動かして入れる提案

- 道順（ADR-0018）：Google から時間・距離・経路を取ること、アプリ内のナビ・現在地、開いたかの記録、ほかの地図アプリ
- 名簿（ADR-0020）：読み込みで人を消すこと、ほかのシートだけの部分の入出力、列ごとの差分の表示、読み込みの取り消し

- スマホ（ADR-0024・ADR-0055）：なぞって開く引き出し、タブの並びの選択、スマホでの訪問の追加・日時の変更・ドラッグ（ADR-0051 の決定5）、下から出る欄をなぞって閉じる・高さを変えること
- パレット（ADR-0027）：履歴での並べ替え・あいまいな一致・設定の値の検索・中での書き換え・キーの変更（訪問は〈利用者さん〉・担当の名前と日付・「担当なし」「要対応」で引ける。D304・D337。ADR-0051・ADR-0055）
- 手直しの記憶（ADR-0043）：記憶の一覧・1件ずつの編集・期限・強さの段階（費用での優遇）、ほかの人の担当からの推測、Excel への書き出し、空き時間に入れる（D50）・欠勤の振り直しへの適用
- 入り切り（ADR-0028）：権限、利用者・端末ごとの入り切り、料金・契約、業種での自動の入り切り、データの削除、Excel への書き出し、ひな形の保存

## 7. 制約

- 期限：初回デモの公開は**着手から1週間以内**（PoC本体 α版と並行し、その作業を止めない分量）
- 予算：0円（GitHub Pages・Actions の無料枠）。そのため**公開リポジトリ**
- 使う技術：React + Vite + TypeScript、Leaflet（国土地理院の地図）、Web Worker。PoC本体の `packages/shared` の純粋関数と seed 生成を**写す**
- 端末：管理者役は PC のブラウザ（Chrome・Edge・Safari の最新）。スマホは見る・取り消す・担当を替えるまで（ADR-0051 の決定5・ADR-0055）
- セキュリティ：架空データのみを同梱し、実データ・パスワード・キーを置かない。入れたデータは端末の外に送らない（外部送信は地図タイルと、ボタンを押したときの郵便番号・住所の検索だけ。ADR-0016）。メール（`mailto:`）と道順のリンクはアプリから何も送らない（ADR-0017・0018）
